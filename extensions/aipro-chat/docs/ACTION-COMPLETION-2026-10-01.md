# 누비 브라우저 액션 완료 품질 개선

2026-10-01. 전체 실모델 품질이 크게 개선됐다고 판정할 단계는 아니다. 이전 고정 ZIP의 Luna 30과제 기록은 개선 전 answered 26, timeout 1, agent_error 2, awaiting_user 1이고 개선 후 answered 22, timeout 2, agent_error 3, awaiting_user 3이다. answered는 응답 전달이며 독립 정답이나 실제 업무 성공률이 아니다. 승인 후 질문 대기는 자동 실패로 묶지 않는다. 이번 후보는 그 두 실모델 ZIP과 다르다.

## 관찰한 원인과 실제 반영

H-09의 실제 모델 실행은 승인 후 파일 선택을 완료했지만 verify_page 없이 계획과 단계/최종 검토만 완료했다. Pi 실행기는 검증 통과로 종료했고 실제 호스트는 verification_required로 응답을 차단했다. 승인 액션이 src/api.js에서 실행된 뒤 runAgent가 만들어지므로 createHarness가 그 액션을 관찰하지 못했다. 성공한 apply_approved_action 영수증을 실행기 시작 시 관찰하도록 수정했다. 파일 선택과 페이지 액션은 현재 결과 검증이 필요하며, Chrome 다운로드는 소유한 transfer_id의 완료 영수증으로만 종료하는 기존 경로를 유지한다. 미확정 액션은 별도 해소 없이는 통과하지 않는다.

E-05의 조회 과제는 명시적 verify_page가 실패했는데 앞선 입력이 없다는 이유로 실행기의 needsCheck가 false였다. 호스트는 실패 상태를 보존해 마지막 답변을 차단했다. 명시적 검증을 실행하면 조회 과제에서도 현재 검증 부채를 유지하도록 수정했다. 새 관찰과 원래 요청의 구체적인 조건을 확인한 뒤 통과한다. 취소와 미확정 쓰기 보호는 유지한다. 실패를 숨기거나 검증 조건을 제거하지 않는다.

## 방법론과 오픈소스 선택

[Anthropic 평가 방법론](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)의 transcript와 실제 outcome 구분을 적용했다. 모델의 완료 선언, 계획 완료와 검토 통과는 실제 파일 선택 검증의 대체물이 아니다. 실모델 실패 형태를 합성 모델로 고정하고 실제 Chrome FileList, 내려받은 바이트, 입력 횟수와 서버 제출 횟수를 독립 검사한다.

[Playwright actionability](https://playwright.dev/docs/actionability)와 결과 assertion을 분리하는 패턴을 유지했다. 기존 Playwright Chrome 실행기를 회귀 검증에 재사용하고 강제 클릭이나 보안 우회는 추가하지 않는다. 기존 Pi agent-core 0.87.1(MIT)의 같은 실행과 도구 결과 피드백을 재사용했다. 프레임워크 교체, 의존성 추가, 외부 런타임, 새 인증 저장소나 추가 병렬 에이전트는 도입하지 않았다. 이 문제는 실행기와 호스트의 검증 상태 연결 결함이므로 새 오픈소스 하네스의 도입으로 대체하지 않았다. [기존 검색 개선](RETRIEVAL-QUALITY-2026-10-01.md)의 MiniSearch와 LangChain 선택도 유지한다.
