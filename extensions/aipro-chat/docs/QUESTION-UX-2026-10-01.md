# 질문 화면 개선

사용자 결정: 선택 가능한 답변은 객관식으로 먼저 보여주고, 맨 아래에 직접 입력을 둔다. ‘기타’ 선택지를 따로 만들지 않고 예시 placeholder로 안내한다. 입력과 버튼 사이에 여백을 둔다.

## 적용

- 공통 질문 지침: 요청이나 관찰 근거로 구성할 수 있는 2~4개 객관식을 기본으로 한다. 알 수 없는 팀 이름, 개인 값, 긴 본문 등은 억지로 선택지를 만들지 않는다. 한 번에 다음 행동에 필요한 질문 하나를 묻는다.
- 공통 QuestionForm: 직접 입력이 있을 때 정확한 ‘기타’, ‘기타 (직접 입력)’, ‘직접 입력’, ‘직접 답변’, ‘Other’ 계열의 중복 입력 버튼을 표시하지 않는다. 실제 업무 이름처럼 ‘기타 업무팀’은 제외 대상이 아니다. 원래 선택 ID를 그대로 제출하며 승인/이미지 선택을 변경하지 않는다.
- 입력란은 모든 선택지 뒤에 항상 보인다. 기본 placeholder를 ‘예: …’로 바꾸고, 모델에는 질문에 맞는 짧은 예시를 요청한다. 예시는 실제 답변이나 사전 입력 값이 아니다.
- 입력/버튼 간격은 0→12px, 입력 영역 안쪽은 세로 8/가로 12→16px, 최소 입력 높이는 52→64px로 바꿨다. 기존 CX/누비 색, 서체, 버튼, 반경과 동작을 재사용한다.
- 직접 답변의 접근성 label은 유지한다. 일반 Enter는 전송하지 않고 화살표 버튼 또는 Ctrl/⌘+Enter로 전송한다. IME, 줄바꿈, 독립된 답변 초안, 전송 실패 복구를 유지한다.

## 방법과 선택

새 UI 패키지 대신 기존 React/CX 컴포넌트와 공통 토큰을 수정했다. 새로운 의존성이나 라이선스 변경이 없다. [W3C 폼 레이블 지침](https://www.w3.org/WAI/tutorials/forms/labels/)에 따라 주변 질문으로 시각적 목적을 설명하면서 프로그램상 label은 보존했다. placeholder를 접근성 이름의 대체물로 쓰지 않는다.

## 검증

`tests/question-forms-browser.mjs`의 실제 Chrome + 합성 제공자 응답 검사에서 다음을 확인했다.

- 320/360/1100px 창의 가로 넘침 없음, 질문/선택지 14px Noto Sans KR.
- 입력란은 선택지 아래 16px 이상, 버튼은 입력란 아래 12px 이상, 입력 영역 안쪽과 버튼 아래 16px 이상.
- 모델이 두 실제 선택지 사이에 ‘기타 (직접 입력)’를 넣어도 화면에는 실제 두 선택지만 표시하고 원래 세 번째 ID로 올바른 답변을 전달한다.
- 선택/직접 입력, 15분 가상 대기 및 새로고침, 대화 전환, 한글 IME, 다중 행 붙여넣기, 길이 초과 거부, 전송 실패 후 내용 보존, 연속 질문/원래 목표 보존 통과.
- 실제 좁은 화면 이미지와 긴 답변 이미지 확인. 모션 감소 환경에서 질문 카드 애니메이션 없음 확인.

전후 스크린샷은 `verification/improvement-2026-10-01/question-ui-before/` 및 `verification/question-choice-{320,360,1100}.png`다. 디자인 검사와 후보 빌드를 통과했다. 실모델의 객관식 생성 빈도는 이 합성 UI 검사의 측정 대상이 아니다.

이 변경은 이미 고정한 Luna/Sol 하네스 비교 후보 A 이후의 후보 B다. A의 실모델 점수를 B의 실측 점수로 표시하지 않는다. 공통 소스를 사용하는 Office/Desktop의 실제 호스트 화면 검증도 이번 Chrome 검증과 별도다.

질문 지침 확장으로 16k 문맥 예산 검사 1개가 실패해 중복 문장을 줄였고, 기존 사용자 조건/최신 정정을 보존하는 38개 집중 검사를 통과했다. 이전 실패는 `pre-release-2026-09-30T17-29-17-998Z`에 남긴다. 별도 입력 영수증 검사에서 고정 300ms 대기 후 취소가 다음 필드의 stale 거부와 경쟁하는 문제를 확인했다. 임시 테스트 확장의 실제 첫 fill 반환 직후 취소하도록 동기화했고, 이미 반영한 첫 값 보존/두 번째 필드 미입력/부분 결과의 미확정 계약은 그대로 검사한다. 제품 취소 코드를 변경한 것은 아니다.

번호 보완 전 후보 B: SHA-256 `9732cc41c4966a6a705fa29a178083b6c3a725f72595dcd13c11f1768806ba07`. `verification/pre-release-2026-09-30T17-37-03-940Z/report.json`에서 전체 단위 1,591개, 디자인, 후보 빌드 및 선택한 Chrome 13개 스위트, 합계 16단계 통과. 소스/검사/의존성 및 빌드 해시가 종료 시 동일함을 확인했다. 전체 브라우저 3회 반복 매트릭스 통과를 의미하지 않는다. 보존 ZIP: `verification/improvement-2026-10-01/question-ui.zip`.

추가 검토에서 숨긴 ‘기타’가 모델의 질문 문맥에는 남아 화면의 선택지 번호와 달라지는 문제를 찾았다. `questionDisplayOptions`를 화면과 모델 문맥에 공통 적용해 보이는 2번을 모델도 2번으로 보도록 맞췄다. 저장된 원래 선택 ID와 답변/승인 계약은 변경하지 않는다. 명시적 승인, 이미지, 자유 입력이 없는 native dialog의 선택지는 그대로 유지한다. 새 회귀 검사는 번호 일치, 원래 ID 답변 연결, 일반 업무 이름 보존을 검증한다.

번호 일치 보완까지 포함한 최종 후보: SHA-256 `997f0b343974634fc51757489744f8c35f3e80ac156e6d3787faf5e8f9bbf2df`. `verification/pre-release-2026-09-30T18-03-05-078Z/report.json`에서 전체 단위 1,599개, 디자인, 후보 빌드와 Chrome 14개 스위트, 합계 17단계를 통과했고 종료 시 해시 일치를 확인했다. 최종 보존 ZIP은 `verification/improvement-2026-10-01/question-ui-final.zip`이다. 이전 후보와 실패 이력은 그대로 남겼다.

최종 검증 중 동일 작업공간의 별도 기능 변경도 확인됐다. 이전 후보와 비교해 질문 관련 파일 외 agent-harness/agent-runtime/background-runner/browser-dom/browser-replay/site-procedures/task-plan 및 public/scripts/tests 해시가 달라졌다. 이 변경을 이번 질문 개선의 성과로 귀속하지 않으며 덮어쓰지 않았다. 최종 ZIP은 그 시점의 작업공간 스냅샷이고, 입력/빌드 해시는 검증 시작과 종료에 동일했다. Luna/Sol 실측은 별도로 동결한 A ZIP에서 실행돼 이 병행 변경과 섞이지 않았다.
