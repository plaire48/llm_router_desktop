# 누비 브라우저 개선 적용과 검증

사이트 절차 재사용, 긴 원문 조건 탐색, 독립 웹 조사와 A2A 연결을 적용했다. **고정 후보의 구현 검사는 통과했으며 Sol/Luna 30과제의 독립 정답 비교는 진행 중**이다. 구현 통과를 실제 업무 정확도나 속도 향상으로 표시하지 않는다.

## 실제 적용한 방법

- [Anthropic 독립 조사 방법](https://www.anthropic.com/engineering/multi-agent-research-system)의 작업 범위/요구 항목/출처 분리와 독립 검색을 기존 Pi에 적용했다. 새 agent framework는 추가하지 않았다. Pi와 p-limit은 기존 MIT 의존성을 재사용한다.
- [A2A 1.0](https://a2a-protocol.org/v1.0.0/specification/)과 Apache-2.0 공식 SDK 1.2.0을 유지한다. Task 완료는 전달 상태이며 호스트 실행/정답/파일 저장 검증은 별도다. 중복 메시지는 영수증과 Task 조회로 복구한다.
- 조건 색인은 결정적 원문 검색 패턴이다. 모델이 읽지 않은 내용을 사실로 합성하는 캐시를 만들지 않았다. 키워드가 많은 문서는 최대 24개 위치와 누락 수를 표시한다.
- 평가 탭이 닫힌 경우 완료/오류/실행 중으로 기록된 과제를 재전송하지 않는다. 같은 후보/모델의 정확한 미시작 나머지만 새 실행에서 이어간다. 원본 보고서를 보존한다.

전체 BP 선택/비선택 근거는 [기존 검토](../../../docs/research/2026-10-01-nubi-browser-harness-quality-bp.md)를 재사용한다. 별도 Python 런타임, MCP 서버와 Chrome debugger 설치를 조사 워커에 추가하지 않았다.

## 실모델 평가 중 발견한 복구 문제와 별도 후보

고정 후보 `e3c3b18e...`의 H-02에서 클릭 응답 시간 초과 뒤 공식 예약 페이지로 실제 이동했지만, 원래 클릭의 미확정 영수증이 남았다. 후속 `verify_page`는 현재 본문의 조건을 확인했을 뿐 원래 동작을 대조하지 못했다. 실행기 진단은 `verification:passed`인데 최종 호스트는 `verification_required`로 응답을 보류했다. 최종 호스트의 차단은 유지해야 한다.

별도 소스 보완은 알려진 정보 링크의 클릭 내부 navigation 대기를 해제하고 기존 관찰과 검증으로 이어간다. `force`를 켜거나 미확정 동작을 자동 재실행하지 않는다. `unresolvedAction`은 하네스와 저장 상태에서도 별도 빚으로 보존하며, 일반 페이지 검사 성공으로 해제하지 않는다. 유효한 호스트의 원래 대상 대조만 해제할 수 있고 그렇지 않으면 같은 실행의 질문으로 사용자 확인을 기다린다.

[Playwright의 ElementHandle.click 문서](https://playwright.dev/docs/api/class-elementhandle#element-handle-click)는 `noWaitAfter`를 navigation 대기에서 벗어나는 예외적인 수단으로 명시한다. 기존 document-bound ElementHandle과 실제 대상 확인은 유지한다. Locator 전환은 관찰한 대상을 임의 재선택할 수 있어 이번 수정에 채택하지 않았다.

- 관련 회귀 검사: 78/78. `post-eval-reconciliation-unit.log`.
- 실제 Chrome와 9초 지연하는 동일 loopback 원문: 개선 전 ZIP은 원문 이동 뒤 `script_timeout`; 별도 보완 후보는 1회 요청, 원문 URL/본문 검증 성공. `before-link-chrome.log`, `post-eval-link-chrome-full.log`. 실제 모델 평가나 전체 속도 개선 점수가 아니다.
- 진행 중인 Sol/Luna 30과제 비교는 원래 고정 후보를 유지한다. 이 보완 후보의 집중 검사를 해당 전체 비교 점수로 섞지 않는다.
- 원래 평가 보고서와 기술적 실패는 보존한다. `before-sol-30-composite.json`은 분리된 과제를 합친 파생 자료이며 H-03의 읽기 전용 하네스 오류 재측정을 별도 provenance로 기록한다. 모델 실패를 이후 성공으로 바꾸지 않는다.

## 코드 실행 실패 추가 개선

사용자 지적 이후 실제 Sol 전후 30과제와 진행 중인 Luna 진단을 다시 분류했다. `browser-failure-audit-2026-10-01.json`은 원본 SHA와 수집 시점을 포함한 진단 스냅샷이다. native `browser_tool`과 runtime `tool_result`는 같은 호출을 서로 다른 계층에서 기록하므로 합산하지 않는다. 이 자료의 부분 Luna 행 수는 완료 과제 수나 정확도가 아니다.

Sol 개선 후에서 실제 `run_playwright` 오류로 기록된 호출은 이전 미확정 동작 때문에 실행을 보류한 1건이다. 그 외 ‘코드 실행 실패’로 보인 사례에는 페이지 로딩과 접근 제한, `wait_page`의 명세 불일치가 섞여 있었다. 관찰하지 못한 내부 JS 예외를 모두 해결했다고 주장하지 않는다.

| 발견한 문제 | 실제 변경 | 복구 경계 |
|---|---|---|
| `wait_page({timeout_ms:...})` 3건을 잘못 거부 | 명세대로 조건 없는 250..15000ms 대기와 새 관찰 지원, 잘못된 조건은 `wait_arguments_invalid` | 대기는 요청 완료나 저장 성공 증거가 아님 |
| 로딩과 접근 제한을 JS 오류로 분류 | 화면의 고정 사유와 모델 복구 지침 분리 | 접근 제한을 권한 부족으로 단정하거나 코드로 우회하지 않음 |
| 입력 형식 오류의 사유가 진행 화면에서 사라짐 | 실행 전 스키마 거부에도 `reason:tool_arguments_invalid` 유지 | 인자를 자동 삭제/변환하거나 거부한 호출을 실행하지 않음 |
| 느린 원문 링크 클릭 후 미확정 상태 | 알려진 정보 링크만 내부 navigation 대기 해제, 실제 본문 대조 | 버튼/거래 승인, 대상 바인딩, 가림/비활성 검사는 유지 |
| 페이지 검사 성공으로 미확정 동작이 해제됨 | 하네스와 저장 상태에서 원래 미확정 영수증 별도 유지 | 원래 대상 대조 없이는 자동 재실행/완료 금지 |

기존 Acorn 사전 검사, QuickJS WASM 실행 격리, 단일 RPC 실행 영수증과 전용 `fill_form`을 재사용한다. 새 framework나 의존성을 추가하지 않는다. [Playwright 공식 actionability](https://playwright.dev/docs/actionability)의 가시성/안정성/실제 입력 수신/활성 상태 검사를 유지한다. 관찰한 입력에는 전용 도구를 쓰고, 스크립트 문법/API 오류는 어떤 입력도 내보내기 전에 거부한다.

`browser-recovery-final-source.json`은 별도 수정 후보를 고정한 기록이다. 이 후보의 집중 Chrome 검사는 9초 지연 원문을 1회만 열어 URL/본문을 대조하고, 대기 계약 및 잘못된 대기 무동작을 확인하며, 문법/미지원 API 실패 뒤 새 관찰의 입력란에 1회 입력하고 실제 값/이벤트 수를 확인한다. 기존 Sol/Luna 30과제의 후보와 점수에 합치지 않는다. 검사 결과는 `browser-recovery-final-*.log`와 별도 `browser-recovery-result.json`에 기록한다.

- 최종 별도 후보: 전체 **1,672/1,672** (검사 동시성 2), 디자인/빌드 통과. 무제한 동시 실행에서는 기존 2500ms 분석 수집 검사 1개가 취소됐고 이전/수정 후보 모두 해당 파일 별도 실행 **4/4** 통과. 실패 로그와 제품 시간 제한을 유지했다.
- 실제 Chrome 집중 **3시나리오 묶음** 통과, 모델 호출 없음. 첫 확장 검사에서 잘못 쓴 `field_equals`는 실제 실행기가 거부했고, 검사만 선언된 `field_value`와 새 ref로 고쳐 전체 재검증했다. 그 실패 로그도 보존했다.
- `browser-recovery.zip`: SHA-256 `f857da87856ebc9cb32804c572d416ace4810870c8fb74919f0a453c5d52230c`. 소스에 반영한 별도 후보이며 설치/배포 성공은 아니다.
