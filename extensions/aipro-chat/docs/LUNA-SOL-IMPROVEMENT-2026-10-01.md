# Luna/Sol 개선 전후 비교

## 고정 기준

개선 전은 beta.41, Chrome 1.4.44, ZIP SHA-256 `9a8e224e627a047bbfae70c78fbb758587ffe82d8a41567a5e2cf669855a8284`다. 소스와 ZIP은 `verification/improvement-2026-10-01/`에 보존했다. 같은 과제의 GPT-5.6 Luna와 Sol을 각각 비교한다. 서로 다른 후보의 성공을 합산하지 않는다.

집중 과제는 E-02/M-04(단순 조회), H-04/H-06(출처 비교), H-07(긴 문서), M-08(조건부 입력), H-10(질문/정정)이다. 집중 검증 이후 전체 30개는 별도 점수로 기록한다. 기존 평가기의 난이도별 제한(쉬움 180초, 중간 300초, 어려움 480초), 최대 모델 호출 120회, 무활동 120초, 화면 결과 뒤 5초 대기를 전후 동일하게 유지한다. 로그인 대기는 업무 실패로 세지 않는다.

## 이번 변경의 선택

1. 모달의 위치만으로 확인/OK를 승인에서 제외하는 규칙을 제거한다. 모호한 확인도 기존 정확한 대상/문서/fingerprint 승인 경로로 보낸다. 명확한 닫기/검색/초안 저장은 기존 분류를 유지한다. 추가 승인과 일반 조작 회귀를 함께 공개한다.
2. 비교 요청의 첫 출처가 확보되면 기존 격리 분석을 바로 시작해 다음 출처 열람과 겹친다. 동시 2개, 미수집 포함 6개, 읽기 전용, 중복 방지와 원래 조건 인계를 유지한다.
3. 주 실행기에 반복 전달되는 자동 캡처 원문은 완전한 실행 내 원본과 정확히 일치할 때만 재조회 참조로 바꾼다. 최근 두 캡처, 실제 행동 영수증, 원본 최종 검토 근거는 보존한다. 유실/절단/다른 출처/실패는 축약하지 않는다.

4. 기준 M-08에서 실제 입력은 완료됐지만 제출 금지의 근거가 없어 78회 호출 후 시간 초과됐다. select_option의 실제 대상 영수증을 보존하고 전체 클릭/입력/선택 이력을 검토기에 제공한다. 별도 제출 동작을 호출하지 않았다는 좁은 사실과 서버 자동 저장 여부를 구분한다.

기존 Pi(MIT), p-limit(MIT), MiniSearch(MIT)를 재사용한다. 새로운 병렬 웹 탐색기는 탭 수명과 권한 경계를 추가하므로 이번 측정과 섞지 않는다. 먼저 기존 탐색과 하위 분석의 실제 겹침, 문맥 중복 제거 효과를 비교한다. 전체 하네스 교체와 워커 수 증가는 채택하지 않는다.

근거는 [Anthropic 병렬 조사](https://www.anthropic.com/engineering/multi-agent-research-system), [문맥 관리](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [결과 중심 평가](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)다. 방법론 참고이며 타 제품 성능을 누비 성능으로 옮기지 않는다.

## 판정

- 응답 전달과 원래 요구사항의 독립 채점을 분리한다. 모델의 complete는 독립 통과가 아니다.
- 성공/실패/미판정, 잘못된 완료, 승인 전 쓰기/중복 쓰기, 불필요한 질문, 모델 호출, 실제 작업 시간과 사용자 대기, 입력량을 각각 보고한다.
- 승인 전 쓰기/중복 쓰기/취소 뒤 실행/다른 탭 조작은 채택 중단 조건이다.
- 단순 조회의 시간/호출 회귀와 복잡한 조사 성공률을 함께 비교한다. 한 회차의 시간 차이를 통계적 개선으로 부르지 않는다.
- 동일 후보의 전체 결과를 확보하기 전 집중 과제 결과를 전체 품질 점수로 표시하지 않는다.

## 상태

개선 전 Luna와 Sol 각 7개 측정과 독립 채점 완료. Luna는 2/7, Sol은 6/7을 확인했다. 개선 후보 A는 SHA-256 `36fbc5372340c5cee0cc58de712fdd1172ed1d76e42804db08ae8d902f22bef8`로 고정해 두 모델의 전후 실측을 마쳤다. 이후 사용자 요청의 질문 화면 수정은 별도 후보 B이며 [질문 UX 기록](QUESTION-UX-2026-10-01.md)에 구분한다.

## 잔여 개선의 수용 기준

- 질문/답변 재개: 같은 작업의 호스트 실행 이력을 질문 전후로 연결하되 작업/대화/사용자 정정 범위를 확인한다. 기록 누락, 다른 작업, 재시작, 미확정 쓰기에는 금지 동작 부재 증명을 부여하지 않는다. 모델 요약으로 이력을 재구성하지 않는다. H-10의 개발팀→운영팀 정정, 원본 메모 보존, 등록 0회와 불필요한 재질문 없이 완료를 실제 모델로 확인한다.
- 긴 문서 분할: 사용자가 독립 구간 분담을 요청한 경우 관찰된 제목/범위로 서로 다른 구간을 배정하고 수집한다. 한 출처에 하위 호출 하나를 추가한 것을 A/B/C 분할 완료로 표시하지 않는다. 말미 예외 원문과 미열람 범위를 별도로 검증한다.
- 기관별 조사: 모든 기관의 독립 원문을 실제로 열고 출처별 조건을 확인한다. 검색결과 요약만 공유한 하위 분석을 기관별 원문 조사로 표시하지 않는다. 별도 탭 조사 도입 여부는 기존 RESEARCH-WORKERS 설계의 권한/수명/취소/출처 혼합 회귀를 먼저 충족해야 한다.

## 로컬 검사 이력

기준 후보는 전체 142개 스위트/291단계를 통과했다. 개선 후보 A의 두 번째 회귀에서는 단위 1,591개, 디자인, 빌드와 101개 단계가 통과한 뒤 Chrome 프로필 시작이 180초 제한을 넘겨 중단됐다. `completion-review-browser-2`의 모델/검토 호출은 모두 0으로 시나리오 시작 전 실패였다. 같은 스위트를 단독 진단 실행해 7개 경우 통과를 확인했다. 원래 실패 보고서는 그대로 보존하며 전체 매트릭스 통과로 바꾸지 않는다. A의 실모델 비교는 진단 실측이며 배포 gate 승인이 아니다.

## Luna 실측 결과

같은 7개 과제에서 독립 통과는 2→4개, 전체 계획/최종 검토를 마친 응답 전달은 2→5개다. 개선 후에는 실패 2개(H-04/H-07), 조건 일부 미확인 1개(H-06)가 남는다. 미확인을 통과로 계산하지 않아 확인된 통과 하한은 4/7(57.1%)이며 확정 성공률은 표시하지 않는다.

- M-08: 실제 DOM은 전후 모두 맞지만 기존에는 검토 반복으로 301.2초/78회 후 시간 초과. 이후에는 69.6초/15회로 응답까지 완료했고 모달 유지, 메모 보존, 제출 0회를 독립 확인했다.
- H-10: 이전에는 개발팀 답변 뒤 확인 반복에 머물렀다. 이후에는 180초 대기 안정성, 개발팀 반영, 운영팀 정정, 원본 메모/제목 보존과 제출 0회를 확인했다. 한 번의 성공이 질문 전후 실행 이력의 구조적 보존을 입증하지는 않는다.
- H-04: 호출 39→29회, 211.5→140.1초지만 모두 제한 답변이다. 실패를 더 빨리 보고한 것을 조사 성공으로 세지 않는다.
- H-07: 이전에는 하위 배정이 없었고 이후에는 실제 3개 하위 작업과 수집이 있었다. 두 경우 모두 최종 제한 답변이며, 이후 A 말미는 host 근거로 확인했으나 B/C의 실제 읽기 범위는 저장된 거친 진단만으로 확정하지 못했다. 호출은 20→40회로 증가했다.
- H-06: 이후 시간표와 첫 출처 재방문은 확인했고 응답은 complete였으나 국립중앙도서관의 예약/로그인 서비스 제외 범위가 명확하지 않아 해당 조건은 미확인으로 남겼다.
- 단순 조회 E-02는 28.9→34.4초로 느려졌고 호출은 5회로 같다. M-04는 108.9→67.6초/24→14회다. 단일 회차이므로 통계적 성능 향상을 주장하지 않는다.

전후 원시 보고서, 독립 `.grades.json`, `.score.json`과 과제별 시간/호출 표는 `verification/improvement-2026-10-01/COMPARISON.md`에 연결한다.

## 다음 조사 개선의 구체화

`comparison-analysis.js`는 리더가 이미 관찰한 스냅샷만 읽기 전용으로 위임한다. 현재 첫 본문 확보 경로는 검색결과도 후보로 포함한다. Luna H-04의 개선 후 host 근거에는 네이버 검색, 서울도서관 홈페이지와 아주 짧은 본문만 있고, 실제 하위 작업도 부분 보고를 반환했다. 따라서 ‘출처 수/하위 호출 수 증가’를 기관별 조사 완료로 간주하지 않는다.

다음 실험은 관찰한 기관별 원문 링크를 리더가 실제로 확보하고, 출처별 요구 항목(자격/시간/절차)과 관찰된 문서 범위를 독립 배정에 연결하는 것이다. 검색 스니펫과 공식 안내 원문을 별도 역할로 표시하고, 하위의 원문 해시/읽은 구간/반환 인용 구간을 호스트 기록에서 대조해야 한다. 빈 홈페이지/링크만으로 원문 조사 작업을 완료 처리하지 않는다. 이 기록은 모델 보고의 자기 선언이 아니라 실제 조회 경계에서 생성해야 한다. 이번 후보 A/B에는 이 후속 설계를 구현한 것으로 표시하지 않는다.
