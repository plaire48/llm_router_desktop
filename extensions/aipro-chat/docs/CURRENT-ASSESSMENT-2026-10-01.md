# 누비 브라우저 익스텐션 현재 평가

2026-10-01 09:46 KST의 소스와 기록을 점검했다. 현재 판단은 **기능 구성 중, 실행 보호는 검증 범위에서 상, 자율 완수 중, 복잡한 조사와 속도 하**다. 제품 전체를 임의 가중 점수로 합치지 않는다.

새 복구 후보 `f857da87...`는 위 전후 평가의 후보가 아니다. 집중 복구 성공을 전체 실모델 성능 향상으로 바꾸지 않는다. Sol 완료 전달은 24→23으로 전체 향상을 입증하지 못했으며 기술 수집 오류도 포함되어 코드가 성능 저하를 일으켰다고 단정할 수 없다.

**속도는 아직 목표에 부족하다.** Sol에서 완료 답변을 전달한 과제만의 관찰 중앙값은 개선 전 64.4초, 비교 후보 67.1초다. 서로 다른 성공 과제 집합이고 일부 평가/검사가 같은 호스트에서 동시에 실행돼 순수 개선율이 아니다.

H-04는 실행 27회, 하위 분석 17회, 검토 9회다. 모델 호출 중인 구간의 합집합은 443.6초로 전체 관찰 시간의 약 93%다. 이는 해당 사례의 host inference 시작/종료 기록이며 모델 순수 계산 시간이나 모든 업무의 병목 비율은 아니다. 병렬 호출의 시간을 단순 합산하지 않았다. 이 사례에서는 클릭 애니메이션보다 필요 없는 원문 재조회/분석/검토와 큰 모델 입력을 줄이는 쪽이 우선이다.

**개선 순서**는 완료 품질을 유지하면서 호출을 줄이는 방향이다.

1. 원래 요청의 필수 항목과 실제 근거를 연결해 미확인 항목만 조회하고, 답변 수정과 새 행동을 구분한다. 완수율/정답률을 먼저 보호한다.
2. 같은 문서/값/요구사항의 통과 검토를 재사용하고, 단순 폼은 전용 도구와 검토형 Wiki 카드로 처리한다. 원래 최종 검토/HITL은 유지한다.
3. 복잡한 조사에서 독립 워커가 실제로 필요한지/실행됐는지 확인하고 원문/누락 항목을 한 번에 인계한다. 병렬화 자체를 개선으로 계산하지 않는다.
4. 동일 후보의 Sol/Luna 30과제와 기준 Qwen 실측, Wiki cold/warm, 처음 보는 양식, 실제 서비스 업무를 분리해 반복 평가한다. 완료 전달/독립 정답/중복 행동/호출/시간을 각각 비교한다.

[Anthropic의 agent evals 방법론](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)의 실행 기록과 최종 환경 결과 분리, 회귀와 능력 평가 분리를 재확인했다. [Playwright actionability](https://playwright.dev/docs/actionability)의 실제 입력 가능 상태 검사와 기존 승인 경계를 유지하는 개선을 우선한다. 기존 MIT Pi/MiniSearch/p-limit와 Acorn/QuickJS를 재사용하는 쪽이 현재 결함과 비용에 맞으며, 새 framework/관측 SDK를 이 평가에서 도입할 근거는 없다. 기존 [BP 검토](../../../docs/research/2026-10-01-nubi-browser-harness-quality-bp.md)의 실제 도입/참고와 라이선스 구분을 유지한다.
