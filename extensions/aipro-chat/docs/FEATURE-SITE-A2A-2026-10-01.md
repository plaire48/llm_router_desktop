## 적용한 변경

사이트 지식은 첫 모델 호출 전 현재 제공자/사이트 범위의 위키를 MiniSearch로 조회한다. 추가 모델 호출은 만들지 않는다. 사용자가 검토한 위키에 **정상 최종 요구사항 검토까지 끝난 단일 폼 입력**만 연결할 수 있다. 과거 값, 승인, DOM ref, ordinal 대상, 스크립트, 클릭/등록 절차를 저장해 자동 승계하지 않는다. 실행 시 위키 버전/해시와 현재 전체 입력 항목, 필수/편집 상태/제약을 두 번 확인해 새 ref에 연결한다. 현재 요청의 값을 기존 fill_form/HITL/native readback 경로로 보내고 일반 단계/최종 검토를 유지한다. 구조 변경/추가 필수 항목/위키 삭제/만료는 쓰기 전에 거절한다. 메뉴 탐색, 조건부 선택, 제출까지 재사용하는 범용 워크플로는 이번 구현이 아니다.

다운로드는 Chrome의 실제 complete/파일명 기록을 typed receipt로 반환한다. 웹페이지 verify_page는 다운로드 완료 근거가 아니며, 해당 일회 전송의 ID가 일치할 때만 그 전송의 미검증 상태를 해소한다. 이전/이후의 다른 페이지 쓰기나 재개 시의 불명확한 상태를 지우지 않는다. 내용 무결성/현재 파일 존재와 전송 완료를 별도 표시한다. 다운로드를 다시 실행해 확인하지 않는다.

업로드는 list_upload_targets가 현재 보이는 native FileList의 파일명과 바이트 수를 반환한다. 파일 경로나 본문을 반환하지 않는다. 선택만 요청한 작업에 서버 등록을 새로운 완료 조건으로 추가하던 안내를 수정했다. 사이트가 선택 즉시 전송할 수 있으므로 기존 정식 승인을 유지한다. 서버 등록 요청은 별도 실제 서버 결과 검증을 요구한다.

## A2A 확인과 구현 범위

기존 packages/nubi-a2a 코어는 있었으나 브라우저 ZIP/설정 UI/RPC/실행 바인딩이 비활성이었다. 설정의 **누비 작업 연결**, 수신 RPC, trusted session 연결, 가져온 초안의 명시적 전송, 해당 호스트 실행의 결과 회신과 SDK/라이선스 번들을 복구했다. 기존 작성 중인 초안과 질문을 덮어쓰지 않는다. 수신 내용은 요청과 참고 자료이며 과거 승인이나 인증은 전달하지 않는다. caller가 임의로 넣은 답변 대신 바인딩된 호스트 답변만 보내고 소스가 달라진 결과는 거절한다.

검증된 범위는 **로컬 조정 서버와 브라우저 사이의 nubi-collaboration-v1 초안 전달**이다. A2A COMPLETED는 초안이 전달됐다는 뜻이다. artifact의 verification은 not_run이며 사이트 테스트/서버 저장 성공을 의미하지 않는다. 현재 내부 subagent를 A2A 워커로 바꾸지 않았다.

사용자 요청에 따라 아래를 후속 필수 구현 범위에 포함한다. 프로토콜 코어가 있다는 이유만으로 완료로 처리하지 않는다. 상세 실행 연결과 통과 기준은 [A2A 통합 명세](../../../docs/superpowers/specs/2026-10-01-nubi-browser-a2a-integration.md)에 기록했다.

1. Desktop 실앱의 비활성 송신 UI/실행 경로를 브라우저와 연결하고 실제 요청/결과 수신을 확인.
2. 코어에 있는 nubi-task-v1 작업 수락/진행/완료/취소를 브라우저 호스트의 동일 실행/HITL에 연결. 현재 코어 13개 검사에는 이 전송 계약도 포함되지만 브라우저 UI는 초안 전달 계약을 사용함.
3. 실제 브라우저 실행의 독립 페이지/파일 증거를 버전과 함께 전달하는 artifact 계약. 현재 초안 텍스트를 검증된 실행 증거로 승격하지 않음.
4. 두 실앱과 실계정 모델의 왕복, 중단/재연결/취소/중복 전송 검증. LAN/클라우드 발견, 자동 원격 실행과 Office 연결은 이번 범위가 아님.

## BP와 선택 근거

사이트 지식 설계는 [조사 및 채택 기록](../../../docs/research/2026-10-01-browser-site-knowledge-automation-bp.md)과 [승인 범위 명세](../../../docs/superpowers/specs/2026-10-01-nubi-browser-site-procedures.md)를 따른다. 기존 Pi/MiniSearch를 유지하고 Stagehand의 현재 대상 확인/결정적 동작 캐시 패턴을 참고했다. 별도 클라우드 캐시, Python 실행기나 새 에이전트 프레임워크는 채택하지 않았다.

파일은 [Chrome downloads 공식 계약](https://developer.chrome.com/docs/extensions/reference/api/downloads)의 complete와 지연된 exists, [native files 계약](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/files)을 재확인했다. 완료/내용/서버 저장을 다른 증거로 다룬다. 파일 확인을 위해 별도 런타임이나 재다운로드를 추가하지 않았다.

A2A는 [공식 1.0 명세](https://a2a-protocol.org/v1.0.0/specification/)와 설치된 @a2a-js/sdk 1.2.0의 실제 JSON-RPC/Agent Card/Task 코드를 재사용했다. Apache-2.0와 종속 jose의 MIT 고지를 함께 번들한다. 직접 만든 유사 프로토콜 대신 기존 SDK를 유지한다. gRPC/streaming/push/외부 모든 에이전트의 적합성 인증은 주장하지 않는다.

## 검증 기록

검사와 미완료 실측은 별도 [증거 폴더](../verification/site-procedures-2026-10-01/)에 보존한다. 이전 검사 및 실패 로그를 교체하지 않는다. 공유 작업 폴더의 다른 개선도 후보에 포함될 수 있어 위키만의 인과 효과로 단정하지 않는다.

- 공통 A2A: 13개 SDK 실제 HTTP/격리/취소/중복/재시작/수신기 검사 통과.
- 브라우저 A2A: [Chrome 7개 검사](../verification/a2a-2026-10-01/chrome.json) 통과. 고정 합성 모델이며 실계정 결과 아님.
- 사이트 절차: Chrome 7개 검사 통과. 새로운 값과 실제 DOM, 일회 실행, 버전/구조 변경 거절 및 삭제 연계 확인.
- 파일 완료: 단위 27개 통과. matching receipt와 불일치/중단/오류 거절, 앞뒤 미확정 쓰기 보존, 호스트 저장 상태 계약 검사 포함. [실제 Chrome 파일 검사](../verification/transfer-completion-2026-10-01/chrome.json) 2개 통과. 다운로드 파일의 독립 SHA-256와 업로드 FileList의 이름/크기/본문을 확인했으며 서버 제출은 0회. 모델 응답은 고정 합성 모델이고 실모델 완료율은 미측정. 승인 재개가 이미 통과한 검증을 일괄 초기화하던 문제를 수정하고 해당 실행의 실제 다운로드 영수증을 검토 근거에 연결했다. 이전/이후 미확정 쓰기는 유지한다.
- 최근 전체 단위 검사: 1,628개 통과. 디자인 검사 통과. 이전 실패는 VM 테스트의 새 모듈 URL 해석 누락으로 수정했다.
- 기존 실모델 로컬 10과제: Sol/Luna 원본 보존. Sol은 8개 답변 전달, H-08/H-09 중단. 전달률은 실제 정답률이 아니다.
- 위키 반복 비교: Luna 기존 위키 5회 재사용 원본 확보. Sol 비교는 Chrome의 재사용 모듈 해시 불일치로 중단 후 실행별 격리를 적용했고 새 SSO 대기로 미완료. 개선량/전체 30과제 점수는 미확정.
