# 하네스 1단계 결과

새 열람 구간의 후속 분석, 실제 원문 인용 대조, 미분석 범위 전달을 구현했다. 단위와 Chrome 회귀는 통과했지만 H-07 실모델 비교에서 **전체 과제 품질 개선은 확인하지 못했다.** 이 후보를 성능 개선판이나 출시 완료로 표시하지 않는다.

## 고정 H-07 비교

| 모델 | 전체 과제 전 → 후 | 독립 조건 전 → 후 | 모델 호출 전 → 후 | 경과 시간 전 → 후 |
| --- | --- | --- | --- | --- |
| GPT-5.6 Luna | 실패 → 실패 | 1/4 → 3/4 | 20 → 40 | 89.5초 → 159.4초 |
| GPT-5.6 Sol | 통과 → 실패 | 4/4 → 4/4 | 21 → 45 | 96.2초 → 207.1초 |

Luna는 C팀/30일을 포함한 비교 값과 실제 하위 배정/수집이 보완됐지만, 관찰된 원문 범위는 모든 말미 예외를 입증하지 못했다. 검색 위치와 맞는 숫자만으로 본문 열람을 인정하지 않았다.

Sol은 독립 정답과 말미 원문 범위를 충족했으나 제품의 최종 검토가 하위 담당 근거를 확인하지 못해 limited 답변으로 끝났다. 실제 배정/수집 기록과 최종 검토에 전달된 정보의 차이를 다음 원인 분석 대상으로 둔다. 모델 검토가 완료라고 선언하는 것만으로도 통과시키지 않으며, 이번에는 반대로 실제 조건 충족과 제품 완료 전달이 불일치했다.

각 모델과 후보를 한 번씩 실행한 집중 진단이다. 임의 종합 점수나 전체 30개 성능, 인과적 향상/하락으로 일반화하지 않는다. 4개 실행 모두 같은 평가 실행기 해시와 원문 text hash를 확인했다. 완료 답변 표시 후 5초 대기를 적용했다. 입력 문자 수는 토큰/청구 비용이 아니다. [상세 실측](../verification/harness-plan-2026-10-01/h07-comparison.json).

## 코드와 로컬 검증

동일 source_key/해시/프레임/페이지에서 새 범위가 생겼을 때만 후속 분석한다. 겹치는 읽기는 새 작업을 만들지 않고, 버전당 3회 보조 분석 이후 남은 내용은 주 실행기에 미분석으로 돌린다. 자동 page_content 분석의 인용은 실제 반환한 원문의 교집합에서 정확히 일치해야 한다. 인용 검증은 의미 정확도나 실행 승인과 다르다.

같은 입력의 gate에서 단위 **1,615개**, 디자인, 후보 빌드, 관련 Chrome **23회**, 총 26단계 통과. [고정 gate](../verification/pre-release-2026-09-30T18-39-01-268Z/report.json). 전체 배포 매트릭스가 아니다.

전후 ZIP은 background-runner.js만 다르고 나머지 압축 해제 파일은 같다. 다른 대화의 동시 변경은 기준 후보에도 동일하게 포함했다. [입력 고정](../verification/harness-plan-2026-10-01/paired-inputs.json). A2A 복구는 이 고정 후보 이후의 별도 변경이다.

## 남은 개선

1. 부분 분석 인계에서 실제 반환 원문과 검색 위치를 분리하고 필요한 말미만 주 실행기가 보충하도록 연결한다.
2. 최종 검토에 실제 하위 배정/수집/읽기 범위를 요구사항별로 전달해 불필요한 반복 검토를 줄인다. 실제 기록이 없는 부분을 완료로 승격하지 않는다.
3. 같은 H-07을 재측정해 호출 증가와 완료 실패를 해소한 뒤 고정 7개와 30개로 넓힌다.

공식 방법론, 라이선스, 채택/비채택 근거와 후속 개발 단계는 [개발 계획](../../../docs/plans/2026-10-01-nubi-browser-harness-development.md)을 따른다. 이번 결과를 이유로 임의의 검증 완화나 배포를 하지 않았다.
