# 누비 브라우저 전체 개선 마무리

요청 범위는 브라우저 기능 개선과 하네스 검증이다. 실제 모델 성능, 사내 Qwen, Windows 설치, 공식 WebArena, 앱 간 실업무 성공은 각각 별도 증거를 요구한다. 소스 반영과 외부 검증을 같은 완료 상태로 표시하지 않는다.

## 반영한 개선

| 기능 | 구현 | 검증 기준 |
| --- | --- | --- |
| 긴 원문과 예외 | 원문 해시/UTF-16 구간, 목차/경계 후보와 실제 반환 본문을 분리. 뒤쪽 예외의 후속 분석과 전체 요청 보존 | 안 읽은 문구 인용 거부, 해시 변경 거부, 2,000자 요청 말미 제한 보존 |
| 필터와 선택 | aria-selected/aria-current와 관찰한 상태를 검증. 표시 링크와 정확한 query 검사를 분리. 상태를 노출하지 않은 요소는 미지원으로 반환 | 실제 Chrome debugger와 page script 양쪽에서 선택/비선택/미노출 상태 검사 |
| 재관찰과 질문 | 기존 읽기 복구와 미확정 쓰기 차단, 선택 대상 영수증, 같은 실행 질문/답변 유지 | 과거 승인 재사용 금지, 재시작/취소/질문 회귀 |
| 독립 조사 | 2~4개 기관 배정, Pi 동시 실행 2개, 작업별 비활성 탭, 기존 허용 origin, 정확한 GET 목적지 보호 | 원래 탭 보존, 실제 탭 병렬 실행, 관찰 링크만 이동, 로그인/리디렉트/외부 소유자 거부 |
| 조사 통합 | 반환 범위의 정확한 인용, 출처 URL/해시/위치, 예외와 미확인 필드 전달 | 인용 문자열 확인과 해석 정확도 구분. 기존 주 실행기 최종 요구사항 검토 유지 |
| 실행 근거 유지 | 원래 목표/배정, 실제 호출/반환 구간/정리 상태의 research_execution 기록 | 최종 검토의 관찰 압축과 페이지 변경에도 유지. 부족한 예산은 context_budget으로 거부 |
| 정리 복구 | 미확정 탭 제거 시 기록/보호 규칙 유지, 실제 제거 뒤 해제. 재시작은 정리만 수행 | 제거 실패 반례, 다음 정리 시 원래 탭 보존. 미정리 결과는 partial로 전달 |

단순 조회, 현재 페이지로 제한한 요청과 변경 작업에는 독립 조사 도구를 추가하지 않는다. 배정은 원래 목표를 공유하되 각 문맥과 페이지 도구는 분리한다. 담당당 12회 호출/150초와 제한된 원문 조회를 유지하며 한도에 도달하면 확인한 결과와 남은 항목을 반환한다. 인증 오류는 동료/대기 작업을 중단한다. GET 제한은 사이트 전체의 서버 무변경을 보장하지 않는다.

## 폼과 CX 아이덴티티

사용자 요청에 따라 질문 입력과 초안 편집의 배경/테두리/포커스를 주변 Deck 표면 토큰으로 맞췄다. 직접 답변은 별도 모드나 반복 안내 없이 연필 아이콘과 기존 예시 입력을 유지한다. 긴 입력 펼치기/접기에는 해당 아이콘과 툴팁을 연결한다. 선택지의 실제 ID, 초안 저장, IME, Enter 줄바꿈, 명시적 답변 전송 계약은 바꾸지 않는다.

공통 DeckField는 CX의 공개 CxField를 조합하며 아이콘과 짧은 이름을 함께 표시한다. 스킬/위키/프롬프트 편집, 대화 이름, 작업 녹화/예약, MCP, OpenWiki/A2A/FabriX 연결에 재사용한다. 주소는 링크, 시각은 시계, 반복은 새로고침, 지침은 작업 목록으로 구분한다. label/id, 필수 입력, 오류와 설명 연결은 기존 CX가 담당한다. 승인 버튼의 명확한 동작 이름은 남기고 확인/수정 아이콘을 추가했다. 초안 보기의 눈 아이콘은 고정하고 접기 화살표만 회전한다.

CX 0.5.4 공개 API와 프로젝트 cx-ui 스킬, icon-system의 의미/접근성 기준을 적용했다. 새 UI 라이브러리나 외부 아이콘 의존성은 추가하지 않았다. 장식 아이콘은 aria-hidden이며 아이콘 버튼의 접근성 이름과 툴팁을 유지한다. 실제 Chrome의 작은 화면/넓은 화면, 초점/키보드/오류/초안/모션 감소를 검사한다. 공유 Office 질문 계약 11개는 통과했다. 이 과정에서 디자인 변경 전에도 존재한 이전 기본 안내 문구 기대값 2개를 공통 폼의 현재 예시 문구에 맞췄다. Office 네이티브 동작 변경이나 빌드 검증은 아니다.

## 방법론과 선택

[Anthropic 다중 에이전트 조사](https://www.anthropic.com/engineering/multi-agent-research-system)의 배정 목표/출력/도구/범위 분리와 [OpenAI trace grading](https://developers.openai.com/api/docs/guides/trace-grading)의 실행 과정/최종 결과 분리를 적용했다. [Chrome DNR 공식 계약](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)에 맞춰 조사 탭의 main_frame을 차단하고 정확한 GET 목적지만 허용한다. 새 엔진으로 전체를 교체하지 않고 기존 Pi 0.87.1, p-limit 7.3.3, Markdown AST와 순수 JS 엔티티 디코더를 재사용한다. 해당 라이선스는 MIT이며 배포 고지의 기존 재귀 수집을 유지한다. 추가 외부 서비스, Python/라우터/Native Messaging 설치와 런타임 비용을 도입하지 않았다.

임의 탐색 도구 확대, 새로운 브라우저 자동화 런타임, 인용 일치를 최종 정답으로 승격하는 방식은 채택하지 않았다. 추가 모델 호출의 속도/비용 개선은 실모델 과제에서 별도로 측정한다.

## 재현과 검증 기록

`verification/full-improvement-2026-10-01/`에 수정 전 소스, 반례 JSON과 실패 테스트를 보존했다. 기존 코드는 제거가 실패한 탭을 남긴 채 `{ok:true}`를 반환하고 보호 규칙/복구 기록을 삭제했다. 수정 전 새 테스트 4개가 실패했고 수정 후 관련 테스트 12개가 통과했다. URL 정책에는 인코딩된 logout 경로를 허용하는 반례도 포함했다. 경로 검사만 디코딩하고 실제 목적지 URL을 임의로 바꾸지 않는다.

`research-workers-browser`는 실제 Chrome의 네이티브 탭/DNR/본문 리더와 Pi 자식 실행을 연결한다. 모델 응답과 사이트, 소유자 연결은 명시적 합성 fixture다. 두 탭의 일반 규칙/10월 예외 원문 전달, 원래 탭 보존, 정리, origin 권한 부족, 인코딩된 금지 경로, 리디렉트 차단, 로그인/외부 소유자/가짜 링크 거부를 검사한다. 실제 모델 정확도나 production SSO 검증으로 표시하지 않는다.

독립 조사 실행 기록이 없거나 14,000자 이후 잘리는 반례도 새 테스트 2개로 재현했다. 호스트가 만든 research_execution만 완전한 기록으로 유지하고 실제 모델 예산을 넘으면 최종 검토를 거부한다. 모델이 말한 완료와 문자열 인용 확인은 실행/사실 증명을 대신하지 않는다. 기존 분석 실행 기록과 정리 검사까지 관련 테스트 23개가 통과했다.

새 담당 ID나 호출 횟수를 외부 작업 진전으로 세는 반례도 수정했다. 실제 원문/검사 변화는 진전으로 유지하고 연구 실행 기록의 숫자만 바뀐 경우는 복구 기회를 새로 만들지 않는다.

전체 예외 연속 읽기 검사를 추가하자 탐색 메타데이터의 어휘가 실제 본문보다 높은 검색 점수를 받아 첫 분석이 partial로 끝나는 통합 결함이 드러났다. 본문을 먼저 직렬화하는 것만으로 해결되지 않아 검색 후보 자체를 실제 반환 Markdown의 JSON wire 구간으로 제한했다. 목차/경계/안내는 보존하지만 그 일치로 원문 조회를 대체하지 않는다. 기존 구조적 경로 계산을 재사용해 이모지/이스케이프와 정확한 인용 좌표 계약을 유지했다. 메타데이터-only 질의는 0개 후보이며 이를 사실 부재로 해석하지 않는다. 관련 검사 22개와 실제 Chrome 예외 연속 읽기가 통과했고 이전 구현을 사용한 음성 대조에서는 새 원문 전달 검사가 실패했다.

첫 전체 검사에서 background-lifetime-browser의 기능 검사는 모두 통과했지만 Chrome 종료 직후 프로필 삭제가 ENOTEMPTY로 실패했다. 고정 500ms 대기를 Chrome 자식 프로세스의 실제 종료 대기로 바꾸고 파일 정리에 한정한 유한 재시도를 적용했다. 기능 검사를 다시 시도해 통과로 꾸미지 않았으며 실패한 원본 보고서를 보존한다.

화면 검증 명령이 같은 dist를 재빌드하면서 uncertain-frame-browser의 후보 복사가 ENOENT로 실패한 실행도 보존한다. 프레임 기능 실패로 해석하지 않는다. 최종 화면 검사와 전체 검사는 입력을 고정한 같은 후보에서 순차 실행하며 진행 중인 dist를 재빌드하지 않는다. 검증 카탈로그에서 A2A가 중복 등록된 문제도 제거했으며 같은 이름의 단계를 두 번 실행/집계하는 카탈로그는 시작 전에 거부한다. 중복 방지 반례를 포함한 검증 계약 검사 19개가 통과했다.

별도 폴더로 분리한 병렬 실행의 핵심 gate에서 browser-routines-browser가 Chrome 시작 응답을 180초 안에 받지 못해 모델/기능 검사 이전에 실패했다. 같은 후보의 화면 gate에서는 기능이 통과했다. 이 실패 보고서를 남기고 최종 핵심 gate는 화면 gate 종료 후 실행해 동시에 띄우는 Chrome 수를 제한한다.

독립된 새 폴더의 화면 gate에서 workspace-group-browser가 검사를 마친 뒤 결과 디렉터리가 없어 ENOENT로 실패한 기록도 보존했다. 이전 실행에서 생성된 폴더에 의존하지 않도록 해당 검사가 저장 디렉터리를 직접 만들게 수정했다. 제품 기능 변경이나 실패를 제거하는 재시도는 아니다.

이미지 선택 화면/다운로드/재개가 통과한 뒤 별도 SVG probe가 images 없는 도구 결과를 받은 화면 gate도 실패로 보존했다. 단독 조회에서는 5개 검사가 통과했지만 최초 도구 오류는 기록되지 않아 원인을 확정하지 않는다. 결과 스키마 assertion에 실제 도구 결과를 연결해 진단을 보강하고 최종 화면 gate는 기본 순차 실행으로 확인한다. 이 단독 통과를 전체 gate로 집계하지 않는다.

평가 후보 검사 도구의 종료 대기가 stage 제한에 걸린 기록도 보존했다. signal로 종료된 실제 자식 프로세스는 exitCode=null, signalCode=SIGTERM이며 이전 조건은 이미 지난 exit 이벤트를 기다리는 반례가 재현됐다. 종료 신호를 함께 확인하고 CDP 연결 종료/소유 프로세스 정리에만 유한 대기를 둔다. 정상 종료를 먼저 시도하고 해당 검사 도구의 자식만 정리하며, 제품/모델 호출이나 사용자 Chrome의 제한을 바꾸지 않는다. 수정 뒤 실제 Chrome에서 실행한 모듈 해시, 같은 프로필의 후보 교체, 누락 모듈 거부가 통과했다. 이 수정은 앞선 종료 대기의 모든 원인을 확정한다는 뜻은 아니다.

긴 확인창에서는 script_timeout/actionIssued/accepted를 기대하면서 입력창은 즉시 ok만 기대하는 검사 불일치도 발견했다. 입력창에도 8초 사용자 대기를 명시하고 결과 미확정 영수증, 독립 페이지 readback의 정확한 입력/한 번 실행과 개인정보의 저장/모델 근거 제외를 모두 요구하도록 수정했다. 실제 Chrome에서 4개 계약이 통과했다. 제품의 타임아웃이나 미확정 재실행 차단은 완화하지 않았다.

동시에 작업 공간에 반영된 알려진 링크의 noWaitAfter와 미확정 동작을 일반 페이지 검증으로 해소하지 않는 하네스/문맥 변경도 검토했다. 같은 현재 소스를 다시 고정한 최종 후보에서 관련 단위/회귀와 함께 검증한다. 앞선 후보의 결과를 이 후보의 전체 통과로 합산하지 않는다.

최종 통합 gate의 error-recovery-browser에서 실제 대상/문서 상태를 확인해 주 실행기의 미확정 상태가 해소돼도 공유 하네스에 해소 영수증이 없어 검토를 반복하는 결함을 발견했다. 기존 모든 대상/문서/값/호스트 검사 조건을 통과한 동일 경계에서만 reconciledAction을 전달한다. 일반 성공 문구나 다른 대상/문서의 조회로 미확정 쓰기를 해소하는 규칙은 추가하지 않았다. 공유 하네스를 켠 정확한 입력 복구 단위 흐름, 관련 67개 검사, Office 공유 계약 23개와 실제 Chrome 오류 복구가 통과했다. 원래 구현을 쓰는 음성 대조와 이전 실패 gate를 별도로 보존한다.

고정 핵심 묶음은 quality-baseline-v10이다. 독립 조사, 선택 상태, 예외 연속 읽기와 본문 전달을 각 3회 반복하며 기존 묶음의 검사를 유지한다. 단위/디자인/후보 빌드 뒤 Chrome 119회, 총 122단계가 필요하다. 부분 결과를 합쳐 이 묶음의 통과로 인정하지 않는다. 최종 후보의 입력 해시와 결과는 검사가 끝난 뒤 아래에 기록한다.
