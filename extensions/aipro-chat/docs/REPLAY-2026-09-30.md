# 검증된 실행을 모델 없이 다시 실행

사용자 요청: "반복되는 작업은 Nanobrowser처럼 LLM 없이 실행할 수 있게 하자." 검증을 통과해 끝난 브라우저 작업의 절차를 답변에 남기고, 같은 작업을 모델 호출 없이 다시 실행한다.

## 참고한 방식과 다르게 한 점

| 항목 | Nanobrowser, browser-use | 누비 |
| --- | --- | --- |
| 기록 | 단계별 모델 출력과 상호작용 요소(XPath, 속성, 해시) | 도구 이름, 대상의 역할·이름·행과 대화상자 문맥·열·안정 id, 입력값 칸 번호 |
| 대상 찾기 | `HistoryTreeProcessor.findHistoryElementInTree`로 해시 대조 | 새 관찰에서 역할과 이름이 같고 문맥이 맞는 컨트롤이 정확히 하나일 때만. 관찰이 컨트롤을 덜 담았으면 대상 이름으로 한 번 더 관찰 |
| 못 찾으면 | 기본값 `skipFailures = true`로 건너뜀, 최대 3회 재시도 | 멈춤. 건너뛴 클릭 뒤의 단계는 예상하지 못한 페이지에서 행동하게 된다 |
| 입력값 | 기록에 포함 | 기록에 넣지 않음. `chrome.storage.session`(메모리)에만 두고 실행 전 폼에서 확인·수정 |
| 최종 반영 | 별도 장치 없음 | 기존 승인 카드. 승인 뒤 남은 단계(승인한 동작, 확인)도 모델 없이 이어감 |
| 대상 | 모든 기록 | 페이지 확인(`verify_page`)이 통과하고 목표 검토가 끝난 작업만 |

근거: Nanobrowser `chrome-extension/src/background/agent/executor.ts`의 `replayHistory(sessionId, maxRetries = 3, skipFailures = true, delayBetweenActions = 2.0)`와 `navigator.ts`의 `executeHistoryStep`, browser-use `Agent.rerun_history`.

## 흐름

1. **기록**: 도구 실행 경로(`RUN_TOOL`)가 실행 전 관찰로 대상 정보를 남긴다(`browser-replay.js`의 `recordStep`). 기록은 작업 단위라 질문이나 승인으로 나뉜 실행도 한 절차로 이어진다. 읽기 도구는 기록하지 않는다.
2. **저장**: 작업이 검증을 통과해 끝나면 답변에 `replay`(단계, 넣을 값 목록)를 붙인다. 입력값과 시작 페이지의 전체 주소는 session에만 둔다. 한 대화에 최근 5개 답변까지 남긴다.
3. **실행 전 확인**: 답변 아래 "모델 없이 다시 실행"을 누르면 입력값 폼이 열린다. 지난 값이 메모리에 있으면 채워 두고, 브라우저를 다시 켰으면 다시 입력받는다.
4. **재실행**: 실행기(`background-runner.js`)가 모델 대신 `runReplay`를 부른다. 도구는 모델이 부를 때와 같은 경로로 실행되므로 관찰, 승인, 영수증, 체크포인트, 미확정 동작 차단이 그대로 적용된다. 기록한 실행이 다른 페이지에서 시작했으면 그 페이지를 먼저 연다.
5. **멈춤**: 대상이 없거나 여럿이거나 가려져 있거나, 도구가 실패하거나, 확인이 통과하지 못하면 멈추고 이유를 답변에 적는다(`replay_stopped`). "작업 이어가기"를 누르면 모델이 같은 작업을 지금 페이지에서 이어받는다. 이미 실행한 단계는 되돌리지 않는다.
6. **새 기록**: 재실행도 기록되므로, 성공하면 결과 답변에 최신 값의 절차가 다시 붙는다. 멈춘 뒤 모델이 이어서 끝낸 작업도 합쳐진 절차로 남는다.

## 도구별 재실행 방식

| 도구 | 기록 | 재실행 |
| --- | --- | --- |
| 클릭, 입력, 선택, 키, 스크롤, 이동, 확인 | 대상 정보, 입력값은 메모리 | 대상을 다시 찾아 같은 도구로 실행 |
| 좌표 클릭(`click_at`) | 클릭한 점을 품은 가장 안쪽 관찰 요소(호스트가 실행 전에 찾음) | 그 요소를 다시 찾아 요소 클릭. 관찰 요소가 없는 점(캔버스 등)은 기록하지 않음 |
| 끌어놓기 | 출발과 도착 대상 | 둘 다 다시 찾아 실행 |
| 탭 전환 | 전환한 탭의 페이지 주소와 제목(탭 번호는 실행마다 달라짐) | 탭 목록에서 같은 페이지의 탭이 하나일 때만 전환 |
| 스크립트(`run_playwright`, 스킬 스크립트) | 코드와 인자는 입력한 글이 들어 있어 메모리에만, 코드 속 `browser.ref(...)` 대상 정보 | 대상을 다시 찾아 참조만 바꾼 코드로 실행 |
| 파일 업로드 | 업로드 칸의 이름과 페이지, 첨부 ID는 메모리 | 업로드 칸 목록에서 다시 찾고 기존 승인 카드를 거침 |
| 파일 다운로드 | 링크 대상 | 다시 찾아 기존 승인 카드를 거침 |

스크립트와 첨부 파일처럼 메모리에만 둔 내용이 필요한 절차는 브라우저를 다시 켠 뒤에는 모델 없이 다시 실행할 수 없고, 입력 카드가 그 사실을 알린다. 외부 도구(MCP)의 동작이나 불확실하게 끝난 동작이 있는 작업은 기록하지 않는다. 단계는 80개까지다.

## 검증

- `tests/browser-replay.test.mjs`: 대상 기록과 대조(행 문맥, 같은 모양 컨트롤의 순서, 열, 역할 변경, 가림, 프레임), 단계 기록과 값 분리, 확인이 입력값을 따라가는지, 승인에서 멈춤과 승인 뒤 이어감, 빠진 칸에서 쓰기 전 멈춤, 덜 담긴 관찰에서 이름으로 다시 관찰, 시작 페이지 열기.
- `tests/replay-browser.mjs`(실제 Chrome): 합성 모델로 입력·확인·승인·등록한 작업에 절차가 남고 입력값은 메모리에만 있음. 다른 페이지에서 "모델 없이 다시 실행"을 눌러 값 하나를 바꾸면 기록한 페이지를 쿼리까지 열고, 같은 승인 카드에서 멈췄다가 한 번 등록한다. 이 동안 모델 요청은 0회다. 칸 이름이 바뀐 페이지에서는 아무것도 쓰지 않고 멈추고 "작업 이어가기"를 보여 준다.
