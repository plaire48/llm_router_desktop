# nubi Beta 1.0.0 — beta41

Chrome 업데이트 번호 **1.4.44**. 기존 `beta40`(1.4.43)은 보존하고 새 ZIP으로 배포한다. 이번 배포는 브라우저 하네스의 속도와 안정성이 중심이다. 실제 모델로 과제 10개를 반복 실측하며 두 모델에 공통으로 걸리는 하네스 문제를 찾아 고쳤다.

## 변경

**속도(모델 호출 수를 줄임)**
- 입력 도구가 모든 칸을 되읽어 확인하고 다른 칸이 처음 본 값 그대로면, 그 입력을 결과 확인으로 본다. 별도 `verify_page` 호출과 거절된 계획 갱신 호출이 없어진다.
- 계획 갱신은 다음 동작과 한 응답에서 처리한다. 확인(`verify_page`) 뒤의 계획 갱신도 같은 응답에서 확인 결과를 보고 처리한다. 확인이 없어 거절될 때는 무엇을 확인할지 알려 준다.
- 단계 검토를 줄였다. 처음부터 지켜본 작업에서는 읽기만 한 단계와 호스트가 되읽기로 확인한 입력 단계를 단계 검토 없이 닫고, 마지막 단계는 변경이 있어도 최종 검토 한 번으로 닫는다. 클릭이나 선택처럼 호스트가 결과를 모르는 변경, 승인된 최종 동작이 있는 단계, 이어서 하는 작업은 전처럼 검토한다. 읽기 단계의 검토가 "확인이 더 필요"를 돌려주며 호출이 5~6번 늘던 고리가 없어졌다. 검토 중에는 계획에 "답변 확인 중"이 보인다.
- 첫 응답이 계획뿐이면 같은 차례에 첫 화면을 읽는다(호출 1번 절약).
- 실행마다 바뀌는 상태(계획, 마지막 동작)를 시스템 메시지에서 빼서 최신 결과 뒤에 둔다. 서버의 프롬프트 캐시가 앞부분을 다시 쓸 수 있다. ChatGPT에는 대화별 캐시 키를 보낸다.

**클릭과 승인**
- 퀵 메뉴처럼 화면 가장자리에 고정된 막대가 버튼을 가리면, 그 클릭 동안만 막대가 마우스를 통과시킨다. 실측에서 서울도서관의 오른쪽 퀵 메뉴(창 높이 전체)에 가린 GO 버튼이 4번 연속 "다른 요소에 가림"이었다. 대화상자, 화면 덮개, 같은 행의 다른 버튼이 가리면 전처럼 누르지 않는다.
- 승인은 버튼 이름으로만 판단한다. 짧은 버튼 이름이 저장, 전송·발송·보내기, 등록, 제출, 신청, 게시·발행, 삭제, 결제·구매, 반영, 승인, 확정, 결재, 상신, 배포로 끝날 때(예: "저장", "메일 보내기", "최종 반영"), 이름이 정확히 "확인"이나 "OK"일 때(대화상자와 레이어 팝업 안의 확인은 제외: 결재선 지정 같은 팝업 단계, 이미 승인한 동작의 확인 창), 영어는 Save, Send, Submit, Delete 등으로 시작할 때만 승인 카드를 띄운다. 버튼 이름은 40자까지, 링크와 행은 12자까지 읽는다(메일 제목 같은 긴 문구는 동작이 아니다). 저장·제출 단축키(Ctrl+S, Ctrl+Enter)와 파일 업로드·다운로드는 전처럼 승인을 받는다.
- 양식 구조로 제출을 추정하던 규칙, 검색 양식 판별, 긴 문구 중간의 동작 단어로 막던 규칙을 없앴다. 사내 시스템의 화면 전체 양식에서 "닫기", "다음"이 막히고, 검색 Enter와 메일 제목 클릭이 막히던 문제다.
- 승인 카드를 띄우기 전에 "초안 검증 필요"로 되돌리지 않는다. 입력 뒤 체크나 날짜 선택이 한 번 있으면 모델 호출이 2번 더 들던 흐름이다. 승인 카드가 초안 미리보기를 보여 주므로 사용자가 카드에서 판단한다.
- 정보만 찾는 요청에서는 링크나 검색 클릭 뒤 단계를 닫을 때마다 확인을 요구하지 않고, 답하기 전에 마지막 동작의 결과만 한 번 확인한다. 세 기관 조사에서 기관마다 호출 2번이 이 확인에 들었다.

**컨텍스트**
- AI Pro 모델 목록이 주는 창 크기(`context`: glm-5.2 524,288, qwen3.8-27b 262,144, gpt-oss-120b 131,072)를 읽는다. 전에는 `context_length`만 읽어 한도를 몰랐고, 원판 비율이 비었으며 압축도 기본값(9만 토큰)이었다.
- 압축은 모델 창을 기준으로 한다. 창에서 출력 자리를 뺀 입력 예산의 90%(glm-5.2 약 45만, qwen3.8-27b 약 21만, gpt-oss-120b 약 10만 토큰)에서 앞부분을 요약한다(128K 미만 창은 75%). 판단은 응답이 알려 준 실제 입력 토큰(`prompt_tokens`)으로 보정한다. 전에는 창과 관계없이 16만 토큰이 상한이었고, 한국어처럼 추정이 크게 나오는 글에서는 실제 13만 토큰 안팎에서 압축이 시작됐다.
- 큰 요청이 서버 오류나 시간 초과로 실패하면 같은 크기로 네 번 다시 보내지 않는다. 한 번만 다시 시도하고, 그래도 실패하면 바로 요약해서 한 번 더 보낸다. 실패한 크기의 80%를 그 모델의 압축 시작점으로 기억한다.
- 작업 중 원판은 가장 최근 모델 요청의 실측 사용량(`total_tokens`, 읽은 페이지 포함)을 보여 준다. 전에는 대화 글만으로 추정해 페이지를 여러 개 읽어도 움직이지 않았다.

**안정성**
- 응답하지 않는 페이지(끝나지 않은 이동, PDF 같은 플러그인 문서)에서도 화면 관찰이 45초 안에 돌아온다. 늦는 프레임은 "읽지 못함"으로 표시하고 나머지를 보여 준다. 이전에는 한 관찰이 작업 한도까지 멈춘 적이 있다.
- "페이지 변경됨"에 원인(이전 관찰의 참조, 발급되지 않은 참조, 사라진 요소, 바뀐 요소, 바뀐 프레임)과 원인별 안내를 붙인다.
- 효과 없는 클릭 뒤 사용자가 연 새 탭을 팝업으로 가져가던 문제를 고쳤다.
- 형식 헤더 없이 오는 PDF(공공기관 안내 등)를 읽는다. 파일 머리의 `%PDF-`로 판단한다.
- 선택하면 나타나는 입력란이 지금 숨겨져 있으면 이름을 알린다(값은 싣지 않음). 모델이 "칸이 없다"며 사용자에게 묻던 경우를 줄인다.
- 입력 결과에 "다른 칸은 처음 본 값 그대로"라는 호스트 비교를 붙이고, 두 검토자가 같은 값 증거 규칙을 쓴다(관찰은 입력값을 생략하므로 현재 값은 `field_value`, 보존은 `field_unchanged`).
- 사내 업무 화면의 요소 판단: 표 머리칸을 입력란 이름으로, 옆 글자를 클래스로 그린 체크의 이름으로 읽는다. role 없는 레이어 팝업을 대화상자로 묶고, 딤이나 모달 뒤에 가려진 컨트롤을 표시한다. 달력처럼 읽기 전용 칸의 값이 바뀐 것도 결과에 남긴다. 한 번에 보는 컨트롤 수를 두 배로 늘렸다.
- Chrome 확대/축소가 100%가 아니거나 Windows 화면 배율 125%와 겹치면 캡처가 "캡처 범위 확인"으로 실패하던 문제를 고쳤다.
- 전달 메일을 쓸 때 원문과 서명을 지우는 입력을 막는다.
- 첫 화면 읽기에서 페이지가 잠깐 응답하지 않으면 "접근이 제한된 페이지"로 잘못 판정하던 문제를 고쳤다. 잠시 뒤 한 번 더 읽는다.
- "중요 표시하고 열어서 알려줘"처럼 변경과 조회가 섞인 요청을 변경 요청으로 분류한다. 조회로 잘못 분류되면 변경의 결과 확인이 빠질 수 있었다.

**기능**
- 에디터 서식 입력: `fill_form`의 `format: "html"`로 문단, 목록, 굵게, 링크, 표를 한 번에 쓴다. 편집기가 붙여넣기를 처리하면 편집기 모델로 넣고, 도착한 서식과 잃은 서식을 알려 준다.
- 검증을 통과한 작업을 모델 없이 다시 실행한다(입력값 확인 카드, 승인 단계는 그대로).
- 답변에 쓰인 HTML 표, 접기, 줄바꿈을 서식대로 보여 준다. 스크립트, 이벤트, 스타일, `javascript:` 링크는 지운다.
- 사용자 메시지 아래 복사 아이콘.

**진단**
- AI Pro와 ChatGPT의 모델 오류를 연결 진단에 상태 코드와 오류 코드(식별자만)로 남긴다. 이미지 거절과 정책 거절은 "AI 서버 오류"와 구분해 안내한다.
- 진단 복사에 모델 호출별 시간(종류, 입력 크기, 전체 시간, 첫 출력 시간)과 종류별 요약을 넣었다. 사내 모델의 병목을 재는 근거다.

권한과 콘텐츠 보안 정책은 beta40과 같다. 새 필수 권한은 없다.

## 설치와 업데이트

ZIP을 풀고 `chrome://extensions`에서 개발자 모드의 **압축해제된 확장 프로그램 로드**를 선택한다. 기존 사용자는 **같은 설치 폴더**의 파일을 교체하고 확장을 새로고침한다. 폴더를 바꾸면 확장 ID와 저장된 대화가 달라질 수 있다. 웹 스토어 배포본은 아니다.

## 검증 범위

전체 브라우저 게이트 **291/291단계 통과**(반복 회귀 3회, 포커스 복원 3회 포함). Chrome에서 합성 사이트와 제어된 모델 응답으로 화면과 기능을 검사했다. 이번 배포의 새 실제 브라우저 검사 8개(가림 클릭과 퀵 메뉴 통과, 에디터 서식 입력, 관찰 시간 한도, 형식 헤더 없는 PDF, 조건부 입력란, 확대 배율 캡처, 사내 화면 위젯, 모델 없는 재실행)를 게이트에 넣었다. 게이트 밖 검사까지 포함한 실제 브라우저 검사 전체에서는 172개 중 167개가 통과했고, 실패 5개는 이전부터 실패하던 비기준 검사다(후보 61 기준).

beta40(1.4.43) 설치본의 같은 폴더를 이번 파일로 교체하는 업데이트 검사를 통과했다. 확장 ID, 현재와 이력의 대화, 입력 중인 초안, 모델, 작업 방식이 Chrome 재시작 뒤에도 유지됐다.

단위 검사 1,583개 통과. 운영 의존성 점검에서 보고된 취약점은 0개다.

실제 모델 실측(ChatGPT 로그인, 과제별 1회). 로컬 평가 페이지 과제는 페이지의 실제 상태로 채점했다.

## 알려진 한계

- 사내 모델(AI Pro)로는 실측하지 않았다. 이 PC에서 접속할 수 없다. 진단 복사의 호출별 시간으로 확인할 예정이다.
- 공개 사이트 조사(H-04 세 기관, H-06 두 기관)는 공식 근거를 다 찾지 못하면 제한 공개로 끝난다. 세 기관 조사는 평가의 8분 한도를 넘는다(Sol 약 483초, 최종 검토의 보충 요구 중). 탭을 따로 쓰는 읽기 전용 조사 담당(병렬 하위 에이전트)이 다음 과제다.
- AI Pro 창 크기 읽기와 작업 중 원판 실측은 AI Pro의 응답 형식(모델 목록의 `context`, 스트림 끝의 `usage`)을 기준으로 만들었고, 사내망 밖인 이 PC에서는 합성 응답으로만 검사했다.
- 조건부 입력란 과제(M-08)에서 Luna는 온라인을 선택하지 않고 이메일 칸을 묻는 경우가 있었다. 숨겨진 입력란 알림은 이 배포에 들어 있다.
- 승인은 버튼 이름으로만 판단한다. "처리", "완료"처럼 목록에 없는 이름의 버튼이 서버에 반영하는 화면에서는 승인 없이 눌린다. 목록에 넣어야 할 이름은 알려 주면 추가한다.
- 실측 기록은 도구 결과의 내용을 남기지 않는다.
