# 브라우저 누비 기능 재평가

후속 구현과 현재 수준은 [전체 개선 적용 기록](FINISH-IMPROVEMENTS-2026-10-01.md)을 따른다. 아래 내용은 당시의 실모델 실패 근거로 보존한다. 독립 조사 워커와 앱 A2A 경로는 이후 구현됐지만 전체 실모델 품질이 통과했다는 뜻은 아니다.

후속 [하네스 방법론 적용](HARNESS-METHODS-2026-10-01.md)은 자동 분석의 요청 잘라내기를 수정했다. 입력 전달/복구 검증과 실모델 의미 정확도를 구분하며 아래 등급을 자동으로 올리지 않는다.

2026-10-01. 사용자 요청에 따라 현재 소스와 기존 실측을 다시 대조했다. **단순 입력과 질문 화면은 강점이며, 여러 출처 조사와 긴 문서의 완주가 가장 부족하다.** 이번에는 긴 작업의 최종 검토에서 실제 하위 분석 기록이 사라지는 결함을 재현하고 수정했다. 전체 실전 품질이 개선됐다는 판정은 별도 실측 전까지 보류한다.

## 상중하 기준

- 상: 명시한 범위에서 반복 검증과 독립 결과 확인이 있는 기능.
- 중: 기본 동작은 있으나 결과 편차, 중요한 제한 또는 실환경 미검증이 있는 기능.
- 하: 사용자의 핵심 결과를 반복해서 완수하지 못한 기능.

미측정은 실패와 구분한다. 단위 검사 수, 구현 항목 수와 합성 모델의 Chrome 통과를 실제 모델 정확도나 사내 업무 성공률로 바꾸지 않는다. 상을 제품 전체나 모든 사이트의 보장으로 읽지 않는다.

## 이번 변경

하위 담당의 배정과 실제 읽은 범위를 호스트가 기록했어도, `goalReviewMessages`의 예산 정리가 이를 일반 오래된 관찰처럼 제거했다. 뒤에 관찰을 30개 추가한 반례에서 두 분석 영수증이 모두 사라졌고, 입력 한도가 부족한 경우에도 영수증을 빼고 검토를 계속했다. 기존 코드에서 새 검사 두 개의 실패를 먼저 보존했다.

유효한 `analysis_receipt / analysis_execution` 기록을 단계/최종 검토의 필수 근거로 유지했다. 원문 출처와 사용자 요구사항, 최신 관찰 및 실행 영수증의 기존 보호도 유지한다. 실제 모델 입력 예산에 맞지 않으면 `context_budget`으로 검토 불가를 반환한다. 실패/절단/대체된 영수증을 유효 근거로 보호하지 않는다.

기록에는 배정, 호출, 전달, 부분 보고 여부와 실제 반환한 원문의 식별자/좌표만 있다. 그 기록을 사실 이해, 전체 문서 열람, 현재 페이지 상태나 실행 승인으로 승격하지 않는다. 주장의 정확도는 별도의 원문과 대조해야 한다. 새 모델 호출, 브라우저 권한 또는 외부 런타임은 추가하지 않았다.

## 방법론과 선택 근거

[Anthropic 문맥 관리](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)의 핵심 상태 보존과 [OpenAI agent evals](https://developers.openai.com/api/docs/guides/agent-evals)의 재현 가능한 평가 원칙을 참고했다. 공식 문서와 [Pi 실행기 소스](https://github.com/earendil-works/pi/blob/main/packages/agent/src/agent.ts)를 현재 확인했다. 상위 저장소 main을 설치한 0.87.1과 같은 버전이라고 간주하지 않는다.

기존 MIT Pi 실행기/문맥 관리와 Apache-2.0 Playwright를 유지했다. 별도 Agents SDK나 연구 프레임워크는 이번 결함인 호스트 기록 누락을 해결하지 않고 MV3/인증/의존성 비용을 늘려 채택하지 않았다. SDK 코드를 복사하거나 모델/인증을 바꾸지 않았다. 독립 조사 워커는 [기존 설계](RESEARCH-WORKERS-2026-09-30.md)의 탭 소유권, 현재 권한, 취소/정리와 근거 검증을 갖춘 후속 구현이다.

## 검증

원본과 변경 파일 해시, 실패 재현, 전체 단위/후보/Chrome 결과는 [증거 폴더](../verification/feature-reassessment-2026-10-01/)에 남긴다. 첫 Chrome gate는 확장 serviceworker 대기 시간 초과로 중단됐다. `CHROME_BINARY`에 실제 Chrome 실행 파일을 지정한 동일 소스의 조사 회귀는 통과했다. 이 환경 실패를 통과나 모델 업무 실패로 세지 않는다.

현재 검증 결과는 별도 `result.json`과 고정 gate 보고서를 기준으로 확인한다. 실모델 개선율, 전체 30과제, Qwen 실계정, 실제 사이트 서버 저장 및 배포 성공은 이번 로컬 회귀 결과와 구분한다.

최종 [동일 후보 핵심 gate](../verification/pre-release-2026-09-30T20-42-38-029Z/report.json)는 단위 **1,631개**, 디자인 검사, 후보 빌드, 실제 Chrome **107회**, 총 110단계 통과다. 현재 소스/검사/공유 Wiki/의존성과 빌드 해시가 실행 전후 일치한다. 변경한 원문 분석 경로는 같은 입력/빌드의 별도 Chrome **3회**도 통과했다. 집중 단위 61개, 공유 Office 화면 검토 22개 및 의도적 인증 실패 대조군도 기록했다. 전체 배포 매트릭스나 실제 모델의 업무 정확도는 아니다. `quality:status`가 NQ-51/NQ-52를 현재 핵심 회귀 통과로 인식한다.

첫 핵심 gate의 `openwiki-agent-browser` 실패도 기록했다. 변경 전 검토 코드로 같은 실패가 재현됐고 입력 해시는 실행 전후 일치했다. 공유 Wiki 엔진은 사용자 결정에 따라 현재 4개 연구 슬롯을 사용하지만 브라우저 검사는 예전의 정확히 2개 시작을 요구했다. 실제 Chrome은 인증 오류 전에 4개를 시작한 뒤 나머지 3개를 취소했다. 제품의 인증/동시성 정책은 유지하고 검사를 현재 계약에 맞췄다. 단순히 시작 수를 늘려 통과시키지 않고, 오류 뒤 새 모델 호출 0, 오류 시점 이후 시작 수 불변, 시작한 모든 동료의 취소, 부모/다른 Wiki 유지 및 후속 재인증 독립성을 확인한다. 단위/Chrome의 타이머도 동료별로 정리한다. 이를 NQ-52로 등록했다.

제품 코드 수정 후 당시 후보의 H-07 Sol 측정은 전용 Chrome의 SSO가 완료되지 않아 0개 과제, 미채점으로 종료했다. 자동 계정 선택/동의/인증값 조회를 하지 않았으며 이 시도에서 만든 브라우저만 닫았다. 인증 대기를 모델 실패나 수정 효과로 세지 않는다.

검사 완화 여부는 별도 실패 대조군으로 확인했다. 임시 probe에서만 인증 중지 호출을 제거하자 총 21회, 오류 뒤 17회 호출 및 동료 취소 0회를 기록하고 새 Chrome 검사가 실패했다. 실제 코드에서는 동시 시작 4회, 오류 뒤 호출 0회, 동료 3개 모두 취소가 확인됐다. 대조군은 제품/후보 코드를 바꾸지 않았다.

## 남은 개선 순서

1. 동일 후보의 H-07에서 답변 정답, 실제 하위 읽은 범위, 최종 완료 전달, 호출/시간을 함께 재측정한다.
2. H-04의 기관별 필수 항목과 미확인 구간을 유지하고, 부족한 기관만 보충하도록 독립 조사 워커를 구현한다. 단순 출처/호출 수 증가를 진전으로 세지 않는다.
3. E-02/H-06의 명시적 연도 예외와 서비스 제외를 독립 채점한다. 프롬프트 강화만으로 정확도 개선을 주장하지 않는다.
4. 파일 완료 수정까지 포함한 고정 7/30과제를 재측정하고 회사망 Qwen 평가를 별도로 확보한다.

작업 목록에는 NQ-51/NQ-52로 등록했다. 소스 수정 및 검사 계약 교정과 실제 품질 향상 확인을 구분한다.
