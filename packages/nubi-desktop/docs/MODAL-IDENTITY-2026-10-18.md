# 모든 모달의 누비 아이덴티티 정렬

사용자의 2026-10-18 추가 요청을 기존 2차 물결과 함께 적용한다. 공통 스타일 소유자는 `design/workspace-dialogs.css`이며 새 모달 시스템은 만들지 않는다.

## 적용

- `label[for]` 입력 라벨은 공통 500 굵기와 본문 글자색을 사용한다. 실제 루틴의 이름 라벨이 400으로 표시되는 실패를 먼저 재현했다.
- 별도 스타일이 없는 오류 안내는 의미별 오류 글자색을 사용한다. 일반 본문과 구분하면서 기존 문구/접근성 역할을 유지한다.
- 모달 본문의 일반 링크는 누비 진한 파랑을 사용한다. 사용자 메일/문서의 내부 콘텐츠와 모델사 로고/고유색을 일괄 재색칠하지 않는다.
- 루틴 삭제와 메일/위키 초기화는 기존 대화 삭제와 같은 의미색을 사용한다. 루틴의 기존 tone 속성은 공통 확인창이 받지 않아 파랑으로 남는 실패를 재현했고, 공통 클래스에 연결했다.
- 기존 흰색 표면, 옅은 파랑 입력/선택, 제목 600, 본문 400, 공통 폰트와 크기, 시작선, 버튼/닫기 크기와 포커스 계약을 유지한다. 강제 색상 모드에서는 시스템 CanvasText/LinkText를 따른다.

## 점검 범위와 근거

직접 `DetailPanel`/`DeckConfirmation` 호출 56곳을 색인했다(`verification/modal-identity/inventory.json`). AI Workspace 내부 모달은 기존 공통 래퍼에서 deck-dialog를 붙이는 것을 확인했다. 호출부 색인은 런타임 상태 조합 전수 검사와 다르다. 운영체제 파일 저장창, Office/외부 브라우저 소유 화면은 누비 CSS 대상이 아니다.

공통 실제 렌더 검사 `assertDialogIdentity`를 기존 모달/전체 화면 검사에 추가했다. 배경, 본문/제목 색, 라벨 굵기/색, 일반 오류와 링크를 토큰의 계산된 색과 대조한다. Wave2 루틴 화면의 실제 추가/주간 설정/수정/예약 끄기/삭제 취소와 확인/읽기 오류도 1280/440/360px에서 검사한다.

정적 CSS 감사는 전체 앱 96파일(번들 연결 92)의 선언 기준이다. 서체 90.6%, 색 78.7%, 간격 79.4%가 토큰을 참조했다. inherit/transparent/0 같은 정상 값도 비참조 분모에 들어가므로 이를 화면 일관성 점수나 나머지 전부의 오류율로 해석하지 않는다. 원시 값 선언은 각각 98/20/102개이며 외부 브라우저와 문서 렌더링 등 모달 밖도 포함한다. 이번 공통 모달 변경은 새 원시 색/폰트 굵기를 추가하지 않는다.

## 검증

- RED: 루틴 이름 라벨 400 != 공통 500 (`verification/modal-identity/red.log`).
- GREEN: 루틴 3개 너비의 설정 흐름과 실제 목록 오류 색 통과 (`routines.log`).
- 전체 화면 117개와 기존 모달 키보드/확대 검사는 통과했다. 마지막 삭제 강조 보완 후 전체 게이트는 진행 전이다. 완료 결과는 아래에 추가한다.
