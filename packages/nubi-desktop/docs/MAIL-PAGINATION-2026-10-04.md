# 메일 페이지와 스크롤

메일 목록을 넘겨도 검색 조건과 열린 원문을 유지한다. 검색/조건과 하단 페이지 조작은 고정하고 목록과 본문만 각각 스크롤한다. 페이지를 바꾸거나 검색/조건/정렬/개수를 바꾸면 새 목록의 맨 위로 이동한다. 같은 결과 페이지를 갱신할 때는 스크롤 위치를 보존한다.

## 적용한 패턴

[Carbon 페이지네이션](https://www.carbondesignsystem.com/building-blocks/core/components/pagination/guidelines)의 개수 선택, 표시 범위, 현재 페이지와 전체 페이지, 같은 형태의 이전/다음을 참고했다. [접근성 지침](https://carbondesignsystem.com/components/pagination/accessibility/)에 따라 조작 이름과 키보드 입력을 유지한다. 기존 CX ActionButton/CxInput과 검색 백엔드를 확장했으며 Carbon 라이브러리나 새 의존성을 추가하지 않았다. 별도 보기 모드나 번호 버튼 나열은 추가하지 않는다.

- 기본은 20개이며 10/20/50/100개씩 선택한다. 마지막 개수 선택만 기기에 보관한다. 메일 내용, 주소, 비밀번호나 인증값은 보관하지 않는다.
- 하단에 `1–20 / 128개`처럼 현재 범위를 표시한다. 페이지 번호는 입력 후 Enter 또는 초점 이동으로 적용한다. Escape는 현재 번호로 되돌리고 잘못된 값은 복원하며 범위를 넘으면 마지막 페이지로 제한한다.
- 한 페이지뿐이면 이전/다음과 번호 입력을 숨기고 개수와 범위는 유지한다. 검색 결과가 없거나 실패한 경우 이전 결과의 페이지 조작을 노출하지 않는다.
- 이전/다음은 브라우저 누비의 AgentTrace와 같은 CX previousMedia/nextMedia 아이콘을 재사용한다. 키보드 초점과 44px 터치 영역을 유지한다. 공간이 충분하면 한 줄, 부족하면 두 줄로 배치한다.
- 스크롤은 공통 4px 토큰과 둥근 track/thumb, 위아래 8px 여백을 재사용한다. 목록을 키보드로 스크롤할 수 있고 목록 경계에서 바깥 영역으로 스크롤을 넘기지 않는다. 채팅의 숨겨진 스크롤바에는 영향을 주지 않는다.
- 좁은 화면에서 미선택 상태의 본문 빈칸은 숨기고 목록이 남은 높이를 사용한다. 선택하면 목록/본문을 위아래로 나누며 각각 스크롤한다. 넓은 화면은 기존 두 열을 유지한다.

## 데이터 연결

MailSearch는 기존 필터 우선 적용, 메일별 묶음과 결정적인 정렬을 유지한다. `page`, `totalPages`, `currentCursor`를 추가해 임의 페이지에 직접 이동한다. page는 안전한 양의 정수만 받고 실제 마지막 페이지로 제한한다. 기존 offset cursor 호출도 유지한다. 같은 snapshot의 currentCursor를 보내며 fingerprint가 바뀌면 기존 reset 계약에 따라 첫 페이지로 이동하고 공통 토스트로 알린다. 선택한 원문은 닫지 않는다.

늦게 도착한 이전 검색 응답은 반영하지 않으며 로딩/실패/조건 변경 중에는 이전 페이지의 항목과 이동 버튼을 차단한다. 적용된 페이지와 입력된 번호를 같은 응답에서 갱신해 개수 변경 직후 이전 번호가 잠깐 보이던 문제를 수정했다. 같은 페이지 갱신은 입력 중인 번호 초안도 덮어쓰지 않는다.

개인 원문/첨부/위키의 검색, 원문 해시 재확인, 다운로드와 OS 저장 계약, POP3 자동 정리 및 메모리 전용 인증은 유지한다.

## 확인 범위

`npm run build:electron` 완료(exit 0). 자동 테스트와 실계정 메일 요청은 실행하지 않았다. 예시 메일 28개로 현재 UI를 수동 확인했다.

- 목록에서 PageDown 후 719px 위치가 동일 페이지 새로 확인 뒤에도 유지되고 검색창/페이지 조작은 고정된다. 다음 페이지에서는 21–28 / 28개, 8개 항목과 scrollTop 0을 확인했다.
- 10개 보기의 3페이지 직접 이동, 20개 변경 후 1페이지/표시 범위/번호의 동시 초기화와 기존 원문 보존을 확인했다. 선택한 개수는 예시 화면을 다시 열어도 유지된다.
- ‘회의’ 검색은 9개 결과, 1–9 / 9개와 단일 페이지 조작 숨김을 확인했다. Unicode 검색의 미리보기 cursor도 정상 생성된다.
- ‘최근 30일’ 조건이 다음 페이지에서도 유지되고, 기존 견적 메일과 첨부는 계속 열린다. 999 입력은 현재 총 2페이지의 마지막으로 제한한다. 50개 보기는 1–28 / 28개와 불필요한 이동 조작 숨김을 확인했다.
- 좁은 화면에서 목록과 원문 각각의 스크롤 및 48px 하단 조작, 넓은 화면의 두 열 배치를 확인했다. 일시적인 viewport override는 원래 크기로 복원했다.

실제 MailSearch 백엔드는 소스/빌드와 기존 mail 검색 라우팅으로 연결을 확인했으며 이번 예시 UI 확인을 실수신 또는 실계정 검색 성공으로 표시하지 않는다. 실행 중인 Electron 갱신은 앞선 자동 승인 검토에서 로그인/미저장 상태 손실 우려로 거절되어 대기 중이다. Windows 설치판과 실메일 동작은 별도 확인 범위다.
