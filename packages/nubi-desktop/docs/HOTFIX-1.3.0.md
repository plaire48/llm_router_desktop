# 누비 Workspace Beta 1.3.0 시험판 (10-23 빌드)

1.3.0 번호로 다시 낸 시험판입니다(사용자 결정 10-23). 10-22 1.3.0 이후 개발한 내용을 모두 담습니다. 앱을 가볍게 정리했고, 메일 받는 방식을 고를 수 있게 했고, 코딩 품질을 높였습니다.

## 바뀐 점

- 가벼운 흐름: 워크플로우와 루틴 화면을 껐습니다. 화면 상태 계산 방식을 바꿔 대화가 길어도 덜 멈춥니다. 쓰지 않는 CSS 선언 184개를 지웠습니다. 애니메이션은 그대로입니다.
- 대화: 프로젝트를 고르지 않아도 바로 대화를 시작합니다. 시작 화면과 빈 대화에서 새와 모델 칩이 맨 위에 나옵니다.
- 위키 모델: 프로젝트 연결, 위키 설정, 다시 만들기, '이미 있어요' 확인 창에서 모델과 추론 정도를 같은 칩으로 고릅니다. 자동으로 두면 대화의 추론 정도를 따릅니다.
- 메일: 받는 방식을 고릅니다. 1. Knox Desktop Message는 PC에 저장된 메일을 읽습니다. 2. POP3는 아이디와 비밀번호를 입력합니다. '아이디 기억'을 켜면 아이디만 OS 보호 저장소에 두고, 비밀번호는 저장하지 않습니다. 포털 연결은 뺐습니다.
- 질문과 입력: 답한 뒤에도 남던 질문 카드와 입력값을 지웁니다. DB 연결 비밀번호는 보내는 즉시 지웁니다. 질문 직전에 보낸 추가 지시는 답한 뒤 이어서 실행합니다.
- 변경 전으로 되돌리기: 수정 적용, 새 파일, 명령 실행 직전마다 시점을 남깁니다. '변경한 파일' 카드에서 시점을 골라 되돌리고, 되돌리기를 취소할 수 있습니다. 프로젝트 git 저장소는 건드리지 않습니다.
- 명령 '항상 허용': 같은 명령뿐 아니라 앞부분이 같은 명령(예: npm run test)도 다음부터 확인 없이 실행합니다. 삭제나 강제 push처럼 되돌릴 수 없는 명령, 삭제와 권한 프로그램은 넓혀 허용하지 않습니다.
- 수정 뒤 타입 오류: TypeScript 수정이 새로 만든 오류를 바로 모델에게 알려 고치게 합니다. 큰 도구 결과는 앞부분만 보내고 전체는 파일로 남겨 다시 읽습니다. 개발 작업에는 프로젝트 코드 지도를 함께 줍니다.
- 코딩: 코드 수정 매칭을 opencode 방식으로 바꿨습니다. 줄 끝(CRLF)을 지키고, 공백 차이를 너그럽게 맞추고, 같은 문구를 한 번에 모두 바꿀 수 있고, 못 찾으면 가장 비슷한 줄을 알려줍니다. 소스 찾기에 정규식과 파일 패턴을 더했습니다. 작업 환경(운영체제, 셸, 날짜, git 분기)을 모델에 알리고, 사용자가 만든 변경은 되돌리지 않게 했습니다. 서버가 바쁠 때(429, 503)는 최대 7번까지 기다려 다시 시도합니다.

## 아직 안 되는 것

- 워크플로우와 루틴은 이번 판에서 꺼져 있습니다.
- Knox Desktop Message 연결은 회사 PC에서 아직 실측하지 않았습니다. 설치 후 첫 시험 대상입니다.
- 1.3.1을 설치한 PC에서는 버전이 낮아 업데이트로 잡히지 않을 수 있습니다. 그때는 1.3.1을 지우고 설치해 주세요.
- 이번 설치 파일은 빠른 빌드입니다. CI는 기본 시험과 설치 파일 만들기만 했습니다. 설치, 업그레이드, 제거, 화면 시험은 직접 확인해 주세요.

Windows 11 회사 PC, Office 2016/NASCA, 회사 로그인과 메일 수신(Knox Desktop Message와 POP3), 외부 Chrome 연결은 설치 후 시험 대상입니다. CI 검사는 해당 환경의 업무 성공을 의미하지 않습니다.
