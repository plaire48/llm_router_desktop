# POP3 인증 실패 점검

사용자 확인: 같은 Windows PC에서 다른 메일 앱은 같은 POP3 계정으로 수신되며 SPA는 꺼져 있다. 회사 서버의 실제 응답과 로그인 이름 형식은 아직 확보하지 않았다.

`mail_auth_failed`는 TLS 연결 뒤 USER 또는 PASS 명령을 거절한 응답을 하나로 묶던 코드다. TLS/인증서 오류는 먼저 `mail_tls_*`로 분류하므로 이 코드만 보고 SSL을 끄거나 인증서 검증을 변경하지 않는다. USER 요청 통과가 계정의 존재나 비밀번호의 유효성을 증명하는 것은 아니다.

확인한 구현 결함: 고정 node-pop3 0.15.3의 `command()`는 명령 전체에 `trim()`을 적용해 비밀번호 끝 공백을 바꾼다. 비밀번호 원문을 유지하는 회사 메일 계약과 맞지 않는다. 기존 TLS 소켓과 응답 이벤트를 재사용하되 인증 명령의 검증된 값을 그대로 전송하는 작은 어댑터로 수정했다. 공급자 패키지는 수정하지 않았다. 오류 메타데이터에는 USER/PASS 이름만 남긴다.

실패는 USER 거절(`mail_auth_user_rejected`), PASS 거절(`mail_auth_login_rejected`)로 구분한다. 표준 `[IN-USE]` 응답만 `mail_mailbox_busy`로 구분한다. 서버의 임의 설명, 계정, 비밀번호는 진단에 노출하지 않는다. 비밀번호 오류나 회사 계정 정책을 서버 응답 없이 단정하지 않는다.

근거: [RFC 1939 USER/PASS](https://www.rfc-editor.org/rfc/rfc1939.html), [RFC 2449 응답 코드](https://www.rfc-editor.org/rfc/rfc2449.html), 저장소에 설치된 node-pop3 소스. 기존 파서/TLS를 유지하면서 명령 값 보존 문제만 고치기 위해 다른 POP3 라이브러리나 NTLM 구현은 도입하지 않았다. SPA가 꺼져 있다는 사용자 확인만으로 해당 서버의 모든 인증 정책을 확정하지 않는다.

검증: 런타임 빌드와 메일 관련 17개 검사 통과. 실제 로컬 TLS 서버에서 공백/탭/특수문자 비밀번호 원문, USER/PASS 거절, UIDL/본문 수집, 취소, 번들 worker 무출력/비밀값 미저장 및 Beta 범위를 확인했다. 회사 서버의 인증 성공은 아직 검증하지 않았다.

이 수정은 로컬 소스와 생성 런타임에 반영했다. 이미 게시한 1.1.3 Windows EXE에는 포함되지 않았다. 설치판 재배포 및 실제 사내 재검증은 별도다.
