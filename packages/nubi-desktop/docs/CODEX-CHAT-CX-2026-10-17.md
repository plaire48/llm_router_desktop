# Codex 채팅 화면 참고와 적용

중앙 채팅의 읽기 흐름, 입력창과 보조 도구 표시를 정돈했다. 바깥 파스텔/흰 작업면, 모델사 고유 색상, 누비 서체와 작은 새, 기존 승인/출처/실행 상태는 유지한다.

## 실제 참고한 화면

[OpenAI 공식 Windows 안내](https://learn.chatgpt.com/docs/windows/windows-app)의 [공식 UI 이미지](https://learn.chatgpt.com/images/codex/windows/codex-windows-light.webp)를 내려받아 직접 확인했다. 사진에서는 중앙의 평문 답변, 같은 읽기 축 위의 입력창, 상대적으로 옅은 실행 기록, 답변과 연결된 변경 검토가 보인다. 이미지를 현재 설치된 최신 Codex의 실측이나 공개 디자인 규격으로 간주하지 않는다. Codex 앱 자체는 자동화 접근 제한이 있어 직접 조작/성능 비교하지 않았다. 공식 소개도 [진행과 결과를 한곳에서 검토하는 흐름](https://openai.com/codex/)을 설명한다.

## 적용

| 요소 | 누비 적용 |
| --- | --- |
| 중앙 읽기 축 | 기존 최대 50rem을 48rem으로 정리. 기본 루트 16px에서 768px. 본문과 입력창은 같은 중앙 폭 |
| 답변 | 흰 바탕의 일반 본문. 본문 안의 추가 78ch 제한을 풀어 표/긴 문장이 정해진 대화 폭을 사용 |
| 사용자 메시지 | 오른쪽의 옅은 중립색 말풍선. 일반 80%, 좁은 작업 영역 92% 한도. 첨부와 긴 문구는 줄바꿈 |
| 대화 간격 | 상단 24px, 답변 사이 32px를 기본 토큰으로 사용. 답변 본문 16px와 보조 14px 유지 |
| 보조 도구 | 일반 마우스에서는 복사/시간/재응답을 hover/키보드 focus 때 표시. 복사 성공/실패도 표시. 터치에서는 항상 보임 |
| 입력창 | 공통 한 겹 테두리와 20px 기본 모서리. 모델/추론/승인/문맥/전송을 기존 입력창 안에 유지 |
| 진행 기록 | 접힌 기록/생각/명령의 제목은 보조 글자 토큰. 승인과 오류는 기존 상태/행동을 유지 |

위 크기는 누비의 적용값이며 Codex에서 추출한 정확한 CSS 값이 아니다. 보조 도구는 opacity로만 조절해 나타날 때 본문 위치가 바뀌지 않으며 키보드 접근을 제거하지 않는다.

## 검증

기존 Workbench에 여러 번의 요청/답변과 표가 있는 합성 대화를 넣었다. 실행판과 같은 `.desktop-shell`, 제목 줄, 바깥 프레임과 `nubi-desktop-host` 부모를 포함한다. 이전 비교 스크립트가 생략하던 프레임/부모를 보완했으며 그 차이를 제품 개선으로 계산하지 않는다. 비교 전/후 모두 같은 보완된 호스트를 사용했다.

- 변경 전: 1920/1280/760/440/360px, 5개 사례
- 변경 후: 같은 5개와 760px 터치, 총 6개. 440px의 200% 글자 확대 포함
- 입력창과 본문의 축, overflow, 버튼 겹침, 서체/크기/대비, 모델사 배경과 마우스/키보드/터치 보조 도구 표시 확인
- 별도 메시지 하단 도구, 전송/복구, 스크롤, 진행 기록, 승인/질문과 전체 화면 회귀를 순차 실행

원장: `artifacts/workspace-codex-chat-2/gates.json`, `before/result.json`, `after/result.json`. 실제 모델 응답 품질, Windows/Office/NASCA, 설치판 배포나 Codex 대비 성능 점수를 뜻하지 않는다.

최종 결과: 채팅 6사례와 440px 200% 확대, 메시지 도구/전송 복구/스크롤/진행/승인 및 전체 화면 117 상태가 모두 종료 0이다. 최종 보강 검사에서 복사 성공과 실패 표시가 hover를 벗어나도 남는지 확인했다. 실제 클립보드는 쓰지 않고 시험 어댑터를 주입했다. 빌드와 정적 디자인 검사도 통과했다. `test:chat-ui`를 `test:gates`에 연결했으며, 전체 게이트 명령을 이번에 한 번에 실행한 것은 아니다.
