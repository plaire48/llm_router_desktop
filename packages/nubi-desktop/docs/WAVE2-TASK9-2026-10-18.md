# Wave 2 Task 9 — 조사와 문서 작업자 공용 큐 (2026-10-18)

## 상태

Task 9 로컬 구현과 전체 게이트를 완료했다. §8.10의 공용 두 파일 연결과 §8.11의 OpenWiki 문서 큐 연결을 사용자가 각각 승인했다. 기본 호출자는 보존하며 Desktop 분석/조사/문서 작업자만 같은 큐를 사용한다. 커밋, push, 릴리스는 하지 않았다.

## 적용 내용

- `delegate_analysis`, `delegate_research`, `analyze_documents`가 실행당 새 작업 합계 6개와 동시 2개 슬롯을 공유한다. 기존 작업 재사용은 새 admission을 쓰지 않으며 수집한 작업도 누적 한도에 남는다.
- 공용 호출자가 scheduler를 주입하지 않으면 기존 큐와 수집 전 6개 한도를 유지한다. 공용 변경은 `agent-runtime.js`, `analysis-agents.js`의 선택적 인자/연결뿐이다.
- 조사에는 기존 source/wiki/mail 읽기 스키마만 제공한다. 지정 경로와 실제 경로를 비교하고 상위 경로 탈출, 허용하지 않은 영역, 쓰기/질문/명령/중첩 위임을 거절한다. 메일은 선택/검색에서 확인한 ID의 본문만 읽으며 첨부 읽기는 제외한다.
- 별도 문맥은 직렬화된 도구와 대화 크기를 포함해 최대 24,000자(전송 지침 여유 포함)다. 큰 결과는 JSON을 자르는 대신 읽기 범위 축소 안내를 반환한다. 원문을 실제로 전달하지 않은 결과는 findings 출처로 인정하지 않는다.
- 최초 최대 20회, 이어 묻기 두 번 각각 최대 5회의 모델 결정 호출이다. 네트워크 재시도는 기존 transport를 재사용하고 실제 시도는 목적 `research` 지표에 기록한다. 메인 60회 결정 예산과 구분한다.
- 조사 결과는 advisory다. 메인의 수정 관찰, 메일 인용, Wiki 근거 또는 독립 검토의 실제 근거로 승격하지 않는다. 메인이 원문을 다시 읽는다.
- 기존 `AnalysisHistory`에 `조사` 역할, 호출/읽기 수, 출처 메타데이터, 미확인 범위를 표시한다. 전체 원문/모델 대화는 진행 저장소에 넣지 않는다.
- 기존 `run-metrics.mjs`에 `research`, `subagentCalls` 집계를 추가했다. 평가 채점 파일과 과제는 바꾸지 않았다.

## 계획 예시 보정

1. 예시 continue의 누적 budget/로컬 calls 비교가 호출 수를 과도하게 늘리므로 최초 20 + 이어 묻기 5 + 5로 제한했다. 같은 문맥/범위를 보존한다.
2. 예시의 `eval/grade.mjs`는 채점만 하므로 기존 telemetry에 집계했다. 평가 기준은 유지한다.
3. 별도 큰 문서 큐는 §8.11에서 사용자 승인을 받고 같은 큐에 연결했다. 새 recovery 문맥도 admission을 쓰되 같은 물리 슬롯을 유지한다. planner/결과 synthesis는 기존 단일 조정 흐름이며 별도 연구 작업자를 만들지 않는다. 실행하지 않은 문서 범위를 합치려고 모델을 추가 호출하지 않는다.
