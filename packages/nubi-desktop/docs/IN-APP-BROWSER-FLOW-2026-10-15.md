# In-app browser actions and latency

The BrowserHost did not register Electron's context-menu event. It now opens a native menu on the clicked contents: editing operations respect Chromium edit flags, HTTP links open in another Nubi tab, and image copying uses Chromium. Authentication tabs preserve their session, owner and automation protection. No external browser or renderer clipboard proxy is introduced.

Agent opening previously required a scheme, while manual navigation recognized bare local addresses. A shared HTTP address normalizer accepts localhost/loopback ports and maps server bind addresses `0.0.0.0`/`[::]` to loopback. Non-web schemes and URL credentials remain rejected. Failed page loading remains in the in-app tab; connection refusal explains checking the terminal server and port, with the existing retry control and common UI. A local recovery test also found that successful page content could remain hidden behind a previous connection-refused state. The host now retains the attempted navigation URL and clears the failure on a successful main-frame navigation. This fixes confirmed input-contract and recovery gaps, not a claim that the user's unrecorded failure was reproduced exactly.

The existing official Playwright MCP connection reuse, per-tab queues, 150ms settle and inline post-action snapshots remain. Opening now also returns a fresh initial DOM snapshot with the tab/document binding, avoiding one model round trip. This extra read has a 1.5s response bound; slow pages retain the opened tab receipt and reusable connection. Browser back now also returns the observed resulting page. No DOM snapshot cache, arbitrary sleeps, hidden retries or approval bypass is introduced.

Local Electron measurements before/after (single runs, milliseconds): open 53 -> 99, subsequent first snapshot 70 -> 3, click plus result 194 -> 186, warm snapshot 2 -> 2. The new open includes the initial snapshot; the saved model round trip is not included in these host timings. No claim about company-network or Windows latency is made.

Verification uses real Electron WebContentsView, worker IPC, official MCP and a local HTTP fixture. Unit checks cover editing flags, link protocol restrictions and local address normalization. The full app fixture separately covers approval, typed input, click readback, native visibility and persisted always-allow after restart. Real accounts and Windows remain separate gates.

Final evidence: 33 focused tests passed; identity check and Electron build passed. The real-app approval fixture passed with native view visibility, DOM readback and restart persistence. The direct host fixture passed an actual Chromium right click, scheme-less loopback opening, initial snapshot delivery, server-off failure followed by server-on same-tab recovery, tab binding and authentication protection. Evidence: `verification/playwright-mcp-2026-10-15/result.json` and `verification/mcp-approval-2026-10-15/result.json`.
