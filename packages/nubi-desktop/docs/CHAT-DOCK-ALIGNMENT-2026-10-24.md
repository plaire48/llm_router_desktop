# Conversation dock alignment

The existing input dock had independent transcript margins, stack padding and a main bottom inset. A built macOS Electron short-draft measurement showed a 20 px gap below the input. The shell-state publisher already supplies `data-has-task` and the existing outer-scroll guard works; neither its ownership nor scrolling logic needed replacement.

Empty and existing conversations now use the shared 16 px horizontal inset and 8 px bottom inset. The transcript, follow-up stack and input use the same available width without a fixed width cap. The input stack no longer adds an extra top margin or vertical padding, placing the existing latest-message control 8 px above the input. Reading content retains its existing inner text alignment, and the Liquid Glass button, focus, draft, question/approval and scroll-following logic are unchanged.

Verification: the initial built-Electron geometry assertion failed at the observed 20 px gap. After the change, four actual local-draft scenarios passed: a short conversation, a long conversation at 1480×900 and 440×900, and 440×600 with 150% text. Each measured an 8 px input bottom inset, matching transcript/input edges, no outer overflow, preserved drafts and working follow-latest. The existing Chrome checker passed six conversation cases and five empty-entry cases, the streaming/manual-reading/follow-latest regression passed, and the question/approval checker passed five cases including narrow and enlarged-text states. Electron build and design identity checks passed. Screenshots were reviewed in the surrounding Workspace. No real model or Windows installer/GPU result is claimed.
