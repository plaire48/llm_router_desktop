# 응답과 메일 정리 시간

사용자 요청에 따라 현재 실행의 경과 시간과 결과가 나오기까지 걸린 시간을 표시한다. 기존 실행기와 영수증을 재사용하며 별도의 타이머 라이브러리를 도입하지 않는다. Calendar timestamp는 OS 표시용이고 실제 duration은 Node/renderer의 performance.now를 사용한다.

채팅은 startAgent의 실행 접수에서 계획, 도구, 추론 재시도, 결과 검토를 거쳐 최종 사용자 응답을 기록할 때까지 측정한다. 답변의 responseTiming에 시작/완료 시각과 durationMs를 저장한다. 진행 중 호스트의 elapsedMs를 state/overview로 보내고 렌더러는 같은 상태 조회 사이만 monotonic 경과를 더한다. 다음 조회는 호스트의 측정값을 기준으로 한다. 답변 아래 복사 버튼과 같은 줄에 시간을 보여주고 실행 중에는 기존 계획/진행 흐름에 경과 시간을 넣는다.

사용자 확인에서 한 실행이 끝나면 시계를 멈추며 답변/승인 후 재개는 새 실행으로 측정한다. 큐에 기다린 시간은 모델 응답 시간으로 합치지 않는다. 중지와 오류는 완료로 바꾸지 않고 재시작으로 측정이 끊긴 실행에 새 duration을 추정하지 않는다. 기존 답변은 기록이 없으면 시간 표시를 생략한다. 서로 다른 실행의 metrics elapsedMs 합계를 응답 전체 시간으로 쓰지 않는다.

메일의 summaryTiming은 원문 재확인부터 모델 정리와 Wiki 저장 readback까지 측정하고 수집 타이머/첨부 처리/모델 연결 대기는 제외한다. 이전 prepared 결과를 저장하는 복구는 정리 시간이 아닌 저장 시간으로 표시한다. 메일 목록/본문, 최근 완료 기록과 하단 진행 상태가 같은 완료 영수증을 사용한다.

이번 수정은 사용자 결정에 따라 Electron 빌드만 수행한다. 실제 새 계정 응답 시간과 첨부 종류별 정리 시간 검증은 별도이며, 기존 메일 10개의 정리 완료 영수증에 시간을 소급해 넣지 않는다.
