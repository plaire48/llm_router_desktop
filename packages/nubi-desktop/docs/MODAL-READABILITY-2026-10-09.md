# Readable model, mail and approval dialogs

기존 CX, NubiSurface, 폰트/팔레트와 핵심 먼저 보기 원칙을 이어 적용했다. 모달의 제목 위 여백은 24px에서 16px, 본문 세로 여백은 16px에서 12px로 줄이고 제목 굵기는 600으로 맞췄다. 좌우 공통 여백과 닫기/Escape/초점 복귀를 유지한다.

모델 선택은 고정 440px 높이를 내용에 맞는 높이로 바꿨다. 긴 목록은 최대 높이와 스크롤을 유지한다. 선택한 모델과 제공자, 검색, 갱신/연결 해제, 문맥/입력 한도 툴팁을 보존한다. 2개 모델 예시의 실제 Electron 모달 높이는 334px다.

메일은 서비스와 계정 입력을 먼저 보여주고 서버 주소를 연결 정보에 둔다. 자동 정리 OFF의 의미는 바로 표시하고 ON의 수집 범위는 펼침에 보관한다. 입력/비밀번호/연결 버튼 순서, 인증 메모리 보관, 취소, 모델 선택과 기존 자료 보존 계약을 유지한다. 승인 설명은 짧게 다듬되 파일 수정과 프로젝트 테스트/빌드/점검의 범위, 관리자 명령/앱 조작의 필수 승인과 항상 허용한 정확한 명령을 유지한다.

기존 디자인 검사에서 오래된 14px/22px 기대값을 발견했다. `identity-browser.mjs`는 승인한 `design/reference.json`의 현재 adaptation 값을 기준으로 검사한다. 실제 CSS 값을 기대값으로 복사하지 않으며 키보드, 초점, viewport, 이름과 입력 가독성 검사를 유지한다. 추가 UI/폰트 라이브러리는 도입하지 않았다. 기존 토큰, details와 모델 컴포넌트의 활용이 이번 범위에 적합하다.

검증: Electron 빌드와 원본 HTML SHA-256 포함 디자인 검사, Chrome의 메일 UI 7개와 모달 UI 24개 검사 통과. 별도 실제 macOS Electron에서 공통 컴포넌트/전체 Electron 스타일의 합성 상태를 캡처하고 모델 창 높이, 세 승인 방식/필수 승인 안내, 서버 정보 펼침 뒤 계정 초안, 좁은 창과 화면 이동 후 대화 초안 보존을 확인했다. Electron 검사 중 페이지 오류는 없었다.

`verification/ui-review/`의 화면 검토 HTML은 캡처를 탭으로 비교하는 검토 자료다. 실제 계정/모델/회사 서버 성공이나 Windows 설치판 검증으로 표현하지 않는다. 전체 기능 게이트는 이번에 다시 실행하지 않았다.
