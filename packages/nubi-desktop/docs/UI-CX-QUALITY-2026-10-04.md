# 누비 Workspace 화면 품질 개선 — 2026-10-04

기존 [기능 품질 점검](QUALITY-AUDIT-2026-10-04.md)을 이어 화면의 정보 순서, 공통 버튼, 작은 모달과 복구 흐름을 확인했다. 사용자가 정한 핵심 문구, 가독성, 아이콘, 일관성 기준을 적용했다. 자동 테스트는 실행하지 않고 Electron 빌드와 별도 예시 화면을 직접 확인했다.

## 정보량과 compact 판단

| 화면 | 처음 보이는 선택과 정보 | 적용한 판단 |
| --- | --- | --- |
| 스킬 빠른 목록 | 등록한 스킬 사용, AI Workspace, 커스텀 관리 | 사용하는 목록과 관리 진입을 두 영역으로 구분한다. 비어 있으면 `등록한 스킬이 없어요.`만 보여 중복 제목을 줄인다. 관리 진입은 목록 스크롤과 분리한다. |
| 스킬 관리 | AI Workspace / 커스텀 관리, 현재 탭의 한 등록 동작 | ZIP/폴더/Markdown을 별도 버튼으로 늘리지 않는다. 기존 단일 등록 흐름을 유지한다. 경로와 세부 정보는 필요할 때 펼친다. |
| 삭제 확인 | 정확한 스킬 이름, 삭제 범위, 취소 / 확인 | 커스텀 삭제는 휴지통 복구를 설명한다. AI Workspace의 프로젝트 설치 제거에는 같은 복구 가능성을 약속하지 않는다. |
| 메일 설정 | 계정 입력, 자동 정리, 접힌 모델과 저장 위치 | 기존 순차 입력과 접기 구조를 유지한다. 저장 위치는 원본/위키 두 경로와 각 복사 버튼으로 구분한다. 모달과 실제 OS 복사는 다른 확인 범위다. |
| 추론과 승인 | 현재 값과 바로 조절할 동작 | 추론 슬라이더와 점, 제공자별 지원 단계를 유지한다. 승인 범위와 변경 영향 설명은 줄이지 않는다. |

전 화면의 폰트와 터치 영역을 함께 줄이지 않았다. 제목 시작 여백은 24px, 본문은 16px의 기존 기준을 유지하고 중복된 첫/마지막 문단 여백과 불필요한 외곽선을 제거했다. 스킬 행의 주 제목과 설명은 다른 명도로 읽는다. 승인 범위나 복구에 필요한 문장은 compact 대상에서 제외했다.

600×480 CSS 화면에서 스킬 모달은 높이 440px, 상단 28px, 하단 468px로 창 안에 들어갔다. 11개 항목 중 목록만 스크롤되고 아래 관리 동작과 X는 남았다. 1480×960에서는 프로젝트 목록, 대화, 파일 편집기를 함께 열어 한 줄 입력 도구와 파일 선택을 확인했다. 임시 화면 크기는 확인 뒤 원복했다. 모바일 제품 지원이나 모든 크기의 통과로 확대하지 않는다.

## 브라우저 코드와 방법론 재사용

- `extensions/aipro-chat/src/AgentTabs.jsx`와 `DeckSurfaces.jsx`의 탭/확인창을 직접 사용했다. 화면마다 새 버튼과 탭을 만드는 분기를 줄였다.
- 설치된 CX DetailPanel의 배경 inert, 초점 순환과 복귀 방식을 작은 모달에 맞춰 적용했다. [WAI-ARIA Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)의 모달 초점, 닫기, 취소 우선, 호출 버튼 복귀 기준과 비교했다. 이는 접근성 인증 결과가 아니다.
- 공통 ActionButton의 이름과 아이콘을 유지했다. [WAI-ARIA Button Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/)을 참고해 아이콘만 있는 버튼에도 접근성 이름을 남겼다.
- 새 의존성이나 IDE 프레임워크를 추가하지 않았다. CX 0.5.4는 이미 사용하는 내부 패키지이며 패키지 라이선스가 UNLICENSED다. 새 오픈소스로 채택했다고 표시하지 않는다.
- Pi, TaskPlan, AgentTrace, QuestionForm, 큐와 사용량의 기존 재사용 계약은 [기능 점검 기록](QUALITY-AUDIT-2026-10-04.md)을 따른다. 실제 계획이나 작업 완료 상태를 시간 기반 애니메이션으로 만들지 않는다.

## 확인 기록과 한계

`npm run build:electron` 완료. 자동 테스트는 실행하지 않았다. 실제 계정이나 사용자 파일을 사용하지 않는 별도 미리보기로 다음을 확인했다.

- 스킬 목록의 비어 있음/11개 목록, 고정 관리 영역과 낮은 창의 스크롤
- 커스텀 관리 탭, 삭제 취소 초점, 예시 삭제 → 휴지통 → 복구
- AI Workspace 제거 실패 → 공통 토스트 → 확인창 유지 → 취소와 복귀
- 모델 오류 → 공통 토스트 → 연결 버튼 유지
- 변경 파일 목록 → 같은 프로젝트의 파일 편집 탭 → 부모 폴더 펼침과 선택 음영
- 메일 저장 위치 접기 → 예시 원본/위키 경로와 복사 아이콘 표시. 실제 OS 클립보드는 이번 화면 확인에서 호출하지 않았다

Windows 설치판, 실제 PowerShell, Gmail POP3와 첨부, 회사 SSO/GHES, 실모델 품질과 Google 패스키 인증은 이번에 성공 검증하지 않았다. [패스키 제한](LOGIN-PASSKEY-2026-10-04.md)을 유지한다. 로그인 최적화나 문구 수정으로 인증 성공을 주장하지 않는다.

실행 중인 실제 Electron의 새로고침은 로그인과 미저장 상태 손실 우려로 앞선 자동 승인 검토에서 거절되어 사용자 응답을 기다린다. 이 기록의 화면은 빌드된 UI를 별도 예시 미리보기에서 확인한 것이다. 기존 실계정 세션은 변경하지 않았다.
