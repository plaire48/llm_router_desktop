# Wave 2 Task 8 모델 재시도와 이어가기

설계 §8.9의 조정안을 보고한 뒤 사용자가 “이어서”라고 지시해 기존 경로로 구현했다. 최종 전체 게이트가 종료 코드 0으로 통과했다.

## 적용

- 제품 변경은 `runtime/recovery.mjs:modelTransport`의 기본값 한 곳이다. 재시도 3회(총 4회), 기준 지연 2/4/8초다. 실제 대기는 기존 공용 실행기의 분산 지연과 서버 cooldown을 따른다.
- 기존 호출별 낮은 한도와 0회, 이미지 무재시도, 취소, 인증/정책 오류 제외, 408과 발행 전 잘못된 응답 복구를 유지한다. 60초보다 긴 Retry-After는 줄이지 않고 중단한다.
- provider 래퍼를 추가하지 않았다. 실제 시도는 기존 실행 지표로 한 번만 센다. 기존 이어가기 버튼과 `resumeAgent`를 재사용해 현재 상태와 영수증을 확인한다. 명령/도구를 재전송하지 않는다.

## 검증

- 실패 재현: 기본 1초 대기와 총 3회 시도로 새 계약의 시험 3개가 실패했다.
- 집중 시험 최종 50/50. 실제 transport 지연/횟수, 같은 원문/영수증 유지, 실제 집계, 낮은 한도와 0회, 인증 거절, 408/응답 복구, 긴/짧은 서버 대기, 취소와 기존 MCP 승인 계약을 검사했다.
- 기존 회귀의 총 3회 기대값을 새 총 4회로 바꾸고 중단/오류/영수증 검사는 유지했다. 새 집계 시험은 실제 `{summary}` 반환 구조에 맞춰 정정했다.
- 1280/440px Chrome 합성 화면에서 이어가기 단추 하나, Enter로 `resumeAgent` 한 번, 추가 `startAgent` 요청 없음, 승인 대기 카드와 원 대화 보존을 확인했다. 440px 화면을 직접 검토했다. 터미널 구문 강조로 분리된 텍스트는 승인 영역 본문으로 검사했다.
- 첫 전체 게이트: 1,983개 중 1,782 통과, 1 실패, 200 건너뜀. 메일 모델 고정 검사의 기존 총 3회 기대값이 새 4회와 달랐다. 별도 TLS fixture로 네 호출 모두 같은 모델임을 확인하고 기대 목록만 맞췄다. 실패/저장 상태 검사와 메일 자체의 별도 3회 재처리 한도는 유지했다.
- 최종 `npm run test:gates` 종료 코드 0. 단위 1,983개 중 1,783 통과/0 실패/200 건너뜀. 디자인, 브라우저 화면, 빌드, macOS Electron, 117 화면 조합, 추가 QA 4종과 산출물 열기 검사를 통과했다. 여섯 소스/검사 파일의 해시는 검사 시작과 같다. 실제 모델/Windows/Office/SSO 성적으로 확대하지 않는다.
