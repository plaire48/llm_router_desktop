## 2026-10-05 현재 범위

[Office 첨부 읽기 계약](OFFICE-ATTACHMENT-READING-2026-10-05.md)이 아래 일반 파서 범위와 OS 실행기 미도입 기록을 Windows Office에 한해 대체한다. PDF와 OCR의 경계는 유지한다.

메일 화면의 `메일 연결`에서 계정, 자동 정리, 모델과 저장 위치를 관리한다. 검색 옆 북마크는 저장한 검색을 열고, 선택한 원문에서 고정과 태그를 관리한다. 검색 조건은 순위를 정하기 전에 적용한다. 고정/태그/저장한 검색은 누비 로컬 상태이며 POP3 서버의 읽음이나 폴더 상태와 동기화하지 않는다. 실패한 저장으로 화면을 성공 상태로 바꾸거나 태그 초안을 지우지 않는다.

첨부 읽기는 PDF의 텍스트, DOCX/DOCM/DOTX/DOTM의 본문, XLSX/XLSM/XLTX/XLTM의 셀과 저장된 값, PPTX/PPTM/PPSX/PPSM/POTX/POTM의 슬라이드 텍스트와 UTF-8 텍스트를 대상으로 한다. 2026-10-14부터 PNG/JPEG/GIF/WebP/BMP 이미지는 연결된 이미지 입력 모델이 읽어 글과 설명을 첨부 본문으로 둔다(`runtime/mail-attachment-image.mjs`). 읽기 순서는 파서 먼저, Windows Office COM은 파서가 못 읽는 파일만(`docs/OFFICE-ATTACHMENT-READING-2026-10-05.md`). 파일 확장자가 누락되거나 `.bin`인 경우 알려진 MIME으로 파서를 선택하고 실제 bytes 해석이 성공해야 읽기 완료로 기록한다. 매크로는 실행하지 않는다. 이미지/OCR, Word 서식, Excel 재계산과 PowerPoint 노트는 현재 읽기 범위 밖이다. 구형 DOC/XLS/PPT, 암호화 문서와 NASCA 원본 해석은 미지원이다. 문서 10MiB, PDF 200쪽, 추출 본문 100,000자와 별도 worker 시간/메모리 제한을 유지한다. 새 확장자 지원은 소스와 빌드까지 확인했으며 실제 파일별 해석 성공을 이번 결과로 주장하지 않는다.

이전 읽기 실패는 연결 화면의 `읽기와 정리 다시 시도`로 재개할 수 있다. 이미 완료한 동일 해시의 첨부는 다시 읽지 않는다. 2026-10-05의 빌드와 예시 화면 확인, 남은 실계정 검증은 [기능 품질 점검](FUNCTIONAL-QUALITY-AUDIT-2026-10-05.md)을 따른다.

Gmail은 이메일 주소와 앱 비밀번호를 입력하며 공백으로 구분된 앱 비밀번호를 정규화한다. 비밀번호는 host/worker 메모리에만 보관하며 앱 재시작 후 다시 연결한다. UI 재진입은 기존 호스트 연결을 조회한다. 정리 모델은 로그인된 제공자 목록에서 별도로 고르며 현재 대화 모델을 변경하지 않는다.

자동 정리의 초기값은 Gmail 테스트에서 OFF다. 스위치는 모델 선택 전에도 켜고 끌 수 있고 재연결 시 사용자의 설정을 유지한다. OFF 연결은 인증과 UIDL 조회만 하고 RETR하지 않는다. ON 연결과 재개는 실제 수신 영수증과 서버 UIDL을 비교해 미수신 메일을 첨부와 함께 5개씩 수집한다. 모델이 연결되지 않았으면 수신과 첨부 읽기를 진행하고 지식 정리는 대기한다. 서버의 LOGIN-DELAY와 기본 60초 간격을 지킨다. Gmail 앱 비밀번호 준비, POP 설정과 실제 로그인/수신/첨부/정리 성공은 별도로 확인한다. 참고: [Google POP 설정](https://support.google.com/mail/answer/7104828), [Google 앱 비밀번호](https://support.google.com/accounts/answer/185833). OAuth를 제품 기본으로 도입하는 작업은 이번 임시 테스트의 범위에 포함하지 않는다.

이번 Gmail 테스트에서는 이전에 저장한 선택이 없으면 Gmail을 먼저 선택한다. 서버 주소를 입력 폼에 표시하고 연결 시도 직전에 status의 연결 대상을 갱신하므로 실패해도 회사/Gmail을 구분할 수 있다. Google의 알려진 인증 거절은 앱 비밀번호 필요, 웹 로그인 확인, POP 비활성, 주소/비밀번호 거절의 고정 코드로만 분류한다. 원문 오류/USER/PASS/서버 응답을 저장하거나 출력하지 않는다. 인식하지 못한 응답은 일반 인증 실패로 남기고 원인을 추측하지 않는다. 인증 거절 후 자동 재로그인을 반복하지 않는다.

대화와 메일 이력의 우상단 `메일 연결`은 같은 계정 폼을 직접 연다. 아이디와 비밀번호를 입력해 기존 POP3 연결 동작을 수행하며 실제 connected 응답에만 성공 토스트를 표시한다. 직접 열었을 때는 다른 화면으로 돌아가기 버튼을 추가하지 않고 닫으면 원래 버튼으로 초점을 복원한다. 설정에서 들어온 경우에는 기존 설정 복귀 흐름을 유지한다. 이번 확인은 Electron 빌드이며 실제 메일 계정 연결 성공은 확인하지 않았다.

- 자동 정리 OFF는 POP3 수집, 첨부 본문 읽기, LLM 정리를 모두 중단한다. 진행 중인 요청을 취소하고 새 원본을 저장하지 않는다. 아직 수신 영수증이 없는 새 원본 디렉터리는 취소 후 정리한다. 이미 수신한 원본과 정리 문서는 보존한다. OFF 중 연결은 인증과 UIDL 조회만 수행하며 RETR하지 않는다.

- 매 확인 종료 후 기본 60초를 기다린다. CAPA LOGIN-DELAY를 우선하고 수동 확인에도 같은 간격을 적용한다. 다음 확인 시각은 재시작 후에도 유지한다. 수집 연결은 하나이며 POP3를 종료한 뒤 모델을 호출한다. 수집 일시중지는 자동 정리 OFF와 별개로 기존 자료의 읽기/정리를 유지한다.

Git 프로젝트에 메일/인증을 기록하지 않는다. 파일명은 메일 제목과 원본 첨부 이름 대신 내용/소스 식별자로 만든다. POSIX 사용자 전용 권한과 OpenWiki Windows ACL 함수를 사용하며 Windows에서 ACL 적용에 실패하면 저장을 중단한다. NASCA 파일은 바이트 그대로 보관하고 외부 복호화나 ZIP 재저장을 하지 않는다.

Gmail의 16자리 앱 비밀번호 요구는 항상 표시하고 발급 방법과 Google 페이지 열기만 선택적으로 펼친다. 새 메일 확인은 메일 이력에서 수행하므로 같은 설정 버튼은 중복하지 않는다. 이전에 수집을 일시중지한 계정의 재개와 읽기/정리 오류 복구는 실제 상태에서 표시한다. 자동 정리 OFF/ON과 인증의 메모리 보관 계약은 변경하지 않는다.

## 실제 채택과 범위

- node-pop3 0.15.3 (MIT): TLS/로그인/명령/스트림을 채택했다. 실제 고정 소스의 chunk 경계 종료 판정에 필요한 5-byte tail 어댑터를 저장소에 추가했으며 node_modules를 수정하지 않는다.
- MailParser 3.9.28 (MIT): MIME, 한국어 charset와 첨부 디코딩에 채택했다. OpenWiki 최소 릴리즈 경과 기간 정책을 지키는 고정 버전이다.
- 기존 SQLite 실행 소유권, p-retry 추론 복구, OpenWiki 정책/검색/Windows ACL, Nubi/CX UI를 재사용했다.
- Fetchmail은 독립 데몬/Windows 배포 비용 때문에 도입하지 않았다. 새 broker/agent framework를 추가하지 않았다.

로컬 TLS fixture와 synthetic model, Chrome UI 검증을 실서버/실모델/Windows NASCA 성공으로 표현하지 않는다. Windows installer/native 최종 빌드는 수행하지 않는다. 스킬 수신 자동 실행, SMTP 답신 발송과 A2A 문서 전달은 아직 구현하지 않았다. 읽기 전용 전문 문서 협업 제안은 `MAIL-DOCUMENT-COLLABORATION.md`를 따른다.

채팅/드롭 등록과 스킬 시작 환경/메일 트리거의 구현 설계는 [MAIL-SKILL-AUTOMATION.md](MAIL-SKILL-AUTOMATION.md)를 따른다. 현재 ON/OFF와 준비 안내 구현을 자동화 실행 완료로 표시하지 않는다.

## 2026-10-02 연결 안내와 재연결

모델 인증과 POP3 비밀번호는 메모리에만 보관한다. OS 보안 저장소에 새 인증을 저장하지 않는다. 앱 실행마다 메일 연결 안내만 모달로 표시하고 같은 실행에서 화면 새로고침만 할 때는 반복하지 않는다. 메일 모델 선택은 채팅의 공통 제공자 탭/모델 목록/연결과 로그아웃 동작을 재사용한다. 정리 목적지의 제공자와 모델 ID만 설정에 기록하며 채팅의 선택 모델은 바꾸지 않는다. 비밀번호 입력은 연결 시도 완료 후 지운다.

자동 정리 OFF 시 수집/첨부 읽기/모델 호출을 중단한다. 다시 ON이면 현재 서버에 남아 있고 수신 영수증이 없는 메일을 제한된 묶음으로 이어 받는다. 삭제된 서버 메일이나 Gmail POP 노출 범위 밖의 메일은 가져올 수 없다. 재연결 직후 같은 계정의 미완료 첨부와 정리 작업을 재개하며 저장한 Wiki는 중복 생성하지 않는다. 이번 변경은 빌드와 수동 화면 확인만 수행하고 실계정 POP3와 실제 모델 정리는 확인하지 않았다.

메일 연결 중에는 서버 확인 상태를 표시하고 중복 연결을 잠근다. 연결 취소는 해당 호스트의 POP3 연결 확인을 중단하며 비밀번호 입력을 지운다. 자동 정리 OFF로 연결 generation이 바뀐 경우에도 원래 요청 객체의 연결 대기 상태를 finally에서 해제한다. 다른 연결 요청의 상태를 지우지 않으며 취소된 연결 결과로 성공 토스트를 표시하지 않는다.

Gmail 앱 비밀번호는 Google의 16자리 형식으로 입력받고 표시용 공백/줄바꿈/유니코드 공백을 제거한 뒤 호스트와 화면에서 같은 순수 함수를 사용해 검증한다. 회사 비밀번호는 변경하지 않는다. 형식 오류와 Google의 인증 거절을 구분하며 인증 오류에 자동 재전송하지 않는다. 이전 앱 비밀번호가 실제로 취소됐는지는 서버 응답만으로 확정하지 않는다. 새 앱 비밀번호 생성과 입력은 사용자가 직접 수행한다. Google 계정 비밀번호 변경 시 앱 비밀번호가 취소되는 공식 정책을 안내한다.

## 화면과 독립된 처리와 진행 표시

메일 연결 후 POP3 확인 타이머는 worker 호스트가 소유한다. 별도의 3초 wakeup은 로그인과 자동 정리 ON 상태에서만 첨부/모델 대기열을 재개하며 다른 대화 작업이 끝나도 다음 화면 조회를 기다리지 않는다. dispose에서 타이머를 해제한다. 수집은 서버 LOGIN-DELAY와 증가하는 오류 간격을 유지하고 화면 새로고침으로 우회하지 않는다.

UIDL 목록 확인 후 같은 계정의 실제 수신 영수증과 보류 UID를 제외한 서버 대기 수만 메타데이터로 기록한다. 하단 공통 상태 줄은 완료(saved), 남음(서버 미수신 + 로컬 정상 대기/정리 중), 확인 필요(첨부/정리/다운로드 보류), 현재 단계와 다음 확인 시각을 표시한다. 보류를 완료로 세지 않으며 서버 남음은 마지막 조회의 값이다. 재시도는 현재 연결 계정의 자료에 한정한다.

2026-10-02 실행 중인 Gmail에서 수신 5개/정리 완료 5개/오류 없음과 실제 다음 확인 간격 300초를 읽어 확인했다. 실제 첨부 파일 종류별 성공이나 새 wakeup 구현의 실계정 검증을 의미하지 않는다. 변경은 Electron 빌드만 수행한다.

메일 이력도 채팅과 같은 프로젝트 사이드바와 남는 콘텐츠 열을 사용하고 공통 페이지 inset/block을 따른다. 제목 옆에는 마지막 서버 확인 시각을 OS locale/timezone으로 표시한다. 새로고침 버튼은 현재 수집 중 중복 실행하지 않으며 허용된 확인 시각 이후에는 실제 POP3 확인과 이력 갱신을 수행한다. 대기 중에는 이력을 갱신하고 다음 서버 확인 시각을 CX 토스트로 알린다. 계정별 최근 12개 확인/정리/오류 기록에는 시각과 개수 및 고정 오류 코드만 보관하며 제목, 계정 ID, 인증값, 원문은 넣지 않는다.

메일 정리 시간은 현재 정리 실행의 시작부터 원문 재확인, 모델 응답, Wiki 저장 readback 완료까지 monotonic performance.now로 측정한다. saved 영수증의 summaryTiming과 최근 처리 기록에 durationMs를 남기며 메일 목록/본문/하단 상태 줄에서 표시한다. 진행 중에는 호스트의 elapsedMs를 받아 렌더러 monotonic clock으로 다음 상태 갱신 사이만 보간한다. 수집 타이머 대기, 미연결 모델 대기와 첨부 읽기는 정리 시간에 포함하지 않는다. 이전에 준비된 결과를 다시 저장하는 복구는 저장 시간으로 표시한다. 기존 기록에 시간이 없으면 추정해서 표시하지 않는다.
