# 대화와 캡처 표시의 크기

사용자 말풍선과 답변 본문은 16px/1.7인데 캡처 표시에는 작업 기록의 14px/1.5가 적용됐다. 공통 대화 아이콘 규칙이 말풍선 내부에도 적용되어 캡처 아이콘이 말풍선 밖으로 8px 나왔다. 수정 전 실제 Workbench의 좌표와 글자 크기 검사로 재현했다.

캡처 요약은 기존 읽기 크기와 줄 간격 토큰을 함께 사용한다. 사용자 말풍선에서는 아이콘이 본문 시작점 안쪽에서 배치되고 본문과 캡처 사이에 공통 8px 간격을 둔다. 답변 쪽은 기존 본문 시작선을 유지하며 선행 아이콘까지 펼침 클릭 영역에 포함한다. 공통 44px 클릭 높이를 유지하고 확대 시 이름은 줄바꿈한다. 사용자 캡처 미리보기의 중복 좌우 여백을 없애 말풍선 안에 맞춘다. 펼침 화살표가 회전 중 약 2px 넘치는 현상도 재현해 공통 4px 끝 여백 안에서 회전하도록 했다.

기존 캡처 저장/지연 읽기/재시도/확대 모달은 재사용한다. JavaScript 레이아웃 측정이나 새 애니메이션은 제품에 추가하지 않았다.

## 검증

- `check-conversation-captures.mjs`: Chromium에서 첫 요청/후속 사용자 메시지/답변의 1280/440/360px 접힘과 펼침, 440px 글자 200%를 확인했다. 회전 중간 상태 6개를 포함한 13개 장면의 캡처 표시 39개에서 본문과 글자 크기/줄 간격 일치, 아이콘 클릭 영역과 말풍선 경계를 확인했다. 실제 이미지 일치, 없는 이미지/손상 이미지 재시도, 공통 확대 모달과 reload도 확인했다.
- `check-electron-app-capture.mjs`: 격리 저장소의 실제 macOS Electron에서 사용자/답변 1280/440px과 글자 200%의 5개 장면을 측정했다. 자동 캡처의 저장 PNG와 확대 모달, 수동 영역 캡처와 취소 후 초안 보존, 700px 표시와 reload의 기존 흐름을 포함해 7개 검사 통과. 440px 검증은 테스트 창의 최소 너비를 완화한 반응형 압축 검사이며 제품 창의 최소 너비 변경이 아니다.
- 캡처/캐시/앱 화면 캡처 Node 검사 16개와 `npm run build` 통과. 기존 CJS import.meta 경고와 PowerShell 부재에 따른 Office 선택 검사 생략은 동일하다.
- 캡처 모달 검사의 과거 원본 파랑 상수 비교를 현재 `reference.json`의 승인된 Desktop 테마 팔레트 비교로 정정했다. 제품 색은 변경하지 않았다.

요청된 `verify:identity`도 실행했으나 기존 `check-electron-shell.mjs:156`이 사용자가 제거하도록 한 “확장 프로그램 없이…” 문구를 계속 요구해 중단됐다. 별도 모달 검사도 새 공통 아이콘 칸을 이미 검증한 뒤 기존 header/body의 paddingLeft가 동일해야 한다는 중복 조건에서 중단됐다. 이번 캡처 전용 CSS는 그 브라우저/모달 경로에 적용되지 않는다. 이 통합 검사들을 통과한 것으로 표시하지 않는다.

실행 기록과 수정 전 실패, 실제 캡처는 `verification/capture-bubble-2026-10-24/`에 남긴다. 외부 앱/UIA와 모델 응답은 합성 입력이며 Windows 실기기, 실제 서비스/모델, 설치판과 CI 결과는 별도다.
