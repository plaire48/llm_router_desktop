# 대화 가독성: 요청당 기록 하나, 보이는 서술, 읽기 리듬 (2026-10-14)

사용자 보고: 채팅에 덕지덕지 붙는 게 많아 핵심이 가려진다. 출처와 reasoning은 두되 Codex처럼 "생각 중" 한 줄이 돌고, 중간에 말하듯 쓰고, 펼치면 뭘 했는지 보이게. 글자 간격과 위아래 간격, 강조(볼드)도 중요하다. 표 아래 글이 표에 붙는다.

실제 앱에서 파일 목록 요청 하나를 돌려 보니, 승인 전 실행과 승인 뒤 이어진 실행이 "작업 계획"과 "진행 기록"을 각각 만들어 같은 요청에 두 벌이 보였고, 모델이 중간에 쓴 말은 접힌 기록 안에 숨었으며, 끝난 명령 블록에 "출력을 기다리고 있어요"가 남았다.

## 바꾼 것

- **요청당 기록 하나.** 승인이나 실패로 멈춘 뒤 이어진 실행은 답도 질문도 없이 같은 메시지를 따른 실행이다. `ui/conversation-activity.mjs`가 이런 실행을 이어진 실행의 `predecessors`로 붙이고, `ui/WorkspaceActivity.jsx`가 그 기록을 앞부분으로 합쳐 보여 준다. 아무도 잇지 않은 실행은 전처럼 제자리에 남는다. 검사 `tests/conversation-activity.test.mjs`.
- **서술은 보이게, 도구는 접어서.** 모델의 진행 메모(`progress_note`)는 대화 속 흐린 글(`nubi-activity-narration`)로 바로 보이고, 도구 단계만 접힌 기록에 남는다.
- **기록 제목.** 진행 중엔 지금 하는 일이나 "생각하고 있어요"와 경과 시간, 끝나면 "1분 7초 작업, 도구 3회"(계획과 호스트의 요구사항 검토는 도구로 세지 않음).
- **끝난 명령 블록**은 "출력이 없었어요"로 표시한다(`ui/Workbench.jsx`).
- **읽기 리듬**(`design/workspace-typography.css`): 본문 글줄 1.7, 자간 −0.01em(Pretendard), 문단 간격 .75em, 목록 .35em, 굵은 글 700. 쉘의 1.6 글줄이 본문 문단에 새어 들어 표(1.8)와 어긋나던 것을 한 값으로 맞췄다. 표·코드 블록·인용 아래 간격을 문단과 같게 했다.
- **파일 목록에 크기**(`runtime/source-search.mjs`, `source_search mode=path`): "어떤 파일이 있고 뭐가 제일 큰가"를 승인 없는 조회로 답한다. 검사 `tests/source-search-sizes.test.mjs`.

되돌린 것: 첫 응답이 읽기 도구뿐이면 계획을 미루는 "쉬운 길"을 넣어 보았으나 하네스 검사 20개가 첫 도구 호출의 계획을 전제로 하고 있어 되돌렸다. 쉬운 요청의 왕복을 줄이는 일은 계획·검토 설계와 함께 다시 본다.
