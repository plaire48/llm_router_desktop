# 누비 Workspace 디자인 톤 재점검

2026-10-01. 주 제품인 VS Code 포크의 내장 Workbench에 반영했다. 원본 llm-router에도 같은 화면 소스를 반영했다. 미커밋 후보이며 Windows 설치판을 생성하지 않았다.

## 확인한 문제와 변경

| 점검 | 확인한 문제 | 반영 |
| --- | --- | --- |
| 토큰과 여백 | 페이지, 행, 아이콘 동작의 간격이 서로 다름 | 페이지 기본 32px, 좁은 창 16px. 섹션/행 24px, 동작 간격 8px를 공통 토큰으로 연결 |
| 글자 위계 | 스킬 제목이 본문과 같은 크기 | 스킬 제목 16px. 일반 UI 14px/22px, 대화 15px/1.75, 큰 글자 대화 17px 유지 |
| 읽기 | 긴 스킬 용도가 한 줄에서 잘림 | 의미 있는 용도를 줄바꿈해 표시. 경로와 버전 이력은 더보기 유지 |
| 핵심 정보 | 접힌 계획에서 같은 상태를 두 번 표시, 빈 동작 행이 자리 차지 | 현재 단계에 상태를 남기고 요약의 중복만 제거. 빈 행은 표시하지 않음 |
| 아이콘 | 스킬 설정은 더보기 아이콘, Workspace 설정은 슬라이더 | 공통 CX 슬라이더 재사용. 추가/더보기/설정은 각각 plus/moreHorizontal/sliders |
| 키보드 | 사용자 정의 아이콘 동작에 키보드 설명이 없음 | WorkspaceIconAction의 접근성 이름, title, 초점 설명과 초점 테두리 |
| 분위기 | 작업 중에도 배경 장식과 강한 그라데이션이 대화와 경쟁 | 로그인/시작은 기존 누비 분위기 유지. 대화는 밝은 읽기 면과 옅은 사용자 메시지 유지 |
| 모션 | 중첩된 화면 진입 모션이 대화 내용에도 반복 적용 | 공통 240ms 진입과 8px 이동. 대화 내부의 중첩 진입 제거. 시스템 모션 감소 유지 |
| 사용자 흐름 | 기능을 잃지 않으면서 읽기 밀도 개선 필요 | 프로젝트/대화/초안, 모델 선택, 승인 범위, 복구 정보, 스킬 설치/업데이트/삭제 흐름 유지 |

## 방법 선택

제공된 agentfactorysdkdeck.html의 팔레트와 번들 Noto Sans KR, 기존 CX 0.5.4와 누비 컴포넌트를 재사용했다. 추가 UI 패키지는 설치하지 않았다. 발표용 제목 크기를 데스크톱 작업 화면에 그대로 적용하지 않고 기존 본문 크기와 행간을 유지했다. 긴 설명을 단순히 없애는 대신 사용자 판단에 필요한 용도를 남기고 경로와 버전 이력은 기존 더보기로 유지했다.

아이콘의 의미와 최소 조작 영역, 초점 표시와 모션 감소는 [W3C 비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [조작 대상 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [상호작용 애니메이션](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)을 참고했다. WCAG 전체 인증을 의미하지 않는다.

## 검증

| 검사 | 통과 | 실패 |
| --- | ---: | ---: |
| Workspace 실제 Chromium 렌더링 | 11 | 0 |
| 모달 일반/좁은/큰 글자 및 초점 복귀 | 42 | 0 |
| 스킬 관리와 설치/업데이트/삭제 | 17 | 0 |
| GHES 계정 합성 로그인과 프로필 화면 | 16 | 0 |
| 추가 디자인 검사 | 11 | 0 |
| VS Code 호스트 단위 검사 | 52 | 0 |
| 실제 macOS VS Code 1.140.0 호스트 통합 | 14 | 0 |
| 같은 호스트의 파일/Git/터미널/테마/스킬 화면 | 12 | 0 |

현재 검증은 화면 97개, 호스트 단위 52개, 실제 macOS 호스트 26개다. 원본 HTML 해시/팔레트 검사, 웹뷰 의존성 빌드 검사, 포크 입력 해시와 diff 공백 검사도 확인한다. 기존 검사 기대값, 빌드 검사와 호스트 허용 목록은 변경하지 않았다.

추가 검사 작성 중 3회 실패가 있었다. 첫 번들에서 생성된 스타일 경로 대신 소스 CSS를 사용해 imports 두 개를 찾지 못했다. 파일 서버에서 읽기 전에 응답 헤더를 보내 favicon 404 처리 오류가 났다. 마우스 입력 후 프로그램으로 focus만 이동한 시나리오가 키보드 힌트를 기다리다 시간 초과됐다. 생성된 공통 스타일 입력, 응답 전 파일 읽기, 실제 Tab/Shift+Tab 시나리오로 각각 수정한 뒤 11개를 통과했다. 제품 검사의 기대값을 낮추지 않았다. 첫 Workspace/모달 검사는 생성된 CSS 갱신 전에 실행돼 최종 수에 쓰지 않았고 호스트 빌드 후 다시 11개/42개를 확인했다.

포크 UI를 빌드하고 실제 렌더링해 확인했다. stock macOS VS Code 개발 호스트에는 포크 코어 패치가 적용되지 않았으므로 그 화면의 Panel 닫기/X와 배치가 최종 Windows 제품의 화면이라는 주장은 하지 않는다. Windows x64 제품 실행판, 실모델 답변의 문장 품질, 실제 회사 GHES/SSO는 미검증이다. GHES 화면 검사는 합성 계정이다. 커밋/푸시와 EXE 생성은 하지 않았다.

## 화면과 로그

변경 전/후 화면과 변경 diff, 실행 로그는 포크 verification/design-tone-review-2026-10-01에 보관한다. 대화 화면은 합성 데이터의 실제 내장 컴포넌트이며 실모델 결과가 아니다. 최종 Windows 제품 화면을 대체하지 않는다.

마지막 원본 대조에서 작업 중 llm-router의 위임 대기 문구가 `브라우저 응답 대기`에서 `연결한 누비 응답 대기`로 바뀐 것을 확인했다. 이번 디자인 변경과 무관한 병행 변경이므로 원본을 되돌리거나 포크 전체를 덮어쓰지 않았다. 디자인 변경 부분은 양쪽에 동일하게 반영했다. 해시 갱신 전 검사에서 AGENTS.md 해시 불일치가 있었으며 변경 입력을 기록한 뒤 재확인한다. 원본 HTML 검사 첫 명령은 패키지 밖에서 실행돼 경로 오류가 있었고 올바른 패키지 경로에서 성공했다.
