# 프로젝트 연결 이후 흐름 단순화

프로젝트 연결 → 같은 화면에서 자료 준비 → 바로 질문 입력으로 이어진다. 사용자가 다음 행동을 찾기 위해 시작 화면이나 확인 창을 반복해서 거치지 않도록 했다.

## 화면 흐름

| 상황 | 사용자가 보는 흐름 |
| --- | --- |
| 처음 시작 | 폴더 열기 또는 Git URL → 실제 프로젝트 로딩 → 자료 준비 → 질문 입력 |
| 프로젝트 없이 대화 | 기존 직접 진입을 유지한다. 빈 대화 기록을 만들지 않고 입력창으로 간다. |
| 메일·위키·대화에서 프로젝트 추가 | 현재 화면 위에 연결 창을 연다. X, Escape, 돌아가기는 원래 화면과 초점으로 돌아간다. |
| 기존 위키가 있는 폴더 | 저장된 위키를 바로 연결한다. 재사용·초기화 선택 창을 생략하고 ‘위키 보기’와 질문 입력을 제공한다. 다시 만들기는 기존 위키 설정에서 명시적으로 실행한다. |
| 새 자료를 읽는 중 | ‘연결 / 자료 정리 / 대화’ 세 단계와 실제 단계별 진행률·경과 시간을 표시한다. 준비 상세는 필요한 경우 펼친다. |
| 분석 범위를 선택해야 함 | 기존 범위 선택 창과 승인을 유지한다. 닫아도 준비 카드의 ‘범위 선택’으로 다시 열 수 있다. |
| 준비 완료 | 같은 카드가 준비 완료로 바뀌고 질문 초점으로 이어진다. 보관한 초안은 유지하며 자동 전송하지 않는다. 다른 편집기에서 입력 중이면 초점을 가져오지 않는다. |
| 연결 실패 | 원래 프로젝트와 대화 초안을 유지한다. 연결 창을 닫으면 원래 화면으로 돌아간다. |

연결 창 아래의 실제 콘텐츠를 계속 마운트한다. 따라서 프로젝트 추가를 열었다 닫는 동작 때문에 위키 탐색이나 메일 화면을 새로 만들지 않는다. 위키 재사용은 기존 호스트의 동작을 그대로 사용하며, 원본을 초기화하거나 위키를 다시 쓰는 동작을 추가하지 않았다.

## 모션 연결

기존 [인터랙션 모션](INTERACTION-ATLAS-2026-10-23.md)과 [프로젝트 로딩 모션](PROJECT-LOADING-MOTION-2026-10-23.md)의 공통 정책을 재사용한다.

- 연결 창: 공통 등장·퇴장, 좁은 창의 시트, Git 입력을 펼칠 때의 크기 보간을 사용한다. 시작 페이지의 Git 입력은 공통 화면 전환을 사용한다. 입력이 렌더링된 뒤 초점을 준다.
- 준비 카드: 단계 강조 표면은 공통 280ms 스프링으로 이동하고 상태 문구는 공통 180ms 페이드로 바뀐다. 초마다 바뀌는 경과 시간으로 문구 모션을 재시작하지 않는다.
- 준비 상세: 사용자의 펼침 조작에만 기존 레이아웃 보간을 연결한다. 백그라운드 진행 갱신은 레이아웃 모션을 시작하지 않는다.
- 모션 감소에서는 단계 이동을 생략하고 짧은 페이드만 사용한다. 기존 숨김·중단 정책과 효과 예산을 유지한다. 새 무한 반복 효과나 CSS `:has()` 선택자를 추가하지 않았다.

진행 단계의 100%를 프로젝트 완료로 해석하지 않는다. 호스트가 `completed` 또는 `existing`이라고 보고한 경우만 준비 완료로 표시한다. 파일 수를 알 수 없는 단계에는 퍼센트를 만들지 않는다. 부분 완료·오류·중지 상태의 기존 복구 계약은 유지한다.

## 검증

모든 UI 검사는 순서대로 실행했다. 실제 모델 호출을 통한 위키 품질 평가와 Windows 설치판 검증은 수행하지 않았다.

| 검사 | 결과와 근거 |
| --- | --- |
| 상태 분류·공통 모션 단위 검사 | 23개 통과. `project-preparation`, `motion-policy`, `motion-consumer-tokens`, `motion-source` 테스트 |
| Electron 빌드 | `npm run build:electron` 성공. 아이콘 검사 포함. |
| 실제 macOS Electron 연결 흐름 | 7개 통과. 위키 검색·초점 복원, 돌아가기, 메일 취소 복귀, 기존 위키 직접 연결과 원본 보존, 대화 초안 보존, 실패 복귀, 620px Git 입력. 로컬 제공자 fixture 사용, 모델 요청 0건. |
| 실제 macOS Electron 개인 대화 회귀 | 5개 통과. 처음 시작 및 좁은 창 직접 진입, 기존 개인 대화·프로젝트 초안 보존, 빈 기록 생성 방지. |
| 실제 macOS Electron 프로젝트 왕복 회귀 | 3개 통과. 선택 대화와 초안 복원, 위키가 없는 프로젝트 직접 진입, 실패 시 원래 대화 유지. |
| 실제 macOS Electron 로딩창 회귀 | 통과. 실제 호스트 진행, 가려진 배경 효과 정지, 단방향 로딩 진행, 준비 화면 공개, 실패 복귀, 모션 감소. |
| 공통 Workbench를 사용한 Chrome 화면 검사 | 7개 통과. 합성 준비 상태로 읽기→정리→범위 선택→완료를 검사했다. 실제 진행률 표시, 상세 펼침, 초안과 초점, 위키 이동, 360px 카드, 모션 감소와 다른 편집기 초점 보존. |

실행 스크립트:

```sh
node --test tests/project-preparation.test.mjs tests/motion-policy.test.mjs tests/motion-consumer-tokens.test.mjs tests/motion-source.test.mjs
npm run build:electron
node scripts/check-project-connection-flow.mjs
node scripts/check-personal-chat-entry.mjs
node scripts/check-project-preparation-ui.mjs
node scripts/check-project-switch-cover.mjs
node scripts/check-project-direct-navigation.mjs
```

결과와 화면은 `verification/project-connection-flow-2026-10-23/`, `verification/project-preparation-2026-10-23/`, `verification/personal-chat-entry-2026-10-23/`, `verification/project-switch-cover-2026-10-23/`, `verification/project-direct-navigation.json`에 기록한다. 기존 화면에서 위키 연결 창이 열리지 않는 수정 전 실패와 검사 도구의 선택자·창 크기 반영 대기 실패는 Codex 작업 폴더에 별도로 보존했다. 후자는 제품 실패로 집계하지 않는다.

전체 게이트와 업로드는 기존 Claude 담당 흐름에서 이어서 확인해야 한다. 이 문서는 해당 후보 브랜치의 반영이나 전체 게이트 통과를 뜻하지 않는다. `design/workspace-density.css`는 이번 변경에 포함하지 않았으며 `0bd7814e`의 두 추론 칩 선택자와 충돌하는 패치를 만들지 않았다.
