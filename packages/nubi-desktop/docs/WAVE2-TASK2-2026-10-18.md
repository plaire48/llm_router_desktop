# 2차 물결 Task 2 적용 기록

설계 §8 답 7을 기준으로 현재 1.2.10 작업 폴더에 적용했다. commit, push, 릴리스는 하지 않는다. Task 1과 Task 0b의 qa79 및 04c380cd 업로드는 사용자가 전달한 Claude 보고이며 이번 실행의 배포 성적이 아니다.

## 적용

- 위험한 셸 명령과 기존 파일 삭제 제안은 자동 승인에서 제외하고 호스트가 사유를 저장한다. 셸의 정확한 문자열 항상 허용 예외와 관리자/앱 제어의 기존 승인은 유지한다.
- MCP는 설계의 readOnlyHint 제외, destructiveHint/openWorldHint, 이름 규칙으로 분류한다. 외부 쓰기/삭제는 저장된 허용이 있어도 다시 승인받고 항상 허용 선택지는 숨긴다. 저장 목록은 삭제하지 않는다.
- 승인한 정확한 호출은 기존 continuation으로 한 번 실행한다. 같은 호출의 완료/취소/미확정 영수증과 기존 복구 경로를 유지한다.
- 최초 화면에서도 호스트 상태 투영에 사유를 넣는다. 자동 승인 API를 호출하지 않는 매번 확인 모드에서도 안내가 보인다. UI에서 권한을 판정하지 않는다.
- 공통 안내 컴포넌트로 명령/수정 명령/파일/MCP 승인 사유를 표시한다. 자동 모드 모달에 설계의 확인 문장을 추가했다. 기본 접힘 설정은 바꾸지 않았다.
- `test:gates`에 신규 승인 화면 검사와 `check-community-wiki-ui`, `check-profile-wiki-ui`, `check-activity-readability`, `check-review-failure-ui`를 순차 연결했다. 기존 네 검사 조건은 이번 작업에서 바꾸지 않았다.

## 확인 근거

신규 모듈 부재, 삭제 자동 반영, 사유 미저장, 저장된 MCP 허용으로 승인 우회가 먼저 실패했다. 구현 후 핵심 24개 검사가 통과했다. 초기 상태의 사유와 실제 저장 사유를 분리해 검사했으며 세 승인 모드, 정확한 명령 예외, 삭제의 이전 제안 자동 반영 방지, 두 요청에서 각각 승인하고 호출은 한 번만 실행하는 흐름을 확인했다.

승인 화면과 자동 모드 안내 문장 부재를 먼저 재현했다. 합성 fixture는 실제 질문 kind/라디오 선택지/호스트 인자 투영에 맞췄다. 1280/440px에서 사유, 항상 허용 숨김, 줄바꿈과 모달을 검사했다. 캡처는 `verification/wave2-approval/`에 있다. **최종 `npm run test:gates` 종료 코드 0.** 단위 1,949개 중 1,749 통과, 실패 0, 환경 조건 200개 제외. 디자인, 빌드, 기존 브라우저와 macOS Electron 흐름, 전체 화면 117개, 새 승인 화면과 추가 QA 4개가 모두 통과했다. 승인/표시 인자 집중 검사는 26/26 통과다. 최종 실행 이후 작업 파일 해시가 그대로임을 확인했다. 로그는 `verification/wave2-approval/task2-gates-final.log`, 실패 재현과 집중 검사 로그도 같은 폴더에 보관했다.

셸 분류기는 설계 대상 명령의 표기를 분류하며 전체 셸 문법 해석기를 뜻하지 않는다. 분류되지 않은 임의 명령을 자동 실행하도록 넓히지 않았다. 인앱 브라우저 클릭/입력은 기존 단계별 승인과 영수증 경계를 유지한다. 로컬 합성 MCP/브라우저 및 macOS Electron 검사는 실제 외부 발송, 회사 SSO, Windows/Office 실행 증거가 아니다.
