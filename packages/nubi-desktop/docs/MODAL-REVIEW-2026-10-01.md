# 누비 Workspace 모달 점검

2026-10-01. 실제 Workbench와 공유 CX 컴포넌트를 Chrome에서 열어 점검했다. 기준은 사용자가 지정한 `agentfactorysdkdeck.html`과 `design/reference.json`이다. 원본 SHA-256 대조도 통과했다.

## 점검 범위

현재 화면에서 여는 설정, 사내 메일, 스킬 관리, OpenWiki, 작업 이력, 앱 연결, 모델 선택, FabriX 연결, 컨텍스트와 대화 삭제 확인의 10개 모달을 확인했다. 자동 승인 메뉴도 같은 범위로 점검했다. Theia의 스킬 ZIP/폴더 선택창, 프로젝트 열기 흐름과 메일 호스트 연결은 별도 실제 호스트 검사로 확인한다.

`실행과 비교`는 현재 화면에서 여는 경로가 없는 기존 코드다. 공통 스타일과 체크박스는 정리했지만 이를 사용 가능한 모달로 계산하지 않는다. 현재 비활성인 A2A와 DB 관리 화면을 다시 노출하지 않는다. Windows의 실제 앱 선택과 OS 네이티브 창 검증은 이번 Chrome 검사에 포함하지 않는다.

## 발견 사항과 반영

| 우선순위 | 발견 사항 | 반영 |
| --- | --- | --- |
| 높음 | 자동 승인 메뉴가 좁은 화면에서 잘리고 상위 스크롤 영역에 가려짐 | CX 툴팁의 portal/viewport 배치 패턴을 적용. 화면 안에 배치하고 긴 목록은 내부 스크롤 |
| 높음 | 접힌 안내 안의 숨은 summary에 CX 포커스 검사상 크기가 남아 Tab이 모달 밖으로 이동 | 접힌 details의 내용을 명시적으로 숨겨 키보드 순환에서 제외 |
| 높음 | 메일을 닫으면 진입 위치와 무관하게 OpenWiki로 이동. 스킬은 설정까지 닫힘 | 진입 화면과 버튼을 보존. 뒤로 또는 닫기로 부모 화면에 복귀하고 포커스 복원 |
| 높음 | OpenWiki에서 파일을 열어도 모달이 편집기를 가림 | 모달을 닫고 실제 편집기로 이동. 작업/파일 대상은 유지 |
| 보통 | 공유 모델/컨텍스트/확인창과 Workspace 모달의 본문 여백이 다름 | 제목, 본문, 하단을 동일한 간격 토큰으로 정렬 |
| 보통 | 자동 승인 메뉴와 파일 버튼이 고정된 작은 글자를 사용 | 본문/레이블 토큰 적용. 큰 글자 설정을 따름 |
| 보통 | 카드 margin과 부모 gap이 중복되어 OpenWiki의 간격이 큼 | 섹션 간 간격을 부모 grid에서 관리 |
| 보통 | 메일과 스킬 메뉴의 아이콘 처리와 파일 버튼 반경이 다름 | 같은 파란 아이콘 타일과 컨트롤 반경. 파일 아이콘과 이름을 한 줄로 배치 |
| 보통 | 승인 메뉴에 방향키와 닫기 후 포커스 복귀가 없음 | 방향키, Home/End, Tab, Escape 처리. 원래 버튼으로 복귀 |
| 낮음 | 기본 셸 설명이 길고 유틸리티 버튼 구현이 제각각 | 설명을 “명령 실행에 사용해요.”로 축약. 검색/열기/새로고침에 공통 ActionButton 사용 |

## 디자인 계약

- 파랑 `#3182F6`, 진한 파랑 `#1B64DA`, 잉크 `#191F28`과 기존 캐릭터/배경을 보존한다.
- 글꼴은 기존 Pretendard/Noto Sans KR 번들을 사용한다. 본문은 14px/22px, 큰 글자는 16px/26px, 제목은 16px/24px이다.
- 모달은 20px 반경, 일반 컨트롤은 12px 반경을 쓴다. 페이지 칩은 기존 100px pill 토큰을 유지한다.
- `--nubi-modal-inset`은 기본 24px, 좁은 화면은 16px이다. 헤더와 하단의 세로 간격은 16px이다. 모달별 임의 값으로 분기하지 않는다.
- 부모 화면으로 돌아가는 아이콘은 헤더 안의 위치에 배치하되 제목의 접근성 이름에 버튼 이름을 섞지 않는다.
- 아이콘 유틸리티에는 접근성 이름과 키보드 툴팁을 유지한다. 연결, 반영, 실행 등 판단이 필요한 동작과 승인 경계는 유지한다.
- 모델에 전달할 내용, 메일 수집 시작 시점, 재연결, 삭제 대상, 실행 권한, 오류 복구 문구는 줄여서 생략하지 않는다. 저장 위치와 보조 안내는 접어 둔다.

## 방법론과 도입 판단

`cognitive-accessibility:review`의 6가지 부담 기준을 적용했다. 선택은 기존 동작을 먼저 보여 주는 방식으로 줄였고, 기억 부담은 부모 화면과 포커스 복귀로 줄였다. 개념은 메일/Wiki/스킬의 기존 사용자 용어를 유지했다. 단계는 파일을 열 때 모달을 따로 닫는 동작을 없앴다. 읽기 부담은 반복 문구만 줄이고 승인/전달/복구 정보를 유지했다. 시각 복잡성은 공통 서체, 간격, 아이콘 타일과 한 개의 주요 동작으로 정리했다.

[W3C 모달 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [버튼 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/button/), [메뉴 버튼 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/)의 이름, 포커스 이동과 키보드 동작을 기준으로 실제 입력을 확인했다. 새로운 모달/아이콘/폼 라이브러리를 추가하지 않고 기존 CX DetailPanel, ActionButton, Checkbox와 공유 Nubi 컴포넌트를 재사용했다. viewport 배치는 현재 설치된 CX KeyboardTooltip의 실제 소스를 검토해 적용했다. 의존성, 라이선스와 런타임 비용은 추가하지 않았다. 설치된 패키지를 직접 수정하지 않는다.

## 검증

`npm run test:modals-ui`는 1280px 일반, 440px 일반, 440px 큰 글자에서 10개 모달과 Wiki 갱신 제안/반영 대기/실패 상태를 확인한다. 실제 계산된 글꼴, 여백, 반경, 입력 이름, 화면 범위, Tab/Shift+Tab, Escape, 부모 화면과 버튼 복귀를 검사한다. 자동 승인 메뉴의 화면 범위와 방향키/Escape도 확인한다. 이는 WCAG 전체 적합성이나 실제 스크린리더 검증을 의미하지 않는다.

이전 Theia 검사에는 9월 30일 없앤 직접 실행/DB 메뉴가 남아 있었다. 현재 메뉴 이름과 정확한 파일 대상에 맞췄다. 직접 실행/비교는 실제 서비스에서 만든 영수증과 로컬 캡처를 화면에서 확인하고, 재열기 뒤 유지되는지 검사한다. 숨은 Monaco DOM을 보는 대신 실제 대상 파일을 연 편집기로 검사한다. dirty 버퍼, undo/save/readback, 수정 명령 승인과 중복 방지, Wiki의 사람 수정 버전 보존, 새 파일 충돌, 변경된 규칙 차단과 HITL 답변 보존 검사는 유지했다. DB 메타데이터의 데이터 행 배제/변경 감지는 기존 런타임 검사와 독립 폼 검사로 유지한다.

검사 결과는 `verification/modal-identity-gate.log`, `verification/modal-runtime.log`, `verification/modal-review/result.json`과 각 UI 결과 JSON에 남긴다. 최종 수치는 아래에 기록한다. 사내 메일 실접속, 실계정 모델, Windows/Electron 설치 성공이나 실모델 답변 품질은 이번 검증의 범위가 아니다.

최종 결과: `verify:identity` 종료 코드 0. 기준 HTML 해시/토큰 대조와 브라우저 빌드 통과. 런타임 655/655, 실제 Theia 43개, 스킬 등록 12개, 공유 UI 45개, 독립 폼 8개, 메일 UI 8개, 모달 42개, 실제 메일 호스트 3개, 프로젝트 열기/설정 3개를 통과했다. 모달 10종의 일반/좁은/큰 글자 캡처와 Wiki 상태별 캡처는 `verification/modal-review/`에 있다.
