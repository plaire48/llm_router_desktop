# 메일 클러스터에서 종류 만들기

관련 메일을 먼저 묶고 그 묶음의 공통 키워드로 종류를 정한다. 기존 종류를 먼저 골라 클러스터를 만드는 순서로 바꾸지 않는다. 개별 메일 제목이나 대표 메일의 제목을 종류 이름으로 복사하지 않는다.

## 적용

- 기존 회신 관계, 주제 유사 후보와 저장된 묶음 식별자를 그대로 사용한다. 서로 연결되지 않은 메일은 각각 독립된 묶음이다.
- 묶음 구성원의 저장된 태그 중 절반 이상이 공유한 짧은 키워드를 최대 2개 사용한다. 여러 메일의 묶음에는 최소 2개 메일의 근거가 있어야 하며 같은 메일의 중복 태그를 중복 집계하지 않는다.
- 키워드가 부족하면 기존 메일 분류의 상위 부문을 참고한다. 서로 다른 분류는 최대 2개와 `외`로 요약한다. 분류 근거도 절반 미만이면 `미분류`로 남긴다.
- 관계 지도와 문서 목록, 종류 필터가 동일한 종류 투영을 사용한다. 이름이 같은 두 클러스터도 주제 보기에서는 별개의 묶음으로 유지한다. 종류 보기에서 함께 표시해도 원래 문서 사이에 새 연결을 만들지 않는다.
- 원래 `category`, 제목, 태그와 관계 근거는 유지한다. 계산한 종류는 읽기 화면의 투영이며 위키 파일의 메타데이터를 자동 저장하지 않는다. `sourceType`으로 기존 종류를 보존하고 반복 투영에서도 동일한 결과를 유지한다.

기존 메일 종류가 모두 `업무`여도, 별개의 관계 묶음이 각각 `접근 권한`과 `장애 대응`을 공통 태그로 갖고 있으면 두 종류로 표시한다. 본문을 새 모델로 재분석한 결과가 아니라 기존 관계와 저장된 메타데이터에서 도출한 표시다.

## 확인

그룹 및 그래프 검사 17개가 통과했다. 공통 키워드, 한 메일만 가진 태그의 배제, 분류 근거 부족, 기존 동일 분류의 서로 다른 종류, 이름이 같은 서로 다른 클러스터, 독립 메일, 원천과 관계 보존을 확인했다.

실제 React 지도와 워커를 사용하는 합성 화면은 1280px와 440px에서 키워드 클러스터, 펼치기, 종류와 날짜 전환, 종류 일치와 3,000문서 이동을 확인했다. WikiBrowser 합성 화면은 1100px, 440px와 360px에서 종류 필터를 포함한 24개 필터 조합, 편집, 저장, 초안 복원과 현재 프로젝트 범위를 확인했다.

화면과 로그는 `verification/wiki-map-keywords-2026-10-16/`에 남긴다. 이 검사는 실메일의 분류 정확도, 회사 계정 또는 실제 Windows 설치판의 검증이 아니다.
