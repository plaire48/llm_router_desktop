# 답변 완료 시스템 알림

새 답변이 저장되면 Windows Notification API로 시스템 알림을 한 번 보낸다. 프로젝트/대화 제목과 ‘답변이 도착했어요. 눌러서 확인하세요.’를 표시한다. 답변 본문, 실행 스크립트, 파일 내용은 알림에 보내지 않는다. 기존 알림과 동일한 앱 아이콘과 무음 설정을 사용하며 표시 위치/알림 허용/방해 금지는 Windows 설정을 따른다.

- 에이전트가 현재 실행의 답변과 완료 시간을 저장한 직후 worker IPC로 main에 전달한다. Renderer 폴링이나 선택된 프로젝트에 의존하지 않아 다른 대화/프로젝트와 최소화 중에도 감지한다.
- 질문, 오류, 취소, 검토 실패와 승인 대기는 완료 알림에서 제외한다. HITL 알림은 기존 경로를 유지한다. 제목은 ‘답변 완료’이며 모든 요구사항이나 제안 반영 성공을 뜻하지 않는다.
- 프로젝트/대화/실행 ID로 중복을 제거한다. 과거 대화 열기와 상태 조회는 알림을 재생하지 않는다. 알림 전송 실패는 저장한 답변에 영향을 주지 않는다. Native 참조는 20개, 중복 ID는 512개로 제한한다.
- 클릭은 최소화된 앱을 복원하고 저장된 대화로 이동한다. 개인 대화는 프로젝트 카탈로그에 없으므로 별도 개인 공간 경로를 사용한다. 미저장 파일/작업 중 터미널의 프로젝트 이동 보호를 유지하며 답변/승인/실행을 자동 수행하지 않는다. 앱 종료 상태의 콜드 스타트는 추가하지 않는다.

## 방법과 검증

기존 `decision-notices.cjs`의 Electron Notification 방식과 문자열 제한을 재사용했다. 별도 toast 패키지나 시스템 알림을 흉내 낸 UI를 추가하지 않았다. 생성 이벤트는 런타임에서, OS 표시와 창 복원은 main에서 담당한다.

- `node --test --test-concurrency=1 tests/answer-notifications.test.mjs tests/decision-notices.test.mjs tests/project-services.test.mjs`: 19개 통과. Windows API는 대역으로 검사했으며 실제 런타임과 임시 저장소에서 전경/백그라운드 에이전트 완료 후 저장된 메시지를 확인했다. 모델은 합성이다.
- `node scripts/check-answer-notice.mjs`: 실제 macOS Electron에서 IPC 클릭 이벤트를 주입해 같은 프로젝트/개인 공간/원래 프로젝트 복귀를 검증했다. Renderer 오류 없음. 산출물은 `verification/answer-notification-2026-10-15/`.
- Electron 빌드와 초기화/아이콘 검사를 통과했다. Windows 11 알림 센터의 실제 표시, 방해 금지 및 설치판은 이 Mac에서 검증하지 않았다. 설치 파일 배포는 수행하지 않았다.
