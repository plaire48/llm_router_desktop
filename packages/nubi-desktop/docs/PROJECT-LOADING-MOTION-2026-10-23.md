# 프로젝트 열기 로딩 모션

프로젝트를 여는 동안의 가림막에 기존 화면 전환의 공통 스프링과 페이드를 적용했다. 새 로딩 효과를 여러 개 겹치지 않고, 등장과 단계 변경 및 준비된 화면으로의 전환을 연결한다.

- 등장: 공통 280ms 스프링으로 작은 이동과 페이드를 함께 사용한다. 단계 문구는 즉시 읽을 수 있는 불투명도에서 시작한다.
- 단계 변경: 실제 호스트 단계가 바뀔 때만 공통 180ms 페이드를 적용한다. 경과 시간 갱신으로 모션을 다시 시작하지 않는다.
- 완료: 공통 180ms 페이드로 가림막을 정리한다. 준비된 화면의 입력은 즉시 풀고, 퇴장 중 가림막은 포인터와 접근성 탐색에서 제외한다. 새 프로젝트를 빠르게 열면 이전 정리 타이머를 취소한다.
- 부하: `data-project-switching` 동안 가려진 배경과 상단 장식의 반복 효과를 기존 모션 정책으로 일시 정지한다. 로딩창의 브랜드는 정지형이며 기존 단방향 진행 막대만 반복한다. 완료 후 기존 모션은 이어진다.
- 모션 감소: 이동 없이 짧은 페이드로 표시하고 진행 막대도 정지한다. 창 숨김과 기존 전역 정지 정책은 로딩 중에도 적용한다.

프로젝트 이름, 실제 단계, 경과 시간과 Git 진행률은 유지한다. 분모가 없는 읽기 단계에 가짜 퍼센트를 만들거나, 입력 가능 시점을 애니메이션이 끝날 때까지 늦추지 않는다. 공통 모션 예산에서 로딩 전환이 뒤쪽 버튼의 색상 전환에 밀리지 않도록 기존 `nubi-view-` 우선순위를 재사용한다.

## 확인한 범위

1. 실제 macOS Electron의 지연된 프로젝트 전환으로 수정 전 실패를 재현했다. 가림막이 열린 상태에서도 배경·상단의 반복 효과 22개가 실행 중이었다.
2. 수정 후 동일 구간에서 22개가 정지하고 `nubi-wiki-scan` 하나만 실행됐다. 등장·단계·완료 전환과 입력 잠금 해제, 실패 시 원래 프로젝트 복귀, 모션 감소를 확인했다.
3. 공통 정책·토큰·소스 회귀 20개가 통과했다.
4. 실제 React 구성 요소를 사용한 Chrome 검사에서 1000px/360px 배치, 실제 진행률과 경과 시간, 단방향 이동, 모션 감소, 빠른 재진입 및 퇴장 정리가 통과했다. 공통 디자인 캡처도 통과했다.
5. Electron 빌드가 성공했다. 이 결과는 Windows 설치판과 모든 화면의 프레임 성능을 검증한 결과가 아니다. 전체 게이트 통과나 원격 브랜치 반영을 뜻하지 않는다.

검사는 `scripts/check-project-switch-cover.mjs`, `scripts/check-git-clone-progress-ui.mjs`와 `tests/motion-policy.test.mjs`에 남겼다. 결과는 `verification/project-switch-cover-2026-10-23/`, `verification/git-clone-progress-loading-2026-10-23/`에 기록한다. 처음 실패와 조사 중 기록은 별도 Codex 작업 폴더에 보존했다.

`design/workspace-density.css`의 추론 칩 선택자 변경은 이번 수정 범위에 포함하지 않았다.
