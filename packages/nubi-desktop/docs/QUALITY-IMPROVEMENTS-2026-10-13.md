# 중간 난이도 평가 후속 개선

고정 40문항의 정답뿐 아니라 호출 기록과 사용자에게 보이는 답변을 검토했다. 기존 52회 시도와 실패 기록은 보존한다. 이번 비교는 GPT-5.6 Sol의 기존 12문항과 동일한 질문, 자료, 사실 및 출처 기준을 사용한다.

## 발견과 수정

1. **질문 범위가 위임 단계에서 늘어났다.** 교육 이수 여부를 묻는 요청에 Agent가 동명이인, 완료일 등 추가 조건을 만들고 전체 문서 검토를 요청했다. OpenWiki는 무관한 도서 대여 문서까지 조사하고, 각 조사자가 다른 페이지의 예외를 미확인으로 보고했다. 요청 범위를 그대로 넘기고 관련 페이지를 종합하는 질문과 전체 자료 검토를 구분하도록 수정했다.
2. **짧은 자료도 같은 내용을 나누어 읽었다.** focused 조사의 전체 자료가 기존 24,000자 읽기 창 안에 들어가면 원래 질문과 계획의 모든 세부 질문을 하나의 조사 범위로 묶는다. 긴 자료의 분담, 명시적 전체 검토의 구간별 읽기, 출처 확인, 실패 및 미확인 표시는 유지한다. 8분/120회 조사 상한도 유지한다.
3. **사용량 제한이 일반 CLI 실패로 숨겨졌다.** Claude의 구조화된 rejected/rate_limit 신호를 `rate_limited`로 전달한다. 경고나 정상 복구 답변은 오류로 만들지 않고 취소가 우선한다. stderr나 계정 관련 자유 텍스트는 판정하거나 저장하지 않는다. 기존 잔여 사용량과 초기화 시각도 유지한다.
4. **연결이 막혀도 뒤의 평가 문제가 계속 실패했다.** 한도, 인증, 실행기 연결 오류 이후 새 문제 투입을 멈춘다. 이미 실행 중인 문제는 결과를 보존하며, 남은 문제는 미실행으로 남긴다. 문제 자체의 형식/자료 오류로 전체 평가를 멈추지는 않는다.
5. **정답 뒤에 같은 근거와 한계가 반복됐다.** 핵심 결론과 필요한 인용을 한 번 제시하고 다음 행동에 영향을 주는 제한만 남기도록 정리했다. 기록 부재를 미결정으로, 미승인을 영구 불가로 바꾸지 않는다. 글자 수로 답변을 잘라내거나 별도의 미용 목적 모델 호출을 추가하지 않는다.

## 방법론과 선택

`HARNESS-METHODS-2026-10-12.md`의 고정 과제, 실제 도구 결과, 독립 채점, 전체 워크플로 지연 측정 원칙을 재사용했다. 기존 Pi/OpenWiki 내부의 조사 단위를 조절했으며 새 프레임워크나 의존성은 추가하지 않았다. 문서를 모델 입력에 무조건 전부 넣는 방식은 기존 명시적 읽기 및 인용 검증을 우회하므로 사용하지 않았다. 답변을 사후에 기계적으로 자르는 방식도 필수 조건과 불확실성을 잃을 수 있어 제외했다.

## 검증

**최종 후보의 실행 대상 회귀 검사 801개 통과, 실패 0개.** Windows 앱 조작과 비활성 A2A 등 198개는 건너뛰었다. 공유 OpenWiki 조사/체크포인트 62개, 문서 조사/위키 평가 18개, OpenWiki TypeScript 검사와 Electron 로컬 빌드도 통과했다.

초기 회귀의 실패 두 건은 로그인 세션과 검사 사이의 콜백 포트 충돌, 늘어난 지시문의 불필요한 압축이었다. 로그인 완료 후 해당 검사를 재확인하고 지시문 중복을 줄여 압축 회귀를 고쳤다. 마지막으로 기존 문장 전체를 비교하던 하네스 검사의 기대값을 동등한 새 문구로 맞췄다. 조건이나 승인/출처 검사를 삭제하지 않았다.

ChatGPT GPT-5.6 Sol, medium, 카탈로그 문맥 272,000으로 동일 12문항을 개선 중간 후보와 최종 후보에서 각각 한 번씩 실행했다. 각 실행 동안 후보 해시는 변하지 않았다. 원래 40문항 전체를 다시 측정한 것은 아니며, 중간 후보 점수를 최종 후보 결과로 대신하지 않는다.

- 정답과 필수 원문/실행/보존 조건: **최종 12/12 확인**. 자동 채점은 11/12였다. wiki-08의 `2026년 11월 1일`은 정답 `2026-11-01`과 같은 날짜여서 별도 audit.json에 보정했다. 중간 후보에는 날짜 뒤 마침표에 의한 같은 유형의 오판이 있었다. 원래 report.json과 v1 채점기는 수정하지 않았고, 다른 날짜/숫자를 수용하지 않는 보정 회귀를 추가했다.
- 전체 모델 호출은 154 → 142회로 줄었다. 실제 명령별 승인, 원문 인용 및 최종 검토는 유지했다.
- 최종 위키의 하위 모델 호출은 8/18/8 → 4/6/19회다. 작은 focused 조사에서는 감소했지만 마지막 문제에서 모델이 전체 검토를 선택해 다시 늘었다. 전체 검토를 focused로 강제해 읽기 범위를 축소하지 않았다.
- 시간에는 제공자 응답 변동, 네 과제 동시 실행 및 동시에 진행한 로컬 회귀 검사의 부하가 포함된다. 호출 수 감소를 일률적인 속도 개선으로 해석하지 않는다.
- 최종 답변 12개를 직접 읽어 사실의 결합과 미확인 표현을 검토했다. 종료 연장 미승인을 영구적인 연장 불가로 바꾸던 표현은 고쳐졌다. 그러나 Bash의 명령/안전 설명 반복, 스킬 양식의 중복 미확인 항목, 위키의 묻지 않은 필드 설명은 남았다. **답변 길이가 전반적으로 줄었다고 결론내리지 않는다.**
- 기존 Claude 세션에서 지정한 보호 대상 11개 중 위키 관련 10개는 기존 해시와 같았다. 의도적으로 바꾼 agent.mjs에도 8분/120회 조사 예산 연결은 유지했다.

## 남은 개선 과제

1. 작은 자료라도 comprehensive로 분류되면 페이지별 조사와 합성이 늘어난다. 후속 변경은 여러 짧은 페이지를 함께 조사하되 각 문자의 실제 읽기/미읽음 복구를 보존하는 방식으로 별도 검증해야 한다.
2. 답변 간결화 지시만으로 Bash와 스킬의 반복을 안정적으로 제거하지 못했다. 도구 실행 상세와 사용자 답변을 분리하는 출력 계약이 다음 검토 대상이다. 단순 글자 수 제한이나 사후 절단은 사용하지 않는다.
3. 동일 문제 3회 반복과 새로운 보류 문제군이 필요하다. 단일 고정 부분집합의 결과를 전체 제품 정확도나 Windows/사내 실서비스 성공으로 확대하지 않는다.
