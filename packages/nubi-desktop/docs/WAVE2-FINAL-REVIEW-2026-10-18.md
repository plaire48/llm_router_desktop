# 2차 물결 최종 독립 리뷰와 보완

한 번의 독립 읽기 전용 리뷰(gpt-6-astra). 판정 With fixes, Critical 0 / Important 4 / Minor 0. 추가 리뷰는 요청하지 않았다. 기존 게이트 실행은 중단했으며 통과로 세지 않는다.

## Important 4건

1. 유휴 화면의 자동 예약 실행 발견 누락: 호스트 타이머는 실행하지만 Workbench가 기존 실행/배경 프로젝트가 없는 상태에서는 state를 읽지 않아 대화와 질문/승인 알림이 늦는다. 수동 실행 버튼의 refresh는 이 문제를 가린다.
2. 위키 작업 중 예약 소진: provider/agent 상태만 확인하고 lastRunAt을 예약한 뒤 createTask에서 wiki_chat_blocked가 나면 대화 없이 하루 예약이 소진된다.
3. 대상 변경 후 이전 프로젝트 제거: 완료한 A 실행 뒤 대상을 B로 바꾸고 A를 제거하면 이전 소유자 조회가 project_missing을 내서 B를 실행할 수 없다. 미확정/질문/승인 대기는 계속 차단해야 한다.
4. 대화 내보내기 비밀값 누락: curl -u Basic 명령의 비밀번호와 여러 줄 PRIVATE KEY 본문이 기존 키워드 필터를 통과한다. 모든 출력 위치와 파일명에 동일한 투영을 적용해야 한다.

## 보완 결정

- 기존 worker → main → onHostEvent에 routine_activity를 추가하고 유휴 Workbench도 현재 프로젝트의 목록과 결정을 다시 읽는다. 현재 대화를 강제로 바꾸지 않고 늦은 다른 프로젝트 응답을 버리며 중첩 이벤트를 합친다. 포커스 복귀도 재확인한다.
- 기존 wikiChatBlocked와 wikiResetting을 예약 전 확인한다. 위키가 끝나면 같은 날 재검사에서 한 번 실행한다. 이미 생성/시작했거나 결과가 미확정인 작업은 재전송하지 않는다.
- 호스트가 실제 마지막 대화와 질문/승인 상태를 읽어 lastSettledTaskId를 기록한다. taskId에 묶인 확인이 있을 때만 제거된 이전 프로젝트를 건너뛴다. 기존 프로젝트 진입점에서 재개/변경을 관찰하고 진행 중이거나 미확정이면 확인을 지운다. 사용자가 저장 API로 확인 필드를 주입할 수 없다. 확인이 없으면 이전 프로젝트를 다시 열도록 정확히 안내한다.
- Basic 명령 줄과 PRIVATE KEY 전체 블록을 내보내기 투영에서 가린다. 원본 기록과 일반 본문은 보존한다. 모든 형태의 임의 비밀값 탐지를 보장하지 않는다.
