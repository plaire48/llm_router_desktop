# 대화 이력의 위키 저장 (제안, 2026-10-14)

사용자 질문: 답변 끝에 "지금까지의 대화를 저장할까요?" 같은 버튼을 두면 어떨지, 대화 이력은 위키에 따로 저장해야 하는지, 관리와 위키화는 어떻게 할지.

## 지금 상태

- 대화(task)는 프로젝트 저장소(SQLite `task:` 키)에만 있다. 대화 검색 화면이 그것을 읽는다.
- 위키(`nubi-wiki/`)에는 프로젝트 소스, 메일, 문서에서 만든 페이지만 있고 대화는 없다.

## 제안

1. **버튼 대신 아이콘**: 마지막 답변의 동작 줄(복사, 다시 생성 옆)에 `save` 아이콘 하나. 누르면 저장하고, 이미 저장한 대화는 같은 페이지를 갱신한다(대화당 페이지 하나). 끝날 때마다 텍스트로 묻지 않는다.
2. **저장 위치와 형식**: `nubi-wiki/대화/YYYY-MM/<제목-slug>.md`. front matter는 메일 페이지와 같은 꼴.
   ```
   ---
   type: Conversation
   title: "무료 배송 기준 수정"
   description: "첫 요청 한 줄"
   tags: [conversation, <프로젝트>]
   task: "<task id>"
   date: "2026-10-14T03:20:00Z"
   model: "aipro/qwen3"
   ---
   ```
   본문은 전사가 아니라 **요약**: 요청, 결정(승인한 명령·변경), 결과(바뀐 파일, 실행한 명령, 확인한 자료 링크), 남은 일. 원문은 `task` 키로 대화 검색에서 연다. 도구 출력과 명령 스크립트는 넣지 않는다(기밀·크기).
3. **위키 화면**: 지도와 표에 "대화" 구역(메일처럼 월별). 관련 문서는 대화가 읽은 위키 페이지와 바꾼 소스 파일로 연결(`wiki-library`의 간선에 `kind:'conversation'`).
4. **자동 저장은 끔**: 설정에 "작업이 끝나면 대화 요약을 위키에 저장" 스위치를 두되 기본은 끔. 사용자가 켜면 변경이 반영된 작업만 자동 저장.
5. **삭제**: 대화를 휴지통으로 지우면 그 페이지도 함께 지운다(2026-09-30 삭제 규칙과 같음).

## 하지 않을 것

- 전체 대화 전사를 위키에 쌓는 일. 검색 품질을 떨어뜨리고 OpenWiki가 지시문을 자료로 읽게 될 위험이 있다.
- 메일·소스 위키와 다른 형식. 같은 front matter를 써야 지도와 검색이 한 규칙으로 돈다.

## 작업량

저장 동작과 요약 프롬프트 2일, 위키 화면 구역 1일, 검사 1일. 사용자 확인 뒤 시작.
