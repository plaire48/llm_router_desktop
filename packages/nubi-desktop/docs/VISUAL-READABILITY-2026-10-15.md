# 화면과 모달 가독성 검토

기존 기능과 사용자 흐름을 유지하고 크기, 정렬, 여백과 글자 위계를 수정했다. 공통 토큰이 이미 적용된 화면을 일괄 축소하지 않고, 실제 렌더링에서 발견한 내부 배치의 불일치만 조정했다.

## 평가와 반영

| 대상 | 관찰 | 평가 | 반영 |
| --- | --- | --- | --- |
| 모달 공통 제목과 조작 | 제목 18/600, 본문 15, 보조 14, 닫기 40px와 좌우 시작선 유지 | 유지 | 외곽 크기, 버튼 동작, 초점과 모션 유지 |
| 입력 필드 이름 | 공통 계약의 500보다 굵은 600이 제목과 경쟁 | 경미한 개선 | 공통 `--nubi-weight-label` 사용 |
| Personal 스킬 | 이름과 설명이 같은 줄에서 경쟁하고 관리 버튼에 위쪽 여백이 남음 | 개선 | 이름 아래에 한 줄 설명, 같은 시작선, 아이콘과 메뉴 중앙 정렬 |
| 스킬 등록 | 아이콘, 제목, 파일 형식과 버튼의 독립 여백이 누적 | 개선 | 아이콘과 안내를 한 그룹으로 배치. 폴더/파일 선택과 드롭 그대로 유지 |
| 위키 설정의 작업 기록 | 모달 내부 카드 패딩 20px로 시작선 불일치, 내부 제목이 모달 제목과 같은 비중 | 개선 | 이중 패딩 제거, 섹션 간격/구분선, 본문 크기 600 강조, 설명은 보조 크기 |
| Claude 연결 | 목록 간격과 문단 margin이 누적 | 경미한 개선 | 문단 margin 제거, 브랜드색과 버튼 유지 |
| 채팅, 메일, 검색 조건, 모델, 사용량, 삭제 확인 | 같은 크기에서 핵심 동작과 정보 위계 확인 | 유지 | 필드 굵기 외 불필요한 재설계 없음 |
| AI Workspace 앱/Talk, 위키 읽기/수정/관계 지도 | 데스크톱과 좁은 화면, 실제 구성요소의 조회/등록/편집 흐름 확인 | 유지 | 동작과 배치를 변경하지 않음 |
| 탐색기, Git 이력/비교, 편집기, 터미널, 웹 보조 탭 | 실제 Electron에서 원문, 입력과 조작 확인 | 유지 | 보조 영역과 중앙 에이전트 구조 유지 |

크기 비교는 동일한 1280×950 화면의 모달 경계로 측정했다.

| 모달 | 수정 전 높이 | 수정 후 높이 |
| --- | ---: | ---: |
| 스킬 관리 | 280px | 281px |
| 스킬 등록 | 300px | 236px |
| 위키 설정 | 418px | 392px |
| Claude 설치 안내 | 334px | 318px |

스킬 관리는 크기 축소가 목적이 아니다. 거의 같은 높이에서 이름과 설명의 위계를 정리했다. 좁은 스킬 목록의 설명은 기존처럼 숨기고 툴팁을 유지한다. 버튼 텍스트와 동작은 바꾸지 않았다.

## 검증

- `check-all-surfaces.mjs`: 전후 각 115개 검사 상태 통과. 1280/440px 및 200% 글자 확대, 대비, 버튼 겹침/줄바꿈, 모달 경계와 최소 글자 크기 포함. 일부 화면명이 반복되는 상태 검사이며 115개의 서로 다른 제품 화면을 의미하지 않는다.
- `check-modals.mjs`: 전후 각 40개 검사 항목 통과. 중첩 모달과 초점 복귀, 삭제 취소, 모델 선택/새로고침, 파일/폴더 선택 노출과 스킬 페이지 이동, 실행 중 입력 포함.
- `check-community-wiki-ui.mjs`: 1100/440/360px에서 앱, Talk 목록/게시/댓글, Wiki 읽기/수정/저장/관계 지도 흐름 통과.
- `check-workspace-embed.mjs`: 1100/440px에서 제품의 내장 앱/Talk 구성요소 및 브리지, 등록 모달, 오류/재시도/재로그인 상태 통과. 회사 요청은 합성 응답이다.
- `check-electron-shell.mjs`: 수정된 빌드에서 22개 동작 확인. 임시 프로젝트의 파일 저장/readback, Git 비교/이력, 실제 PTY 상태 유지/복사/한글 입력, 웹 탭, 좁은 창 포함.
- 스킬 선택 플랫폼 분기와 모달 모션 검사 5건, 디자인 검사, Electron 로컬 빌드 통과.

합성 계정/문서 기반 실제 렌더링과 로컬 실행 검증이다. Windows 설치판, 사내 SSO 실계정, 외부 사이트의 모든 상태나 OS 파일 선택창 자체의 시각 품질은 검증하지 않았다. 개인 프로젝트나 현재 로그인 세션을 변경하지 않았다.

## 산출물

- `verification/visual-polish-2026-10-15/index.html`: 화면 선택, 모달 중심/전체 보기, 원본 캡처 링크를 갖춘 전후 비교.
- `before/`, `after/`: 원본 Electron 캡처와 레이아웃 측정.
- `compare-skills-1280.png`, `compare-registration-1280.png`, `compare-library-1280.png`, `compare-fabrix-1280.png`: 실제 캡처를 나란히 표시한 비교 페이지 스크린샷.
- 재생성: `node scripts/build-visual-review.mjs`. 수정 전 캡처는 덮어쓰지 않는다.

가독성 판단은 visual-critique의 시선 시작점, 읽는 순서, 시각적 비중, 강조 기준으로 수행했다. 새 라이브러리를 도입하지 않고 기존 CX 컴포넌트와 누비의 8/16/24 간격, 400/500/600 글자 굵기, 의미별 색상 토큰을 적용했다.
