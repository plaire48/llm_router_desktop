# 연결 방식에 따른 위키 갱신

위키 화면의 **동기화 및 갱신**과 `/wiki_update`가 같은 런타임 경로를 사용한다. 기존 화면 버튼은 원격을 받지 않았고, 명령 경로는 Git 받기에 실패해도 로컬 자료로 갱신할 수 있었던 차이를 수정했다.

| 연결 | 갱신 기준 |
| --- | --- |
| 원격 Git에서 받아 연결 | 현재 브랜치의 upstream을 fetch하고 fast-forward한 리비전 |
| 폴더 열기, 기존 Git 있음 | 현재 Git 이력과 미커밋 작업 파일 |
| 폴더 열기, Git 없음 | 허용 파일의 스냅샷을 누비 전용 Git에 자동 커밋 |

연결 방식은 프로젝트 저장소에 저장해 재진입/재시작 때 유지한다. 이 구분을 저장하지 않았던 이전 프로젝트는 기존 동작과 호환되도록 remote 설정으로 판단한다. 폴더 열기로 다시 선택하면 로컬 기준으로 명시된다. 원격 연결은 추적 브랜치가 없거나 detached HEAD이면 설정 확인을 안내한다. 기본 브랜치를 임의로 추정하지 않는다.

## 코드 동기화와 보존

원격과 같은 리비전을 사용할 수 있을 때만 위키를 작성한다. 미커밋 소스, 원격보다 앞선 로컬 커밋, 갈라진 이력은 중단 사유다. 자동 stash, reset, rebase, push를 하지 않는다. 로컬 위키 파일은 보존하며 Git이 덮어쓰기를 거부하면 갱신도 중단한다. 원격 기준 갱신은 분석 사본에 이후 로컬 소스 수정을 섞지 않는다.

Git 없는 폴더의 커밋은 앱의 프로젝트별 저장소 아래 `wiki-folder-history`에 남긴다. 원본에 `.git`을 만들지 않고 사용자의 기존 Git에 자동 커밋하지 않는다. 변경 없는 호출은 새 커밋을 만들지 않는다. 추가/수정/삭제 이력이 다음 분석 사본에도 이어진다. 기존 파일 접근 규칙, `.openwikiignore`, 비공개 경로 제외를 따른다. 스냅샷 커밋은 사용자 원본 커밋으로 표시하지 않는다.

위키가 없으면 생성부터 시작한다. 로컬에서 위키가 최신이어도 갱신 버튼을 유지해 원격 변경을 확인할 수 있다. 실패를 ‘최신’으로 표시하지 않는다. 코드 동기화 중에는 해당 프로젝트의 새 채팅을 막고 실제 경과 시간을 표시하며 중지할 수 있다. 다른 프로젝트는 계속 사용할 수 있다. **생성 결과는 기존대로 확인 후 반영한다.** 원격 코드는 먼저 동기화되므로 위키 결과를 버려도 받은 코드가 되돌아가지는 않는다. 결과 반영 시 사람이 수정한 위키의 해시 충돌 보호를 유지한다.

## 사내 Git 인증

clone과 갱신이 Electron main의 같은 일시적 askpass 경로를 사용한다. 워커는 프로젝트 경로와 고정 동기화 요청만 전달한다. main이 Git 명령을 구성하며, 토큰은 지정된 사내 GitHub origin에 대한 인증 요청에만 전달한다. 워커, 모델, 렌더러와 실행 결과에 토큰을 넣지 않는다. 로그인 세대 변경과 만료를 검사하고 TLS 검증을 유지한다. Git stderr에 있을 수 있는 서버 주소/인증값은 반환하지 않고 고정 오류 코드로 구분한다. 다른 원격 서버는 기존 Git 인증 설정을 사용한다.

새 Git 구현 라이브러리 대신 설치/번들된 Git의 fetch, upstream, fast-forward 계약과 기존 앱 askpass를 재사용했다. 이미 사용 중인 인증과 Windows Git 배포 경로를 유지하고 Git 이력 해석을 별도 라이브러리와 이중화하지 않기 위한 선택이다.

## 확인 결과

- 61개 관련 검사 통과. 실제 로컬 원격 저장소의 fast-forward, 로컬 수정/앞선 커밋/분기 충돌 보존, 폴더 스냅샷 이력/삭제, 위키 생성과 반영, 원본 충돌 보호, 동기화 중 채팅/취소와 프로젝트 격리를 포함한다.
- 인증 소켓은 가짜 인증값으로 지정 origin만 허용함을 확인했다. 이것은 실제 사내 SSO 성공 증거가 아니다.
- 런타임 compile 및 Electron main 메모리 번들 검사 통과. 설치 파일은 생성하지 않았다.
- 실제 React/CX 컴포넌트를 로컬 API fixture로 420px/1280px에서 렌더링했다. 두 화면의 가로 잘림 없음, 갱신 호출 경로, 대기 중 버튼 비활성화, 변경 없음 문구, 실패 뒤 오류 안내 유지가 통과했다.
- 원시 로그와 화면: `verification/wiki-refresh-2026-10-15/`.

회사망 GHES 실계정, 외부 Git 서버 인증 및 Windows 설치판의 MinGit 실행은 이번 환경에서 검증하지 않았다. 코드 동기화가 실패하면 위키 모델 호출을 시작하지 않으므로, 실제 회사 환경에서 실패 시 인증/추적 브랜치/로컬 충돌 안내에 따라 원인을 확인할 수 있다.
