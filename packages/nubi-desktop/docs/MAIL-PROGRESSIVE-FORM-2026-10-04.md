# 메일 연결과 스크롤바

메일 연결은 한 열에 서비스/주소부터 표시한다. 주소 형식이 유효해지면 비밀번호를 추가하고, 비밀번호 형식이 유효하면 연결 버튼을 표시한다. 입력 중 초점을 강제로 옮기지 않으며 주소의 Enter는 비밀번호로 이동한다. 이미 표시된 항목은 수정/실패 후에도 유지한다. 서비스 변경은 비밀번호와 단계만 초기화한다.

첫 연결 후 모델 선택, 자동 정리와 저장 위치를 표시한다. 기존 수신 자료나 저장한 정리 목적지가 있으면 재로그인 중에도 해당 관리 항목은 유지한다. 연결 시도 완료/취소 뒤 비밀번호 삭제, 메모리 전용 인증, Gmail의 공백을 제외한 16자리 정규화와 회사 비밀번호 보존은 기존 계약을 사용한다. 폼 노출만으로 연결하거나 수집을 시작하지 않는다.

공통 스크롤바는 4px 손잡이와 옅은 트랙, 둥근 끝과 8px 끝 여백으로 통일했다. 기존 `--deck-muted`가 정의되지 않아 트랙/손잡이가 투명하게 계산되던 문제를 현재의 공통 회색 토큰으로 수정했다. 터치와 강제 색상 모드에서는 6px을 유지한다. 채팅 본문/입력창의 숨긴 스크롤바와 실제 스크롤 동작은 유지한다.

기존 CX 입력/모달/초점 계약과 단계별 공개 패턴을 재사용했다. 새 폼 또는 스크롤바 라이브러리는 추가하지 않았다. Chromium의 둥근 스타일은 표준 `thin`과 충돌할 수 있어 필요한 목록/모달에서 `auto`로 복원했다. 참고: [MDN scrollbar-width](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scrollbar-width), [MDN ::-webkit-scrollbar](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/::-webkit-scrollbar).

## 확인 범위

- `npm run build:electron` 성공. 사용자 결정대로 자동 테스트는 실행하지 않았다.
- 4320 예시 화면: 미완성 주소에는 비밀번호가 없음, 완성된 주소 뒤 비밀번호 표시, 예시 15자리에는 연결 버튼 없음, 예시 16자리에는 연결 가능, 주소 수정 후 입력란 보존/연결 차단, Enter 이동, 서비스 변경 시 비밀번호 초기화, 회사 입력과 연결 뒤 관리 항목 표시를 확인했다.
- 스킬 예시 목록: 높이 216px/내용 670px, 스크롤바 4px, 트랙/손잡이 반경 100px, 위아래 여백 8px와 유효한 색상을 확인했다. 키보드로 마지막 항목까지 이동한 뒤 실제 scrollTop 454px을 확인했다.
- 실제 POP3/모델 인증과 Windows는 확인하지 않았다. 실행 중인 Electron 재로드는 앞선 자동 승인 검토의 로그인/미저장 상태 손실 우려로 대기 중이다.
- 예시 연결은 원격 서버에 접속하지 않고 계정/비밀번호를 조회하거나 기록하지 않는다.
