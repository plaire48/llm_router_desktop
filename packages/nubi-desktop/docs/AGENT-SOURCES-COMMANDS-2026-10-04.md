# Agent 출처와 명령

2026-10-04 사용자 요청에 따른 Desktop 구현. 기존 Pi 실행기와 위키, 개인 메일, 명령 승인 및 스킬 도구를 연결한다.

## 사용자 흐름

- 일반 질문에서도 프로젝트 위키와 개인 메일을 필요한 경우 검색한다. 개인 메일은 프로젝트 위키와 구분한다.
- 답변의 근거 문장 옆에는 작은 출처 번호를 둔다. 답변 아래 같은 번호와 문서명 또는 메일 제목을 표시한다.
- 위키/파일 출처는 현재 대화의 프로젝트 파일 탭과 실제 줄 위치를 연다. 메일 출처는 메일 원문을, 첨부 출처는 해당 문서를 연다. 추출된 쪽/슬라이드/시트가 있는 경우 그 구간을 먼저 표시한다.
- 실제 읽었지만 답변이 인용하지 않은 자료는 접힌 `참고 자료`에 둔다. 읽었다는 사실을 문장 지원이나 검증 성공으로 바꾸지 않는다.
- `/` 입력 시 입력창 위에 명령과 현재 등록한 스킬을 표시한다. 이름/설명/명령으로 필터링하고 ↑↓와 Enter/Tab으로 선택한다. Escape로 접으며 한글 조합 중 Enter는 선택/전송하지 않는다.

| 명령 | 동작 |
| --- | --- |
| `/wiki 질문` | 프로젝트 위키 검색 후 필요한 현재 원문 확인 |
| `/mail 질문` | 개인 메일/첨부 검색 후 현재 원문 확인 |
| `/plan 요청` | 자료와 스킬을 읽어 계획 작성. 이 실행에서는 수정/명령 제안/실행/외부 행동 차단 |
| `/bash 명령` | 실제 OS 셸과 환경 확인, 기존 승인에 따른 명령 실행 및 결과 확인 |
| `/스킬명 요청` | 현재 카탈로그의 고유 이름과 경로/해시로 지침을 불러온 뒤 사용 |
| `/skills` | 기존 스킬 관리 열기 |
| `/model` | 기존 모델 선택 열기 |
| `/usage` | 기존 사용량 화면 열기 |

`bash`는 Bash 설치를 강제하는 기능이 아니다. Windows에서는 사용자가 설정한 PowerShell/cmd 프로필을 사용한다. 스킬이나 명령 선택은 실행 승인이 아니다. 승인 정책과 미확정 실행의 복구 계약을 유지한다. 예약 메시지는 적용되는 시점에 명령을 다시 해석하고 등록 스킬을 확인한다.

## 반영한 공식 사례

1. [Codex 명령](https://learn.chatgpt.com/docs/developer-commands?surface=cli): `/` 팝업, 검색과 키보드 선택을 적용했다. 실제 기존 도구와 UI를 호출하는 작은 명령 목록을 사용한다.
2. [Claude Code 스킬](https://code.claude.com/docs/en/skills): 메타데이터 검색 후 필요한 스킬 지침을 불러오는 구조와 `/skill-name` 호출을 적용했다. 지침과 실행 권한은 분리한다.
3. [OpenAI File Search](https://developers.openai.com/api/docs/guides/tools-file-search): 도구의 검색 결과와 답변 출처 메타데이터를 분리하는 방식을 적용했다.
4. [Anthropic Search Results](https://platform.claude.com/docs/en/build-with-claude/search-results): 안정된 출처 식별자, 제목과 실제 위치를 갖는 검색 근거를 사용한다. 반환된 근거에만 문장별 출처를 연결한다.

OpenAI/Anthropic의 전용 인용 API를 호출하는 구현은 아니다. AI Pro/ChatGPT/FabriX에 공통 적용되는 호스트 출처 레지스트리와 기존 Markdown 렌더러를 사용한다. 새 검색 프레임워크나 셸 실행 라이브러리는 추가하지 않았다. 기존 MiniSearch/OpenWiki 검색, Pi, SKILL.md 로더, react-markdown 및 Monaco를 재사용했다. 이미 포함된 라이선스와 소스 출처를 유지한다.

## 근거 및 보호

- 도구가 실제 반환한 위키 발췌, 파일 본문, 메일 본문/첨부 추출 결과만 출처를 등록한다. 제목이나 검색 ID만 확인한 자료에는 인용을 만들지 않는다.
- 호스트가 종류/경로/현재 해시/위치로 식별자를 만든다. 모델이 만든 파일 경로나 외부 URL을 출처 버튼의 실행 대상으로 신뢰하지 않는다.
- 답변에 있는 식별자가 호스트 목록과 맞을 때만 번호 버튼을 표시한다. 알 수 없는 식별자는 연결하지 않으며 확인하지 못한 출처가 있음을 표시한다.
- 파일을 열 때 저장 원문의 해시를 확인한다. 메일 원문과 첨부도 각각 해시를 확인하고, 변경된 원문을 기존 답변의 근거로 조용히 대체하지 않는다. 미저장 편집기는 덮어쓰지 않는다.
- 메일은 발신자의 주장과 문서 내용이다. 사실 확인, 사용자 지시 또는 실행 승인으로 취급하지 않는다. 메일 연결 암호와 인증 저장소의 값을 프롬프트나 출처로 전달하지 않는다.
- 없는 PDF 쪽 번호를 추정하지 않는다. Word는 실제 추출한 텍스트에만 연결한다. 이미지/OCR 등 미확인 범위는 기존 추출 coverage를 유지한다.
- 다시 답변 받기는 저장된 출처만 사용하며 도구/명령/파일 수정을 다시 실행하지 않는다.
- 출처는 최대 60개로 제한한다. 이 레지스트리는 읽은 자료의 신원을 보장하며 모델 문장 전체의 의미적 정확도를 보증하지 않는다. 기존 독립 결과 검토를 유지한다.

## 확인 범위

Electron 빌드만 수행한다. 자동 테스트, 실계정 모델 호출, 메일 전송/수신 검증, Windows 설치 또는 로그인된 앱 재시작은 수행하지 않는다. `?conversation&sources&skills`의 예시 화면은 명확히 미리보기로 표시한다. 실제 서비스 결과와 섞지 않는다.

예시 화면에서 확인한 동작: `/` 목록 표시, 이름/설명 검색, `/docs` Tab 선택, `/model` Enter → 기존 모델 모달과 검색 입력 초점, 위키 출처 → Monaco 파일 탭, 메일 출처 → 해당 원문, 첨부 출처 → 실제 추출 구간 먼저 표시, 원문 → 대화 복귀. 저장된 대화와 새 메시지의 두 렌더링 경로에 동일하게 연결했다. 실제 모델의 인용 정확도는 이번 범위에서 측정하지 않았다.

접힌 사이드바의 고정 로고가 메일 복귀 버튼과 대화 제목을 가리던 상단 겹침도 수정했다. 로고와 펼치기 버튼의 위치는 유지하며 원문을 열고 돌아와도 대화 초안을 보존한다. 기존 로그인된 실행은 유지했으며 백엔드 변경은 다음 실행부터 적용된다.
