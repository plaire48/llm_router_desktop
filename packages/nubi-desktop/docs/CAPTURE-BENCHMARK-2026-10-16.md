# 필요한 영역을 선명하게 캡처하기

조사일: 2026-10-16. 결론은 **작은 미리보기와 실제 모델에 전달할 원본 영역을 분리하고, 목적에 맞는 영역부터 선택하는 것**이다. 누비에 이미 있는 원본 영역 자르기를 수동 캡처에도 연결하는 것을 우선한다.

## 비교 범위

Codex 앱과 Claude Code 앱의 계정 연결 상태에서 같은 업무를 실행한 속도 대결은 아니다. 공식 문서, 공개 소스의 이미지 처리와 누비의 실제 전처리 함수로 만든 로컬 실험을 비교했다. 추가로 설치된 공식 CLI에서 이미지 읽기 4회를 실행했으나, 앱의 캡처 UI나 일반 업무 성능 비교는 아니다. Claude Code의 이미지 첨부 기능과 Claude Computer/Browser Use API의 도구 설계를 구분했다. 비공개 앱의 캡처 엔진을 확인했다고 표시하지 않는다.

### Codex에서 참고할 점

[OpenAI Docs의 이미지 가이드](https://developers.openai.com/api/docs/guides/images-vision)는 모델별 크기/패치 예산과 detail을 구분한다. 작은 글자와 정밀 판독에는 지원되는 original을 고려하지만, original도 제한을 적용할 수 있다. 해상도를 무조건 올리는 정책은 맞지 않는다.

[공식 앱 브라우저 문서](https://learn.chatgpt.com/docs/browser#computer-use-in-the-browser)는 페이지의 렌더링 상태 검사와 스크린샷을 함께 사용하는 흐름을 설명한다. 문서만으로 영역 선택 정확도나 처리 속도 수치는 확인할 수 없다.

공개 소스는 `openai/codex`의 `4eb4a65407d98cebc4c83bf13be440b9fbc78a7c`를 고정해 읽었다.

- [view_image](https://github.com/openai/codex/blob/4eb4a65407d98cebc4c83bf13be440b9fbc78a7c/codex-rs/core/src/tools/handlers/view_image.rs)는 이미지 유효성을 확인하고 모델 지원/옵션에 맞춰 detail을 정한다. 실제 전처리는 history 삽입 경로에 맡긴다.
- [이미지 유틸리티](https://github.com/openai/codex/blob/4eb4a65407d98cebc4c83bf13be440b9fbc78a7c/codex-rs/utils/image/src/lib.rs)는 입력 해시와 처리 모드를 캐시 키로 사용한다. 크기 변경이 필요 없고 형식을 유지할 수 있으면 원본 인코딩을 재사용한다. 처리 정책에 픽셀 크기와 패치 예산을 함께 둔다. 이 파일의 특정 상수를 모든 Codex 모델의 실제 정책으로 일반화하지 않는다.

### Claude에서 참고할 점

[Claude Code](https://code.claude.com/docs/en/interactive-mode)는 클립보드 이미지를 입력 위치의 이미지 표식으로 첨부한다. 이 문서는 자체 OS 캡처 엔진이나 자동 영역 선택 성적을 보장하지 않는다.

[Computer Use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)는 전체 관찰과 zoom을 나누고, 확대 후에도 기준 좌표계를 유지한다. [Browser Use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool)는 트리/텍스트 읽기와 스크린샷을 구분하고, 매 클릭 뒤 스크린샷을 요구하지 않는다. [Vision 가이드](https://platform.claude.com/docs/en/build-with-claude/vision)는 모델별 이미지 한도와 압축에 따른 작은 글자 손실을 설명한다.

[공식 예제의 zoom 구현](https://github.com/anthropics/claude-quickstarts/blob/9ec32b91df50b0d4906cae64b13c6298055ff40d/computer-use-demo/computer_use_demo/tools/computer.py)은 영역을 물리 해상도에 매핑한 뒤 원본에서 잘라낸다. 이 공개 예제는 Claude Code의 내부 구현이 아니다. 누비 수동 선택에는 새 프레임을 찍는 부분을 그대로 옮기지 않고, 사용자가 본 동일한 프레임을 유지해야 한다.

## 로컬 측정

합성 한국어 업무 화면 3종에서 동일한 CSS 영역 720×440을 정답 영역으로 지정했다. 자동으로 필요한 영역을 찾은 성적은 아니다. 제품의 `captureImage`와 `cropCapture`를 그대로 호출했고 제품 실행 경로는 변경하지 않았다.

비교안은 작은 미리보기를 표시하되 최종 이미지는 동일 원본에서 자르는 방식이다. 작은 원본은 불필요하게 줄이지 않고, 큰 원본의 미리보기만 1280px로 제한했다. 각 단계는 첫 회를 제외한 9회 중앙값을 사용했다. PNG 파일에서 만든 NativeImage의 인코딩 캐시로 무축소 경로가 유리해지는 초기 측정은 제외하고, 최종 측정은 매 회 raw bitmap으로 NativeImage를 새로 만들었다.

| 화면 조건 | 현재 선택 이미지 | 원본 영역 이미지 | 현재 전처리 | 비교안 전처리 |
| --- | --- | --- | ---: | ---: |
| 1440×900, DPR 1 | 720×440 | 720×440 | 16.8ms | 16.7ms |
| 1920×1080, DPR 2, 원본 3840×2160 | 900×550 | 1440×880 | 84.5ms | 40.6ms |
| 3840×2160, DPR 2, 원본 7680×4320 | 450×275 | 1440×880 | 111.8ms | 68.6ms |

전처리는 **미리보기 준비 단계 중앙값과 최종 crop 단계 중앙값의 합**이다. 화면 획득, bitmap 생성, IPC, 사용자의 영역 선택, 모델 전송과 추론은 제외한다. 전체 사용 시간을 그만큼 줄였다고 표시하지 않는다. 작은 화면의 속도 차이는 사실상 없고 큰 화면에서 개선 가능성이 관찰됐다.

가장 큰 원본 사례는 같은 내용의 픽셀이 10.24배 늘었다. 최종 PNG는 24,382바이트에서 41,358바이트로 증가했다. 필요한 세부를 보존하면 파일 크기와 이미지 토큰이 늘 수도 있다. 미리보기는 709,805바이트에서 222,832바이트로 작아졌다. 8K raw bitmap만 약 126.6MiB이므로 원본 캐시를 무제한으로 둘 수 없다.

### 문자 판독 보조 평가

macOS Apple Vision의 accurate OCR, 한국어/영어, 언어 교정 활성화로 3회 반복했다. 이름, 상태, 날짜, 금액, 코드 5개 필드에서 공백만 제거하고 문장 부호와 대소문자는 그대로 비교했다.

| 조건 | 현재 | 원본 영역 | 반복 결과 |
| --- | ---: | ---: | --- |
| 일반 화면 | 4/5 | 4/5 | 3회 동일. 양쪽 모두 금액 쉼표를 점으로 읽는 오류가 남았다. |
| 4K 원본 | 5/5 | 5/5 | 3회 동일 |
| 8K 원본 | 0/5 | 5/5 | 3회 동일 |

이는 **로컬 OCR을 이용한 선명도 지표**다. Codex/Claude 모델의 이해도, 추론 정답률이나 실제 회사 화면의 품질 성적이 아니다.

## 설치된 Codex와 Claude Code 이미지 읽기 파일럿

합성 8K 사례의 현재 선택 이미지와 원본 영역 이미지를 두 CLI에 각각 한 번씩 첨부했다. Codex의 셸/웹 검색/다중 에이전트를 끄고 Claude의 도구 목록을 비운 뒤, 도구를 쓰지 않고 정확한 이름, 상태, 날짜, 금액, 코드를 JSON으로 반환하게 했다. 저장소 밖의 임시 폴더에서 기존 CLI 인증만 사용했으며 계정/모델/권한 설정은 바꾸지 않았다.

| 실행 | 현재 이미지 | 원본 영역 이미지 | 판독 결과 |
| --- | ---: | ---: | --- |
| Codex CLI 0.162.0-alpha.17.2 | 8.10초 | 6.50초 | 양쪽 5/5 |
| Claude Code 2.1.296 | 6.48초 | 5.84초 | 양쪽 5/5 |

Claude가 반환한 모델 식별자는 `claude-fable-5-1`이다. Codex JSON 이벤트는 모델 식별자를 반환하지 않아 기록하지 못했다. 실행 당시 각 CLI의 기본 설정을 사용했다. 시간은 프로세스 시작부터 종료까지이며 순서는 각 도구의 현재 이미지 → 원본 영역이었다. 모델, 서버 부하, 캐시, 기본 지침과 출력/추론 토큰을 통제하지 않은 **각 1회 파일럿**이다. 이 수치로 제품 속도 우열이나 원본 영역의 추론 단축 효과를 확정하지 않는다.

두 도구 모두 현재의 축소 이미지도 읽었다. 따라서 로컬 OCR의 0/5 → 5/5를 LLM 정확도 향상으로 옮길 수 없다. 더 복잡한 작은 표/주변 문맥/오류 원문 평가가 필요하다. 같은 원본 영역은 현재 이미지보다 픽셀 수가 커서 모델 입력도 늘 수 있다. CLI가 보고한 입력 토큰은 시스템 지침과 캐시까지 포함하므로 이미지 토큰으로 표시하지 않는다.

초기 호출은 CLI 인자 문제로 모델 실행 전에 실패했다. Codex에는 프롬프트를 stdin으로 넘기고 Claude에는 stream-json 출력 옵션을 맞춘 뒤 위 4회를 실행했다. 성공 출력에 포함된 인증 관련 시작 진단을 실패로 오분류한 기록도 수정했다. 자격 증명이나 로그인 상태는 변경하지 않았다. 원문 필드, 시간과 숫자 사용량은 `cli-pilot.json`, 초기 실패는 `initial-cli-invocation-run.log`에 보존했다.

## 적용 순서

1. **수동 캡처도 원본에서 먼저 자르기.** main에 짧게 고정한 프레임 ID와 작은 미리보기를 만들고, 사용자가 고른 좌표만 main으로 보낸다. 같은 원본에서 crop 후 한 번 인코딩한다. 사용자 선택 뒤 새 스크린샷을 찍지 않는다. child view도 원본 픽셀로 합성하거나 선택 영역과 교차하는 부분만 처리한다.
2. **캡처할 대상을 먼저 좁히기.** 현재 웹페이지, 보조 문서/편집기, Workspace 영역을 구분한다. 자체 화면과 웹 DOM에서 선택한 항목/대화상자/표를 추천 범위로 강조하고, 사용자가 드래그로 조정하게 한다. 전체 화면은 명시적인 별도 동작으로 제안한다. 기존 클릭=전체 규칙을 바꾸는 UX 변경이므로 적용 시 동작을 함께 검토한다.
3. **자동 캡처는 질문과 현재 관찰에 묶기.** 요청에 필요한 텍스트/DOM으로 충분하면 이미지를 만들지 않는다. 시각 확인이 필요하면 현재 관찰에서 얻은 정확한 target과 범위로 캡처한다. 표는 제목, 열 머리글과 단위, 오류는 발생 위치와 메시지처럼 해석에 필요한 주변부를 포함한다. 사용자가 명시한 수동 영역을 자동으로 넓히지는 않는다.
4. **선명도가 부족할 때 같은 원본의 세부 영역만 추가하기.** 원본이 이미 축소된 경우 단순 확대를 고화질로 표시하지 않는다. 기본은 필요한 영역 한 장이며 전체 요약과 여러 crop을 항상 함께 전송하지 않는다. 자동 조작의 좌표는 원래 viewport 기준을 유지한다.
5. **모델 전달과 응답 품질도 함께 개선하기.** 현재 선택 모델의 이미지 지원이 확인되면 기존 호출 경로에 직접 전달하는 방식을 평가한다. 텍스트 전용 GLM에는 같은 제공자의 검증된 이미지 모델 분석을 유지하되 원문 필드, 관찰 범위와 판독 불가를 구조화한다. 6문장 요약만으로 표/오류 세부를 대체하지 않는다. 사용자의 선택 모델이나 인증을 임의로 바꾸지 않는다.
6. **성능 상한을 두기.** 캡처 획득 중 단일 요청, 프로젝트/탭/문서 세대 확인, 원본 하나의 메모리/수명 상한과 취소/실패/전환 시 즉시 해제를 둔다. PNG는 텍스트 품질 기준으로 유지하고 사진형 화면의 JPEG/WebP는 별도 비교한다. 모델마다 width뿐 아니라 height, 픽셀/패치와 bytes 예산을 적용한다. 별도 이미지 처리 라이브러리는 이 경로 정리 뒤 추가 이득을 측정해 선택한다.

로그인 화면 제외, 현재 탭과 revision 검증, 캡처의 별도 저장, 읽을 수 없는 부분을 모른다고 보고하는 기존 계약은 유지한다. 과거 고정 화면은 수동 첨부의 근거가 될 수 있지만 현재 페이지의 자동 조작 근거로 재사용하지 않는다.

## 실제 모델 비교의 다음 평가 조건

같은 합성 과제에서 현재 누비/원본 crop/필요 시 추가 세부 읽기를 각각 반복하고, 같은 질문과 표시 영역을 유지한다. 한국어 작은 글자, 수치와 오류 원문, 차트 범례, 표 단위, 긴 페이지, 브라우저 zoom과 DPR, 선택/취소 중 화면 변경을 포함한다. 불필요한 영역 비율, 필요한 필드 보존율, 읽지 못한 내용의 정직한 보고, 사용자 재선택 횟수, 요청 bytes/실제 보고 토큰, 캡처/전처리/모델/전체 p50과 p95를 따로 기록한다.

현재 결과로 자동 영역 선택 성공률, 실제 모델의 추가 호출 감소율, Windows 다중 모니터와 회사 웹/Office 품질은 확정하지 않는다. 이번 산출물은 조사 보고서와 재현 가능한 벤치마크 및 제한된 CLI 파일럿이며 제품 적용 성적은 후속이다.

재현: `node scripts/benchmark-capture-pipeline.mjs`. macOS OCR 재현 소스는 `verification/capture-benchmark-2026-10-16/recognize.swift`, 픽셀/전처리 결과는 `result.json`, OCR 원문/채점은 `ocr-run-*.json`과 `ocr-score.json`에 있다.

CLI 파일럿 재현: `node scripts/benchmark-capture-cli-pilot.mjs`. 이 명령은 기존 인증으로 외부 모델에 합성 이미지 4개를 보내며 사용량이 발생한다.
