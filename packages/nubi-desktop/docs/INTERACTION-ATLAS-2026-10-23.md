# Workspace interaction atlas

사용자가 제공한 `motion_interaction_atlas.html`의 18가지 유형을 Workspace의 실제 동작에 연결했다. 예제의 색상 대신 기존 누비 색상, 글꼴, 공통 간격과 모션 토큰을 사용한다. 기존 구현이 있던 유형은 재사용하고 필요한 동작을 보강했다.

현재 브랜드 기준은 [20개 브랜드 모션](BRAND-MOTION-GUIDE.md)이다. 이 문서의 18개 상호작용에 기존 물방울/모래시계 2개를 더해 상황별 목록으로 관리한다.

| 유형 | 적용 위치와 체험 방법 |
| --- | --- |
| Fluid Layout Expansion | Electron에서 오른쪽 보조 영역을 열면 필요한 너비만 창을 확장한다. 화면 작업 영역을 넘지 않으며 닫으면 자동으로 넓힌 부분만 복귀한다. 사용자가 창을 이동하거나 크기를 바꾸면 그 선택을 보존한다. |
| Animated Layout Reflow | 보조 영역의 크기 변경과 진행 기록 펼치기를 비활성 표면의 이동과 크기 보간으로 연결한다. 실제 레이아웃과 입력은 즉시 반영하고 본문 글자는 확대하지 않는다. |
| Concentric Corner Morph | 일반 및 확장 보조 영역에서 바깥 곡률, 안쪽 간격과 안쪽 곡률을 함께 조정한다. `inner = outer - gap` 관계를 유지한다. |
| Magnetic Window Snapping | 외부 브라우저를 가져올 때 실제 native viewport와 같은 측정값으로 드롭 표면을 맞춘다. 기존 Windows 창 후보 확인, DWM 미리보기, 단일 attach와 native 영수증 계약을 유지한다. |
| Shared Element Morphing | 메일과 위키 항목의 표면에서 오른쪽 상세 표면으로 이어진다. 비동기 본문이 먼저 준비되고 패널이 나중에 표시되어도 연결한다. 본문과 편집기는 다시 마운트하지 않는다. |
| Seamless Crossfade | 중앙 화면 교체와 상세 제목, 진행 기록의 새 내용을 짧게 페이드한다. |
| Spring Page Push | 기존 중앙 화면의 View Transition을 재사용한다. 돌아가기와 목록 복귀는 반대 방향을 사용하며 다음 입력은 이전 캡처를 취소한다. |
| Spring Bottom Sheet | 760px 이하의 창에서 모달이 아래에서 올라온다. 기존 모달의 초점, 닫기, 승인과 퇴장 정리 계약을 유지한다. |
| Dynamic Capsule Expansion | 접힌 진행 기록의 요약 캡슐을 누르면 전체 기록 표면으로 확장한다. |
| Staggered Content Reveal | 시작 화면의 첫 세 작업 카드가 공통 24ms 간격으로 나타난다. 지연 중에도 읽고 선택할 수 있도록 시작 불투명도를 0.65로 유지한다. 기존 대화나 승인 표시를 지연하지 않는다. |
| Rubber-Band Overscroll | 메일, 위키와 대화 목록에서 스크롤 경계에 도달한 경우에만 내부 콘텐츠가 최대 12px 반응하고 복귀한다. 기본 스크롤을 가로채지 않는다. |
| Swipe Actions | 터치 또는 펜으로 대화 행을 왼쪽으로 밀면 기존 관리 메뉴를 연다. 수직 스크롤은 유지하고 고정, 보관, 삭제를 자동 실행하지 않는다. 기존 클릭과 키보드 접근도 유지한다. |
| Dock Magnification | 왼쪽 도구 막대의 가까운 아이콘 최대 세 개가 거리에 따라 반응한다. 버튼의 클릭 영역과 글자는 고정한다. |
| Spring Squish Feedback | 공통 버튼을 누르면 가로 1.025, 세로 0.95 배율로 짧게 눌렸다 공통 스프링으로 복귀한다. |
| Sliding Segmented Control | 위키와 공용 카탈로그의 선택 표시가 실제 선택 탭의 위치와 너비를 따라 이동한다. 기존 제공자 고유 색을 보존한다. |
| Spring Context Menu | 도구 메뉴와 대화 관리 메뉴가 트리거를 기준으로 확장한다. 메뉴의 키보드 이동과 확인 대화상자는 기존 동작을 사용한다. |
| Liquid Glass Reaction | 시작 화면의 브랜드 뒤에 제한된 크기의 유리 표면이 포인터에 반응한다. 문서 본문 뒤에 필터를 추가하지 않는다. |
| 3D Parallax & Depth | 같은 장식 표면이 최대 약 4도와 3도 기울기 및 8px와 6px 이동으로 반응한다. 제목과 본문은 정지한다. |

## 동작과 정리

`ui/workspace-interactions.js`는 애플리케이션 상태나 쓰기를 소유하지 않는다. 크기 보간에는 inert 표면만 사용하며, 새 입력, 모션 감소, 창 비활성화와 해제에서 장식 상태를 정리한다. 장기 애니메이션과 새로운 무한 반복은 추가하지 않았다. 비활성 표면의 효과는 최대 세 개이고 기존 공통 모션 정책을 유지한다. 배경 진행이나 스트리밍은 사용자 레이아웃 모션의 시작 조건이 아니다.

Electron 창 확장은 `window-expansion.cjs`와 `useWindowExpansion.js`에서 관리한다. 네이티브 창 상태 변경은 Electron 전용 요청이다. 최대화, 전체 화면, 최소화, 수동 이동과 크기 변경, 모니터 변경은 자동 복귀의 소유권을 해제한다. 닫기 직후 다시 열면 이전 축소를 취소한다. 모션 감소가 바뀌면 진행 중인 크기 변경도 새 설정을 반영한다. 네이티브 브라우저 창의 도킹 중에는 별도 창 확장을 시작하지 않는다.

## 로컬 검증

- 관련 Node 회귀 75개: 창 확장 9개와 기존 모션, 모달, 목록, 외부 브라우저 및 도킹 계약. 새 검사에는 음수 모니터 좌표, 화면 경계, 수동 변경, 빠른 닫기와 재열기, 모션 감소와 타이머 정리가 포함된다.
- 실제 공통 React 컴포넌트를 연결한 Chrome 화면 검증 20개: 메일과 위키 상세, 곡률, 탭, 실제 CDP 터치 밀기, 기본 스크롤 보존, 메뉴, 좁은 창의 시트와 모션 감소, 초안과 쓰기 경계. 합성 로컬 자료를 사용했다.
- 빠른 패널 전환 중 입력의 다음 프레임 지연을 5회 측정했다. 최종 수치는 `verification/interaction-atlas-2026-10-23/checks.json`에 보존하며 이 구간에 50ms 이상 긴 작업은 없었다. 제품 전체나 Windows 성능 수치가 아니다.
- 실제 macOS Electron 창 검증 5개: 연속 너비 확장, 원래 크기 복귀, 수동 위치와 너비 보존, 모션 감소의 단일 변경, 렌더링 오류 없음. 실제 OS 포인터와 검증 창의 간섭을 막기 위해 검사 안에서만 `setIgnoreMouseEvents(true)`를 사용하고 UI는 CDP로 조작했다. 실제 마우스로 OS 창을 드래그한 결과와 구분한다.
- 실제 Electron 메일과 위키 회귀 3개: 로컬 EML 가져오기와 오른쪽 본문 읽기, 위키 재열기와 미저장 초안 및 원본 보존, 상세 확대와 복귀 및 중앙 목록 유지.
- Electron 빌드와 공통 디자인 검사를 통과했다. PowerShell이 없는 macOS 환경으로 Windows Office 파서는 실행하지 않았다.

검증 도중 발견한 안쪽 곡률의 이전 값 상속, 패널 표시 시점의 공유 전환 누락, 스와이프의 프로그램 메뉴 클릭 억제 순서는 수정했다. 도킹 미리보기는 애니메이션이 정착한 좌표를 검사하며 테두리를 포함한 크기로 맞췄다. 과거 회전 스피너를 기대하던 소스 검사는 이미 선택한 4초 모래시계 계약에 맞췄다.

`verification/interaction-atlas-2026-10-23/`의 `checks.json`, `native-checks.json`과 이미지, `verification/reader-shell-2026-10-23/checks.json`이 근거다. 최초 곡률 실패와 미리보기 측정 실패는 별도 JSON으로 남겼다.

Windows의 실제 브라우저 창 드래그와 DWM, 사내 로그인, 설치 및 업데이트는 이 로컬 검사에 포함하지 않았다. 웹 개발 미리보기는 Electron 창 자체를 넓히지 않는다.

## 브랜드 후속 연결

- 전환/선택 표면은 브랜드 20% + 흰색 80%, 유리/프로젝트 로딩은 8% + 92%를 같은 원본 토큰으로 사용한다. 본문과 입력의 위치/읽기 면은 유지한다.
- 프로젝트 읽기/정리 단계의 선택 표시는 같은 브랜드 표면을 실제 단계 위치로 이동한다. 기존 스프링/페이드/진행 막대를 재사용하고 실제 준비 시점이나 입력을 늦추지 않는다.
- 모달/프로젝트 전환/창 숨김에서 남아 있던 Atlas 장식을 즉시 정리하고 그동안 새 포인터 효과를 억제한다. 가림 해제 후에는 다음 상호작용부터 반응한다. 메일/위키/대화에서는 물방울을 정지한다.
- 강제 색상에서 장식 표면/유리는 숨기고 실제 드롭 안내에는 시스템 색 윤곽을 남긴다. 비활성 기능은 모션을 위해 켜지 않는다.
- 최종 renderer CSS/브랜드 아이콘을 사용하는 공통 컴포넌트 검사 27개 통과. 기존 인터랙션 20개 검사에 여섯 색 유리/재배치 표면, 강제 색상, 세 가림 상태의 정리/억제와 재진입 검사를 더했다. 초안/스크롤/쓰기 경계와 좁은 시트/모션 감소도 유지했다.
- 실제 macOS Electron 브랜딩 13개와 모션/창 숨김/타이틀바/소비자 토큰 단위 28개, Electron 전체 빌드와 identity를 통과했다. 실제 호스트에서는 열린 프로젝트 연결 모달의 장식 정리와 메일/위키의 두 물방울 정지도 확인했다.

증거는 `verification/interaction-atlas-2026-10-23/checks.json`, `verification/calm-liquid-2026-10-23/result.json`과 Codex 작업 폴더의 `brand-motion-*.log`에 있다. 이전 문단의 과거 검사 수와 이번 후속 검사 수는 실행 범위가 다르다. Windows와 실계정/실자료/실모델 검증을 이 로컬 결과로 대신하지 않는다.

프로젝트 열기/단계/완료/실패 복귀/모션 감소의 실제 Electron 검사와 프로젝트 연결 흐름 7개도 통과했다. 터치 밀기 검사는 이전 패널의 실제 퇴장이 끝난 뒤 수행해 가림 상태와 입력 가능한 상태를 구분한다. 검증 장면의 입력 다음 프레임 표본 5개에서 50ms 이상 긴 작업은 없었으며 Windows 전체 성능으로 일반화하지 않는다.
