# 창을 닫은 뒤 입력이 막히는 문제

사용자는 특정 상황에 한정되지 않고 화면이 자주 멈춘다고 보고했다. 일반적인 렌더링 정지와 화면 갱신은 계속되지만 클릭/입력이 막히는 상태를 구분해 조사했다. 아래는 후자의 재현과 수정이며 사용자의 모든 정지 원인이 확인되었다는 뜻은 아니다.

## 재현과 원인

기존 선택 메뉴의 `useAnchoredModal`은 자체적으로 배경 `inert`와 focus/Tab 제어를 관리했다. 전체 모달은 CX `DetailPanel`의 별도 공유 스택을 사용했다.

1. 선택 메뉴를 열면 자체 훅이 root 입력을 잠근다.
2. 그 위에 CX 상세 창을 열면 CX는 이미 잠긴 root를 원래 상태로 저장한다.
3. 상세 창이 열린 상태에서 아래 메뉴가 먼저 제거된다.
4. 마지막 상세 창을 닫으면 CX가 root의 `inert=true`를 복원한다.
5. 열린 창은 없는데 메인 입력과 버튼이 응답하지 않는다. 타이머는 계속 갱신된다.

실제 React/CX와 제품 훅을 사용하는 `check-ui-responsiveness.mjs`에서 수정 전 root가 `true`로 남는 것을 검출했다. 이는 단순히 잠시 애니메이션이 도는 현상과 다르다. 테스트의 첫 실행에서 발생한 CSS alias 설정 오류는 재현 실패로 계산하지 않는다.

## 수정

`AnchoredDialog`가 기존 CX `DetailPanel`을 통해 선택 메뉴의 수명을 관리한다. 스킬/도구, 승인 방식과 추론 메뉴에서 자체 잠금 훅을 제거했다. 기존 메뉴 내용과 위치 계산, 닫기 버튼을 유지하고 배경 잠금, Tab, Escape와 초점 복귀는 전체 모달과 같은 CX 스택이 소유한다. `node_modules`나 CX 패키지 자체를 수정하지 않았다.

처음 위치를 측정하는 동안 숨겨지는 메뉴는 보일 때 초기 초점을 한 번 마무리한다. 일반적인 리사이즈나 상태 갱신에는 초점을 다시 가져오지 않는다. 추론 설정을 저장하는 동안 Escape도 CX의 busy 가드를 따른다.

메뉴 전환에서 닫기 애니메이션용으로 남은 inert 그림을 활성 창으로 오인하지 않는다. 실제 활성 모달이나 배경 잠금이 남아 있으면 후속 버튼을 실행하지 않는다. 모든 inert를 강제로 지우는 복구 타이머는 추가하지 않았다. 시작/셸의 독립 입력 잠금도 그대로 유지한다.

## 확인 범위

- 같은 메뉴 위에 창을 열고 아래 메뉴부터 제거한 뒤 마지막 창을 닫기, 배경 보호 유지, 메인 입력과 버튼의 실제 응답을 검사한다.
- 애니메이션 사용/감소 각각 6회 반복하고 시작/셸의 별도 잠금 보존을 확인한다.
- 독립 macOS Electron 프로젝트에서 실제 애니메이션을 켜고 메뉴 열기/닫기 12회와 메뉴 교체 3회를 추가 검사한다. 이후 기존 스킬 등록/선택/실행/재시작 검사를 이어간다. 모델은 로컬 모의 제공자다.
- 1280/440/360px에서 각 창의 최초 초점과 화면 경계, `/` 재입력, 다른 메뉴 전환과 선택 해제를 확인한다. 공통 모달과 자동실행 안내의 관련 검사도 다시 실행한다.

소규모 격리 프로젝트의 수정 전 Electron 탐색 3회에서 프레임 간격 p95는 20.4~20.8ms였고 관측한 long task는 없었다. 이 짧은 탐색은 장시간 사용, 큰 대화/위키, 실계정, 실제 Windows PC의 렌더링 정지를 배제하지 않는다. Playwright 클릭 완료 시간은 애니메이션 안정화 대기도 포함하므로 순수 입력 처리 시간으로 사용하지 않는다.

재현 전후와 최종 검사의 로그는 `verification/ui-input-lock-2026-10-16/`에 보관한다. Windows 설치판의 사용자 증상 재검증과 배포는 별도다.

## 결과

입력 잠금 재현의 수정 전 실패와 수정 후 12회, 별도 셸 잠금 보존을 확인했다. 공통 UI 38항목, 모달 회귀 40항목, 혼합 모달 스택 검사, 1280/440/360px 입력창 전환 검사와 실제 애니메이션을 켠 Electron 스킬 흐름 12항목이 통과했다. 전체 회귀는 1,705개 중 1,509개 통과, 196개 건너뜀, 실패 0개다. Electron 빌드와 디자인 검사도 통과했다. 빌드의 Office reader 파서는 macOS의 PowerShell 미설치로 건너뛰었다.

독립 잠금 회귀를 `npm run test:responsiveness-ui`로 실행할 수 있게 하고 기존 순차 `test:gates`에도 추가했다. 이번 작업에서 전체 `test:gates`를 실행한 것은 아니며 위에 명시한 검사들을 실행했다.
