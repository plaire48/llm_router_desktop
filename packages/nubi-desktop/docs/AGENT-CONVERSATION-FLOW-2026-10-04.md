# 계획과 진행, 질문의 대화 연결

브라우저 확장의 `TaskPlan`, `AgentTrace`, `QuestionForm`, Pi `runAgent`를 직접 사용한다. 별도 UI 프레임워크나 실행기는 추가하지 않았다. 기존 공개 발화의 비밀값 제거, 600자 한도, 원래 요청 보존과 승인/복구 계약을 유지한다.

## 반영

- 계획의 ISO 시각을 브라우저 컴포넌트가 받는 epoch 시각으로 변환한다. 이전에는 계획 수정의 추가/제외와 이유가 정규화에서 빠졌다.
- 질문 메시지에 실행 ID, 질문 ID, 실제 시각과 모델을 붙인다. 진행은 해당 질문/답변 바로 앞에 표시하고 질문 텍스트와 폼의 중복을 없앴다. 선택, 직접 입력, 긴 입력과 초안 저장은 같은 질문 계약을 사용한다.
- 대기열에서 적용된 요청도 대화 하단의 기존 위치를 유지한다. 아직 답변이 없는 현재 실행은 마지막 메시지 아래에 진행과 폼을 표시한다.
- 실행이 끝날 때 공개 계획과 최대 80개 실제 trace를 SQLite task의 `activityHistory`에 저장한다. 화면은 기존 공유 정규화의 최대 32개 기록을 사용한다. 다음 요청에서 이전 계획/발화가 사라지지 않으며 이전 계획과 진행은 접어서 표시한다. 답변 없는 중단 기록은 마지막 메시지 뒤의 위치를 유지한다.
- 독립 검토에 단계별 `expected_outcome`을 별도 항목으로 전달한다. 검토가 ready이고 해당 계획 revision의 항목이 supported 근거를 가진 경우만 호스트가 단계를 완료로 바꾼다. pending/unknown 단계와 승인 대기는 남긴다. 계획 자체는 사용자 요구사항을 대체하거나 추가 실행 권한을 주지 않는다.
- 프로젝트 도구 호출 전과 의미 있는 결과 후의 짧은 공개 안내를 요청한다. 비공개 reasoning 필드는 사용하지 않으며 모델이 내지 않은 발화를 생성하지 않는다. 일반 대화에는 계획을 강제하지 않는다.

## 선택 근거

현재 브라우저 소스와 [기존 하네스 적용 기록](BROWSER-HARNESS-PARITY-2026-10-02.md)을 확인하고 같은 컴포넌트/이벤트 계약을 연결했다. 기존 Pi 라이선스와 의존성을 유지했다. 새 라이브러리를 도입할 효과가 없어 추가하지 않았다. 브라우저의 DOM 검증이나 Computer Use/A2A 권한을 Desktop으로 확대하지 않았다.

## 확인 범위

`npm run build`의 Electron 빌드가 통과했다. 예시 전용 웹 화면에서 계획 수정의 추가 단계와 변경 이유, 공개 발화, 진행 아래 선택/직접 입력 폼을 확인했다. 직접 입력 전송과 선택 버튼 응답 후 폼이 닫히고 질문/답변과 이전 진행 기록이 대화의 원래 위치에 남는 것을 각각 수동 확인했다. 이미 대화에 남은 결정은 별도 요구사항 목록에 중복 표시하지 않는다. 자동 테스트는 실행하지 않았다. 예시 데이터는 실제 모델이나 파일/명령 실행 증거가 아니다. 실계정 모델, Windows와 실제 도구 완료율은 이번 확인 범위가 아니다.

실행기 변경은 앱 재시작 후 적용된다. 현재 연결된 메일/모델의 메모리 인증은 재시작하면 사라지므로 기존 연결을 유지한 채 빌드한다.

## 페이지 연결 후 질문 위치 보완

2026-10-04. 이전 실행의 질문 문구와 새 질문이 같으면, `questionId`가 없는 과거 메시지를 텍스트만으로 찾아 그 위치에 새 폼을 붙이는 문제를 예시 화면에서 재현했다. 현재 진행은 새 실행의 첫 메시지 앞에 있어 질문이 진행보다 위에 나타났다.

현재 질문 ID와 실행 ID를 우선 사용하고 현재 진행의 위치는 대기 중인 질문 메시지를 기준으로 한다. 옛 기록의 텍스트 호환은 실행 ID가 같은 마지막 메시지로 한정한다. 일치하는 메시지가 없으면 현재 진행과 폼을 대화 하단에 함께 표시한다. 과거 질문/답변을 새 폼으로 바꾸지 않는다. 현재 실행 ID 계산을 질문 배치와 WorkspaceActivity가 공유해 오래된 timing이 질문의 진행을 바꾸지 않게 한다.

답변 후 과거 진행도 저장된 질문 ID 또는 마지막 메시지 위치를 사용해 질문 바로 앞/원래 위치를 유지한다. 첫 번째 assistant 메시지를 기준으로 다시 위로 옮기지 않는다.

브라우저 확장의 `QuestionForm`, 질문 메시지 바로 앞의 계획/진행 배치와 기존 React 메시지 key를 재사용한다. 질문 초안 저장, 직접 입력, 선택 답변과 기존 스크롤 보존은 유지하며 새 UI 라이브러리를 추가하지 않는다. 예시 화면은 `?conversation&activity&page-question=legacy|current`이고 실제 브라우저 제어나 모델 실행의 증거가 아니다. Computer Use/A2A를 활성화하지 않는다.

최종 `npm run build:electron`은 exit 0으로 완료했다. 예시 화면에서 같은 문구의 과거 메시지는 일반 기록으로 남고 새 폼은 현재 진행 아래에 한 개만 표시됐다. 현재 실행에 먼저 발화가 있고 질문 메시지가 뒤에 있는 경우도 진행 바로 다음에 폼을 표시했다. 직접 답변 전송 후 폼이 닫히고 해당 진행 → 질문 → 사용자 답변 → 새 응답의 순서가 유지됐다. 예시 화면 콘솔 오류는 없었다. 자동 테스트와 실모델 요청은 수행하지 않았다. 기록은 `evidence/page-question-legacy-2026-10-04.png`, `page-question-current-2026-10-04.png`, `page-question-answered-2026-10-04.png`다. 기존 실행 중 Electron은 인증/미저장 상태 보존을 위해 재로드 승인 대기 중이며 새 실행판 적용 성공으로 표시하지 않는다.
