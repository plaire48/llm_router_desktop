# 아이콘과 텍스트 시작선

모달의 제목/본문/설정 항목과 대화의 모델 이름/검토 표시가 서로 다른 지점에서 시작했다. 실제 renderer에서 첫 모달의 제목은 x=404, 본문은 x=372로 32px 차이가 났다. 대화는 입력 텍스트 x=113에 비해 검토 문구 x=137, 모델 이름 x=133이었다.

모달은 기존 32px 바깥 여백(좁은 창 24px)을 유지하고 안쪽에 24px 아이콘 칸과 8px 간격을 공통 사용한다. 제목에 아이콘이 없는 경우도 같은 텍스트 칸을 예약한다. 공통 토큰과 `workspace-dialogs.css`가 제목/본문/필드/푸터와 항목의 칸을 소유하며 기능 CSS에서 임의 여백을 더하지 않는다. 계정 헤더의 사진/대체 표시도 같은 칸으로 정리했다.

설정 구획, 필드 이름, 메일 조건/모델/저장 위치, 계정 정보와 접힌 항목의 아이콘은 공통 칸에 놓는다. 클릭 가능한 필드 이름과 요약은 아이콘까지 클릭 영역에 포함한다. 입력 컨트롤 안쪽 12px, 닫기 버튼의 기존 위치/크기, 좁은 하단 시트와 키보드/초점/초안 계약을 유지한다. 앵커 메뉴, 사용자 문서/표의 들여쓰기와 제공자 색상은 별도 의미를 보존한다.

대화는 기존 `workspace-alignment.css`의 선행 아이콘 칸을 모델 표시와 검토 제목/설명에도 적용한다. 검토 상세의 상태 아이콘과 번호가 이중 들여쓰기를 만들지 않게 정리하며 작성된 답변의 Markdown 목록은 바꾸지 않는다.

아이콘 유무는 기존 제한된 shell-state 관찰에서 해당 모달의 제목만 조회해 attribute로 발행한다. 새로운 `:has()`, 화면 크기 측정 루프, 입력 이벤트마다의 전체 재탐색은 추가하지 않았다. 검증 코드의 Range 측정은 제품 실행 코드에 들어가지 않는다.

## 검증

수정 전 시작선 차이를 실제 UI 검사 실패로 재현했다. 기존 검사에는 실제 제목/본문/주요 항목의 텍스트 좌표, 공통 32px 칸과 선행 아이콘의 클릭 영역 확인을 추가했다. 각 모달의 실제 측정값도 화면 검사 기록에 보관한다.

- 전체 제품 CSS를 쓰는 격리 Electron 화면 검사 117개 상태 통과. 그중 전체 모달 78개 상태, 주요 항목 96개와 클릭 영역 30개를 측정했고 시작선 차이는 0px였다. 1280/440px과 글자 200% 상태, 모달을 여는 주변 화면, 기존 입력/서체/대비/버튼/모션 검사를 포함한다.
- 실제 macOS Electron 앱 7개 장면 통과. 1280/440px 대화, 설정/모델 모달과 440px 글자 200% 설정에서 시작선, Escape 후 원래 버튼의 초점과 미전송 초안 유지를 확인했다. 격리 저장소와 로컬 제공자 fixture를 사용했다.
- 실시간 대화 5개 너비(440~2560px) 통과. 입력/모델 이름/검토 문구/추가 점검의 제목과 설명 좌표를 확인하고 기존 폼 제출/복구/실시간 출력 검사를 유지했다.
- shell-state 관련 Node 검사 8개, `npm run build:electron`, `npm run design:check` 통과. 기존 Windows Bash CJS import.meta 경고와 PowerShell 부재에 따른 선택 Office 파서 검사 생략은 동일하다.

초기 좌표 실패와 공통 칸 도입 중의 CSS 상속/계정 헤더/투명 테두리/클릭 영역 보완 전 실패 기록은 보존했다. 이는 실패를 포함해 확인한 변형을 최종 공통 기준으로 맞춘 과정이며 처음부터 모든 화면이 통과했다는 뜻은 아니다.

상세 실행/캡처와 실패 기록은 `verification/text-axis-2026-10-24/`에 남긴다. 합성 API를 사용하는 제품 renderer, 격리 저장소의 실제 macOS Electron, Windows 설치판/실서비스의 확인 범위는 구분한다.
