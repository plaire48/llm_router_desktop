# 쉬운 과제 80개 실제 Agent 평가

사용자 요청: Bash 연속 실행, 여러 메일 정보, 적절한 스킬 활용, OpenWiki 정보 조회 각각 20개. 각 과제 최초 1회로 기준선을 만들고, 실패 원인과 변경 후 재검사를 구분한다.

## 고정 조건

- 실제 연결: 공식 Claude Code CLI의 `claude-opus-5-5`, 요청 effort `medium`, CLI가 제공한 문맥 한도 1,000,000. 실제 적용 effort는 CLI가 확인하지 않아 요청값으로만 기록한다.
- 누비 제품의 ProjectService와 Pi Agent를 그대로 호출한다. 출력 문구/계획 ready만으로 통과시키지 않는다.
- 작업당 별도 임시 Git 저장소와 상태 DB. 사용자의 프로젝트, 개인 메일과 인증은 평가 자료로 복사하지 않는다.
- 80개 질문/입력/정답/채점기 해시를 모델 실행 전에 고정한다. 정답은 모델 작업 공간에 두지 않는다.
- 최대 4개 작업 동시 실행. 서로 파일, 대화, 작업 ID를 공유하지 않는다. 경과 시간에는 제공자의 병렬 부하가 포함된다.
- 각 과제 10분, 주 모델 60회, 위임 160회, 승인 상호작용 16회가 평가 중단 기준이다. 제품 한도를 바꾸지 않는다. 제품의 OpenWiki 질문 8분 / 실행당 조사 120회 정책은 유지한다.
- 명령은 격리 폴더의 고정 보고서 도구와 버전 조회만 평가 사용자가 승인한다. 네트워크, 관리자 권한, 사용자 파일 변경, 임의 셸 연산자는 승인하지 않는다.
- 실패, 사람 확인 필요, 오류와 미실행은 80개 분모에 남긴다. 수정 전 보고서를 덮어쓰지 않는다.

## 채점과 해석

정답의 고정 사실과 실제 실행/조회 기록을 함께 검사한다. Bash는 목록 조회→ID 계산의 순서와 성공 영수증, 메일은 실제 Personal Wiki 검색→원문 복수 조회→복수 인용, 스킬은 검색→해당 지침 읽기→형식/내용 준수, Wiki는 두 문서의 조회 근거와 인용을 확인한다. 모든 과제에서 원본 파일의 불필요한 변경을 검사한다.

핵심 사실을 문자열/동의 표현으로 검사하므로 의역이나 정정 문장의 의미는 자동 채점만으로 완벽하게 판단하지 못한다. 실패와 의심 사례는 원문 답변/도구 결과를 다시 검토하며 단순 채점기 오류와 제품 오류를 구분한다. 수동 재분류는 사유를 남기고 최초 기계 채점을 보존한다.

20/20 한 번 성공은 20개 쉬운 과제의 관측 성적이다. 반복 일관성, 어려운 작업, 사내 Qwen/AI Pro, 실제 POP3 수신, 위키 생성, Windows PowerShell 성적이나 제품 전체 100점으로 확대하지 않는다. 메일 원문 전송은 평가 fixture이며 Personal Wiki 조회 코드는 실제 제품이다.

## 평가 연결부 수정

80개 측정 준비 중 기존 평가 recorder/relay가 `toolChoice`, `responseFormat`, `maxTokens`를 생략하던 점을 확인했다. 제품과 같은 요청 계약을 전달하고, CLI 누적 사용량과 현재 문맥 사용량을 구분하는 `contextUsage`도 보존했다. 인증이나 임의 제공자 설정은 전달하지 않는다. 이에 따라 이전 평가와의 단순 속도/성공률 비교는 하지 않는다.

기존 `docs/HARNESS-METHODS-2026-10-12.md`의 전체 작업 흐름 평가, 고정 과제/독립 검사, 완료 선언과 실행 상태 구분 방법을 재사용했다. 새 에이전트 프레임워크나 외부 의존성을 도입하지 않았다. Pi 실행기와 기존 승인/복구 정책을 유지한다.

과제 목록: `eval/easy-80/README.md`. 정답 포함 명세: `eval/easy-80/cases.json`. 실행 결과: `verification/eval-live/easy80-opus55-medium-20261012/`.

## 교정 실행 보존

본 측정 전 각 영역 1개씩 실행한 기록은 `verification/eval-live/easy80-calibration-20261012/`에 보존한다. 스킬은 초기 호스트 카탈로그만으로 선택할 수 있으므로 추가 discover 호출을 필수로 강제하지 않는다. `/code`의 시스템 범위 메시지가 먼저 오는 경우도 주 Agent의 원문 조회로 인정한다. 이 두 채점기 오류는 제품 실패로 계산하지 않으며 원래 기계 채점과 수정된 근거 판정을 `calibration-review.json`에 나란히 기록했다. 교정 실행 네 건은 80개 본 평가 성적에 합산하지 않는다.

Bash 20개는 기존 읽기 전용 로컬 보고서 CLI의 목록 조회, 데이터 선택, 계산 실행, 출력 대조를 측정한다. 합계/최대값/누락/중복 등 20개 유형을 다루지만 자유로운 셸 스크립트 작성, 빌드 장애 복구나 임의 시스템 관리까지 검증하지 않는다.
