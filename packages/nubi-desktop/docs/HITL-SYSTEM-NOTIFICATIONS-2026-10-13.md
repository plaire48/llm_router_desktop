# 사용자 확인과 Windows 시스템 알림

사용자 결정: 질문과 승인 같은 HITL은 앱 내부 알림 모양으로 흉내 내지 않는다. Windows 11 시스템 알림으로 알리고 누르면 해당 대화의 확인 화면을 연다. 폼은 OpenAI/Codex의 질문, 선택 목록, 기타 입력, 전송 구조를 참고하되 누비의 공통 서체와 색상 토큰을 사용한다. 중첩 카드, 외곽선과 장식 아이콘을 제거한다.

## 적용

- `humanDecisions`가 전체 대화에서 질문, 파일 변경 검토, 명령 실행/수정 승인, 앱 연결/연결 후 계속, 앱 동작/미확정 결과 확인을 수집한다. 실행 중이거나 취소된 대화는 제외한다. 한 대화에서는 선행 확인 하나부터 알리고 해소되면 다음 확인을 알린다. 비활성 Computer Use/A2A 기능을 새로 켜지 않는다.
- Electron main의 `Notification`이 실제 OS 알림을 만든다. 설치 프로그램과 실행 앱의 AppUserModelID는 모두 `nubi.workspace`다. 사용자 후속 결정에 따라 프로젝트 이름과 요청 종류를 제목에, 대화 제목과 실제 질문 또는 승인할 작업을 본문에 표시한다. 프로젝트 40자, 대화 제목 55자, 질문/작업 160자로 제한하고 명령 스크립트와 파일 본문은 전달하지 않는다. 앱이 앞에 있어도 알리며 같은 대기 ID는 한 번만 표시한다.
- 시스템 알림 클릭은 창을 복원하고 해당 대화를 선택한다. 최신 상태를 다시 읽은 뒤 질문/명령 확인 폼, 파일 비교, 앱 확인 화면 중 해당 진입점을 연다. 알림 클릭만으로 답변, 반영, 명령 실행, 앱 연결이나 재시작을 수행하지 않는다.
- 이미 해결/취소된 요청은 알림을 닫고 오래된 클릭도 무시한다. Renderer 재시작/앱 종료 시 native 알림 참조를 정리한다. 작업 중 Electron은 창이 숨겨져도 기존 상태 조회를 이어가 새 확인 요청을 감지한다.
- 일반 질문은 여러 선택지와 기타 입력란 하나다. 선택으로 전송하지 않으며 `답변 보내기`로만 전송한다. 폼을 닫았다 다시 열면 선택과 텍스트가 남는다. 질문 ID 검증은 기존 런타임을 사용한다. 연결할 앱처럼 한 대상만 가능한 폼은 단일 선택을 사용한다. 선택과 자유 입력은 실행 승인을 대체하지 않는다.
- 공통 확장 `QuestionForm`과 `InteractionSurface`에 선택적 확인 전송/제목 생략을 추가했다. Desktop만 이 모드를 사용하며 기존 확장/Office의 기본 동작은 유지한다. 기본 글꼴, 크기, 색은 기존 CX/Nubi 토큰을 사용하고 선택은 체크와 옅은 배경으로 구분한다. 키보드 선택 초점은 남긴다.

## 방법과 검증 경계

Electron 공식 Notification API를 사용한다: https://www.electronjs.org/docs/latest/api/notification . 별도 Windows 토스트 패키지와 가짜 화면 오버레이를 도입하지 않는다. 시스템 알림 표시 위치와 알림 허용 여부는 Windows 설정을 따른다. 앱이 완전히 종료된 상태의 알림으로 콜드 스타트하는 기능은 포함하지 않는다.

- native 알림 3개 단위 검사: 전경/배경, 중복 방지, 클릭, 해소된 알림, 참조 정리. Electron Notification 대역을 사용하며 실제 Windows 표시 증거가 아니다.
- 확인 종류 3개 단위 검사: 전체 대화, 선행 확인 순서, 취소/실행 상태, Computer Use 비활성 유지, 연결/실행/결과 상태별 식별자.
- 브라우저 통합: 1280/440/360px 폼 경계, 체크박스 키보드 선택, 닫기/다시 열기, 초안, 빈 답변, IME, 기타만 답변, 실패 후 재전송. native 이벤트 대역으로 해당 대화 열기와 오래된 클릭 무효화를 검사한다.
- 실제 Windows 11 설치판에서 알림 표시, 방해 금지 설정, 최소화 복원은 아직 검증하지 않았다. macOS Electron과 대역 검사를 Windows 성공으로 표시하지 않는다.

최종 로컬 검사: 전체 단위 검사 989개 중 791 통과, 실패 0, 198 건너뜀. 디자인 토큰 검사와 Electron 빌드 통과. 실제 macOS Electron의 임시 프로젝트/검사 모델에서 10개 흐름(제안, 비교, 반영, 결과 검토, 오류 복구, 질문 응답 후 계속 등) 통과. 브라우저 폼 검사와 native 이벤트 대역 검사를 함께 통과했다. Windows 설치 파일은 이번 변경으로 다시 만들거나 배포하지 않았다.

추가 공통 UI 회귀도 완료했다. 이전의 자동 모달 열기 기대를 명시적 `확인하고 실행` 클릭으로 바꿨으며, 관리자 승인/거절, 파일 반영 후 계속, 문맥 정리, 대화/메일/대기열 화면의 기존 계약을 유지했다. Computer Use 관련 검사는 제품의 비활성 설정에 따라 건너뛰었다.
# 사용자 이미지 기준 질문 폼 후속 반영

2026-10-13 제공된 참고 이미지에 맞춰 질문을 작은 상단 표시, 본문 질문, 번호 선택 목록, 하단 직접 입력과 동작 한 줄로 구성했다. 최대 폭은 740px이며 작은 창에서는 화면 안에 맞춘다. 선택지 외곽 테두리는 없고 선택한 번호 자리만 체크로 바뀐다. 글자와 색은 기존 누비 토큰을 사용한다. 긴 선택 설명은 좁은 창에서 숨기되 전체 내용 툴팁과 접근성 이름을 보존한다.

여러 개 선택과 기타 답변은 명시적인 보내기로 제출한다. 나중에는 답변을 보내지 않고 닫으며 초안과 선택을 유지한다. 현재 Agent는 질문을 한 번에 하나씩 보내므로 임의의 1/2 표시나 동작하지 않는 앞/뒤 버튼을 만들지 않았다. 실제 시스템 알림 클릭은 같은 질문 폼을 연다.

Desktop 전용 compact 옵션으로 공유 QuestionForm을 재사용한다. 브라우저와 Office의 기본 폼은 변경하지 않았다. 1280/440/360px 실제 브라우저 렌더링에서 번호/선택, 직접 입력, 한글 IME, 실패 후 재전송, 나중에/재열기, OS 이벤트 클릭을 검사했다. Windows 알림 전달은 이번 Mac에서 실측하지 않았고 OS 이벤트 연결만 모의 검사했다. 공통 화면 36개, 관련 단위 7개, 평가기 회귀 11개가 통과했으며 디자인 검사와 Electron 빌드도 통과했다.

미리보기: `verification/decision-flow/question-empty-1280.png`, `question-empty-360.png`. 이 이미지는 시험 자료를 사용한 실제 렌더링이며 실계정 질문을 캡처한 것은 아니다.
