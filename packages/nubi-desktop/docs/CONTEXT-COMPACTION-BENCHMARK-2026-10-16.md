# 문맥 압축과 중간 정리 비교

2026-10-16. 공식 문서와 현재 소스를 비교한 설계 검토다. 새 제공자 API 연결이나 실모델 속도 개선을 완료했다는 의미가 아니다.

## 결론

누비에는 자동 압축이 이미 있다. 다음 개선은 압축 횟수를 늘리는 것이 아니라 **미리 준비한 요약 + 최근 원문 + 실제 실행 기록**으로 이어가는 것이다. 사용자 화면의 중간 정리는 별도 기능으로 두고, 작업 전환이나 중요한 발견이 있을 때만 결과와 다음 행동을 짧게 알린다.

## 공식 사례

| 사례 | 확인한 방법 | 누비 적용 판단 |
| --- | --- | --- |
| [OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction) | 임계치 기반 서버 압축과 명시적 `/responses/compact`. 암호화된 상태는 사람이 읽는 요약이 아니며 명시적 압축의 반환 문맥을 그대로 다음 요청에 전달한다. | 모델용 압축과 화면용 진행 설명을 분리한다. 현재 OpenCode/Claude CLI/AI Pro 연결에 Responses 전용 API를 그대로 붙이지 않는다. 제공자 지원 확인이 먼저다. |
| [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | 중요한 결정과 미해결 문제를 보존하고 반복 도구 출력을 줄인다. 구조화한 메모와 필요할 때 원문을 다시 읽는 방법을 함께 사용한다. | 요약을 근거 원본이나 실행 성공 증거로 사용하지 않는다. 원본 조회 도구와 실행 기록을 유지한다. |
| [Claude session memory cookbook](https://platform.claude.com/cookbook/misc-session-memory-compaction) | 사용자 정정을 우선 보존하고, 새로 늘어난 내용을 백그라운드에서 요약해 한도 도달 때의 대기를 줄이는 예제다. | 완료한 구간만 사전 요약하고 변경된 구간은 재검증한다. 이 예제를 현재 Claude Code 내부 구현 전체로 단정하지 않는다. |

## 현재 누비에서 확인한 것

- `context-policy.mjs`: 큰 문맥은 전체 한도의 75%에서 요약한다. 출력 예약과 작은 모델의 입력 한도를 별도로 보호한다. 수치는 추정 토큰 기준이다.
- `runtime/conversation-context.mjs`: 원본은 남기고 요약 경계 ID와 앞부분 해시가 맞을 때만 저장 요약을 재사용한다. 저장 직전에도 대화 변경을 검사한다. 보통 최근 두 턴을 유지하고 입력 공간이 부족하면 한 턴으로 줄인다.
- `extensions/aipro-chat/context-manager.js`: 목표, 제약, 결정, 완료, 남은 일, 출처, 실패와 현재 위치를 구조화한다. 사용자 요청 일부를 별도 원문으로 보존한다. 잘못된 요약은 한 번 형식 복구하며, 원문이 입력 한도에 들어갈 때는 압축 실패를 유예할 수 있다.
- `runtime/agent.mjs`: 최초 요청과 답변 중인 요청을 보호한다. 압축 뒤 오래된 읽기 결과를 무조건 현재 관찰로 인정하지 않는다. 큰 도구 결과는 조회 참조로 대체하는 복구 경로가 있다.
- `read_conversation`과 `read_process_output`: 대화 원문과 실행 로그를 범위 안에서 다시 조회할 수 있다.

## 제안하는 다음 구현 범위

1. **사전 요약 후보 저장**: 여유 구간에서 완료한 턴의 요약을 하나만 준비한다. 현재 질문, 승인 대기, 진행 중 명령은 제외한다. 작업/모델/경계 해시가 일치하는 후보만 전환한다. 취소는 재개하지 않는다.
2. **증분 갱신**: 이전 요약과 새로 완료한 구간만 입력한다. 매 도구 호출마다 요약하지 않는다. 요약이 실패해도 여유가 있으면 본 작업을 계속하고, 여유가 없으면 안전한 기존 압축 경로로 처리한다.
3. **화면의 중간 정리**: `확인한 핵심 → 다음 행동` 한두 문장. 매 호출마다 별도 카드로 쌓지 않는다. 터미널과 출처는 접힌 기록에서 확인하고 마지막 답변은 결과부터 정리한다. 비공개 추론을 노출하지 않는다.
4. **복구 기록**: 실제 완료/실패/미확정/승인 대기는 호스트 실행 기록에서 가져온다. 요약으로 승인이나 성공 상태를 만들지 않고, 결과가 불명확한 쓰기를 자동 재실행하지 않는다.

## 비교 평가 조건

기존과 후보를 같은 모델, 같은 기록, 같은 문제로 각 3회 비교한다. 사용자 요구 변경, 긴 터미널 출력, 여러 메일의 날짜/출처, 코드 위키의 수정 전후, 승인 대기 중 압축, 취소, 실행 응답 유실, 요약 생성 중 새 입력을 포함한다.

- 필수: 사용자 정정/미완료 작업 누락 0, 출처 및 숫자 왜곡 0, 승인 재사용 0, 미확정 쓰기 중복 실행 0.
- 측정: 압축 대기 시간 p50/p95, 다음 답변까지 시간, 추가 모델 호출/토큰, 원문 재조회 횟수, 최종 정답률.
- 비용이나 정확도가 악화되면 백그라운드 요약 빈도를 낮추거나 기존 방식으로 되돌린다. 사내 AI Pro의 동시 호출과 Windows 복구는 별도 실환경 검증이다.
