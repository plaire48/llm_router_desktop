# 진행 모달의 백그라운드 작업 큐

사용자는 진행 바가 있는 모달이 작업 화면을 계속 점유하지 않고 백그라운드에서 이어지도록 요청했다. 이어 목록은 전체 모달 대신 하단 아이콘 위의 작은 작업창으로 열고 2D 모션을 쓰도록 정정했다.

## 화면과 작업 소유권

- 기존 하단 상태 바의 44px 아이콘은 숫자 배지 없이 표시하며 누르면 최대 360px의 낮은 작업창이 열린다. 배경 막과 `aria-modal`, 전체 화면의 inert/초점 잠금은 없다. 바깥을 누르거나 Escape로 접는다. 창의 왼쪽은 아이콘의 왼쪽에 붙고 화면 크기/스크롤/내용 변화에서 위치를 보정한다.
- 공통 모션 토큰으로 translate/2D scale/opacity를 짧게 연결한다. 닫는 그림만 잠시 남고 포인터/키보드 입력은 즉시 풀린다. 모션 감소에서는 변형을 정지하고 강제 색상과 200% 글자 확대를 지원한다. 새 3D 재질이나 이동하는 무한 장식을 넣지 않는다.
- 기본 목록은 진행/확인 작업을 최대 3개까지 보여주고 초과분은 작은 이전/다음 버튼으로 넘긴다. 세로 스크롤 영역과 오른쪽 스크롤 바를 만들지 않는다. 완료/취소 이력은 작은 기록 아이콘을 눌러야 보인다. 사용자의 후속 요청대로 너비를 늘리고 각 작업의 아이콘/현재 상태, 공통 진행 바, %, 남은 시간을 한 줄로 표시한다. 모든 행의 상태/바/%/시간 시작선을 같은 열에 맞추고 글자를 작게 줄이거나 정보를 여러 줄로 빼지 않는다. 남은 시간은 ~1:20 형식으로 표시하고 전체 한국어 뜻은 접근성 이름과 툴팁에 보존한다. 남은 시간은 기존 처리량 추정기를 재사용하며 실제 증가분과 현재 단계로 계산한다. 첫 관찰/알 수 없는 분모에서는 계산 중, 100% 뒤 실제 결과 전에는 확인 중으로 표시한다. 팝업을 접어도 관찰 기준을 유지하며 단계 변경/처리량 감소/분모 변경에는 속도를 다시 측정한다. 정체된 작업을 시간으로 완료시키거나 0초로 세지 않는다. 제목/큰 버튼/설명 영역은 두지 않는다. 경과 시간과 주의 사항은 행의 툴팁에서 확인하며 상태 행을 누르면 원래 폼으로 돌아간다. 실제 분모가 없는 진행률은 숫자를 만들지 않고 —로 표시한다. 중지 API가 있는 작업만 중지할 수 있고 실패/중단/입력 대기를 완료로 표시하지 않는다. 실행을 다시 보내는 재시도 버튼은 큐에 두지 않는다.
- 큐는 기존 실행기의 작업을 표시한다. 새 모델 실행기나 별도 쓰기 스케줄러, 새 승인 흐름을 만들지 않는다. 실제 직렬화/실행 잠금/취소/승인/영수증은 기존 호스트가 소유한다. 앱을 종료한 뒤 계속 실행하는 서비스라고 표시하지 않는다.

## 공통 적용

Desktop의 기존 `desktopIconsPlugin`은 고정 CX 0.5.4 원본 소스를 사용한다. 그 진입점에서 `DetailPanel`에 작은 수명 어댑터를 합성한다. 원본 패키지 파일을 수정하거나 자식 폼을 unmount하지 않고, 숨길 때 CX 자신의 focus/inert effect를 정리하고 다시 열 때 같은 계약을 복구한다. 상위 모달도 함께 접고 해당 작업을 다시 열면 그 폼 한 개를 활성화한다. 다시 연 폼을 직접 닫으면 기존 상위 설정으로 돌아가고 자동 완료 때는 상위 설정을 재개방하지 않는다. 원본 구조가 바뀌면 빌드를 실패시킨다.

공통 `TaskProgressBar`는 실제 모달 안에서만 작업을 연결하고 첫 진행 때 그 모달을 접는다. 큐 안의 복제 바는 수집하지 않는다. 문맥 사용량 막대와 앱 최초/재실행/프로젝트 전환의 보호 화면은 작업 모달이 아니므로 기존 표현을 유지한다. 숨긴 모달은 시각 쌓임, 모션 presence와 view transition의 활성 모달로 계산하지 않는다.

| 범위 | 완료와 대기의 근거 |
| --- | --- |
| 메일 저장 위치 변경 | 기존 API의 실제 응답/실패, 파일/바이트 진행 조회 |
| 승인한 메일 초기화와 위키 다시 만들기 | 기존 명시적 확인 뒤 API 결과. 삭제 범위와 보존 조건 유지 |
| 포털 로그인 확인 | 기존 세션 조회/브라우저 로그인 요청. 직접 로그인 대기와 취소 구분 |
| 메일 파일 가져오기 | 기존 하단 메일 상태 조회의 localImport. 닫아도 조회 지속 |
| 프로젝트 위키 준비 | 기존 App의 위키 작업 상태. 부분 완료/중단/연결 대기 구분 |
| 공유 위키 폴더 확인과 업로드 | 폴더 확인 뒤 문서 선택 대기. 명시한 공유 요청 뒤 실제 저장 결과 |
| 업데이트 다운로드 | 기존 다운로드/검증 상태. 화면을 떠나면 읽기 전용 조회로 이어 추적. 설치/재시작은 기존 보호 조건 유지 |
| 이후 추가되는 공통 진행 모달 | 동일 자동 접기. 연결한 결과 계약이 없다면 표시 종료는 결과 확인 대기이며 완료로 추정하지 않음 |

실행 중 모달을 접거나 다시 여는 것은 새 API 요청이 아니다. 일반 작업 promise는 폼을 떠나도 큐에 결과를 기록한다. 업로드 중 폼 해제로 취소 요청을 발행하지 않으며, 실제 선택/초안은 마운트된 동안 유지한다. 실행 중 화면 자체가 해제돼 결과 소유권이 없는 경우에는 중단/확인 상태로 남긴다. 늦은 진행 응답으로 종료 작업을 되살리지 않으며 다른 작업의 취소 콜백을 재사용하지 않는다.

큐에는 정해진 이름/상태/수치/시간/주의 문구만 보관한다. 원문/명령/URL/인증값과 API 응답 전체는 보관하지 않는다. 완료 이력은 세션 메모리의 최근 30개이며 진행/확인 대기 작업을 자동 삭제하지 않는다.

로컬 Chrome의 실제 제품 컴포넌트와 합성 지연 서비스, 빌드한 macOS Electron의 제품 진입점과 지연 IPC를 구분해 기록한다. 실제 회사 계정, 메일 위치 이동/위키 원격 저장/업데이트 설치와 Windows GPU/설치판은 이 UI 검사로 통과시키지 않는다. 전체 `test:gates` 통과나 설치판 배포를 주장하지 않는다.
