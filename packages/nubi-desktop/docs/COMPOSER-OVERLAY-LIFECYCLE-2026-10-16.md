# 입력창 메뉴와 모달 수명 관리

사용자가 요청한 벤치마킹 대상은 `/` 명령의 종류가 아니라 창의 열기, 닫기, 전환과 복귀다. 기존 CX의 포커스와 승인 경계를 재사용하면서 Desktop의 공통 `useModalDismissalPolicy`와 `modalStack`에서 입력창 메뉴의 관계를 관리한다.

후속 화면 정지 조사에서 선택 메뉴의 자체 입력 잠금과 CX 모달 잠금 사이의 충돌을 재현했다. 선택 메뉴도 `AnchoredDialog`를 통해 같은 CX 스택을 사용하도록 통합했다. 원인, 재현과 검증 범위는 [입력 잠금 수정](UI-INPUT-LOCK-RECOVERY-2026-10-16.md)을 따른다.

## 참고한 Codex 방식

- [공식 앱 slash 문서](https://learn.chatgpt.com/docs/reference/slash-commands): 입력창에서 `/`로 목록을 열고 입력에 따라 검색한다. 활성 스킬도 목록에 포함한다.
- [공개 CLI ChatComposer](https://github.com/openai/codex/blob/main/codex-rs/tui/src/bottom_pane/chat_composer.rs): 활성 팝업에 입력을 먼저 전달한 뒤 버퍼와 커서에 맞춰 동기화한다. Escape로 닫은 명령 토큰은 그대로인 동안 숨기고, 수정하면 다시 열 수 있다. 가려진 제안은 초안을 잃지 않는다.
- [공개 CLI BottomPane](https://github.com/openai/codex/blob/main/codex-rs/tui/src/bottom_pane/mod.rs): 별도의 view stack과 가장 위 view를 사용하고, 완료와 취소에 따라 되돌아갈 단계를 관리한다.

이는 공식 문서와 공개 CLI 코드의 구조 참고다. Desktop 앱의 비공개 모달 구현을 확인한 결과가 아니다. 로컬 앱 화면 접근은 컴퓨터 사용 도구에서 제한되어 실제 Codex Desktop의 클릭 지연, 애니메이션이나 화면 일치도를 측정하지 않았다. 누비는 터미널 UI 구현을 옮기지 않고 기존 React/CX 수명 주기에 원칙을 적용한다.

## 적용 규칙

| 입력 | 동작 |
| --- | --- |
| `/` 입력 | 입력창에 초점을 유지한 채 고정 위치의 제안 목록을 연다. |
| 방향키, Enter, Tab | 현재 목록이 먼저 처리한다. 선택 동작이 요청 전송으로 중복 전달되지 않는다. IME 조합은 가로채지 않는다. |
| Escape | 현재 목록을 닫는다. 초안을 지우거나 요청을 보내지 않는다. 수정하거나 새 `/`를 입력하면 다시 연다. |
| `+`, 모델, 추론, 승인 방식, 컨텍스트 열기 | 제안 목록을 닫고 선택한 창을 표시한다. 같은 입력창의 보이는 다른 버튼은 이전 창을 닫은 다음 한 번만 연다. |
| 같은 버튼 다시 클릭 | 기존 닫기 동작을 거쳐 닫고 버튼으로 초점을 복귀한다. |
| `/model` 등 명령으로 열기 | 사라진 목록 행 대신 지속되는 입력창 버튼에 창의 소유 관계를 연결한다. 아이콘 클릭으로 연 경우와 같은 전환 규칙을 쓴다. |
| 실제 모달에 가려진 버튼 | 클릭 대상으로 취급하지 않는다. 창을 먼저 닫은 뒤 접근한다. |
| 모달 닫기 | 기존 CX의 Escape, 초점 가두기, 배경 inert와 복귀 처리를 사용한다. 처리 중 닫기 제한을 우회하지 않는다. |
| 바깥 클릭 | 기존 사용자의 모달 바깥 클릭 닫기 금지 결정을 유지한다. 배경 버튼을 같이 실행하지 않는다. |

`useModalDismissalPolicy`가 안정적인 입력창 버튼과 창을 연결한다. 전환은 실제 닫기 버튼의 가드를 통과하고 이전 창의 DOM 제거와 배경 잠금 해제를 확인한 다음 진행한다. 아직 다른 모달이 활성 상태면 새 메뉴를 열지 않는다. 해제 시 예약된 전환 프레임도 취소한다. 화면 이동 중 남은 콜백이 사라진 버튼을 실행하지 않는다.

제안 목록은 단일 스크롤 영역을 사용하고 현재 입력창과 뷰포트에 맞춰 위치와 높이를 계산한다. 화면 위아래 공간에 따라 배치하며 빈 결과에는 불필요한 스크롤이 생기지 않는다.

선택 결과는 목록에서 사용한 아이콘과 이름 하나만 표시한다. 다른 명령이나 스킬을 고르면 교체한다. X는 두지 않고 두 번 클릭하면 해제한다. 키보드는 선택 표시에서 Enter, Space, Delete, Backspace로, 본문 맨 앞에서는 Backspace로 해제할 수 있다. 기존 요청 직렬화와 backend 명령/승인 범위는 보존한다.

## 검증과 한계

`check-interaction-controls.mjs`는 실제 Workbench 구성 요소를 합성 데이터로 렌더링해 1280px, 440px, 360px에서 재입력, 교체, 두 번 클릭 해제, 열린 창 간 전환과 초점 복귀를 확인한다. `/model`로 연 창의 전환도 검사한다. 작은 화면에서 버튼이 창에 가려진 경우에는 Escape 뒤 다시 여는 경로를 사용한다.

최초 `/model` 전환 검사는 모달에 가려진 `+` 위치를 클릭한 잘못된 검사였다. 이후 컨텍스트 버튼이 실제 보이는 경우만 직접 전환하고, 가려진 경우 닫기 후 접근하도록 수정했다. 뒤의 한 실패는 화면 제목을 `컨텍스트`로 가정한 검사 오류이며 실제 제목인 `컨텍스트 사용량`으로 정정했다. 이 두 결과를 제품 전환 실패의 근거로 쓰지 않는다.

`check-workflow-ui.mjs`는 전체 명령/스킬 목록과 키보드 스크롤, `check-shared-ui.mjs`는 자동 실행 안내의 취소/확인/넓은 창/좁은 창/글자 확대를 확인한다. 네이티브 Electron 스킬 검사는 독립 시험 프로젝트와 로컬 모의 모델을 사용한다. 이 근거는 실제 Windows 설치판, 사용자 계정이나 회사 서비스 실행 성공을 뜻하지 않는다.

최종 소스에서 명령 범위/스킬/입력 상태/모션 검사 12개, 공통 UI 38항목, 모달 회귀 40항목, 네이티브 Electron 스킬 흐름 11항목이 통과했다. 입력창 전환 검사는 1280/440/360px, 명령/스킬 목록 검사는 1000/440/360px에서 통과했다. `design:check`와 Electron 빌드도 통과했다. 이번 macOS 빌드의 Office reader gate는 PowerShell 미설치로 건너뛰었으며 Windows Office 검증으로 세지 않는다.

전체 회귀는 마지막 공통 관리기 보완 전 상태에서 1,705개 중 1,509개 통과, 196개 건너뜀, 실패 0개였다. 마지막 보완 뒤에는 위의 관련 검사들을 실행했다. 로그와 소스 해시는 `verification/composer-pickers-2026-10-16/`에 보관한다.
