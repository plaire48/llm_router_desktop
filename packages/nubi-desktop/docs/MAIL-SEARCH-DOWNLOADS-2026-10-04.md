# 메일 검색과 다운로드

2026-10-04 사용자 요청에 따라 검색 화면을 실제 메일 검색 백엔드에 연결했다. 검색 조건은 필요한 때만 펼치며 `검색 → 메일 선택 → 본문/첨부 확인` 흐름을 유지한다.

## 화면

- 공통 CX SearchField의 돋보기를 항상 검색어 앞에 둔다. 제목, 보낸 사람, 본문, 읽은 첨부, 정리한 개인 위키를 한 검색창에서 찾는다.
- 결과는 메일당 한 항목이다. 보낸 사람과 메일 날짜, 제목, 검색어 주변 두 줄, 찾은 위치를 표시한다. 빈 검색은 본문 미리보기를 보여주며 제목/보낸 사람을 중복하지 않는다.
- 기간, 보낸 사람, 첨부 여부/형식은 ‘검색 조건’에서 펼친다. 적용한 조건은 작은 칩과 같은 X 버튼으로 해제한다. 잘못된 날짜 범위는 요청하지 않는다.
- 검색어가 있으면 관련도순, 없으면 최신순이다. 정렬과 10/20/50/100개씩 보기, 이전/다음과 페이지 번호 직접 이동은 실제 커서 검색 계약에 연결한다. 원문/조건이 바뀌어 커서가 무효화되면 첫 페이지로 돌아간다. 최신 동작과 검증 범위는 [메일 페이지와 스크롤](MAIL-PAGINATION-2026-10-04.md)을 따른다.
- 메일 선택 후 본문과 첨부에 실제 검색어만 옅은 파랑으로 강조한다. 첨부 결과는 추출해 확인한 페이지/슬라이드/시트가 있는 경우 해당 구간을 오른쪽 문서에서 먼저 연다. 페이지 번호를 추정하지 않는다.
- 읽지 못한 첨부는 파일명만 검색한다. 긴 본문 또는 원문을 읽을 수 없는 경우의 검색 범위는 보조 정보로 접는다. 메일 날짜가 없으면 ‘날짜 미확인’이며 수집 시각을 발신 시각으로 표시하지 않는다. 날짜 형식은 OS 로케일을 따른다.
- 넓은 화면은 목록/원문을 나란히 둔다. 좁은 화면은 목록 위, 원문 아래로 바뀐다. 목록과 원문 스크롤, 페이지 버튼을 유지하며 새 테두리나 왼쪽 강조선을 추가하지 않는다.

## 이전 화면에서 바꾼 점

| 이전 | 현재 | 이유 |
|---|---|---|
| 최근 100개 이력과 상위 5개 지식 구간을 별도 표시 | 같은 검색 결과와 실제 총수/페이지 | 과거 메일과 본문/첨부를 한 흐름에서 찾기 |
| 본문 검색 범위가 정리한 위키로 표현됨 | 수집 원문/추출 첨부/개인 위키 백엔드에 직접 연결 | 화면 설명과 검색 대상 일치 |
| 같은 메일의 여러 구간이 별도 결과 | 메일별 한 결과와 찾은 위치 | 중복을 줄이고 목록을 빠르게 훑기 |
| 첨부 클릭은 미리보기만 제공 | 같은 다운로드 아이콘으로 원래 첨부 저장 | 미리보기 지원과 원본 확보를 분리 |
| 선택/조건을 추가 화면으로 이동 | 조건을 접고 칩으로 표시 | 기억해야 할 조건과 화면 전환 줄이기 |

## 다운로드

본문 제목 옆에 TXT 다운로드, 첨부 이름 옆과 오른쪽 문서에 원래 첨부 다운로드를 둔다. 원본 EML은 ‘원본 메일’ 보조 메뉴에 둔다. 모든 다운로드는 공통 다운로드 아이콘, 접근성 이름, 툴팁과 2초 CX 토스트를 재사용한다. 미리보기 실패/암호화 문서여도 수집한 bytes를 저장할 수 있다.

`downloadMail`은 호스트가 현재 원문/첨부 해시를 재확인한 후 OS 저장 창을 연다. 원래 첨부와 EML은 변환하지 않는다. TXT는 원본 EML을 다시 파싱해 화면의 잘린 본문 대신 전체 파싱된 텍스트를 UTF-8 BOM/CRLF로 저장한다. 파일명은 경로와 Windows 금지 문자를 제거하고 예약 이름을 처리한다. IPC packet의 크기/해시와 실제 저장 파일의 SHA-256을 대조한 뒤 성공을 표시한다. 취소는 성공 토스트를 내지 않는다. renderer는 bytes나 선택한 절대 경로를 받지 않는다.

로그인/POP3 정책, 자동 정리, 원본 보존 위치와 개인 메일 격리는 변경하지 않았다. 다운로드는 사용자 UI 동작이며 Agent의 도구 권한이나 실행 승인이 아니다.

## 공식 사례와 적용 판단

- [Google Gmail 검색](https://support.google.com/mail/answer/7190?hl=ko): 보낸 사람, 기간, 첨부/파일 형식처럼 익숙한 조건을 채택했다. Gmail 검색 문법 전체를 사용자에게 요구하지 않는다.
- [Google 첨부 다운로드](https://support.google.com/mail/answer/30719?hl=en): 메일 열기 후 첨부 옆에서 다운로드하는 위치를 채택했다.
- [Google 원본 메일 다운로드](https://support.google.com/mail/answer/9261412?hl=en): EML을 보조 다운로드로 제공한다. 원래 메일 bytes를 유지한다.
- [OpenAI Retrieval](https://developers.openai.com/api/docs/guides/retrieval): 검색 전 메타데이터 필터링 원칙을 기존 MailSearch에 유지하고 UI를 연결했다. 상위 5개에 필터를 사후 적용하지 않는다.
- [Anthropic search results](https://platform.claude.com/docs/en/build-with-claude/search-results): 안정적인 원문 식별자, 제목, 실제 근거 구간과 위치를 유지하는 설계를 참고했다. 새 Anthropic 연결이나 원격 업로드를 도입하지 않았다.

기존 MiniSearch(MIT), MailParser(MIT), CX 컴포넌트를 재사용한다. 설치된 각 패키지의 LICENSE를 확인했다. 검색 엔진/메일 UI 프레임워크를 추가하지 않았으며 현재 작업에 새 의존성이나 원격 저장소 비용이 필요하지 않다. `cognitive-accessibility:simplify`의 인지 부담 점검, 쉬운 문장, 핵심 동작 우선 원칙으로 기본 화면의 조건/부가 설명을 접었다.

## 확인 범위

- Electron 빌드만 수행한다. 사용자 요청대로 자동 테스트/전체 검사를 실행하지 않는다.
- `?conversation&mail-search` 미리보기는 28개 합성 메일과 PDF/암호화 첨부 예시로 목록, 필터, 강조, 페이지 UI를 확인하기 위한 화면이다. 실제 계정이나 파일을 읽지 않는다.
- 미리보기 다운로드는 실제 저장 대신 ‘화면 미리보기’ 토스트를 표시한다. 이것은 OS 저장/실메일 원본 다운로드 검증이 아니다.
- 실행 중인 실제 로그인 앱은 재시작하지 않는다. 새 네이티브 다운로드 경로는 다음 앱 실행에 적용된다. 실제 Gmail/회사 POP3, Windows 설치판, OS 저장 성공은 별도 확인이 필요하다.
- Electron 빌드 성공(exit 0). 예시 화면에서 다음 페이지(21–28 / 28), 기간/보낸 사람 조건(4개), PDF 조건 칩, 첨부 내용 검색 → 3쪽 문서 연결과 검색어 강조, 다운로드의 미리보기 안내를 수동으로 확인했다. 좁은 창과 넓은 창의 단일 열/목록-원문 배치를 확인했다. 실제 저장 성공을 뜻하지 않는다.
