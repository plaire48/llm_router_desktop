# Agent 실행과 두괄식 답변 개선

사용자 요청: 쉬운 80개 평가에서 드러난 누락, 반복 호출, 긴 답변을 개선한다. 답변은 요청한 결과부터 보여 준다.

## 반영

- 승인할 명령이 준비되면 기존 Pi `requiresUserInput` 대기 경로로 즉시 멈춘다. 승인 카드의 정확한 명령, 영향, 적용 선행 조건은 유지한다. 승인 전에 답변 생성과 최종 검토를 반복하지 않으며 완료를 선언하지 않는다. 거절/미확정 기록은 이 대기 최적화의 대상이 아니다.
- 성공한 승인 명령의 후속 실행은 기존 계획을 재사용한다. 원래 요청과 추가 사용자 발화, 조건, 답변, 프로젝트 경로, 루트 규칙, 검색 범위, 선택 메일, 스킬 해시를 호스트가 묶는다. 실제 명령 및 승인 기록이 맞고 조건이 동일할 때만 계획을 이어간다. 계획은 잠정 해석이며 완료 표시는 다시 검토한다. 소스 관찰/스킬 본문/수정 권한/실행 승인은 재사용하지 않는다. 실패나 변경이 있으면 기존 재계획 경로를 따른다.
- 독립된 메일 검색과 원문 읽기를 같은 모델 턴에서 여러 개 요청할 수 있다. 원문 해시, 선택 범위, 개별 출처는 각각 검증한다.
- 메일의 모든 검색어가 한 메일에 있어야 함을 결과 안내에서도 명시한다. 빠진 요구 정보가 있으면 같은 필터와 주제에서 단어를 줄여 재검색하도록 한다. 호스트가 필터나 선택 범위를 자동으로 넓히지 않는다.
- Wiki의 단순 사실은 검색/현재 페이지에서 답하고, 종합/이유 분석/누락은 OpenWiki 위임을 선택한다. 경로 선택은 모델이 하며 도구를 금지하지 않는다. 기존 위임 예산과 근거 대조를 유지한다.
- 답변은 요청한 값, 결론, 결과물부터 쓴다. 핵심만 선택적으로 강조하고 근거를 가까이 인용한다. UI의 출처 목록과 중복되는 목록, 스킬 이름 안내, 도구 사용 소감, 묻지 않은 필드는 생략한다. 실제 불확실성, 미완료, 승인 범위는 남긴다. 응답을 잘라내거나 검증을 생략하는 방식은 사용하지 않는다.

## 방법론과 선택

`HARNESS-METHODS-2026-10-12.md`와 `TASK-DECISIONS-CONTINUATION-2026-10-12.md`의 조사 결과를 재사용했다. 작은 충분한 실행 경로, 실제 결과에 따른 후속 행동, 전체 워크플로 평가를 기존 Pi/ProjectService에 적용한다. 새 프레임워크/의존성이나 모델별 별도 실행기를 추가하지 않는다. 승인 전 최종 답변을 검토하던 호출은 줄이되 최종 결과의 독립 검토는 유지한다.

## 평가판

기존 `cases.json`과 최초 결과는 보존한다. `cases-v2.json`은 Bash 09의 초→분 단위, skill 06의 배포 안내문, skill 10의 고객 답변 초안을 명시한다. 나머지 77개의 질문은 동일하다. Wiki 직접 읽기/검색/위임 경로는 별도 진단값으로 기록하며, 실제 두 문서 내용과 인용 검사는 유지한다. 경로만 다르다고 사실 정답을 실패로 보거나 읽지 않은 자료를 통과시키지 않는다. v2 점수를 v1의 엄밀한 동일 문제 전후 점수로 표현하지 않는다.

실제 모델 80개 1회 평가가 끝났다. 실제 모델/합성 자료, 브라우저 모달, macOS Bash, Windows 설치판과 회사 메일은 별개 범위다.


## 실제 모델 재평가 (v2, 1회)

실행 모델은 연결된 Claude Code `claude-opus-5-5`, 추론 medium, 실제 카탈로그의 1,000,000 문맥이다. 합성 자료로 제품 Agent와 macOS Bash를 실행했다. 동시성은 4다. 후보 `dc65df78ad1df800e2860adfb55fd277ad94c2938ff5d9249fc17b5c9ce45ee9` (470개 파일)는 평가 중 변하지 않았다. 이후 변경은 HITL UI/시스템 알림이며 모델 평가에 사용한 런타임은 유지했다.

79/80은 이 고정 평가판의 1회 결과다. 반복 신뢰도나 전체 제품 정확도가 아니다. 첫 평가와 질문 3개 및 Wiki 경로 채점이 달라졌으므로 엄밀히 동일한 80문제의 전후 정확도 개선으로 제시하지 않는다. 모델 응답 수신과 정답/근거/실행 영수증 조건을 구분한다.

남은 `skill-05`: 입력은 검색 성능 변경, 단위 검사 통과, Windows 미검사이고 원하는 산출물은 명시하지 않았다. 기대 스킬은 release-notes이지만 모델은 handoff-note를 선택했다. 세 사실 자체는 유지했으나 기대 스킬/형식 채점은 실패이며 그대로 남겼다. 이 결과를 전체 사실 오류나 허위 실행 완료로 확대 해석하지 않는다. 요청의 산출물 모호성과 후보 선택 문제를 분리해 후속 반복 평가해야 한다. 실패를 통과로 바꾸거나 분모에서 빼지 않았다.

답변 길이 중앙값은 Bash 439.5, 메일 812, 스킬 277.5, Wiki 590.5자다. 기존 기록의 646/944.5/409.5/878자보다 짧지만 일부 메일/Wiki 답변에는 출처 목록과 필요 이상의 확인 범위 설명이 남아 있다. 두괄식 지시는 적용했으나 간결성까지 완성됐다고 보지 않는다. 3회 반복은 이번 기록에 없다.

원본: `verification/eval-live/easy80-v2-trial1-20261013/report.json`, 문제별 transcript와 operations. Windows PowerShell, 회사 메일/SSO, 실제 Windows 시스템 알림/설치판은 별도 검증 대상이다.
