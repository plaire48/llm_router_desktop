# MCP 서버 연결 (2026-10-14)

사용자 결정: stdio와 HTTP 두 방식 모두 지원한다.

## 구성

| 부분 | 파일 | 역할 |
| --- | --- | --- |
| 레지스트리 | `runtime/mcp.mjs` `McpRegistry` | 서버 목록(`<저장소>/mcp-servers.json`), 연결, 도구 목록, 호출, 결과 정리. 저장소 루트마다 하나를 모든 프로젝트 서비스가 공유한다 |
| 비밀값 | 연결 보관소 `mcp:<서버 id>` (`safeStorage`) | 환경 변수 값과 HTTP 헤더 값. 파일에는 이름만 남는다 |
| 에이전트 | `runtime/agent.mjs` | 연결된 서버의 도구를 `mcp__<서버>__<도구>`로 제공. 처음 요청 때 `enabled` 서버에 자동 연결 |
| 승인 | `runtime/approval-policy.mjs` `allowedMcpTools` | 읽기 전용(`readOnlyHint`) 도구는 바로 실행. 그 밖의 도구는 질문(실행 / 항상 허용 / 취소)으로 묻고, 답은 대화·토스트·Windows 알림 어디서든 할 수 있다. '항상 허용'은 서버+도구 단위로 기억 |
| 화면 | `ui/McpPanel.jsx` (설정 → MCP 서버) | 목록(상태, 도구 수, 도구 이름과 읽기/쓰기 표시), 추가·편집 폼(stdio: 명령·인자·작업 폴더·환경 변수 이름, http: 주소·헤더 이름, 비밀값은 비밀번호 칸), 연결·끊기·삭제 |

## 흐름

1. 설정 → MCP 서버 → 추가. stdio는 `명령`과 `인자`(예: `npx -y @scope/server`), http는 `https://…/mcp`. 비밀값이 필요하면 이름을 적고 값을 넣는다.
2. 연결하면 도구 목록이 보인다. 앱을 다시 켜면 `자동 연결`이 켜진 서버는 첫 대화 때 연결된다.
3. 모델이 도구를 부르면 읽기 전용은 바로 실행된다. 쓰기 도구는 "MCP 도구 x/y을(를) 실행할까요? 인자: …" 질문이 뜬다. '실행'은 그 호출(같은 인자)만, '항상 허용'은 이후 묻지 않는다.
4. 결과는 텍스트 24,000자까지 모델에 전달되고, 이미지·리소스는 종류만 적는다.

## 한계

- 회사 PC에는 Python이 없다. stdio 서버는 Node 실행 파일(`node`, `npx`) 또는 실행 파일만 가능하다.
- HTTP는 Streamable HTTP만(SSE 전용 서버는 미지원). 인증은 헤더 값으로만.
- 서버 16개, 서버당 도구 64개, 호출 60초, 연결 20초 상한.
- 실제 사내 서버 연결은 회사 PC에서 확인한다. 검사는 `tests/mcp-fixture-server.mjs`(stdio·HTTP 모두)로 돈다.
