# 누비 Workspace 품질 재점검 — 2026-10-04

요청한 화면과 실제 연결을 함께 비교했다. 이번 수정은 메일 근거 연결, 큐 편집 보존, 비동기 응답의 대상 확인, 반영 파일 요약, 공통 알림에 집중한다. 자동 테스트는 사용자의 Electron 빌드만 수행 결정을 따라 실행하지 않았다. 화면 확인에는 실제 계정에 접속하지 않는 별도 미리보기를 사용했다.

후속 모달, 가독성, compact와 브라우저 공통 컴포넌트 개선은 [화면 품질 개선](UI-CX-QUALITY-2026-10-04.md)에 기록했다. 소스 계약, 예시 화면 동작과 실계정 성공을 구분한다.

## 다시 확인한 기존 계약

아래는 현재 소스를 따라 확인한 구현 상태다. 이 목록은 실제 서버 또는 실모델 성공 결과가 아니다.

- **위키 시작:** 모델 연결 후 중앙 폴더/Git URL 카드로 시작한다. 명시적으로 선택한 프로젝트에서만 초기화를 시작하며 실제 처리 수와 경과 시간을 사용한다.
- **계획과 질문:** 브라우저 확장의 Pi, TaskPlan, AgentTrace, QuestionForm을 재사용한다. 실행 ID로 과거 기록과 현재 질문을 묶고 실제 도구 결과와 승인/복구 상태를 구분한다. 모델의 선언만으로 완료를 표시하지 않는다.
- **출처와 명령:** `/wiki`, `/mail`, `/skills`, `/model`, `/usage` 등의 기존 명령과 호스트가 등록한 출처만 사용한다. 파일, 메일 원문, 첨부의 실제 위치를 열고 오래된 해시는 거부한다. 문서 내용을 실행 권한으로 취급하지 않는다.
- **스킬:** AI Workspace와 커스텀 관리, 단일 등록 진입, 폴더/ZIP/Markdown 등록, 편집, 휴지통과 복구 흐름을 유지한다. 회사 SSO와 네트워크/권한 문제를 같은 성공 상태로 표시하지 않는다.
- **컨텍스트:** 모델 목록의 실제 최대 한도를 사용해 75% 요약 기준을 계산한다. 응답 사용량과 추정을 구분하고 다른 모델의 사용량을 섞지 않는다.
- **추론:** AI Pro는 Low/Medium에 `reasoning_effort`를 보내고 Extra high에는 해당 필드를 생략한다. FabriX는 추론 옵션을 노출하거나 전달하지 않는다. ChatGPT는 해당 모델의 지원 목록과 기존 어댑터 매핑을 따른다.
- **메일:** 수집은 화면과 독립된 호스트 작업이다. 자동 정리 OFF는 수집/첨부 읽기/원본 저장/새 모델 호출을 멈춘다. ON/재로그인 시 서버에 남은 UIDL 기반 미수신 항목을 가져온다. 서버 LOGIN-DELAY를 지킨다. 비밀번호와 모델 인증은 메모리에만 둔다.
- **메일 검색:** 조건을 적용한 원문/첨부 검색, 메일별 결과 묶음, 실제 찾은 위치, 페이지 이동과 보기 개수, 본문/첨부 다운로드를 유지한다. 암호화 또는 읽지 못한 문서를 검색 완료로 표시하지 않는다.
- **파일과 터미널:** React Arborist 탐색과 Monaco 파일 탭, 별도 터미널 탭을 유지한다. Windows PowerShell은 UTF-16LE 명령 전달과 UTF-8 입출력을 사용하며 OS 실행 정책/인증서 신뢰를 바꾸지 않는다.
- **Beta:** Desktop A2A와 Computer Use는 비활성이다. 오른쪽 보조 영역은 기존 레이아웃/최소 채팅 너비 계약을 사용한다.

## 반영 파일 수의 의미

`반영한 파일`은 해당 대화의 `applied` 저장 기록만 포함한다. 전체 Git 변경, 다른 대화의 파일, 아직 승인하지 않은 제안과 섞지 않는다. 현재 파일과 마지막 반영 해시가 다르면 줄 수를 표시하지 않는다. 연속된 기록만 확인한 경우 `최근 반영`으로 표시하고 전체 합계는 숨긴다. 큰 차이는 기존 bounded diff 제한 안에서 계산하며 제한에 걸리면 값을 추정하지 않는다. 파일의 원래 내용이 저장된 snapshot의 범위와 해시도 확인한다.

목록은 기존 스킬 팝업의 화면 경계 배치 패턴을 재사용해 스크롤 영역에 잘리지 않도록 한다. 메일 근거 검증은 입력 데이터가 어떤 필드를 포함하든 읽기 전용 `evidence` 동작으로 고정한다. 요청 ID에 다른 근거를 덮어쓰면 입력 형식 오류 대신 해당 대기 메시지가 바뀌었다고 안내한다.

### 변경 목록과 파일 탐색기 연결

변경 요약의 추가/삭제 합계는 처음부터 읽고 목록을 열 때 현재 파일을 다시 확인한다. 파일을 선택하면 개별 편집 탭을 열면서 탐색기의 상위 폴더를 펼치고 선택된 파일까지 스크롤한다. 기존 검색 필터를 지우고 필요하면 프로젝트 루트로 돌아가며 부모 폴더 목록을 다시 읽어 새 파일도 표시한다. 좁은 영역에서 편집 탭을 열 때 탐색기를 자동으로 접던 동작은 이 진입에서는 적용하지 않는다.

별도 worktree에서 진행한 대화는 편집기와 탐색기가 모두 같은 `taskId`의 실제 작업 폴더를 사용한다. 다른 프로젝트나 대화로 이동한 뒤 도착한 이전 열기 응답은 새 화면을 덮어쓰지 않는다. 기존 React Arborist의 `open`/`scrollTo` API와 Monaco를 재사용하며 새 라이브러리를 도입하지 않았다. 설치된 3.16.0 소스와 API 문서로 동작을 확인했다.

Electron 빌드를 완료하고 예시 미리보기에서 `2개 파일 변경됨 +11 −1` → 파일별 목록 → `src/welcome.js` 편집 탭과 `src` 폴더 펼침/선택 음영을 확인했다. 다른 폴더와 일치하지 않는 필터가 남은 상태에서 다시 선택해도 루트 복귀/필터 해제/파일 선택을 확인했다. 실제 별도 worktree의 데이터와 Windows 설치판은 이번 화면 확인에 사용하지 않았다. [변경 목록](evidence/applied-files-list-2026-10-04.png)과 [파일 연결](evidence/applied-file-reveal-2026-10-04.png)은 예시 데이터의 화면 기록이다.

## 방법론과 오픈소스 선택

[OpenAI Agent evals](https://developers.openai.com/api/docs/guides/agent-evals)의 실제 실행 경로 검토와 [Anthropic 에이전트 평가](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)의 대화 기록과 최종 산출물 구분을 적용했다. 이번에는 실제 화면 이동과 전송되는 근거, 호스트의 저장/readback 계약을 확인했다. 평가용 예시 답변을 실모델 품질로 채점하지 않았다. 반복 실모델 평가와 독립 결과 검증은 별도 검증이다.

[Anthropic citations](https://platform.claude.com/docs/en/build-with-claude/citations)의 원문 위치를 유지하는 패턴을 참고했다. 해당 API를 새로 호출한 것은 아니며 기존 누비 출처 레지스트리를 사용한다. 페이지 번호는 실제 추출한 경우에만 전달한다.

새 프레임워크를 추가하지 않았다. 기존 라이브러리와 브라우저 확장의 계약을 재사용하면 패키지 증가와 화면 분기를 줄일 수 있다.

| 선택 | 실제 반영/유지 | 라이선스와 판단 |
| --- | --- | --- |
| [jsdiff](https://github.com/kpdecker/jsdiff) `diff` 9.0.0 | 반영 파일의 추가/삭제 줄 수 계산에 기존 `diffLines` 제한 함수 재사용 | BSD-3-Clause. 현재 설치 패키지의 라이선스를 확인했다. 별도 diff 엔진을 추가하지 않는다. |
| [MiniSearch](https://github.com/lucaong/minisearch) 7.2.0 | 기존 로컬 원문/첨부 검색 유지 | MIT. 로컬 검색과 조건 필터에 적합하며 새 서버 검색 의존성을 요구하지 않는다. |
| React Arborist 3.16.0 / Monaco 0.57.0 / xterm 6.0.0 | 기존 탐색/편집/터미널 연결 유지 | 설치된 패키지의 MIT 라이선스를 확인했다. 새로운 IDE 호스트로 교체하지 않는다. |

## 확인 범위와 남은 제한

- `npm run build:electron`으로 Electron 런타임/화면 빌드를 완료했다. 자동 테스트는 실행하지 않았다.
- 별도 웹 미리보기의 예시 데이터로 초안 보존, 첨부 위치, 큐 편집, 파일 탭 연결, 스킬 모달과 추론 슬라이더를 직접 확인했다. 슬라이더는 키보드 Medium → Extra high, 드래그 → Low, Tab 초점 순환과 Escape 복귀를 확인했다. 성공 토스트는 표시하지 않았다.
- 로그인된 기존 앱은 재시작하지 않았다. 호스트 변경은 다음 실행에 적용된다.
- 실제 Gmail POP3/첨부 다운로드, 회사 SSO/GHES, 실모델 답변/추론/검색 정확도와 Windows 설치판/PowerShell 동작은 이번에 재측정하지 않았다.
- Google 패스키 문제는 `LOGIN-PASSKEY-2026-10-04.md`의 호스트 인증 지원 제한이 남아 있다. HTML 최적화로 해결됐다고 표시하지 않는다. 인증 값/계정/패스키를 진단 기록에 저장하거나 인증서 검증을 해제하지 않는다.
- 역사적인 전체 검사/모델 점수는 이번 수정의 점수로 재사용하지 않는다. 전체 기능 통과 또는 품질 등급을 부여하지 않는다.

[최종 화면 기록](evidence/quality-audit-2026-10-04.png)은 예시 데이터로 구성한 미리보기다. 반영 파일 목록과 작성 중인 요청의 첨부 근거를 함께 확인할 수 있다. 최종 빌드에서 목록 바깥을 클릭해도 닫히거나 초점이 배경으로 이동하지 않는 것을 확인했다. 확인 중 미리보기 콘솔에 기록된 오류는 없었다.
