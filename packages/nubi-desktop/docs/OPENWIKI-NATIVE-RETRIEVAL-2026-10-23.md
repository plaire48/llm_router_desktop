# OpenWiki 원생 검색과 내용 검토

Desktop 코드 Wiki의 검색과 질문은 OpenWiki-SDS 코어의 같은 절 파서와 SQLite FTS5/BM25 검색기를 사용한다. Desktop의 별도 MiniSearch 순위 계산과 관계 점수 RRF 결합은 제거했다. 브라우저 사이트 Wiki와 일반 첨부 문서의 기존 조회 계약은 이번 전환 범위에 포함하지 않는다.

`packages/openwiki/src/retrieval/wiki.ts`의 `searchWiki`/`readWikiSections`와 호스트 스냅샷용 `createWikiSnapshotReader`가 구현을 공유한다. 스냅샷 API는 이번에 OpenWiki-SDS 안에 추가한 호스트 연결점이며, 독립 CLI나 외부 검색 서비스를 새로 실행하지 않는다. 원본 upstream API를 수정 없이 연결했다고 표현하지 않는다.

## 검색과 원문 읽기

- Markdown H1을 frontmatter가 없는 문서의 제목으로 사용한다. 한국어 조사는 원형과 제거한 형태를 함께 색인하며 원문을 변경하지 않는다.
- 출처 경로 힌트 뒤에는 BM25 관련성을 우선한다. 일반 단어를 많이 공유한다는 이유로 다른 대상을 위로 올리지 않는다. 단일 오류 식별자는 다른 식별자로 대체하지 않는다.
- 현재 프로젝트가 허용한 문서만 색인한다. 질문 담당에 배정한 문서 ID는 결과 개수 제한 전에 필터링한다. 연결된 다른 workspace를 자동으로 열지 않는다.
- 검색 결과의 절을 같은 코어로 읽는다. CRLF, 중복 제목 anchor, 실제 UTF-16 위치와 표 머리글을 보존한다. 화면 검색은 검색한 페이지를 다시 읽고 해시를 검증한다.
- Claims 문장과 사용자가 선언한 용어집은 탐색 힌트다. 검색 결과나 원문 인용으로 대체하지 않는다. 소스 버전 일치와 사실 정확도는 별도 상태다.
- 원생 검색 순위를 유지한다. 관련된 오래된 문서를 무관한 최신 문서 뒤로 숨기는 별도 재정렬을 하지 않고, 각 결과의 최신성을 함께 반환한다.

## 캐시와 수명

파일/Claims/제외 규칙/선언 용어가 바뀌면 스냅샷 색인을 교체한다. 반복 질의는 같은 색인을 사용한다. 사용 중인 이전 색인은 요청이 끝난 후 닫는다. 폴더별 원문 LRU는 기존 8MiB 제한을 유지하고, 검색 범위에는 64MiB 누적 절단을 두지 않는다. FTS 색인 자체의 메모리까지 8MiB라고 주장하지 않는다.

질문 전용 색인은 질문이 끝나거나 실패하면 닫는다. 원문을 보관하지 않는 색인의 읽기는 현재 원문을 별도로 받고, 색인 당시 SHA-256과 다르면 거절한다. 임의 다른 원문으로 같은 위치를 재사용할 수 없다.

## 문장 정확도

OpenWiki-SDS의 기존 페이지 의미 검토를 유지한다. 일반 검토가 잠정 통과한 `모든`/`항상`/`all`/`every`/`always`/`never` 문장은 별도의 새 문맥에서 원문으로 반례를 찾는다. 특히 task, wait, validation, 마지막 시도의 예외 경계를 구분한다. 앞선 검토 결과나 작성자의 확신은 근거로 전달하지 않는다.

이 검토도 모델 기반 소스 추론이며 실제 실행 증명이 아니다. 근거 부족/반려/중단을 성공으로 바꾸지 않고, 생성물의 기존 승인과 충돌 방지를 유지한다.

## 확인 범위

검증 결과와 실패 원장은 작업 산출물의 `native-openwiki/`에 보관한다. 개발용 200문항의 검색 점수, 위키 생성 시간, 문장 의미 검토, 모델 질문, Electron UI를 구분해 보고한다. 독립 보류 질문, Windows 설치판과 사내 자료 검증은 별도다.
