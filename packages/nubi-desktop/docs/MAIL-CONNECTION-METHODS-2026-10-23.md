# 메일 연결 세 방식 — 2026-10-23

최신 사용자 결정은 Knox Desktop, POP3, 포털을 세 독립 방식으로 유지하는 것이다. 기존의 “포털 실패 후에만 POP3”와 Desktop 단일 기본 연결 지침은 이 범위에서 대체한다.

| 방식 | 수집 경로 | 원문과 첨부 범위 | 작업 담당 |
| --- | --- | --- | --- |
| Knox Desktop | Windows UIA로 연결한 창에서 현재 열린 메일을 읽음 | 관측한 본문·메타데이터의 암호화 JSON. 전체 메일함, 원본 MIME, 미다운로드 첨부는 미확인 | Knox Desktop UIA 메일 읽기 확인 |
| POP3 | 회사 POP3S, UIDL 증분 수집 | 받은 원본 MIME와 실제 보관한 첨부. 비밀번호는 메모리에만 유지 | 1.3.0 공통 통합 |
| 포털 | 외부 브라우저 SSO 탭의 같은 세션에서 고정 메일 조회 API 사용 | 조회해 받은 원문·첨부. 브라우저 확장 연결과 포털 읽기 허용 필요 | 외부 브라우저 탭 기반 SSO 방식 검토 |

## 공통 동작

- 메일 설정의 연결 방식에서 세 방법을 직접 선택한다. 선택 값은 `setting:mail-connection-method`, 상태는 `connectionMethod=desktop|pop3|portal`로 전달한다.
- 명시적 선택이 우선이며 기존 저장 설정은 유지한다. 신규 설정은 포털로 시작한다. 파일 가져오기는 보조 수집 동작이다.
- 선택 전환은 수집 세션과 이전 방식의 타이머를 중단한다. 기존 원문/첨부/개인 위키는 보존한다. 진행 중인 수집·생성·첨부 읽기·원문 이동에는 전환을 허용하지 않는다.
- POP3는 포털의 실패 상태 없이 연결할 수 있다. 앱 재시작 후 선택을 유지하고 비밀번호는 다시 입력한다. 취소는 해당 연결 요청 ID를 POP3 실행기에 전달한다.
- 포털 로그인은 외부 브라우저 모드와 오른쪽 연결 콘텐츠를 연다. 내부 브라우저 설정을 사용한 경우에도 메일 포털을 내부 로그인으로 대체하지 않는다. 실제 브라우저 탭과 로그인 세션의 소유권은 외부 브라우저에 남는다.
- 확장 미연결·읽기 권한 미허용은 연결 필요 상태로 표시한다. 코드만으로 실제 SSO가 완료됐다고 표시하지 않는다.
- 외부 콘텐츠의 인증 보호, 캡처 차단, 종료 정리는 기존 전용 포트를 사용한다. 모델/웹 RPC에는 미러 입력 포트를 제공하지 않는다.

## 위키 근거

UIA에 첨부 목록이 없다는 사실은 “첨부 없음”이 아니다. `attachmentsRead=false`와 `originalMimeAvailable=false`는 검색, 요약 검증, 대화 위키 모두 부분 확인으로 전파한다. 대화 위키에는 UIA 읽기 기록임을 표시하고 원문 해시와 관측 범위를 저장한다. 이 범위가 달라지면 이전 생성 캐시를 재사용하지 않는다.

Office 첨부는 실제 보관 바이트가 있을 때 기존 Windows Office COM 경로를 사용한다. UIA 본문 관측만으로 원본 MIME나 첨부 다운로드를 만들어내지 않는다.

## 검증 경계

연결 방식 선택/전환/보존, 독립 POP3 계약, 요청 취소 및 외부 콘텐츠 진입은 로컬 검사 대상이다. 합성 메일/관측, 임시 POP3 전송 대역과 실제 macOS Electron을 구분한다. 사내 POP3 접속·TLS·인증, 실제 SSO와 포털 API 응답, Windows Knox/DRM UIA, Office COM/NASCA는 별도 실환경 검증이 필요하다.

이번 변경은 설치 파일 배포나 Windows/사내 검증 완료를 의미하지 않는다. 실행 로그와 캡처는 `1-3-0/mail-methods`, 위키 관측 범위 검증은 `1-3-0/uia-original-storage`, 각 전용 경로의 추가 검증은 해당 작업의 산출물에 남긴다.
