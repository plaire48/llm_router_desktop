# 누비 Workspace Beta 1.1.6

## 변경

- 메일을 열면 HTML 표, 글자 강조, 본문 이미지가 바로 표시됩니다. CID 삽입 이미지, HTTP/HTTPS 이미지와 래스터 data 이미지가 대상입니다. 별도의 이미지 표시 버튼은 없습니다.
- 메일 연결 중 새와 회전 표시, 실제 경과 시간을 제공합니다. X, Esc, 바깥 클릭으로 연결 창을 닫을 수 없고 연결 취소는 유지합니다. 완료/실패/취소 뒤 다시 닫을 수 있습니다.
- 시작 화면의 준비 문장을 새와 회전 표시로 바꿉니다. 시스템 모션 감소 설정에서는 회전을 멈춥니다.
- 질문의 선택지와 직접 입력란을 대화 안에 바로 표시합니다. 답변하기 버튼/질문 모달을 거치지 않습니다. OS 시스템 알림 클릭은 해당 대화의 질문으로 이동합니다.
- GHES 프로필 사진의 API 요청이 실패하면 누비 내부 SSO 브라우저 세션으로 같은 서버에 다시 요청합니다. 다른 서버로 인증값을 보내거나 쿠키를 추출하지 않습니다. 서버가 MIME을 생략한 PNG/JPEG/GIF/WebP도 파일 서명을 확인합니다.
- 공유 위키 조회의 409/422를 저장 충돌로 오해하지 않도록 구분합니다. Git 참조 조회가 실패하면 Commit API로 한 번 조회하며, 계속 실패하면 읽기 실패를 표시합니다. 파일 해시 불일치는 무결성 오류로 표시합니다. 쓰기 시 HEAD 확인과 강제 갱신 금지는 유지합니다.
- 1.1.5의 메일 본문 복구, 삽입 이미지/첨부 구분, ASAR 밖 OpenWiki 준비 자산 수정도 포함합니다. 예전 실패 기록은 위키 준비의 다시 시도로 재실행합니다.

## 표시와 근거

HTML은 기존 DOMPurify 3.4.15 허용 목록으로 정리한 후 스크립트/폼/외부 프레임/임의 CSS 요청이 막힌 프레임에서 표시합니다. 표와 본문 스타일은 Workspace 바깥으로 적용되지 않습니다. 링크는 누비 브라우저로 엽니다. 이미지는 원본 참조대로 자동 요청하며 Referer를 보내지 않습니다. CID 이미지 전송은 본문 삽입 PNG/JPEG/GIF/WebP 합계 8MB까지입니다. HTML 표시 범위는 500,000자입니다.

검색, Agent 질문, Personal Wiki 정리에는 기존 원문 텍스트만 사용합니다. HTML/이미지는 화면 표시 요청에만 전달하며 원본과 manifest 영수증을 수정하지 않습니다. 첨부 파일 내용 분석은 Beta에서 지원하지 않습니다.

## 검증 범위

- 로컬 실제 컴포넌트 렌더링: 표/CID/외부 이미지 자동 표시, 검색어 강조, 실행 요소 제거, X/Esc/바깥 클릭 차단과 완료 후 해제.
- 검증된 합성 MIME: HTML/이미지 표시, AI 근거의 텍스트 유지, 영수증 보존, 바뀐 원본 거절.
- GHES 합성 응답: 내부 SSO 세션 요청 보완, 인증값 없는 브라우저 사진 요청, 동일 서버/리다이렉트와 파일 서명 보호.
- 위키 관련 5개 회귀: 참조 조회 복구, 지속 읽기 실패의 구분, 해시 불일치 거절, 쓰기 전/최종 참조 충돌 보호.
- Windows 빌드와 패키지 내 준비 자산 무결성을 확인합니다. 사용자 요청에 따라 추가 전체 기능/모델/설치 회귀는 생략합니다.

사내 GHES 실계정의 사진/공유 위키 성공과 실제 Windows 11 메일 서버의 HTML 표시, 사용자 PC 업데이트는 별도 확인이 필요합니다. 외부망 빌드 성공을 사내 서비스 성공으로 표시하지 않습니다.

## 방법론

기존 DOMPurify/격리 프레임 패턴을 재사용하고 새 의존성은 추가하지 않았습니다. [DOMPurify](https://github.com/cure53/DOMPurify), [iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe), [GitHub Git references](https://docs.github.com/en/rest/git/refs?apiVersion=2022-11-28)를 확인했습니다. 화면과 검색/AI 근거를 분리하며 조회 실패 복구가 쓰기 권한/CAS 확인을 완화하지 않도록 했습니다.

## 추가 반영 2026-10-13

- 대화 실행 중 다른 폴더를 열 수 있습니다. 실행 중인 프로젝트의 Agent/저장소를 보존하고 새 프로젝트는 별도로 실행합니다. 뒤에서 진행 중인 작업/질문을 목록에 표시하고 OS 알림은 원래 프로젝트/대화로 이동합니다. 늦게 도착한 화면 요청과 오래된 프로젝트의 쓰기 요청을 거절합니다. 계정, 사용량, 메일, SSO는 앱에서 공유합니다.
- 사용자 후속 결정에 따라 IMAP 전환을 취소하고 회사 메일은 POP3 `pop3.samsung.net:995`로 복원합니다. 받은메일만 수집하며 보낸메일 수집 미지원을 안내합니다. 기존 원문/영수증, HTML 본문과 필터/정렬 개선은 보존합니다.
- 본인 주소가 없는 아이디 로그인은 메일 설정에서 본인 메일 주소를 입력해 수신/참조/비밀참조를 구분합니다. 주소는 분류용 해시로 저장합니다. 비밀참조 헤더가 없으면 추측하지 않습니다. 보낸메일의 구분은 발신으로 표시합니다.
- 표의 제목/보낸사람/구분/날짜 헤더에 필터를 붙입니다. 초안 선택 후 적용/초기화하고 정렬/페이지네이션 전에 전체 수집 목록에 적용합니다. E2E Report의 열 옆 필터 패턴을 재사용하며 새로운 라이브러리는 추가하지 않습니다.

### 추가 검증 경계

실제 Agent 실행기를 합성 모델과 두 임시 프로젝트로 실행해 동시에 답변하는 동안 원본/저장소/결과/질문이 섞이지 않는지 검사했습니다. Git 하위 폴더의 같은 저장소 재사용, 실패한 폴더 열기의 이전 프로젝트 보존, 오래된 화면의 다른 프로젝트 쓰기 차단, 공유 계정/사용량의 단일 소유권도 확인했습니다.

IMAP 시도는 사용자 요청으로 철회했습니다. 해당 worker/연결 설정/ImapFlow 의존성/전용 검사를 최종 1.1.6에서 제거합니다. 기존 개발판의 IMAP 선택 설정은 POP3로 복원합니다. 실제 회사 POP3 로그인과 수신은 사용자 PC에서 확인해야 합니다.

1.1.6 공개는 사용자의 배포 지시에 맞춰 진행합니다. 앞서 만든 비공개 1.1.6 빌드는 이 추가 변경 전의 후보이며 최종 설치판으로 사용하지 않습니다.

철회 전 개발 후보의 검사 기록(최종 POP3 설치판의 성적으로 사용하지 않음): 프로젝트/대화 동시 실행과 IMAP/검색 관련 25건 통과, 기존 POP3 TLS 회귀 13건 통과, 공식 ImapFlow 및 최종 번들 worker의 로컬 TLS IMAP 수집 검사 1건 통과. 로컬 Electron 빌드 통과. 실제 공유 컴포넌트 Chrome 렌더링에서 보낸메일 폴더 선택, 제목/구분 필터, 보낸사람 정렬, 440px/1100px 선택 창 잘림과 Esc 닫기를 확인했습니다. 화면 검사는 합성 API이며 사내 계정 성공의 증거가 아닙니다.

- 작업 기록의 다음 단계는 제목과 내용 사이 12px 공통 간격을 두고 첫 줄 기준선을 맞춥니다. 제목은 한 줄로 유지하고 좁은 화면에서도 본문이 제목 아래로 섞이거나 잘리지 않도록 합니다.

### 채팅 추가 입력과 다시 응답 받기

초기 계획의 checkpoint가 없거나 답변 재작성 중에도 실제 responseTiming runId를 사용해 메시지를 대기열에 받습니다. 전송 결과가 불확실한 요청은 자동 재전송하지 않습니다. 다시 응답 받기는 해당 대화의 미승인 제안만 superseded로 보관하고 최신 요청을 새로 수행하며 실제 실행/반영 영수증을 보존합니다. 준비 중 저장 오류는 트랜잭션으로 원복하고 Agent 시작 실패도 기존 답변과 제안을 복원합니다. 실행 중인 명령이나 승인 후 시작 중인 동작은 별도 안내하며 반복 실행하지 않습니다.

‘일부만 확인됨’은 ‘문서 미열람 구간 있음’과 ‘분석 결과 확인 필요’로 구분합니다. 실제 미열람 개수/원본/문자 범위를 유지하며 문서 분석, 주의 안내, 원문 출처에 공통 아이콘을 추가합니다. Chrome 실제 컴포넌트에서 360px/800px 정렬과 잘림, 미열람 구간, 출처 아이콘을 확인했습니다. 합성 분석 기록이며 Windows 실서비스 검증을 대신하지 않습니다.

### 회전 표시 옆 경과 시간

채팅 전송/시작 대기, 실행 도구와 분담 분석의 회전 표시 바로 옆에 실제 경과 시간을 초 단위로 표시합니다. 1분 0초처럼 초를 생략하지 않고, 처음에는 0초로 시작하며 0분 표시는 하지 않습니다. 실제 기록된 단계 startedAt을 상태 갱신 때 보존하고 화면 타이머는 단조 시계로 이어갑니다. 완료/중지/전송 미확인 상태에서는 live 타이머를 정리합니다. 공용 웹/Office 화면은 새 렌더 콜백을 전달하지 않으면 기존 표시를 유지합니다.

관련 검사 15건과 로컬 Electron 빌드 통과. 360px/800px 실제 채팅 컴포넌트에서 제어 시계로 초 증가, 회전 표시와 정렬/간격, 완료 후 정지와 실패 전송 타이머 제거를 확인했습니다. 시간과 실행 이벤트는 합성 검증 자료이며 실제 Windows 계정 작업 완료를 뜻하지 않습니다.

### GHES 프로필 사진 유지

GHES가 외부 사진 주소를 반환하거나 기본 사진 경로가 실패하면 동일 서버의 기존 `/avatars/u/<id>` 경로로도 조회합니다. API 인증과 앱 SSO 브라우저 요청을 분리하고 외부 주소/리다이렉트에 인증을 보내지 않습니다. 사진 조회의 전체 대기는 5초로 제한하며 정상 계정 로그인을 사진 실패로 거부하지 않습니다.

Desktop은 검증된 512 KiB 이하 사진만 기존 OS 보호 연결 기록에 보관합니다. 사진의 계정 ID와 원본 주소 해시를 현재 `/user` 결과에 대조하며 최근 5분의 사진은 불필요하게 다시 조회하지 않습니다. 프로필 새로고침은 강제로 재조회하고 같은 계정/원본의 일시 실패에는 마지막 사진을 유지합니다. 로그아웃과 계정/원본 변경에는 이전 사진을 재사용하지 않습니다. 512 KiB를 넘는 이미지의 표시 제한은 기존 1 MiB이며 저장 캐시는 생략합니다.

관련 계정/사진 검사 27건과 로컬 Electron 빌드 통과. 실제 계정 컴포넌트와 GHES 실행 코드를 합성 계정/응답에 연결해 360px/800px 상단 사진/이름, 모달 사진, 새로고침 실패의 사진 유지와 호스트 재생성 후 보존을 확인합니다. 회사 GHES와 Windows 설치판의 실제 사진 수신은 별도 검증이며 1.1.6은 아직 배포 전입니다. 사용자 API의 `avatar_url` 계약은 [GitHub Enterprise Server 공식 문서](https://docs.github.com/en/enterprise-server%403.19/rest/users/users#get-the-authenticated-user)를 참고했습니다.
