# 누비 A2A 연결

> 2026-10-01 Workspace/Chrome 작업 수락과 결과 회신, Office 초안 receiver를 활성화하고 실제 SDK HTTP로 검사했습니다. 인증된 메일 첨부 전문 분석은 아직 연결되지 않았습니다. 필수 범위는 [메일 문서 협업](MAIL-DOCUMENT-COLLABORATION.md), 현재 검증은 [A2A 검증 기록](A2A-VALIDATION-2026-10-01.md)을 따릅니다.

데스크톱이 확인한 소스와 OpenWiki 근거를 브라우저와 Office에 전달하고, 각 앱의 기존 채팅에서 나온 답변을 원래 작업으로 돌려받는다. 수신한 초안은 다음 데스크톱 분석의 참고 문맥에 포함된다.

## 선택 근거

[A2A 1.0 공식 명세](https://a2a-protocol.org/v1.0.0/specification/)와 [공식 JavaScript SDK](https://github.com/a2aproject/a2a-js)를 확인해 `@a2a-js/sdk` 1.2.0을 도입했다. Task와 Artifact, context ID, 수신자별 권한, 입력 대기와 결과 전달을 표준 전송 계층으로 연결한다. 요청 재전송의 부작용은 SDK가 보장한다고 가정하지 않고 로컬 영수증과 실제 Task 조회로 처리한다.

기존 OpenWiki 조회만으로는 작업 상태와 결과를 주고받을 수 없어 A2A를 별도로 둔다. MCP나 OpenWiki 도구는 조회 수단으로 유지한다. Pi와 Office 네이티브 실행기를 교체하거나 대화/인증 저장소를 합치지 않는다. Chrome MV3는 서버 포트를 열 수 없어 데스크톱이 조정 서버를 맡고, 브라우저와 Office는 작업을 조회하는 클라이언트로 연결한다.

무거운 메시지 브로커, 별도 agent framework, 외부 클라우드 서비스는 현재 단일 PC 작업에 필요하지 않아 추가하지 않았다. Apache-2.0 SDK와 기존 SQLite를 재사용한다. Windows 설치 파일은 만들지 않았다.

## 반영한 흐름

Workspace의 작업 보내기는 `nubi-task-v1` 요청을 물리 SQLite와 SDK Task에 보존한다. 브라우저 사용자가 수락하면 기존 Pi 채팅 실행기로 처리한다. 브라우저가 Workspace에 보낸 요청은 새 읽기 전용 대화로 가져오며 Workspace 사용자가 직접 시작한다. 수락을 다시 눌러도 같은 대화를 반환한다. 미선언 수정/실행 도구는 호스트에서도 차단한다.

Workspace 회신은 해당 실행의 실제 assistant answer와 최종 검토 영수증, source hash를 대조한다. 입력 문자열을 완료 답변으로 받지 않는다. 요청과 완료 조건이 바뀌면 결과를 stale로 분리하고 원래 Artifact를 보존한다. A2A 토큰은 모델 문맥에 포함하지 않으며 요청자가 붙인 context는 참고 자료로 구분한다.

- 작업의 ‘다른 누비와 작업’에서 시나리오 또는 검토 문서를 요청한다.
- 각 앱의 ‘설정 → 누비 작업 연결’에서 데스크톱이 만든 주소를 붙여넣는다.
- 요구사항 ID, 소스 해시, Wiki 출처와 발췌를 채팅에 가져온다. 사용자가 전송하면 기존 실행기와 HITL을 따른다.
- 해당 요청에서 실제 생성된 답변만 보낼 수 있다. 기존 초안을 덮어쓰거나 임의의 답변을 완료 결과로 전달하지 않는다.
- 데스크톱이 현재 소스와 Wiki를 재확인한 뒤 결과를 저장하고 화면에 표시한다. 결과가 와도 완료 조건은 미확인으로 남는다.

연결과 상태 계약, 제한, 복구 동작은 [공통 패키지](../../nubi-a2a/README.md)를 따른다. 현재 브라우저 peer 작업은 URL/원문 인용이 있는 사실 결과를 반환하고, 기존 초안 계약은 소스/Wiki 발췌를 전달한다. Office 파일 bytes와 native coverage 전송은 아직 포함하지 않는다.

## 검증

현재 결과는 [2026-10-01 검증 기록](A2A-VALIDATION-2026-10-01.md)이다. 아래 수치는 과거 구현의 검증 이력이며 현재 소스 전체 검사의 대체 자료가 아니다.

2026-09-23 로컬 검사:

- 공통 A2A와 Desktop/Office 연결 검사 9개 통과. 번들 Node 24에서도 같은 검사를 통과했다. 실제 SDK HTTP 왕복, 수신자 격리, 중복 요청, 서버 재시작, 오래된 소스, 재연결 시 실행 연결 유지, 기존 초안 보존을 확인했다.
- Desktop 런타임 62개, 실제 Theia 화면 32개, 공통 UI 6개 통과. 요청 생성과 결과 표시, 화면 재진입도 검사했다.
- 실제 Chrome 확장에서 로컬 A2A 서버 연결, 요청 가져오기, 정상 Pi 실행 경로, 화면 새로고침, 답변 회신을 확인했다. 모델 응답은 합성값이다.
- 브라우저 회귀 검사 468개 통과. 후보 확장 빌드와 CX 정적 검사 통과. Desktop 브라우저/Electron 개발 빌드도 통과했다.
- Office 관련 소스 검사 32개 통과. UI와 worker의 메모리 내 번들 검사 통과. 실제 Windows Office 실행/COM/모델 검증은 수행하지 않았다.
- Office의 기존 공통 UI 해시 검사는 이번에 수정하지 않은 7개 공유 파일의 기준 불일치로 실패했다. 기준을 임의 갱신하지 않았다. 최종 Office 빌드 전에 기존 UI 변경 검토와 기준 동기화가 필요하다.

합성 응답 검사는 실제 Qwen 정확도, AI Pro 연결 성공, Windows 설치 성공이나 문서 저장 성공의 증거가 아니다. A2A 전체 적합성 인증을 주장하지 않는다.
