# 프로젝트 없는 메일 질문과 계획 완료

사용자 보고: AI Pro의 일반 대화에서 답변은 도착했으나 메일 원문 조회에 입력 형식 안내가 남고 계획이 2/3으로 끝났다.

## 확인과 수정

- 계획 갱신 검사가 마지막 갱신에도 정확히 한 단계의 진행 중 상태를 요구했다. 초기 계획은 기존 기준을 유지하고, 실행 이후 모든 단계가 완료인 갱신은 허용한다.
- 완료 선언 자체를 검증으로 취급하지 않는다. 동일 실행과 동일 계획 revision의 독립 결과 검토가 근거를 확인한 단계만 verified로 확정한다. 확인하지 못한 단계는 다시 pending으로 표시한다.
- 검색 결과가 제공하는 sourceId와 원문 읽기 도구의 id 차이를 안전하게 정규화한다. 같은 문자열 ID의 별칭과 손실 없는 정수 offset만 처리한다. 서로 다른 ID, 여러 ID, 잘못된 수치와 추가 인자는 기존 스키마가 거절한다.
- 형식 오류를 사용자가 답변해야 하는 질문처럼 표시하지 않고 호출 형식 오류로 구분한다. 실제 실패 기록을 성공이나 복구 완료로 덮어쓰지 않는다.
- 계획이 2/3인 경우 남은 단계의 확인 필요 상태를 표시한다. 답변 도착만으로 3/3을 만들지 않는다. 기존 공통 아이콘, 접기, 글꼴, 간격을 유지한다.

기존 Pi 도구 인자 정규화와 독립 검토 패턴을 재사용했다. 새 의존성이나 모델별 임의 완료 규칙은 도입하지 않았다.

## 검증 범위

`tests/mail-tool-arguments.test.mjs`는 빈 일반 대화 폴더에서 AI Pro 제공자 인터페이스의 합성 응답으로 검색, 원문 읽기, 출처, 전체 완료 갱신, 독립 검토를 순서대로 실행한다. 잘못된 별칭과 상충하는 ID를 거절하는 검사도 포함한다. 실제 사용자 AI Pro 응답 payload는 확보하지 못했으므로 별칭 불일치를 그 호출의 확정 원인으로 표현하지 않는다. 회사 메일이나 AI Pro 실서비스 성공과 이 재현 검사는 구분한다.
