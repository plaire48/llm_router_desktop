# 위키 상호작용 최적화 — 2026-10-16

기존 배치, 아이콘, 색상, 전환 애니메이션을 유지하며 입력과 화면 이동 중 반복 계산을 줄였습니다. 릴리즈는 사용자 요청에 따라 보류합니다.

## 변경

- 목록은 문서나 정렬 기준이 바뀔 때만 정렬합니다. 검색은 정렬된 순서를 유지하며 좁히고, 페이지 이동과 문서 읽기는 정렬을 다시 하지 않습니다.
- 지도 이동과 hover에서 문서 집합, 연결, 검색 결과, 경로 색인을 재사용합니다. 화면 밖 도형 생략과 worker 계산은 유지하며 클러스터 집계는 해당 보기를 열 때만 합니다.
- 문서 편집은 초안의 추가/삭제 때만 목록을 갱신합니다. 매 글자 입력마다 그래프 전체를 만들지 않습니다. 본문 초안 자체는 즉시 저장합니다.
- 필터 위치 계산은 프레임당 한 번으로 합칩니다. 실제 위치가 같으면 React 상태를 다시 갱신하지 않으며 닫을 때 예약된 갱신을 취소합니다.

## 동일 부하 비교

합성 문서 3,000개와 연결 2,900개. 실제 WikiBrowser, WikiMap, 레이아웃 worker를 Chrome에서 실행했습니다. CPU 4배 감속으로 3회씩 측정한 중앙값입니다. 아래 수치는 여러 동작의 **누적 처리 시간**이며 클릭 한 번의 대기 시간이나 앱 전체 속도가 아닙니다. 두 버전 모두 측정한 검색/이동 구간에서 50ms 이상 long task는 없었습니다.

## 검증 범위

- 위키 그래프/묶음 단위 검사 11개 통과.
- 코드/메일 4개 필터 × 3개 너비: 적용, 재열기, 초기화, 빈 결과 복구 통과.
- 지도 3,000개에서 최초 42개, 이동 후 40개 도형만 표시. 이동/창 크기 변경 중 레이아웃 worker 재시작 없음. 클러스터 전환, 자료 열기, 모션 감소 통과.
- 모달의 늘이기/줄이기, 빠른 닫기/열기, 초점 보존, 화면 전환 중 실제 클릭, 좁은 화면, 모션 감소 8개 검증 통과.
- 긴 대화는 기존 최근 40개 우선 표시를 유지합니다. 240개/1,000개 대화 진입을 각 3회 측정했고 중앙값은 약 255ms/233ms였습니다. 이번 위키 변경으로 채팅 속도가 향상되었다는 의미는 아닙니다. 이전 기록 추가, 읽던 위치/DOM 보존, 최신 답변과 보류 질문 노출 회귀 검사 통과.

로컬 Electron 빌드도 통과했습니다. 격리된 작은 프로젝트로 실제 macOS Electron을 3회 실행해 AI Workspace, 메일, 설정 전환을 확인했습니다. 전환 구간 프레임 간격 p95는 20.9/21.3/21.4ms였고 50ms 이상 long task와 화면 오류는 없었습니다. 최초 1회 launch-to-window에는 5.84초의 편차가 있었으며 이후 두 번은 386/369ms였습니다. 초기화/실행 도구를 포함하는 시간으로 앱 렌더링 병목으로 단정하거나 개선 성적으로 사용하지 않습니다. 이 검사는 위키 부하 측정과 별개이며 변경 전후 비교가 아닙니다. 결과: `verification/performance-2026-10-14/smooth-2026-10-16.json`.

원격 모델 응답, 대용량 실제 메일, 사내 SSO 및 Windows 설치판 체감 속도는 이번 측정 범위에 포함되지 않습니다. 사용자 환경의 모든 버벅임이 해소되었다고 일반화하지 않습니다.
