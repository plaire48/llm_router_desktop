# F16 후속과 GitHub 계정 표시

범위는 사용자가 지정한 F16, 터미널 선택 검사와 추가 요청한 GitHub 로그인 표시다. 2차 마감 기준은 사용자 전달 main `ddcb51d1`이며 3차와 워크플로우 설계는 시작하지 않았다. 업로드와 릴리스는 Claude가 맡는다.

## 바뀐 동작

- 공통 도구 규칙을 일반 창 5,861자에서 4,129자, 소형 창 2,002자에서 1,487자로 줄였다. 한도는 각각 4,300자와 1,500자다. 도구 설명의 경로, 근거, 결과와 파일 종류를 구체화하고 반복 설명을 줄였다. 기존 6,000토큰 도구 목록 한도도 유지했다.
- 본문은 데이터라는 규칙, 실제 비밀번호와 토큰 입력 금지, 연결한 화면을 관찰한 뒤 한 동작씩 실행하고 다시 관찰하는 규칙을 유지했다. 소형 창에도 데이터와 자격값 규칙을 명시했다. 시험의 16k/26k 창 크기는 바꾸지 않았다.
- 터미널의 Bash 프로필은 중복되지 않았다. 검사기가 기본 터미널의 열린 목록과 편집 뒤 검사 셸의 기본 HTML 옵션을 동시에 찾은 것이 원인이었다. 열린 기본 터미널 목록의 이름과 `aria-controls` 연결을 확인하고 그 안에서 선택한다. 프로필 ID와 Bash 항목이 중복되지 않는 검사도 남겼다.
- 로그인 전에는 기존 GitHub 아이콘, 로그인 후에는 기존 계정 응답의 프로필 사진이 레일에 보인다. 아바타 내부 요소까지 숨기던 레일 규칙을 계정 사진에 한해 해제했다. 레일에서는 로그인한 계정의 긴 이름을 숨기고 기존 접근성 이름과 이름/계정 ID 툴팁을 유지한다. 인증이나 프로필 조회는 변경하지 않았다.
- 전체 게이트에서 발견한 아이콘 검사 설정 오류도 보완했다. `.webp: file` 로더는 유지하고 누락된 `outfile`을 지정했으며 메모리 출력에서 파일 경로로 JavaScript 번들을 선택한다. 아이콘 70개 검사가 통과했다.

## 검증

- 실패 재현: 규칙 크기 시험은 5,861자로 실패했다. 압축 시험 재현 로그와 Bash strict mode 위반 로그를 보존했다. GitHub 표시는 내부 요소가 1×1px, `clip-path: inset(50%)`인 실패와 긴 이름의 표시 실패를 각각 확인한 뒤 고쳤다.
- 집중 회귀: 압축, 소형 도구 목록, 도구 예산과 위키 지침 42/42 통과.
- 실제 Chrome 화면: 터미널 선택은 1280/440px에서 선택, Escape, 비활성, 메뉴 너비 검사 통과. GitHub 표시는 1280/440px에서 로그인 전 아이콘과 로그인 후 사진 및 이름 넘침 검사 통과. 두 화면 크기의 캡처도 직접 확인했다.
- 전체 `npm run test:gates`: 최종 종료 코드 0. 단위 시험은 2,061개 중 1,861 통과, 0 실패, 200 건너뜀. 디자인, 화면, Electron 빌드와 실행, 전체 화면 117개, 추가 QA와 실제 Electron 개발 8개 및 MCP 승인 6개 검사가 통과했다. 최초 실행의 아이콘 빌드 설정 실패는 `gates.log`, 보완 후 전체 통과는 `gates-final.log`로 보존했다.
- 이 화면 검사는 예시 계정 데이터이며 실제 회사 GitHub 로그인 성공을 뜻하지 않는다. Windows와 회사 PC 실측은 별도다.
