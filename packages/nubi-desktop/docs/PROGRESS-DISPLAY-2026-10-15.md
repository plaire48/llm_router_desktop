# Progress display and answer reveal

사용자 요청: 설정에서 작업 과정을 켜거나 끄고, 두 모드 모두 답변이 부드럽게 나타나게 한다.

- 설정의 `진행 과정 표시`는 기본 켜짐. 앱 전용 localStorage에 저장하고 즉시 적용한다.
- 끄면 작업 계획, 도구 기록, 모델 작업 메모, 분석 이력과 완료한 명령 기록을 숨긴다. 기록 삭제나 모델 추론 강도 변경, 검증 생략은 하지 않는다.
- 질문, 실행 승인, 활성 명령의 중지, 변경 제안과 오류 및 미확정 검토 결과는 유지한다. 대기 중에는 작은 진행 표시와 실제 경과 시간을 보여준다.
- 다시 켜면 원래 기록을 표시한다. 설정의 작업 기록은 별도로 열 수 있다.
- 기존 답변 표시 흐름을 재사용했다. 새 답변의 글자 묶음을 순서대로 240ms 동안 드러내며 0.8px 흐림을 제거한다. 레이아웃은 처음부터 고정한다. 비공개 추론이나 검토 전 응답을 최종 답변으로 스트리밍하지 않는다.
- 표시 조각 수와 지연 상한, 긴 답변의 즉시 표시, 코드와 출처, 이전 대화의 즉시 표시, 시스템 모션 감소를 유지한다.

검증: `scripts/check-progress-display.mjs`에서 실제 Workbench 컴포넌트의 설정 전환과 새로고침 유지, 1280/440px 화면, 질문과 승인 및 검토 실패 노출을 확인한다. `scripts/check-answer-reveal.mjs`에서 두 표시 모드의 등장 효과, 줄 위치 유지, 코드/인용 보존, 과거 답변, 모션 감소를 확인한다. 별도 단위 검사 2건과 디자인/아이콘/TDZ 검사, Electron 렌더러 빌드를 수행한다.

검증 범위는 합성 데이터의 로컬 브라우저다. Windows 설치판이나 실모델 응답 속도 개선을 뜻하지 않는다. 설치 파일 배포는 하지 않았다.

## 경과 시간과 진행 배경 후속

- 과정 표시를 꺼도 `12초 동안 작업 중`을 유지하고 1초마다 실제 경과 시간을 갱신한다. 1분 이후에는 분과 초를 함께 표시한다. 타이밍 정보가 없으면 임의의 시간을 만들지 않는다.
- 작업 중 제목과 위키 진행 영역에 옅은 누비 파랑 배경을 사용한다. 공통 8초 모션 토큰으로 빛의 위치와 불투명도만 천천히 바꾸고 글자와 레이아웃은 움직이지 않는다.
- 공통 진행 막대의 배경 효과는 실제 진행률과 독립이다. 완료 또는 오류 상태에서는 해당 장식을 제거하며 모션 감소 시 정지하고 숨겨진 창에서는 일시 정지한다.
- 기존 CSS 애니메이션과 공통 진행 컴포넌트를 재사용했다. 매 프레임 React 상태 변경, 새 애니메이션 패키지, 넓은 blur 필터는 추가하지 않았다.
- 로컬 Workbench와 위키 모달 검증에서 초 단위 갱신, 1280/440px 배치, 레이아웃 고정, 실패 중지와 모션 감소를 확인했다. Windows 저사양 장비의 프레임 속도는 별도 측정하지 않았다.
