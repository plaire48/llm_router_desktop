# Wave 2 Task 12 — 루틴

로컬 구현과 집중 검사를 진행했다. 전체 게이트는 아직 미완료이며 commit/push/릴리스는 하지 않는다.

설정의 루틴에서 프로젝트, 요청, 매일/매주 시각과 켜기/끄기를 관리한다. 지금 실행은 기존 프로젝트 대화를 만들고 같은 에이전트를 시작한다. 실행 시각은 PC의 로컬 시간이다. 놓친 예약은 다음 시작 때 한 번만 보충하며 마지막 실행을 모델 호출 전에 저장한다. 모델 미연결과 다른 실행 중에는 시각을 소비하지 않는다.

질문과 승인은 기존 대화 및 결정 알림으로 대기한다. 열린 대화, 중단된 실행, 승인 대기가 남으면 같은 루틴을 중복 실행하지 않는다. 두 저장소 사이에서 앱이 끊긴 경우 routineId로 기존 대화를 복구 확인한다. 준비 중 루틴 삭제/수정/끄기가 발생하면 오래된 요청은 발행하지 않는다. 새 대상 프로젝트를 선택해도 이전 프로젝트의 대기가 먼저 확인된다. 루틴 삭제는 기존 대화를 삭제하지 않는다.

## 구현 판단

- 계획의 projects.service(projectId) 예시는 현재 API에 없어, 기존 ProjectServices에 catalog의 경로와 ID를 검증하는 service(project)를 추가했다. 백그라운드 프로젝트를 열되 현재 화면 선택을 바꾸지 않는다.
- 루틴 메타데이터는 createTask의 호스트 전용 두 번째 인자로 연결했다. 일반 렌더러 요청이 임의로 루틴 바인딩을 만들지 않는다.
- 알림 문구는 이미 분리된 decision-notices.cjs와 기존 SystemDecisionNotifications를 사용한다. main에 중복 알림을 만들지 않는다.
- 메일 자동 확인, 명령 기록의 기본 접힘, 평가 과제/채점은 변경하지 않는다.

## 검증 기록

- 최초 RED: routines 모듈 부재. task12-red.log.
- 집중 검사에서 저장소 간 끊김 뒤 승인 대기 누락을 재현했다(task12-restart-red.log). routineId 역조회 후 통과했다.
- 준비 중 삭제된 루틴이 실행되는 실패를 재현했다(task12-stale-red.log). 발행 직전 저장 레코드 재검증 후 통과했다.
- 실제 macOS Electron에서 UI 추가, 지금 실행, 질문 대기, 사이드바 대화 표시, worker 강제 종료와 재시작 후 설정/대화 연결 보존을 확인했다. 기존 다중 실행/창 크기/없는 프로젝트/포트 충돌 검사도 통과했다. 첫 대화 버튼의 접근성 이름에는 상태 문구도 포함되어 정확한 task ID로 찾도록 검사만 수정했다.
- 화면은 공통 모달/확인창과 디자인 토큰을 사용한다. 확인창의 기존 역할 alertdialog를 검사에 반영했다.
- 예약 시간은 단위 검사만 수행했다. 실제 모델, Windows 알림/Office/NASCA/설치판 성공으로 확대하지 않는다.

## 최종 리뷰 보완

독립 리뷰의 네 Important를 한 번에 보완했다. 예약 실행은 기존 호스트 이벤트로 유휴 화면에도 전달되고, 위키 실행 중에는 시각을 소진하지 않는다. 이전 프로젝트 제거는 마지막 대화의 호스트 확인에 묶으며 재개 시 확인을 무효화한다. 대화 내보내기의 Basic 명령과 PRIVATE KEY 블록 가림도 포함했다.
