# 버튼 토큰과 배치 검증

버튼의 공통 토큰, 아이콘 위치와 한쪽에 몰린 동작 그룹을 점검했다. 기존 CX 컨트롤과 아이콘 원형, 브랜드/제공자/상태 색, 접근성 이름과 동작은 유지한다. 역할별 기준은 [누비 브랜드 관리 기준](NUBI-BRAND-GUIDE.md)에 있다.

## 발견과 수정

- 좁은 창에서 상단 버튼 간격이 2px까지 줄어들었다. 상단은 공통 8px를 유지하고, 입력창은 일반 8px / 좁은 마우스 환경 4px / 터치 8px로 정리했다.
- 작은 펼침 화살표와 일반 이전/다음 동작의 구분이 일관되지 않았다. 실제 펼침 컨트롤만 12px 토큰을 사용하며 독립 동작은 일반 16px 역할을 유지한다. 목록은 14px, 상단은 17px, 탐색 메뉴는 20px이며 글자 크기에 따라 조정된다.
- 모델 창의 새로고침과 연결 해제가 오른쪽에 붙어 있었다. 연결 관련 일반 동작은 왼쪽, 연결 해제는 오른쪽으로 분리했다. 동작/인증 코드는 변경하지 않았다.
- 실제 앱의 최종 `workspace-alignment.css`가 합성 화면 fixture에 누락되어 있었다. 이 파일을 마지막에 불러오도록 수정한 뒤, 메일 첨부 아이콘이 버튼 바깥에 배치되는 문제와 대화 목록 아이콘의 토큰 불일치를 발견했다. 첨부 버튼 영역을 아이콘까지 넓히고 기존 텍스트 축을 유지했으며, 대화 목록은 14px 아이콘과 대칭 여백으로 맞췄다.
- 터치 환경에서 로그인 버튼은 44×36px, 캡처 버튼은 32×44px, 설정 스위치는 44×27px였다. `--nubi-work-control-touch:44px`를 사용해 클릭 영역을 넓혔다. 스위치 트랙은 44×27px 모양을 유지한다.

## 확인 결과

`scripts/button-layout-audit.mjs`는 현재 활성 모달 또는 화면의 버튼을 측정한다. 숨김/비활성 배경과 원본 문서·메일/코드 콘텐츠는 제외한다. 아이콘이 클릭 영역 안에 있는지, 일반 한 줄 버튼의 수직 중심과 역할 토큰이 맞는지, 지정한 동작 그룹에서 버튼이 겹치거나 간격이 부족한지 확인한다. 여러 줄 카드는 별도 배치를 유지하며 그룹의 좌우 분포도 기록한다. 의도적인 우측 정렬을 그 자체로 오류 처리하지 않는다.

- 공통 Electron 합성 상태: **116개 화면/모달, 버튼 표본 1,371개, 동작 그룹 157개**. 넓은/좁은 창과 200% 글자를 포함해 겹침, 아이콘 영역 이탈, 토큰 크기와 그룹 간격 위반 0건, 정렬 관찰 사항 0건. 총 117개 검사 중 나머지 1개는 기존 새 모션 기록이다. 결과: `verification/button-layout-audit-final-2026-10-23/`.
- 실제 macOS Electron 호스트: **12개 검사 통과**. 시작/입력창/프로젝트 연결/좁은 입력창/모델 창의 5개 버튼 범위에서 표본 81개, 위반 0건. 모델 창의 좌측 새로고침과 우측 연결 해제, 모달 대비와 양방향 Tab 순환도 확인했다. 결과: `verification/calm-liquid-2026-10-23/`, 모델 창 캡처 `model-actions.png`.
- Chrome의 실제 컴포넌트와 최종 Desktop CSS: **아이콘 18개 그룹**, 대화/설정 **6개 배치 범위, 버튼 표본 96개**, 위반/정렬 관찰 사항 0건. 1280px 기본 글자, 440px 125% 글자, 440px coarse pointer에서 확인했다. 마지막 터치 영역 보완 뒤 실행한 결과이며, 기존 제공자 4종의 색도 일치했다. 결과: `verification/icon-scale-2026-10-17/after.json`, `after-*-440-touch.png`.

공통 116개 화면과 네이티브 12개 검사는 마지막 터치 전용 영역 보완 전에 통과했다. 마지막 보완은 coarse pointer에만 적용했으며, 이후 Chrome coarse pointer를 포함한 6개 범위를 다시 통과했다. 터치 스위치의 트랙 밖 위/아래 클릭 영역으로 실제 설정을 켜고 끈 뒤 원상 복귀했다. 최종 소스의 Electron 번들과 identity도 통과했다.

합성 데이터와 격리 저장소를 사용한 로컬 검증이다. 실계정/실모델/실제 메일·위키 자료, Windows 설치/업데이트/재실행이나 Windows의 전반적 끊김 해소를 증명하지 않는다. 후보 브랜치의 전체 게이트와 업로드는 Claude 소유로 유지하며 푸시/머지는 하지 않았다. `workspace-density.css`와 사용자 추론 선택자 확장은 변경하지 않았다. 새 CSS `:has()` 선택자는 추가하지 않았다.

후속 Lucide 교체 뒤에도 공통 117개 검사와 실제 호스트 13개, 아이콘 18개 그룹/6개 버튼 범위를 다시 통과했다. 배치 표본 수와 위반 0건은 동일하다. 새 결과는 `verification/lucide-surfaces-2026-10-23/`와 [아이콘 검증 기록](LUCIDE-ICONS-2026-10-23.md)에 있다.
