# 하단 상태 바의 현재 동작

사용자 요청에 따라 상단 host-busy 이동 선을 제거했다. 기존 하단 상태 바에 실제 동작 이름을 표시한다. 새 설정이나 별도 창은 추가하지 않는다.

`host-activity.mjs`는 실제 호스트 요청의 시작/종료를 관찰한다. 파일 읽기, 저장 결과 확인, 브라우저 연결처럼 고정된 사용자 문구를 사용하며 원문, 명령, URL이나 비밀번호를 snapshot에 넣지 않는다. 150ms 안에 끝난 요청은 표시하지 않고 상태/스트림/메일 등 반복 조회를 장식 동작으로 만들지 않는다. 메일은 기존 처리 단계 표시를 그대로 사용한다. 여러 요청에서는 가장 최근의 지속 중인 요청과 나머지 개수를 표시하고, 하나가 끝나면 남은 요청으로 돌아간다. 관찰자 오류가 실제 작업의 성공을 실패로 바꾸거나 실행을 반복하지 않는다.

Workbench는 실제 실행 ID의 도구, 대화 압축, 공개 초안과 질문/승인 대기 상태를 쉘에 전달한다. 텍스트 조각마다 상위 화면을 갱신하지 않고 작업명이나 상태가 바뀔 때만 전달한다. 현재 실행과 다른 과거 trace를 진행 중으로 표시하지 않는다. 실행 중 명령은 actor가 끝났어도 남는다. 답변/승인 대기는 움직이는 실행 표시와 구분한다.

기존 `MailProgress`의 하단 바를 재사용해 메일과 위키 상태를 유지한다. 공통 시간 모래 아이콘, 글꼴, 글자색과 여백을 사용하며 모션 감소에서도 작업명은 남긴다. 상단 선의 CSS/keyframes와 ambient registry 항목도 제거했다.

검증 명령은 `npm run test:footer-operation`이다. Node의 요청 동시성/실패/조회 제외/실행 범위 검사, 실제 빌드 앱의 지연된 파일 읽기와 임시 프로젝트 실제 저장, 1280/440px, 모션 감소, 대화 작성/대기/명령의 하단 표시와 POP3 폼 회귀를 포함한다. 지연 응답은 테스트 IPC가 제어하며 실제 저장은 기존 worker를 사용한다. 실제 제공자, 회사 계정과 Windows 설치판 검증은 별도다.

결과는 `verification/footer-operation-2026-10-23/report.json`과 `verification/footer-operation-gate-2026-10-23.log`에 보존한다.

최종 게이트는 빌드, Node 18개, 실제 파일 처리 화면 5개, 대화 화면 1280/440px와 POP3 화면 4개 검사를 통과했다. 화면 실행 오류는 없었다. 파일 화면은 미디어 설정 변경 뒤에도 뷰포트가 유지되도록 보완해 1280/440px 캡처를 다시 확인했다. 실제 임시 파일 저장을 독립 재읽었으며 읽기/저장/실패 요청은 총 3회로 재실행되지 않았다.

첫 모션 감소 검사는 `animation-name:none`만 허용해 실패했다. 기존 공통 모션 시스템은 타임라인을 보존하고 `animation-play-state:paused`로 정지하므로 검사 조건을 정정한 뒤 통과했다. 최초 검사 로그와 실패 화면은 `verification/footer-operation-gate-motion-assertion-before-2026-10-23.log`와 결과 폴더의 `previous-motion-oracle/`에 남긴다. 빌드의 기존 Windows bash CJS `import.meta` 경고와 PowerShell 검사 제외는 해결/검증한 것으로 표시하지 않는다.
