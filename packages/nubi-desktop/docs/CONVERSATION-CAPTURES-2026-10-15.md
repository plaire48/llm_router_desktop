# 대화에서 사용한 캡처 표시

에이전트의 앱/웹 확인과 Playwright browser_capture는 분석 문장만 반환하고 이미지 기록을 남기지 않았다. 실제 모델에 전달하는 PNG를 기존 capture 저장소에 보관하고 실행 기록과 답변에 ID 참조를 연결했다. 사용자 첨부 경로는 유지한다.

- 이름과 썸네일로 어떤 화면인지 표시한다. 일부 영역만 캡처했으면 확대 모달에 선택 영역과 픽셀 크기를 표시한다.
- 후속 요청: 보낸 이미지와 사용한 이미지는 공통 아이콘이 있는 한 줄 아코디언으로 기본 접힘 처리한다. 펼칠 때 썸네일을 불러오고 닫으면 렌더링을 해제한다. 전송 전 첨부는 계속 바로 보여 삭제와 전송 대상을 확인할 수 있다. 메일에서 사용한 첨부 이미지도 같은 접힘 방식을 따른다.
- Codex의 간결한 이미지 표시를 참고해 공통 이미지 아이콘과 한 줄 이름을 배치한다. 첨부 제거는 공통 WorkspaceAction과 32px 조작 영역을 사용하고 돌출 테두리나 그림자를 추가하지 않는다. 누비의 폰트와 모달 스타일은 유지한다.
- 확대는 기존 DetailPanel/CX 토큰을 사용한다. 대화 레이아웃을 늘리는 방식 대신 모달에서 실제 같은 이미지 bytes를 표시한다.
- 화면에 가까운 이미지만 지연 로딩한다. 캐시는 최대 12개이며 API 변경 시 초기화하고 실패한 조회는 영구 캐시하지 않는다. 한 메시지에 4장씩 표시하며 나머지는 더 보기로 연다.
- 대화와 진행 상태에는 이미지 bytes나 페이지 URL의 쿼리 정보를 넣지 않는다. 캡처 성공과 이미지 분석 성공은 구분한다. 분석 실패 후에도 이미 찍은 화면은 해당 실행 기록에서 확인한다. 저장되지 않았던 과거 에이전트 캡처를 복원하거나 만들어 표시하지 않는다.
- 사용자 첨부는 기존 4MB 한도를 유지한다. 호스트 캡처는 Playwright의 기존 이미지 한도와 맞춰 8MB 이내 저장을 지원한다. 미리보기 보관 실패는 기존 분석을 중단하지 않는다.

검증: capture 저장/모델 전달/실행 기록/답변 연결 및 Playwright 경로의 자동 검사. `check-conversation-captures.mjs`는 실제 Workbench 컴포넌트에 합성 캡처를 사용하여 1280/440px 썸네일, 공통 모달, 같은 이미지 확대, 누락 상태와 재진입을 확인한다. 실서비스/Windows 화면 캡처 성공과 구분하며 설치판 배포는 이번 범위가 아니다.

결과: 관련 자동 검사 9건 통과. 작업 기록 펼침과 답변 썸네일, 확대 이미지 일치, 재진입을 1280/440px에서 확인했다. 아이콘과 디자인 검사, Electron 로컬 빌드도 통과했다. 확인 중 작업 기록의 웹/앱 캡처 도구 이름이 누락되어 숨겨지는 경로를 함께 수정했다.

접힘 표시 후속 검증: 캡처와 메일 이미지의 기본 접힘, 펼치기 전 조회 없음, 실제 이미지 펼침, 명령/출력 표시와 하단 승인 유지 검사를 통과했다. Electron/macOS Bash에서 실행 후 결과 펼침, 터미널 탭 재열기 시 중복 실행 없음, 직접 입력과 Ctrl+C도 확인했다. Windows 실행은 이번 검사에 포함하지 않았다.
