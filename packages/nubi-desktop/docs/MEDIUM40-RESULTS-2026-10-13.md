# 중간 난이도 40문항 평가 결과

**40개 서로 다른 과제에서 정답과 필수 실행/출처 조건을 확인했다. Claude 28개와 ChatGPT 12개의 혼합 결과이며 단일 모델 40/40 또는 전체 제품 정확도를 뜻하지 않는다.**

| 분야 | 문제 수 | Claude 완료 | ChatGPT 완료 | 정답·근거 재검토 | 완료 시간 중앙값 |
|---|---:|---:|---:|---:|---:|
| Bash | 10 | 7 | 3 | 10/10 | 119.8초 |
| 메일 | 10 | 7 | 3 | 10/10 | 53.3초 |
| 스킬 | 10 | 7 | 3 | 10/10 | 55.8초 |
| OpenWiki | 10 | 7 | 3 | 10/10 | 41.1초 |

## 실행과 채점 경계

- 실제 누비 ProjectService/Pi Agent와 연결된 모델을 실행했다. 입력은 합성 자료다. Bash는 macOS에서 실행했고 메일은 실제 PersonalMail 검색/읽기에 시험 원문을 연결했다.
- Claude Code Opus 5.5, 요청 effort medium, 카탈로그 문맥 1,000,000으로 28개 완료. 나머지 12개에서 claude_cli_failed가 발생했다. 공식 CLI 단일 진단으로 five_hour 한도 utilization=1 및 rejected를 확인했다. 원래 실패 12건은 report.json에 남아 있다.
- 사용자의 대체 모델 승인과 로그인 후 ChatGPT GPT-5.6 Sol, medium, 카탈로그 문맥 272,000으로 같은 12문항을 실행해 모두 통과했다. 질문/자료/기준은 바꾸지 않았다.
- 서로 다른 40문항에 총 52번 시도했다. 최초 12개의 공급자 오류를 삭제하거나 완료로 덮어쓰지 않았다. 한도 초기화 시각은 CLI가 2026-10-13 03:00 KST로 보고했다.
- 최종 사용한 40개 답변의 자동 채점은 36개 통과. 네 표현 오판은 원문과 사전 정답을 대조한 audit.json 및 audit-facts.mjs에 별도 기록했다. 원래 채점 결과는 보존한다.
- 보정은 mail-01(시각과 호실 경계), bash-03(8.0% = 8%), bash-04(한국어 조사), bash-07(주문 번호와 일수 경계)다. 잘못된 값과 다른 숫자는 그대로 실패하는 회귀 검사를 추가했다.
- 실행 중 각 후보 해시는 변하지 않았다. 두 실행 사이 사용자 요청의 질문 폼 UI 변경으로 제품 해시는 다르다. 이 작업에서는 Agent 런타임을 수정하지 않았다. 두 후보 및 동일 benchmarkHash는 combined-report.json에 기록했다.

## 실제 확인한 흐름

- Bash 10개 모두 catalog 뒤 자료 2개를 각각 승인/실행하고 실제 출력을 읽어 결합, 필터, 계산했다. 원본 파일 변경은 없었다.
- 메일 10개 모두 정정/취소/이동/중복 제외 등 서로 다른 원문을 결합했고 필수 메일 원문과 인용 조건을 충족했다. 첨부 분석과 실계정 수신은 평가하지 않았다.
- 스킬 10개 모두 해당 산출물의 기본 스킬과 source-boundaries를 읽었다. 개인정보 가림, 미실행/미확인, 승인 약정과 제외 조건을 유지했다.
- 위키 10개 모두 3개 필수 문서를 읽고 인용했다. Claude 완료 7개는 직접 읽기/검색, ChatGPT 3개는 실제 ask_openwiki 위임을 사용했다. 위임 모델 호출은 각각 8/18/8회였다. 위키 생성/자동 갱신 시험은 아니다.

## 개선 우선순위

1. **답변 반복 줄이기:** 결론은 첫 부분에 나온다. 그러나 Claude 답변 다수는 같은 사실을 근거 목록에서 다시 길게 설명하며, 묻지 않은 필드나 무관한 메일 가능성까지 한계로 나열한다. 결과/필요한 근거/결정에 영향을 주는 제한만 남기고 실행 목록은 상세에 둬야 한다.
2. **위임 비용 줄이기:** 작은 3페이지 문제에도 OpenWiki 위임이 8~18회 발생했다. wiki-09는 약 154초였다. 필요한 자료가 모두 모였는지와 남은 질문을 기준으로 조사 종료를 판단하도록 후속 개선할 수 있다. 이 결과만으로 전체 OpenWiki가 느리다고 단정하지 않는다.
3. **사용량 오류 분리:** CLI가 rate_limit을 보고해도 현재 어댑터는 claude_cli_failed로 표시한다. 공급자 한도/초기화 정보와 일반 CLI 오류를 구분하고 평가 실행기 역시 연속 공급자 실패 후 다음 과제 투입을 멈추는 보강이 필요하다.
4. **미확인 문구 정확화:** 기록에 없는 일정은 “정해지지 않았다”보다 “자료에 없다”, 승인되지 않은 연장은 “연장되지 않는다”보다 “현재 연장 승인 기록이 없다”가 정확하다. 필수 정답 채점 밖의 표현 위험으로 남긴다.
