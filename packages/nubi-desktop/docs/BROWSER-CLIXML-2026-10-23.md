# Browser MCP PowerShell transport

The user reported repeated PowerShell CLIXML failures when opening a browser through MCP. The accessible Mac registry uses the built-in Playwright transport. The user's Windows error body and registry were unavailable, so this identifies a source defect in that path rather than proving the exact original Windows failure.

Before the change, browser discovery invoked `powershell.exe -Command` through PATH without the Text input/output and UTF-8 contract already used by normal project commands. It parsed the entire stdout as JSON and collapsed subprocess failures, timeouts and response parsing into `browser_samsung_unavailable`. The browser path also had no regression test through the actual built-in MCP registry and discovery/launcher boundary.

The fixed read-only helper now uses the Windows system PowerShell path, the existing Text/UTF-8 configuration and a UTF-16LE EncodedCommand. It suppresses only the helper's decorative progress stream, not real errors. A single `NUBI_BROWSER_DISCOVERY:` stdout frame carries JSON. Unrelated stdout is excluded from the data protocol; malformed, duplicated, relative-path and CLIXML responses cannot become executable metadata. No CLIXML object deserialization is used for this protocol. The existing display-only CLIXML decoder and raw process logs are unchanged.

Nonzero exit status always rejects the result, even if stdout contains a valid frame. The original subprocess error remains the cause and its numeric exit code remains available on the discovery error. Timeout and output/protocol failures have separate fixed error codes. No discovery failure automatically launches or retries a browser. Existing browser permissions, tab choice, profile preservation and command approvals remain in force. MCP tool guidance explicitly rejects repeated launches, PowerShell/shell workarounds and Playwright installation as connection recovery.

`tests/browser-powershell.test.mjs` verifies transport, Korean paths, stderr CLIXML alongside valid metadata, exit-code preservation, timeout, buffer limits and invalid metadata. `tests/browser-mcp-discovery.test.mjs` runs the real McpRegistry and official Playwright MCP with a projected Windows helper/launcher: successful metadata opens exactly once and returns the connection wait; a real helper failure opens zero browsers and does not retry. The PowerShell subprocess itself is injected in these tests.

Final focused regression: 72 tests, 70 passed, 2 Windows-only tests skipped, 0 failed. `verification/browser-clixml-final-unit-2026-10-23.log` includes existing raw-log, real Node pipe, encoding and MCP approval checks. The two skips are actual Windows discovery-script execution and actual Windows PowerShell text encoding. The first four failing source-contract tests are retained in `verification/browser-clixml-before-2026-10-23.log`.

Electron build passed. Actual built Electron settings/error/re-entry checks passed 6 cases with no renderer errors, including a projected discovery failure with a readable message and available retry. That case injects a fixed host error code, not Windows execution. An actual temporary Chromium/direct-CDP/official Playwright MCP test passed page open, snapshot and exactly-one observed-ref click. Results: `verification/browser-clixml-electron-2026-10-23.log`, `verification/direct-browser-shell-2026-10-23/report.json` and `verification/direct-playwright-2026-10-23/report.json`.

These checks do not verify the user's Windows PowerShell parser/runtime, actual Samsung installation, connection permission UI, enterprise SSO or installed package. Existing CJS import.meta/module-type build warnings are separate and were not resolved by this change.

Microsoft documents the Text/XML output switch and UTF-16LE EncodedCommand in [about_PowerShell_exe](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-5.1). The progress preference applies only to this fixed helper as described in [about_Preference_Variables](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_preference_variables?view=powershell-7.6).
