# 반영 직후 화면 응답

반영과 승인, 질문 답변을 누르면 먼저 폼을 숨기고 같은 대화에 처리 상태를 표시한다. 작성 중 공개 응답과 현재 동작은 접을 수 있는 진행 기록 밖에서 갱신한다.

## 원인과 변경

기존 제출 훅은 React 상태를 예약한 직후 작업 콜백을 실행했다. 지연 응답 테스트에서는 폼이 빨리 접혔지만 실제 콜백 시작 시점에는 폼이 남고 처리 표시도 없었다. 콜백 앞부분의 편집기 준비 등 동기 작업이 길어지면 이 상태로 화면 그리기가 밀릴 수 있었다. 새 Electron 회귀 검사는 기존 소스에서 `formHidden:false, activityVisible:false, painted:false`로 실패했다. 이 재현만으로 사용자 Windows의 모든 끊김 원인을 확정하지 않는다.

제출 상태는 즉시 커밋하고 다음 화면 그리기를 거친 뒤 기존 작업을 한 번 호출한다. 숨겨진 창에서도 요청이 멈추지 않도록 제한된 타이머를 함께 둔다. 대화별 잠금은 그 사이 다른 승인이나 중복 클릭이 실행을 더 만들지 않게 한다. 처리 중 폼과 초안은 계속 마운트되며 실패 시 같은 내용을 복원한다. 명시적 제출 시에는 최신 진행 위치를 따라가고 이후 사용자가 이전 내용을 읽으면 기존 스크롤 동작을 유지한다.

공개 작성 초안은 진행 기록의 펼침 여부와 분리했다. 현재 동작과 경과 시간도 같은 위치에 표시하고 기존 하단 상태와 같은 실제 도구/작성/대기 구분을 사용한다. 공개 actor 텍스트만 초안에 사용하며 완료 판정, 최종 답변 검토와 저장 재확인 계약은 유지한다. 이 변경은 작업 실행기나 승인 권한을 새로 소유하지 않는다.

## 검증 경계

- 관련 Node 검사 49개 통과, 실패 0. 상태 신호, 스트림, 늦은 snapshot, 질문과 승인, 파일 상태와 진행 순서를 포함한다.
- 실제 Electron renderer의 2560/1920/1280/760/440px 다섯 흐름 통과. 지연시킨 합성 작업의 파일 반영/질문/명령 콜백 25회 모두 호출 전에 폼 숨김과 처리 표시, 앞선 프레임을 관찰했다. 폼 숨김 관찰은 11~18ms이며 실제 저장/모델 완료 시간은 아니다.
- 기록 접기와 현재 도구명, 공개 초안 갱신, 후속 실행의 공백, 입력 중 초점, 실패 후 초안/오류 복원과 중복 클릭을 확인했다. 화면 오류는 0이다.
- 기존 질문/명령 흐름은 Chrome 1280/440/360px와 주입한 OS 알림에서 통과했다. 별도 Electron 승인/순서/초안 보존 다섯 장면도 통과했다. 원래의 모션 감소, 확대 글자와 좁은 화면 검사를 유지한다.

최종 로그와 화면 보고서는 `verification/realtime-feedback-2026-10-24/`에 보존한다. Electron 빌드와 소스 입력/안전 검사 결과도 여기에 둔다. 합성 제공자와 실제 렌더러 검증을 Windows 설치판, Samsung/SSO, 실모델 업무 완료나 모든 화면의 성능 검증으로 확대하지 않는다.
