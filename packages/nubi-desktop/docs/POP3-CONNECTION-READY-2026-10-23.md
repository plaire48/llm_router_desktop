# POP3 로그인 확인 즉시 알림과 폼 닫기

사용자 요청: POP3 연결이 확인되면 바로 알려주고 대기 폼을 닫는다.

기존 흐름은 TLS와 USER/PASS 인증 뒤에도 CAPA, UIDL, 첫 메일 본문과 intake가 끝날 때까지 연결 대기로 묶였다. 이제 개인 저장 보호 준비와 PASS 성공이 확인되면 로그인 성공을 별도로 전달한다. 첫 목록/본문 수집과 정리는 기존 작업에서 계속한다.

- 기존 OpenWiki POP3 전송기에 선택 `onAuthenticated` 관찰만 추가했다. 클라이언트, 인증/조회/중단 알고리즘은 재사용한다. 콜백은 계정, 비밀번호나 서버 응답을 전달하지 않는다.
- 메일 worker의 진행 메시지는 최종 결과와 구분한다. 기존 직접 worker 사용은 기본적으로 최종 메시지 하나만 받는다.
- 서비스 → main → renderer는 `requestId`만 전달한다. UI는 현재 연결과 같은 요청인지 다시 읽어 확인한 뒤 성공 알림을 한 번 표시한다. 제출했던 POP3 폼만 닫으며 재진입한 설정을 닫지 않는다.
- 비밀번호는 기존 메모리 범위를 유지하고 제출 폼에서는 즉시 지운다. 개인 저장 보호 실패, 거절, 취소 또는 이전 요청의 늦은 성공은 완료로 표시하지 않는다.
- 하단 메일 상태도 같은 이벤트에서 새로 읽는다. 폼을 닫으면서 연결을 취소하거나 수집을 다시 시작하지 않는다.

검증:

- 로컬 TLS 서버로 PASS 성공/거절과 UIDL 실패를 분리했다. 인증 성공 콜백은 목록 조회보다 먼저 발생하고 거절 때는 발생하지 않는다.
- 실제 worker가 진행 메시지 뒤에도 계속 실행하고 최종 UIDL 결과를 반환하는 것을 확인했다.
- 메일 회귀 317개 통과, 실제 worker 진행 검사 1개 통과. 초기 집중 검사 23개와 취소/저장 계약도 통과했다.
- 빌드된 실제 Electron UI에서 호스트 인증 상태만 합성했다. 첫 수집 요청을 일부러 끝내지 않은 상태에서도 알림과 폼 닫힘이 최초 28ms, 최종 반복 25ms에 일어났다. 중복 알림, 설정 재진입, 로그인 거절, 취소와 늦은 성공 신호 등 4개 검사 및 renderer 오류 0개를 확인했다. 최종 반복 측정값은 아래 report가 기준이다.
- 실제 회사 POP3 계정이나 Windows에서 성공한 기록은 아니다. 로컬 TLS, 실제 worker, 합성 IPC의 실제 UI 검증을 구분한다.
