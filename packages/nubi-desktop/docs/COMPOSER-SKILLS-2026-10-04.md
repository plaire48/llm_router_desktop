# 입력창 스킬 메뉴

사용자가 등록한 스킬과 추가할 스킬을 구분하고 주변 화면에 맞는 간결한 모달을 요청했다.

## 반영

- 위쪽은 현재 작업의 `listSkills` 결과다. 스킬 이름 아래에 설명을 두며 누르면 기존 초안의 마지막에 `$<name>`을 추가하고 입력창으로 돌아온다.
- 아래쪽은 옅은 공통 파랑 배경의 추가 및 관리 영역이다. AI Workspace는 새 스킬 목록으로, 커스텀 관리는 기존 등록/수정 목록으로 연결한다. 큰 관리 모달의 같은 탭 이름도 맞췄다.
- 등록 목록만 스크롤한다. 관리 버튼과 X는 목록 밖에 유지한다. 긴 이름은 기존 DriftLabel을 재사용하고 설명은 두 줄까지 표시한다.
- 기존 CX 0.5.4의 CxButton, Icon과 누비 FolderMark, 색상/서체/반경/그림자 토큰을 재사용했다. 새 의존성은 추가하지 않았다. 요청에 스킬을 넣는 동작과 등록/설치를 다른 영역에 두고 상세 작업은 기존 관리 화면에서 제공한다.
- 고정 포털을 입력창 +에 맞춰 배치해 컨테이너에 잘리지 않도록 했다. 창/입력창 크기 변경과 스크롤 때 화면 안으로 다시 맞춘다. X/Escape와 Tab 순환, 호출한 +로 초점 복귀를 제공한다. 바깥 클릭으로 닫지 않는다.
- 빈 목록과 로딩을 구분한다. 조회 실패는 공통 토스트와 회색 상태/다시 확인 버튼을 제공하며 등록 항목으로 표시하지 않는다. 이전 조회의 늦은 결과는 닫힌 메뉴나 다른 작업에 적용하지 않는다.

## 발견한 연결 오류

기존 `addSkillToDraft`는 React 상태 함수처럼 updater 함수를 `useComposerDraft`에 전달했다. 이 훅은 문자열을 직접 저장하므로 함수가 초안에 들어가고 `request.trim()` 렌더링이 실패했다. 현재 문자열 초안 뒤에 스킬 호출을 붙이도록 수정했다. 스킬 선택은 모델 호출, 도구 실행이나 파일 변경을 시작하지 않는다.

## 확인 범위

`npm run build` 성공. 사용자 지시에 따라 자동 테스트는 실행하지 않았다. 기존 4320 예시 브리지를 사용해 화면을 직접 확인했다.

- 등록한 스킬 11개와 긴 한국어 이름/설명, 등록 목록 스크롤 중 추가 및 관리 영역 유지.
- 실제 계산한 680×700의 좁은 뷰포트에서 360×440 메뉴가 화면 안에 표시됨. 확인 뒤 뷰포트 원복.
- 기존 초안 보존, 스킬 호출 추가, 공통 토스트와 입력창 초점 복귀.
- AI Workspace/커스텀 관리의 각각 선택된 탭, 모달을 닫고 +로 복귀.
- 기본 뷰포트에서 바깥 클릭 유지, Escape 닫기, Tab/Shift+Tab 순환.
- 빈 목록, 조회 실패와 다시 확인 버튼.

예시 목록은 `?conversation&skills`, 실패 상태는 `?conversation&skills-error`에서만 생성한다. 미리보기는 인증값이나 실제 프로젝트를 읽지 않는다. 실계정 GHES 목록/설치, 모델의 스킬 실행과 Windows 설치판 검증은 이번 확인 범위가 아니다. 실행 중인 Electron 프로세스는 재시작하지 않았다.
