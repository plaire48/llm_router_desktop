# 모든 작업 진행 바 통일

2026-10-23. 사용자가 빠르게 이동하는 진행 바를 모든 화면과 모달에서 같은 채움 방식으로 바꾸고, 프로젝트 로딩과 최초 앱 시작 장면도 포함하도록 요청했다.

## 적용한 동작

- 작업 진행 바는 `TaskProgressBar` 한 컴포넌트로 표시한다. 높이 6px, 공통 둥근 모서리, 옅은 트랙과 누비 파랑 채움을 사용한다.
- 실제 진행률은 왼쪽을 고정한 채 600ms 동안 부드럽게 채운다. `width`를 프레임마다 바꾸지 않고 `transform:scaleX()`로 표시한다. 접근성 값은 실제 수치를 즉시 반영한다.
- 진행률을 모르면 숫자 없이 12초 동안 한 번 차오른 뒤 유지한다. 기존 1.8초짜리 짧은 조각의 횡단/반복을 제거했다. 시각적 활동 표현은 8%에서 68% 폭까지이며 실제 완료율로 노출하지 않는다. 이 상태에는 `aria-valuenow`와 숫자 %가 없다. 시간만으로 100%를 만들지 않는다.
- 앱 시작/준비가 실제로 완료됐을 때만 기존 ready 신호로 100%를 표시한다. 프로젝트 열기는 기존 호스트 완료에 맞춰 덮개를 내리고 입력을 돌려준다. 새 진행 효과를 끝까지 보여주려고 작업이나 화면 전환을 늦추지 않는다. 실패한 프로젝트 열기를 완료로 승격하지 않는다.
- 실제 총량과 처리 수를 유지한다. 위키 갱신의 `5/11`처럼 원래 개수로 제공하던 접근성 범위도 그대로 유지한다. ETA는 기존 실측 처리량 계산을 사용한다.

## 화면 범위

| 화면 | 적용 |
| --- | --- |
| 앱 최초/재실행 시작 장면 | `CinematicIntro`의 자체 이동 막대를 공통 진행 바로 교체. 비행 장면/브랜드/준비 신호와 기존 종료 조건 유지 |
| 모델과 화면 준비 | `NubiPreparing`의 자체 이동 막대를 교체. 실제 ready 때만 완료 |
| 프로젝트 열기/전환/ZIP/Git | `ProjectSwitchCover`의 기본 막대와 기존 `ProjectOpenProgress`/`GitCloneProgress`를 같은 컴포넌트로 표시 |
| 프로젝트 위키 준비와 상세 모달 | `ProjectWikiProgress`, `WikiInitializationProgress`의 실제 단계 진행률 유지 |
| 위키 갱신 | 직접 작성하던 막대를 공통 컴포넌트로 교체. 아직 개수를 모르는 실행에도 공통 대기 표시 제공 |
| 메일 로그인, 파일 가져오기/재개 | 기존 공통 컴포넌트가 새 채움 방식 사용. 실제 완료 수와 연결/취소 계약 유지 |
| 메일 저장 위치 이동과 초기화 확인 | 기존 공통 컴포넌트의 스타일/속도 통일. 단계별 처리 수 유지 |
| 앱 업데이트 다운로드 모달 | native `<progress>`를 공통 컴포넌트로 교체. 실제 다운로드 %와 바이트/남은 시간 유지 |
| 위키 공유/업로드 모달 | native `<progress>`를 교체. 업로드 개수/저장 확인과 미확정 진행 구분 |
| 컨텍스트/제공자 사용량 | 트랙 높이와 모서리 통일. 작업 진행으로 취급하지 않고 실제 사용량/한도와 제공자 고유 색 유지. 대기 애니메이션 없음 |

Desktop `ui/`의 작업 `role="progressbar"`와 native `<progress>`를 검색해 직접 그리던 작업 막대가 공통 컴포넌트에 모인 것을 확인했다. 별도 shared `ContextMeter`는 실제 용량 지표로 유지한다. 스피너, 작업 상태 문구, 입력 슬라이더와 외부 사이트 자체 UI는 작업 진행 바와 구분한다.

## 모션과 성능 계약

공통 시간은 `design/workspace-motion.css`, 재질/높이는 `workspace-identity.css`에 있다. 화면별 CSS에는 시작/프로젝트 화면의 가용 너비나 주변 간격만 남긴다. 새 CSS `:has()`와 의존성은 추가하지 않았다.

기존 모션 정책은 300ms를 넘는 일반 상호작용을 취소한다. 진행 바에만 정확한 600ms transform 전환과 12초 대기 채움을 등록했다. 다른 긴 전환, width 애니메이션과 알 수 없는 반복은 계속 거부한다. 진행을 위해 일반 동시 상호작용 수나 모달 시간 기준을 늘리지 않았다.

활성 최상위 모달의 작업 진행은 계속 보이고, 덮인 페이지의 장식 모션은 기존대로 멈춘다. 숨긴 창, 프로젝트 전환과 시스템 모션 감소를 따른다. 모션 감소에서는 대기 효과를 같은 위치에서 정지하고 실제 % 갱신은 즉시 표시한다. 강제 색상에서는 시스템 배경/강조색으로 구분한다. per-frame JavaScript 타이머나 가짜 처리량은 추가하지 않았다.

초기 검사에서 기존 모션 감소의 광범위 `animation:none!important`가 대기 효과의 객체를 없애 재개 위치를 잃는 문제가 드러났다. 기존 공통 모션 레이어의 정지/재개 방식으로 합쳐 같은 phase를 보존하도록 보완했다. 첫 실패 로그와 후속 통과를 보존한다.

## 검증과 한계

- 관련 단위 검사 37/37 통과. 활성 모달의 진행/배경 정지, 숨긴 창의 동일 phase 유지와 정확한 진행 바 전환만 허용하는 회귀를 추가했다.
- 전체 단위 회귀 2,669개 중 2,468개 통과, 실패 0, 생략 201개. 전체 실행 중 후속 트랙 토큰과 위키 미확정 표시를 보완했으며 이 후속은 최종 관련 단위 검사와 최종 렌더링 검사로 별도 확인했다. 다른 시점의 검사를 모두 최종 화면 검사로 합산하지 않는다.
- 최종 공통 진행 UI 검사 28/28 통과. 실제 제품 컴포넌트와 모달/모션 정책을 사용해 1280/440px에서 실행했다. 페이지, 다운로드/보관/위키 공유 모달, `5/11` 갱신, 모션 감소/복귀, 숨김, 강제 색상과 시작/프로젝트 장면을 포함한다. 시작/준비는 실제 ready 신호 뒤 `aria-valuenow=100`과 종료를 확인했다. 합성 API를 사용하며 실제 다운로드/업로드/메일 쓰기는 하지 않는다.
- 공통 모션 품질 145/145 통과. 초기 phase 보존 실패 뒤 정정한 결과이며 기준을 낮추지 않았다.
- 실제 빌드 Electron에서 임시 두 프로젝트 전환을 확인했다. 덮개/실제 호스트 단계/경과 시간, 배경 정지, 성공 후 새 프로젝트 노출, 실패 후 원래 프로젝트/입력 복원과 모션 감소가 통과했다. Git 진행, 기존 ETA, 메일 이어 가져오기 검사도 통과했다.
- `build:electron`, `design:check` 통과. 기존 CJS/import.meta 경고는 이 변경으로 해결했다고 표시하지 않는다.

전체 `verify:identity`는 통과하지 않았다. 실제 Electron shell 24개 확인 뒤 스킬 회귀가 대화의 답변을 확인하는 단언에서 실패했다. 스킬 실행/검토 근거와 이 UI 단언 실패를 진행 바 성공으로 숨기지 않는다. 추가 위키 재개 검사는 진행 바에 도달하기 전에 별도 아이콘 크기 기대값(16px)과 현재 표시(14px)의 차이로 실패했다. 이를 통과시키려고 제품 아이콘이나 단언을 바꾸지 않았다. 위키 바의 실제 개수/분모와 미확정 전환은 최종 공통 UI 검사에 따로 포함했다. SVG를 읽지 못하던 관련 fixture 로더는 수정했다.

근거는 `verification/progress-unification-2026-10-23/`에 있다. `ui/result.json`, `ui-regressions.json`, `full-unit.log`, `unit-verified.log`, `identity.log`와 변경 전 소스를 보존했다. 실제 Electron 전환의 화면/결과는 `verification/project-switch-cover-2026-10-23/`, 모션 145개 결과는 `verification/motion-1.3.0/progress-fill-final/`에 있다.

이 결과는 로컬 macOS 소스와 Electron/Chrome 검증이다. Windows 설치 파일 제작/배포/설치/재실행이나 사용자 PC 체감 검증은 하지 않았다. 기존 설치된 Windows 앱에 자동 반영됐다고 보고하지 않는다.
