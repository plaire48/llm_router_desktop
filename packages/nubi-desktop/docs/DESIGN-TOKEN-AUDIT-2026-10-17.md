# Workspace 화면과 모달 토큰 점검

대화, 메일과 첨부 미리보기, 위키, 설정, 스킬, AI Workspace 및 오른쪽 도구에 쓰이는 스타일을 조사하고 공통 토큰에 맞췄다. 후속 사용자 의견에 따라 [iOS 참고 아이콘 크기](ICON-SCALE-IOS-2026-10-17.md)를 조정하고 전체 화면/모달 검사를 다시 수행했다. CSS 선언 조사와 실제 렌더링 검사를 구분한다. 외부 웹사이트와 사용자가 작성한 문서의 서식은 앱 UI 검사 대상과 구분한다.

## 수정 내용

- `design/workspace-identity.css`를 글꼴, 글자 크기, 굵기, 의미별 색상과 간격의 기준으로 유지했다. 개별 화면의 고정값을 공통 토큰으로 치환했다.
- CX 기본 CSS를 renderer의 첫 import로 이동했다. 일부 화면의 스타일 뒤에 기본 CSS가 로드되면서 계정 이름, 날짜, 담당자 선택 등이 12px로 되돌아가던 순서를 수정했다. 검증 fixture도 같은 순서로 맞췄고 `design:check`에 순서 검사를 추가했다.
- body portal, 상단 도구와 AI Workspace의 CX 글자 토큰도 누비 값에 연결했다. 주요 UI는 15px, 읽기 본문은 16px, 보조는 14px, 모달 제목은 18px/600을 기준으로 한다. 모든 값은 rem으로 확대를 따른다. 큰 본문 17px, 섹션 20px와 화면 제목 24px도 명시한 토큰으로 유지한다.
- 굵기는 일반 400, 라벨 500, 제목/선택 강조 600, 본문 strong 700으로 정리했다. 개별 화면의 650/800/900 등 불규칙한 굵기를 제거했다.
- 선택/주 동작은 누비 파랑, 일반/보조/오류/경고/성공은 의미별 전경과 배경을 사용한다. 그림자와 시작 장면 색상도 이름 있는 토큰으로 관리한다. Office 앱 식별색, 제공자 표시, 코드/터미널과 시작 그림은 용도별 토큰을 유지한다.
- 정의 없이 참조하던 위키 제목, 메일 저장 안내, 첨부 이미지 배경, 스킬 선택 색상 등의 이름을 실제 토큰으로 연결했다. CX 내부의 프로필 오류 배경과 작은 프로필 글자에도 호환 토큰을 제공한다.
- 모달은 기존 공통 계약의 가로 여백 24px, 좁은 화면 16px, 섹션 간격 20px, 40px 동작 영역과 공통 닫기를 유지한다. 표와 목록의 배치 크기는 임의로 늘리지 않았다.
- 첨부 메일의 HTML iframe에도 앱 글자 배율, 허용된 테마 변수와 번들된 한글 FontFace를 전달한다. 같은 글꼴 이름만 표시하고 OS 글꼴로 대체되는 문제를 방지한다. 실제 iframe에서 Noto Sans KR 로드까지 확인했다.
- 대화 `…`에는 항상 옅은 배경을 넣었다. 고정 대화는 날짜보다 앞의 `고정` 영역에 모으고 최근에 고정한 순서로 표시한다. 고정 후 키보드 초점, 프로젝트 구분, 새로고침과 앱 재시작 보존도 확인했다. 상세는 [대화 고정](CONVERSATION-PINS-2026-10-17.md).

원문 HTML의 인라인 서식, Word 문단, PPT 개체와 Excel 데이터 영역은 문서 보존 계약을 따른다. 문서 눈금, 파일 종류 기호와 편집기 코드는 일반 UI 글자 크기의 예외다. 외부 로그인 페이지와 OS 대화상자는 해당 앱의 UI를 유지한다.

## 소스 조사

`scripts/audit-design-tokens.py`는 esbuild 실제 입력 목록을 기준으로 도달 가능한 CSS를 구분한다. 사용자 정의 토큰의 선언 자체는 아래 집계에서 제외한다. Python `tinycss2`가 필요한 개발용 조사이며 제품 실행 의존성은 아니다.

| 항목 | 최초 조사 | 최종 조사 |
| --- | ---: | ---: |
| 조사 CSS / 활성 CSS | 83 / 79 | 85 / 81 |
| 글꼴/크기/굵기/행간/자간 선언의 토큰 참조 | 59.9% | 91.7% |
| 색상 관련 선언의 토큰 참조 | 75.7% | 79.2% |
| 여백/간격/모서리 선언의 토큰 참조 | 57.9% | 79.8% |
| Desktop 자체 CSS의 타이포그래피 고정값 후보 | 691 | 0 |
| Desktop 자체 CSS의 색상 고정값 후보 | 191 | 0 |

작업 중 활성 스타일이 추가되어 분모가 다르다. 이 비율은 디자인 준수율이나 사용자 평가 점수가 아니다. `inherit`, `transparent`, `0`, `currentColor`처럼 토큰이 필요 없는 값도 분모에 포함된다. shared extension CSS에는 타이포그래피 고정값 후보 74개가 남으며 Desktop의 마지막 스타일 계층과 실제 계산값으로 확인한다. 여백 고정값 후보 77개 중 자체 CSS 72개는 상대 본문 간격과 배치 기하 등을 포함한다. 후보를 모두 오류로 간주하거나 100% 토큰화로 표시하지 않는다.

조사 원장과 최초/수정 후 기록: `verification/design-token-audit-2026-10-17/`. `baseline-inventory.json`, `final-inventory.json`과 두 `migrations*.json`을 보존한다.

전체 Node 회귀 이후에 CSS 순서/토큰/표시, 개발용 검사와 모션 훅을 추가로 수정했다. 모션 훅의 관련 Node 25개와 모션 활성/감소 반복 검사를 별도로 통과했다. 최종 UI 재검사와 빌드를 별도로 남겼으며 전체 Node 회귀를 그 이후 다시 실행했다고 표시하지 않는다. `test:gates`에는 AI Workspace 추가 검사를 `test:workspace-ui`로, 아이콘 크기 검사를 `test:icons-ui`로 연결했다. 문서 미리보기의 기존 읽기 크기 계산을 같은 스타일 함수로 정리한 후 관련 Node 검사 16개도 별도 통과했다. 전체 `test:gates` 명령 자체를 이번 작업에서 한 번에 실행한 것은 아니다.

글자 검사는 보이는 앱 텍스트의 계산된 font-family, 크기와 굵기를 확인하고 작성 문서/코드/숨긴 글자는 제외한다. 색상은 실제 값의 목록과 공통 의미 색 7쌍의 대비 4.5 이상을 확인한다. 모든 가능한 배경 조합의 접근성 인증을 뜻하지 않는다. 자동 검사 외에 대화, 고정 목록과 프로필의 실제 스크린샷을 확인했다.

최초 전체 화면 검사는 숨긴 닫기 버튼을 0px 버튼으로 판정했다. 검사기가 보이는 버튼만 검사하도록 수정했다. 추가 패널 fixture는 처음에 실제 앱의 `.desktop-shell` 부모를 빠뜨려 Desktop 공통 모달 스타일이 적용되지 않았다. 부모를 실제 구조에 맞춘 뒤 다시 확인했다. 이 두 시험 설정 오류를 제품 수정 효과로 집계하지 않는다.
