# 실행 중 메시지와 진행 표시

누비 브라우저의 `TaskPlan`, `AgentTrace`, `QuestionForm`, `QueuedInputs`, `agent-inbox`와 Pi `takeInput`을 Electron Workspace에 직접 연결했다. 실행별 계획/발화와 질문 배치의 최신 계약은 [대화 흐름 보완](AGENT-CONVERSATION-FLOW-2026-10-04.md)을 따른다.

## 사용자 흐름

Electron의 모달과 작은 팝오버는 흰 표면에 누비 파랑 선택/호버를 사용한다. 포털 모달의 위험색 버튼도 같은 강조색을 사용하며 승인/삭제 대상과 설명은 유지한다. 카드, 헤더/푸터와 일반 컨트롤의 외곽선은 제거하고 키보드 초점은 유지한다. 복구 대기 표지판만 기존 크기로 빨간색 표시한다. 오류 토스트의 기존 상태 구분은 유지한다.

대화의 모델 답변에 공통 뱁새의 눈깜빡임과 작은 숨쉬기, 유휴/호버 표현을 재사용한다. 작은 아이콘의 이동은 1px이며 성공이나 진행 상태를 애니메이션으로 추정하지 않는다. 시작 화면의 새는 입력창 초점으로 멈추지 않으며 배경은 기존 입력 중 정지 규칙을 유지한다. OS 모션 감소와 숨겨진 화면의 정지는 유지한다. 추론 글자색은 누비 파랑이며 번개는 표시하지 않는다.

- 실행 중에도 입력한다. Enter 또는 위 화살표로 대기열에 넣는다. Shift+Enter는 줄바꿈이다.
- 대기 메시지의 위 화살표는 **지금 반영**이다. 모델 응답을 중단하고 같은 실행에 전달한다. 실행 중인 도구는 끝날 때까지 기다리고 그 결과를 보존한다.
- 대기 메시지는 순서대로 이어서 실행한다. 수정하면 입력창으로 돌아오고, 휴지통으로 지운다. 손잡이로 끌거나 Space와 방향키로 순서를 바꾼다.
- 질문, 승인, 브라우저 위임, 앱 연결 또는 미확정 실행 대기에서는 자동으로 이어가지 않는다. 중지한 대기열은 보존하고 사용자가 실행해야 한다.
- 계획은 현재 단계와 짧은 요약을 먼저 보여준다. 단계 목록, 완료 기준과 계획 변경은 펼쳐 본다. 진행은 실제 실행 이벤트에 연결한다. 답변 종료를 단계 완료나 검증 통과로 바꾸지 않는다.

## 실행 경계

### Electron 진행 화면 보완 2026-10-02

Electron Workbench는 공유 `TaskPlan`과 `AgentTrace`를 함께 렌더링한다. 이전에는 Pi의 도구 진행과 공개 발화가 `task.trace`에 저장돼도 화면에는 계획만 표시됐다. 이제 계획 수립/수정, 실제 도구 시작과 결과, 모델이 도구 호출 전에 보낸 공개 안내를 같은 대화 안에 표시한다. 공개 안내는 기존 비밀값 제거와 600자 제한을 재사용하며 비공개 추론은 읽거나 표시하지 않는다.

호스트의 실행 ID를 계획 변경, trace와 최종 답변에 연결한다. 현재 실행의 계획과 진행만 해당 답변 앞에 배치하며, 새 요청에는 이전 실행의 계획/진행을 섞지 않는다. 공개 안내와 최근 완료 동작 3개는 유지하고 전체 진단은 기본 화면에 추가하지 않는다. 기존 계획 변경 비교와 펼치기, 사용자 스크롤 위치 보존을 재사용한다. 중단된 actor의 미확정 도구는 결과 확인 대기로 표시하고 완료/취소로 추정하지 않는다.

Desktop의 고정 도구 목록과 호스트 ID 검사만 공유 trace 정규화기에 전달한다. 브라우저와 Office의 기본 허용 목록/표시 방식은 유지한다. 새 패키지는 추가하지 않았다. 이번 변경은 Electron 빌드로 확인했으며 사용자 결정에 따라 테스트, 실행 화면 검사와 실계정 모델 검증은 수행하지 않았다.

SQLite task inbox에 먼저 저장한 뒤 모델이 가져간다. 제출 ID는 중복 제거에 쓰고, 현재 작업과 실행 체인 및 워커의 제공자/모델 연결 세대에 묶는다. 순서 변경은 드래그 시작 시 목록과 비교한다. 계정 변경이나 워커 재시작 뒤 이전 연결 메시지를 자동 전달하지 않는다. 삭제/수정으로 복구해 다시 보낼 수 있다. 인증값은 저장하거나 모델에 전달하지 않는다.

`지금 반영`은 actor 추론만 중단한다. Pi는 이전 응답과 그 응답의 미실행 도구를 폐기하고 실제 사용자 메시지를 같은 대화에 넣는다. 현재 도구, 원래 요청, 승인, 관찰과 영수증을 보존한다. 최종 검토 중 새 메시지가 오면 오래된 판정을 게시하지 않고 추가 요청을 포함해 다시 검토한다. 큐 내용은 승인이나 새로운 관찰 권한이 아니다.

대화 본문만 스크롤하고 대기열과 입력창은 공통 `composer-stack`으로 화면 아래에 함께 배치한다. 좁은 입력창에서는 컨트롤을 줄바꿈해 버튼과 이름을 가리지 않는다. 공통 토큰, 아이콘, 접근성 이름과 툴팁, 키보드 이동, 모션 감소 설정을 사용한다. 전송 응답을 기다리는 동안 입력한 초안은 지우지 않는다.

## Electron 화면 보완 2026-10-02

컨텍스트 도넛은 새 대화와 기존 대화의 입력창 모두에서 추론 오른쪽에 표시한다. 첫 응답 전이나 실패로 사용량이 없더라도 숨기지 않는다. 비어 있는 새 대화는 0, 사용량이 미확인인 대화는 `—`로 표시하며 모달에서 현재 선택한 모델의 카탈로그 한도를 확인한다. 다른 모델의 이전 사용량을 현재 모델의 비율로 표시하지 않는다. 한도가 미제공이면 임의의 숫자로 채우지 않으며 응답 종료를 사용량 수신으로 취급하지 않는다. 0 사용량에서도 도넛 형태를 볼 수 있도록 옅은 트랙만 유지하고 버튼 외곽선은 추가하지 않는다. Electron 빌드만 수행하며 테스트와 실계정 확인은 별도다.

별도 큐 실행기를 만들지 않고 기존 공통 inbox와 QueuedInputs, Pi takeInput을 유지한다. 반영 대기 메시지는 대화 본문의 맨아래에 표시한다. inbox에서 실제 대화로 들어온 첫 메시지의 inputId를 기준으로 이후 메시지와 답변도 같은 하단 영역에 시간 순서대로 이어지며, 반영 후 기존 작업 카드 위로 이동하지 않는다. 입력창의 대기열은 그 아래에 유지한다.

브라우저 App의 followReply와 ResizeObserver 방식을 Desktop의 대화 viewport에 적용한다. 메시지를 보내거나 지금 반영할 때 최신 위치를 따라간다. 이후 사용자 발화가 실제 대화에 추가될 때도 하단으로 이동한다. 사용자가 이전 내용을 읽으려고 위로 스크롤하면 일반 진행 변경이나 답변 때문에 하단으로 강제로 이동하지 않으며 최신 메시지로 돌아가는 아이콘을 제공한다. 앱 전체나 상위 메뉴를 스크롤하지 않는다.

입력창 컨트롤은 공통 NubiComposerBar의 양쪽 슬롯으로 나눈다. 최신 사용자 결정(2026-10-02)에 따라 왼쪽은 스킬, 모델, 추론, 토큰 도넛 순서다. 도넛은 추론 조절 바로 오른쪽에 둔다. 오른쪽은 입력 펼치기(필요할 때), 승인 방식, 위 화살표 순서이며 실행 중 중지 아이콘도 오른쪽에 둔다. 좁은 창에서는 같은 정렬을 유지한 채 줄바꿈한다.

추론 팝오버는 파란 단계 이름, 기본값 복귀와 단계 점이 보이는 가로 슬라이더를 사용한다. 번개, 모델명과 중복 단계 설명은 표시하지 않는다. native range의 클릭, 드래그와 키보드 조절을 유지하고 드래그 중에는 미리보기만 갱신하며 놓을 때 한 번 적용한다. 취소하면 기존 적용값으로 되돌린다. 화면의 `Ultra`는 표시 이름이며 Pi API 요청값은 `max`다. 이전 `ultra` 저장값은 경계에서 `max`로 정규화한다. 계정 카탈로그의 `supported_reasoning_levels`와 `default_reasoning_level`을 보존하고 모델 선택 시 지원 단계를 다시 확인한다. 서버의 요청 거절은 공통 오류 분류기를 재사용하며 HTTP 상태, 허용된 parameter와 오류 코드, 실제 추론 값만 진단에 남긴다. 본문과 인증값은 기록하지 않는다. public API와 설치된 Pi 계약을 확인한 수정이며 실제 로그인 모델의 정상 응답 여부는 별도 확인해야 한다. 실행 중인 워커에 새 허용값을 적용하려면 앱을 다시 실행해야 한다.

스킬과 추론 팝오버의 알림은 E2E Report의 `src/Toast.jsx`, `toastStore.js`, `toast.css`에서 단일 알림 교체, 밝은 카드, 상태 아이콘과 같은 시계를 사용하는 만료 표시를 가져왔다. 공통 `WorkspaceToast`에 연결하고 누비의 상단 배치와 2초 기준을 유지한다. 알림에 키보드 초점이 있거나 화면이 숨겨지면 만료 시계를 멈추며, Escape 또는 닫기로 원래 초점을 복귀한다. 모션 감소에서는 원형 시간 표시를 세 단계로 갱신한다. 오류는 카드 전체를 붉게 강조하지 않고 아이콘으로 구분한다. 별도 패키지는 도입하지 않았다.

스킬 선택은 기존 초안을 보존하면서 `$스킬이름` 참조를 요청 끝에 추가한 뒤 토스트를 표시한다. 실제 실행이나 설치 완료를 뜻하지 않으며 기존 계획과 `use_skill` 계약을 유지한다. 스킬 목록 조회 실패는 빈 목록 성공으로 처리하지 않는다. 추론은 제공자 응답의 적용값을 확인한 뒤 저장하며 성공 토스트는 표시하지 않는다. 실패하면 이전 선택으로 되돌리고 2초 오류 토스트를 표시한다. 적용 중 중복 입력은 차단한다. 이번 변경은 Electron 빌드만 수행하며 사용자 결정에 따라 테스트와 실모델 호출은 하지 않는다.

ChatGPT 계정 모델 목록 API의 `context_window`와 `max_context_window`를 현재 카탈로그 한도와 모델 최대 한도로 각각 보존한다. 최대 한도는 토큰 상세에서 별도로 표시하며 도넛과 실행 예산의 분모를 자동으로 올리지 않는다. API가 현재 한도를 주지 않아 내장 목록으로 보충하면 출처를 표시한다. 최대 입력/출력은 제공된 필드만 사용하며 값이 없다고 컨텍스트 한도를 복사하지 않는다. 워커 재실행 후 모델 목록을 다시 받아야 새 메타데이터가 적용된다. 로컬 Codex 캐시에서 필드 구조를 확인한 결과와 누비 실계정의 새 API 응답 성공은 구분한다.

이번 변경은 `npm run build:electron` 빌드를 완료했다. 사용자 결정에 따라 테스트, Electron 실행 검사와 실모델 측정은 수행하지 않았다. 아래 검사는 기존 계약과 검사 방법의 기록이며 이번 변경의 실행 결과가 아니다.

## 선택 근거와 검사

기존 브라우저의 검증된 큐 계약과 Pi steering을 재사용해 호스트마다 별도 큐 실행기를 만드는 비용과 차이를 줄였다. 브라우저에 고정된 MIT `@dnd-kit/core`, `sortable`, `utilities`를 그대로 사용하고 새 패키지를 추가하지 않았다. 계획의 실제 완료 판정은 [기존 작업 계획 계약](TASK-FIRST-WORKSPACE.md)을 유지한다. 모델의 completed 입력을 허용하거나 체크 표시를 추정하지 않는다.

- `node --test tests/agent-input.test.mjs`: FIFO, 중복, 추론 중단, 실행 중 도구 보존, 취소, 순서 스냅샷, 연결 격리와 최종 검토 중 입력.
- `node scripts/check-agent-input.mjs`: 실제 Workbench, SQLite와 소스 조회를 사용하는 Chromium 검사. Enter, 초안 보존, 키보드 순서 변경, 수정/삭제/지금 반영, 작은 창과 실제 계획 상태를 확인한다.
- 공유 실행기 회귀, 기존 호스트 허용 목록 대조, 화면 검사, 웹뷰/워커 빌드와 실제 macOS VS Code 통합 결과는 주 포크 `docs/WORKSPACE-PARITY-2026-10-01.md`에 기록한다.

모델 응답은 합성 입력이다. 실모델 품질과 Windows 제품 실행은 미검증이다. 최종 설치 파일을 만들거나 커밋/푸시하지 않았다.


### 이름의 호버 모션

디렉토리, 프로젝트, 대화 목록과 제목, 파일 이름, 검색 결과, 스킬과 모델 이름은 Desktop `DriftLabel`을 재사용한다. 정지한 위치에서 왼쪽으로 48px/s 이동하고 완전히 사라진 뒤 오른쪽 경계에서 다시 들어온다. 반복 중 반대 방향 이동은 없다. 실제 글자와 표시 영역의 폭으로 시간을 계산하며 시스템 모션 감소와 숨겨진 창을 존중한다. Web Animations API를 사용하고 새 의존성은 추가하지 않았다. 이번 확인은 Electron 빌드이며 자동 테스트와 실계정 응답 검증을 대체하지 않는다.


### 프로젝트 도구와 고정 대화

왼쪽 레일의 점 세 개 메뉴를 제거했다. 설정에는 기본 터미널 선택만 남기고 프로젝트 도구를 중복하지 않는다. 기본 셸 변경이 확인되면 이전 일회 셸 선택을 해제해 다음 실행에 적용한다. 파일과 Git 변경은 왼쪽 레일에서 열고, 터미널은 보조 영역의 도구 추가에서 탭으로 연다. 고정 압정은 기존 액션 자리에 항상 보이며 다른 버튼은 기존 hover/focus 규칙을 유지한다. 불투명도만 바뀌므로 호버 전후 위치와 행 폭이 같다. 이번 확인은 Electron 빌드에 한정한다.
