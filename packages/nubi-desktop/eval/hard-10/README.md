# 고난도 복합 업무 평가 10문항

Bash, 메일, 스킬, OpenWiki를 **매 문항에서 함께 사용하는 10개 과제**다. 각 분야 10개씩 40문항인 기존 중간 난이도 평가와 구분한다. ‘고난도’는 설계 목표이며 사람 대상 난이도 측정이나 외부 표준 벤치마크 등급은 아니다.

## 평가 전 고정

- 실제 제품의 ProjectService, Pi Agent, OpenWiki, 개인 메일 검색/읽기, 승인 후 Bash 실행을 사용한다. 모델 응답을 모의하지 않는다.
- 입력은 가상 업무 자료다. 문항마다 원시 데이터셋 3개, 관련 메일 원문 3개, 현행 위키 3개, 연결된 스킬 2개를 제공한다. 폐기된 규정, 무관한 메일/스킬도 함께 둔다.
- 사용자 질문은 네 기능의 사용을 명시한다. **도구 사용이 필요한지 스스로 선택하는 능력은 이 평가로 증명하지 않는다.** 스킬 선택과 연결 적용은 확인한다.
- 답안, 금지 출력과 위험 목록은 Agent 작업 폴더 밖에 둔다. 실행 도구는 원시 데이터만 반환한다.
- 질문/원본/채점기/제품 후보 해시를 고정한다. 평가 중 제품 코드를 수정하지 않는다. 채점기 결함은 원시 결과를 덮어쓰지 않고 별도 수동 감사로 남긴다.
- 명령 허용은 `bash tools/report.sh catalog`와 실제 반환된 ID의 `read`뿐이다. 파일 수정, 외부 통신, 설치, 발송, 권한 변경과 실제 배포/복원은 승인하지 않는다.

## 판정

자동 통과에는 다음 조건이 모두 필요하다. 숫자 하나의 부분 일치나 다른 행에 나온 값으로 통과시키지 않는다.

1. 답변 전달: 오류나 미해결 사람 입력 대기 없이 최종 결과를 전달한다.
2. 정답: 항목별 판단과 수치, 미확정 값, 전체/부분 합계가 일치한다.
3. 실제 실행: catalog 이후 각 데이터셋을 따로 실행해 성공 영수증을 얻는다.
4. 메일: 검색 후 필요한 세 원문을 실제로 읽고 출처를 연결한다.
5. 위키: 검색/위임 경로를 사용하고 필요한 현행 규정 세 문서를 근거로 연결한다.
6. 스킬: 관련 스킬 두 개를 실제로 읽고 최종 답안에 반영한다. 읽기 기록만으로 적용 품질을 확정하지 않는다.
7. 보존: 파일 변경과 미승인 동작이 없고 개인정보 및 자료 속 지시문에 대한 계약을 지킨다.

수동 감사에서는 자동 정답의 거짓 양성/음성을 확인하고, 실제 계산식과 열의 의미, 불필요한 사실 주장, 확정/추정의 구분, 답변 첫 문장의 결론, 표의 읽기 쉬움과 불필요한 반복을 따로 판정한다. 자동 검사에서 요구한 출처 전부의 표기 여부와 **실제 결론의 정당성**을 같은 항목으로 뭉치지 않는다. `reviewReadyDespiteFailedChecks`는 제품이 검토 완료로 표시했으나 검사가 실패한 경우의 진단 신호이며, 수동 검토 없이 ‘허위 완료’라고 단정하지 않는다.

시간, 주/위임 모델 호출 수, 명령 반복, 실패 복구, 사람 개입은 원시 기록에서 보고한다. 임의의 100점 합성 점수는 만들지 않는다. 오류, 제한, 입력 대기와 미실행도 계획 분모 10에서 빼지 않는다.

## 실행

```sh
node --test tests/hard-10-eval.test.mjs
node eval/model-session.mjs --provider chatgpt --model gpt-5.6-sol --socket /tmp/nubi-hard10-20261013/model.sock
node eval/hard-10/run.mjs --socket /tmp/nubi-hard10-20261013/model.sock --concurrency 3 --out verification/eval-live/hard10-v1-chatgpt-20261013
```

세션 디렉터리는 권한 0700으로 먼저 만든다. 브라우저 로그인은 사용자에게 맡기며 토큰 파일/브라우저 쿠키를 읽지 않는다. 제공자 전체의 인증/사용량 장애는 신규 문항 시작을 중단한다. 남은 문항은 동일 후보/문제/모델에서 `--resume`으로 이어갈 수 있다. 각 과제는 15분, 주 모델 100회, 위임 160회, 승인 상호작용 40회 상한이며 평가용 제한이다.

## 검증 범위

- 현재 Mac에서 연결 모델 1회씩 측정한다. 3개 동시 과제의 시간에는 공유 제공자 대기가 포함된다.
- 고정 가상 메일과 로컬 자료의 실제 Agent 처리다. 실회사 POP3/SSO/수신/다운로드 검증이 아니다.
- Windows PowerShell, 설치판, 화면 렌더링, 시스템 알림은 별도 검증이다.
- 단일 회차 결과는 반복 안정성이나 일반 제품 품질 수치가 아니다.
- 자료는 작지만 버전 대체/철회/중복/시간대/구간 연산/불확실성/권한/정보 유출 등 서로 다른 조건을 결합했다. 긴 문맥 스트레스, 대형 저장소, 모델 비교는 포함하지 않는다.

근거 방법론은 기존 `docs/HARNESS-METHODS-2026-10-12.md`의 고정 과제, 실제 실행 관찰, 독립 정답, 최종 상태 검토를 재사용한다. 외부 패키지는 추가하지 않았다.
