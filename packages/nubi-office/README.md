## Excel, Word, PowerPoint 특화 확장 (0.8.2 사전 배포판)

하나의 설치 파일에서 **Excel / Word / PowerPoint**를 선택하도록 구성했습니다. 공통 누비 UI와 실행 엔진은 함께 포함되며 앱별로 별도 프로그램을 설치하지 않습니다. 0.8.2에는 아래 기능과 로컬 Python 스킬 실행, 작업 위치/화면 관찰이 포함됩니다.

- Word: 기본 제목 스타일, 문단과 표 작성, 선택한 단순 문단 수정, 새 사본 저장.
- PowerPoint: 제목/본문/발표자 노트 작성, 생성 슬라이드 보완, 선택 슬라이드 복제, 단순 도형 텍스트 수정과 넘침 확인.
- 공통: 앱별 native 도구, 계획과 순차 실행, 제안/결과 검토, HITL, 충돌 확인과 미확정 쓰기 재전송 금지.
- Open XML SDK를 Word의 메모리 XML 검사에 추가했습니다. 기존 파일의 외부 ZIP 재저장을 하지 않습니다.

Word/PPT native 컴파일과 새 선택형 설치를 Windows에서 검사했습니다. 실제 Office 2016, 회사 모델과 NASCA는 아직 검증하지 않았습니다. 복잡한 Word 필드/변경 추적, PPT rich text/차트/이미지 생성은 지원 완료 항목이 아닙니다. [앱별 기능, BP, 오픈소스 비교와 검증 경계](docs/OFFICE-2016-SPECIALIZATION.md).

아래 버전별 기록은 당시 Excel 구현의 이력입니다. 현재 UI는 작업 방식을 자동 선택하고 추가 도구는 더 보기에 둡니다.

[적용 근거와 검증 범위](docs/AGENT-QUALITY-BP.md). 0.8.2 설치 파일에 포함됩니다.

## 기존 양식 채우기 (소스 반영)

원본에서 항목·수식·병합·입력 제한을 분석하고, 항목과 셀 연결을 확인한 뒤 같은 실행의 객관식·주관식 질문으로 부족한 값을 받습니다. **양식 채우기** 모드는 확인된 입력 칸의 값만 바꾸고 기존 수식·서식을 유지합니다. 분석 명세는 Excel 사본 내부 XML에 등록해 재사용하며, 비교한 항목·차이·미확인 항목을 보여줍니다. NASCA는 회사의 Excel 열기/저장 경로를 사용하되 암호화 상태는 미검증입니다. 0.8.2 설치 파일에 포함됩니다. [분석과 작성의 역할·사용 흐름·검증 범위](docs/TEMPLATE-FILLING.md)

## Excel 2016 다중 시트·하위 분석 확장 (소스 반영)

통합문서의 여러 시트·값·수식과 표/차트/피벗/이름 정의를 조회하고, 독립적인 범위 분석을 선택 모델로 나누어 수행하는 경로를 추가했습니다. 수정은 기존 선택 범위와 HITL을 유지하며 참고한 원본이 바뀌면 반영 전에 다시 검토합니다. 0.8.2 설치 파일에 포함됩니다. [지원 범위·Anthropic 방법론·검증 상태](docs/EXCEL-2016-AGENT.md)를 참고하세요.

## 0.8.2 연결 오류와 반복 복구 수정

- 연결 실패의 원인을 인증서·주소·서버 접속·시간 초과·응답 형식으로 구분해 표시합니다. Windows에 이미 등록된 인증서를 자동 사용하며 별도 인증서 설치나 검증 해제는 하지 않습니다.
- 정상적인 `R1` 요구사항 ID와 JSON을 감싼 Markdown을 처리합니다. 계획도 나오지 않은 상태에서 복구 안내만 쌓이던 재현 사례를 수정했습니다.
- 도구 1개 실행 → 실제 결과 → 다음 모델 호출 순서로 진행합니다. 도구 호출을 만들지 못하는 응답은 같은 모델에 JSON 도구 요청으로 바꿔 검증합니다.
- 진전 없는 응답이 3회 반복되면 원인과 보존한 초안을 보여주고 **다시 시도 / 작업 중지**를 기다립니다. 재시도 자체를 완료한 작업처럼 표시하지 않습니다.

0.8.2는 Windows 설치 검사와 설치된 native worker 실행 검사를 통과한 사전 배포판입니다. UI 동기화 문맥 대기와 UTF-8 선행 문자(BOM)로 인한 worker 첫 응답 실패를 수정했습니다. 사용자 PC에서 보고된 일반 오류의 정확한 원인은 아직 확인되지 않았으며, 이 변경으로 실모델 품질이나 해당 PC의 연결 성공을 입증한 것은 아닙니다.

## 0.8.0 Qwen 기준 자동 복구와 HITL

**Windows Excel 2016 / Qwen 3.8 27B**를 기준으로 요구사항 → 계획 → 도구 실행 → 실제 문서 검증 → 보완 → 사용자 확인 → 반영을 수행한다. 모델 목록에 Qwen이 있으면 처음 연결 시 우선 선택하며, 다른 모델과 사용자가 명시한 선택은 유지한다.

- 세 번 보완·전체 호출 수·전체 시간에 도달했다는 이유로 목표를 종료하지 않는다. 0.8.2부터 진전 없는 재시도는 HITL에서 대기합니다. 일시적 연결 오류는 재호출하고 형식/내용 오류는 현재 상태와 함께 모델에 돌려주어 수정한다. 실행 중 작업을 8턴 단위로 이어가며 기존 초안과 검증된 단계를 보존한다.
- 긴 시트는 작은 셀 묶음으로 작성하고 마지막에 검증한다. 요청 전체의 조건을 통과하기 전에는 완료로 표시하지 않는다.
- 기존 셀 변경과 최종 파일 저장은 채팅의 HITL 카드에서 대상·내용·검증 결과를 확인한 뒤 실행한다. 취소 후 자동 재개하지 않는다.
- 모호한 요구사항은 누비의 객관식/주관식 질문 폼으로 확인한다. 선택지 외 직접 입력도 가능하다.
- 편집·저장 응답 유실은 실제 실행 기록과 문서 상태를 읽어 복원한다. 완료한 쓰기를 반복하지 않는다. 확인된 부분 변경은 충돌 검사 후 복원하고 수정 방법을 다시 요청한다.

[BP·오픈소스 검토와 실행 계약](docs/HARNESS-BP.md)을 참고한다. 검토 패키지는 [GitHub 배포 페이지](https://github.com/plaire48/ai_workspace/releases/tag/nubi-office-v0.8.0)에서 제공한다. 인증 불가·미지원 기능·외부 변경은 해결했다고 표시하지 않는다. 재시작 후 실행 복구는 아직 없으며, 현재 자동 재개는 살아 있는 worker 세션 안에서 동작한다.

## 0.7.0 요구사항에서 문서 전체 작성

기본 작업 방식은 **문서 작성**이다. 사용자는 필요한 문서와 내용·조건을 채팅으로 전달한다. 셀 주소나 선택 범위를 미리 지정하지 않는다. 기존 셀 편집만으로 문서 전체 작성이 구현됐다고 보던 범위를 바로잡았다.

1. 요구사항을 내용·데이터·계산·구성·양식 조건으로 정리한다. 꼭 필요한 업무 정보만 질문한다.
2. 요구사항과 연결한 시트 구성을 정하고 계획을 먼저 채팅에 표시한다.
3. 누비의 Pi 실행기와 선택한 제공자가 각 시트의 본문·표·날짜/금액·시트 간 수식을 작성한다. 글꼴·정렬·병합 제목·테두리·행열 크기·인쇄 영역도 구성한다.
4. ExcelJS로 실제 XLSX 파일을 생성하고 다시 읽어 직렬화를 확인한다. Windows 호스트는 생성한 전용 초안만 Excel로 열고 시트 간 계산과 값·수식·서식·레이아웃을 읽는다.
5. AI가 원래 요구사항 전체를 실제 관찰값과 비교한다. 빠진 내용이나 잘못된 계산/양식이 있으면 해당 시트를 수정하고 다시 검사한다. 0.8.0부터 불충족 조건을 계속 보완한다. 필수 정보가 없으면 완료를 선언하지 않고 질문한다.
6. 검토가 끝나고 사용자 HITL 확인을 받으면 Windows **내 문서/NubiOffice**에 새 이름의 `.xlsx`로 저장한다. 성공을 확인한 결과 카드에서 열린 문서를 다시 볼 수 있다. 저장이 미확정이면 다시 쓰거나 완료 처리하지 않는다.

새 문서의 초안은 기존 사용자 파일을 수정하지 않는다. 초안 보완 시 사용자가 Excel에서 바꾼 내용이 있으면 덮어쓰거나 닫지 않는다. 자동 생성 파일은 매번 고유 이름으로 저장한다. 회사 양식의 Excel 사본 등록/열기는 별도 양식 채우기 모드의 새 소스이며, 회사 공용 카탈로그는 미구현이다. 일반 셀 분석·수정은 작업 방식에서 선택할 수 있다.

**현재 범위:** 최대 8개 시트, 시트별 A1부터 시작하는 영역 1,000셀, 전체 명세 120,000자. 본문·표·지원하는 Excel 2016 함수·직접 서식·병합 제목·테두리·행열 크기·A4 인쇄를 지원한다. Word/PPT, 차트·피벗·매크로, 기업 카탈로그, 재시작 후 작성 재개는 지원 완료 항목이 아니다. 모든 유형의 기업 문서를 완벽히 생성한다는 의미가 아니다.

[문서 작성 화면](verification/components-preview.html), [실제 작성 파일 예시](verification/workbooks/document/교육-운영계획-작성결과.xlsx), [출력 예시 PDF](verification/workbooks/document/교육-운영계획-작성결과.pdf). 예시는 **지정한 입력 명세**로 운영계획·예산 2개 시트를 생성하고, LibreOffice에서 계산한 총액 840,000원과 저장 파일 재열기를 확인한 결과다. **실모델이 생성한 결과나 Windows Excel 2016 실행 증거는 아니다.** LibreOffice 변환은 열 너비와 글꼴을 바꿀 수 있어 계산 결과 캐시만 원본 양식에 넣은 예시 파일을 제공한다. 실제 Windows 호스트는 Excel의 열 너비·인쇄 설정을 적용하고 다시 검사한다.

[실제 파일 검사](verification/document-artifact.json)와 [화면·실행 흐름 검사](verification/document-browser.json)를 구분한다. 실제 회사 SSO·모델의 문서 완성도와 Windows 설치/COM 실행은 미검증이며 기존 연결 불가 상태가 유지된다. 생성 파일·화면 검사를 이 검증의 대체물로 표시하지 않는다.

## 0.6.0 값·속성·기존 양식 함께 맞추기

이 버전은 선택 범위의 값과 서식을 함께 다룬다. Excel의 `Value2`와 표시된 `Text`를 구분해 읽고, 수식·글꼴·정렬·잠금·병합 위치·행 높이/열 너비·데이터 유효성 규칙·문서의 날짜 체계를 함께 전달한다. 작업창의 선택 범위 왼쪽 표 아이콘에서 **셀 값과 서식**을 열면 셀별 실제 속성을 확인하고 그 셀에 대한 요청을 작성할 수 있다.

- `set_typed_values`: 텍스트 코드의 앞자리 0, 숫자, 퍼센트, 날짜, 논리 값을 구분한다. 날짜는 모호한 지역 표기 대신 YYYY-MM-DD를 받고 1900/1904 체계에 따라 변환한다. 숫자형 퍼센트는 비율이고 문자열은 `12.5%`처럼 단위가 있어야 한다. 0·false는 빈 값이 아니다. 단위나 통화의 업무 의미를 추측하지 않는다.
- `format_range`: 굵게·기울임·글꼴·크기·글자색·배경색·표시 형식·가로/세로 정렬·줄바꿈을 지원한다. 글자 크기와 형식을 native에서도 검사한다.
- `copy_format`: 같은 선택 범위 안의 기준 셀에서 지원하는 서식만 가져온다. 값·수식은 복사하지 않는다. 날짜/퍼센트/코드의 표시 형식은 별도 기준이며 기존 양식의 형식을 명시해 유지할 수 있다.
- 적용 후 실제 값과 요청한 모든 서식, 기존 수식, 다른 셀의 속성을 비교한다. 입력 제한 위반이나 서식 불일치는 완료로 표시하지 않는다. 쓰기 이후 실패는 자동 재전송하지 않고 변경 기록을 남긴다. 예상 밖의 양식 구조 변경은 자동 복원 가능으로 표시하지 않는다.

값을 입력할 때 **고객 코드 00123, 비율 12.5%, 날짜 2026-09-23, B2와 같은 글꼴·정렬**처럼 요청할 수 있다. 합계 셀에 기존 수식이 있으면 해당 입력 셀을 수정하고 수식을 유지한다. 행 높이는 값·글꼴·줄바꿈 변경으로 자동 확장되지 않도록 기존 높이를 보존한다.

[셀 속성 화면](verification/components-preview.html), [값·서식·수식 보존·복원 통합 검사](verification/value-format-native.json). 1900/1904 날짜와 앞자리 0, 입력 제한 실패, 잘못된 글꼴 크기, 비대상 셀 서식 훼손을 검사했다. 실제 Pi와 컴파일된 변경 엔진을 연결했으나 Excel COM과 모델 응답은 테스트 대역이다. Windows 실제 날짜 표시·입력 제한·회사 양식의 결과 품질은 미검증이다.

**범위:** 선택한 연속 영역과 위 속성에 한정된다. 테두리·조건부 서식·테마 연결·병합 구조 편집·행/열 크기 변경·인쇄 설정·다중 시트 매핑·회사 양식 카탈로그는 이 구현의 지원 완료 항목이 아니다. 입력 필드 명세를 사본에 등록하는 새 소스는 위 양식 채우기를 참고한다. 공용 카탈로그는 미구현이다. 서식 보존/읽기/수정은 같은 의미가 아니다.

Excel 계약 참고: [Value2](https://learn.microsoft.com/en-us/office/vba/api/excel.range.value2), [Text](https://learn.microsoft.com/en-us/office/vba/api/excel.range.text), [Date1904](https://learn.microsoft.com/en-us/office/vba/api/excel.workbook.date1904), [Validation.Value](https://learn.microsoft.com/en-us/office/vba/api/excel.validation.value), [WrapText와 행 높이](https://learn.microsoft.com/en-us/office/vba/api/excel.range.wraptext).

## 0.5.0 전체 화면과 모델 목록 확인

첨부한 `agentfactorysdkdeck.html`의 카드·상태 배지·입력 영역·버튼·타이포·모션을 공통 토큰과 `DeckSurfaces`로 반영했다. 기존 누비 채팅·모델·대화 이력에 더해 직접 연결, 도움말, 분석/수정 방식, 사용량 빈 상태, 변경 비교와 복원, 검증/검토 기록까지 같은 스타일을 사용한다. 추가 질문은 누비의 `QuestionForm`을 직접 사용하며 질문 답변과 입력창 초안을 따로 유지한다.

모델 창은 목록이 있어도 새로고침할 수 있고 전체·검색 결과·서버 수신·표시 개수를 표시한다. Office 전용 API 응답은 HTTP 상태·수신/이름 오류/중복 개수·조회 시각만 진단에 보관한다. 토큰과 응답 원문은 진단에 넣지 않는다. 새로고침 실패 시 기존 목록과 선택을 유지하고 오류를 표시한다. API가 실제로 5개만 반환하면 5개로 표시하며 모델을 임의로 추가하지 않는다.

사용자가 보고한 `glm-5.2_CLI`, `Qwen3-Coder_rag`, `QWEN3-CODER-128K_general`, `qwen3.8-27b_CLI`, `GPT-OSS-128K_CLI`만 반환하는 경우와 이후 10개로 갱신되는 경우를 별도로 검사했다. `aipro-fast-model` 검색·선택 및 원본 ID 전달을 확인했다. 이는 응답을 제어한 회귀 검사이며, 사용자 실서비스에서 5개가 나온 원인은 실제 응답을 확보하지 못해 미확정이다.

## 연결과 사용

Windows에서 VSTO 추가 기능을 설치한 뒤 Excel 리본의 **누비 → 누비 열기**에서 연결을 선택한다. 셀을 선택하고 분석 또는 셀 수정을 요청한다. 채팅에 작업 계획이 먼저 나타나고, 셀 읽기·수정·결과 검토가 진행되는 즉시 기록이 쌓인다. 진행 중 표시가 완료 체크로 바뀌며 다음 단계 안내와 완료 개수·경과 시간을 보여준다. 계획을 펼치면 전체 단계를 확인한다. 위로 스크롤하면 이전 기록을 읽을 수 있고, **최신 작업 보기**를 누르면 실시간 진행으로 돌아온다. 중지 버튼으로 실행을 멈출 수 있으며 필요한 정보가 없으면 누비가 질문하고 답변을 받아 이어간다. 완료 후 변경 기록에서 수정 전후를 확인하거나 되돌린다.

| 연결 | 인증과 모델 선택 | 누비에서 재사용하는 구현 |
|---|---|---|
| AI Pro | 전용 브라우저 SSO, `/api/models`의 실제 모델 ID | Bearer/SSE 계약, 응답 파서; Office 전용 SSO |
| ChatGPT | 별도 브라우저 로그인·PKCE·토큰 갱신 | `chatgpt-auth.js`, `chatgpt-api.js`, 기존 모델 카탈로그 |
| FabriX | Endpoint·Client Key·API Token, 제공자 모델 목록 | `fabrix.js`, nonce·도구 응답 검증·한 번의 형식 재요청 |
| AI Pro CLI | Base URL·토큰·Model ID 직접 입력 | OpenAI 호환 요청, `User-Agent: AIPROCLI` |
| OpenAI 호환 | Base URL·토큰·Model ID 직접 입력 | OpenAI 호환 요청; 로컬 라우터도 지정 가능 |

공유 어댑터의 호환성과 화면에 표시하는 세 연결을 각각 검사한다. 특정 모델을 하드코딩해 AI Pro에만 고정하지 않는다. ChatGPT 카탈로그는 계정별 접근 가능성의 증거가 아니며, 각 제공자의 권한·모델별 도구 호출 지원은 실계정 검증 대상이다. 임의의 모델이 모두 Excel 편집에 성공한다는 뜻은 아니다.

인증값은 해당 작업창의 전용 worker 메모리에만 둔다. 누비 확장·Codex·라우터의 기존 인증 저장소를 읽지 않는다. Excel 종료 후 다시 로그인한다. ChatGPT 콜백 포트 `1455`가 사용 중이면 로그인 오류를 표시한다.

## 적용한 오픈소스와 BP

- **Office AI Agent**: Apache-2.0 VSTO 호스트를 고정 커밋으로 포함했다. Excel 2016의 IE 작업창 대신 WebView2를 사용하고 리본 진입점을 누비로 연결했다.
- **누비 + Pi 0.86.1**: 실제 `agent-runtime.js`, 모델별 인증·추론 어댑터, `completion-reader.js`, 브랜드 이미지·테마를 재사용한다. 숨겨진 번들 Node 프로세스와 JSON RPC로 연결하므로 사용자가 Node·Python·라우터·Chrome 확장을 따로 설치하지 않는다.
- **Pi for Excel BP**: 실행 중인 문서에 바인딩한 범위, 직렬 실행, 실제 셀 readback, 변경 기록과 충돌을 확인하는 복구를 새 COM 엔진으로 구현했다. Office.js 코드를 VSTO에 그대로 붙이지 않았다.
- **ExcelMcp BP**: 자유 코드 실행 대신 용도가 정해진 도구를 노출한다. ExcelMcp 런타임 자체는 추가하지 않았다.
- **계획과 결과 평가 BP**: Deep Agents의 할 일 추적, LangGraph의 계획/실행 분리와 평가/보완 흐름을 참고했다. 기존 Pi에 Office 감독기를 연결하며 다른 에이전트 런타임을 중복 실행하지 않는다. 누비의 `goal-review.js` 증거 검증 파서를 재사용한다. Promptfoo custom provider 평가 어댑터도 제공한다.
- **Microsoft VSTO/WebView2 지침**: COM 호출은 Excel UI/STA 스레드에서 수행한다. WebView는 고정 로컬 페이지와 명시적 RPC만 허용한다.

## 편집 범위와 동작

선택한 연속 범위의 최대 1,000셀, 직렬화된 셀 상태 120,000자까지 지원한다. 도구는 값·Excel 2016 수식과 위에 명시한 10가지 서식 속성을 수정한다. 속성이 많은 범위는 1,000셀보다 작아도 상태 크기 제한에 걸릴 수 있다. 분석 모드에는 쓰기 도구가 없다. 행 삽입·삭제, 차트·피벗·VBA·임의 코드 실행은 현재 구현 범위 밖이다.

문서와 시트 식별자를 고정하고 적용 직전 셀 상태를 비교한다. 다른 문서로 전환해도 기존 요청이 새 문서에 적용되지 않는다. 셀이 바뀌면 중단한다. 병합셀·배열수식·숨긴 행/열·보호된 시트·읽기 전용 문서와 외부 연결 수식은 제한한다. 값 문자열은 Excel의 자동 수식/숫자 변환을 피하도록 텍스트로 쓴다.

각 작업 ID를 쓰기 전에 기록한다. 부분 수정·읽기 실패가 발생하면 쓰기를 자동 재시도하지 않는다. 작업 계획은 3~6단계로 표시하며 첫 미완료 단계에 해당하는 변경만 허용한다. 각 편집은 수정 전 AI 검토→실제 셀 비교→단계 결과 AI 검토를 거친 뒤 완료 표시가 붙는다. 마지막에는 원래 요청 전체를 별도로 재검토한다. 잘못된 값, 누락된 서식, 요청하지 않은 상수·수식·서식 변경, 새 계산 오류는 완료로 처리하지 않는다. 0.8.0부터 불충족 조건은 현재 상태를 보존해 계속 보완한다. 모델의 중간 완료 문장은 검토가 끝날 때까지 최종 답변으로 표시하지 않는다. 최근 20개 변경을 메모리에 보관하며, 되돌리기도 현재 상태가 기록과 같을 때만 수행한다. 변경 기록은 Excel/작업창 종료 시 사라지고 Excel 기본 Undo 스택을 대신하지 않는다. 파일 저장은 사용자가 Excel에서 수행한다.

## 0.3.1 실시간 작업 화면

[진행 화면 녹화](verification/activity-preview.html)에서 채팅에 중간 결과가 나타나는 흐름을 볼 수 있다. UI와 Pi 실행기·변경 엔진을 사용하되 모델 응답과 Excel COM은 테스트 구현이다. 녹화용 응답 지연은 테스트 코드에만 있으며, 제품의 진행 기록은 실제 호출 시작·응답·결과 검사에 따라 갱신된다. 시간에 맞춰 가상의 단계를 완료시키거나 모델의 비공개 추론을 표시하지 않는다. 최종 답변이 나오기 전 기록 추가, 쓰기 결과 확인 후 완료 전환, 오류·중지 시 진행 표시 종료와 스크롤 유지 동작을 검사했다.

## 0.3.2 실패 후 수정과 재검증

도구 입력 오류·잘못된 수식/서식·범위/순서 오류·결과 검토 불충족을 만나면 최신 셀을 다시 읽고 실패 결과, 시도한 수정, 완료한 단계와 원래 요청을 AI에 전달한다. AI는 짧은 원인 설명과 수정 방법, 필요한 질문 또는 진행 불가 판단을 구조화해 반환한다. 실행기는 이를 받아 실패한 입력이나 접근을 고쳐 실제 도구를 다시 호출한다. 수정 방법을 생성한 것만으로 완료시키지 않으며 셀 readback과 독립 검토까지 통과해야 복구 완료로 표시한다. 이 흐름은 누비의 모든 연결 제공자에 공통으로 적용된다.

0.8.0에서 횟수 기반 중단을 제거하고 오류에 따라 수정·재검증을 계속한다. 선택 범위·원래 검증 조건·기존 수식 보호 규칙은 AI가 완화할 수 없다. 완료한 쓰기는 반복하지 않고 필요한 업무 값은 질문한다. 쓰기 응답 유실은 실행 기록과 readback으로 확인하고, 확인된 부분 변경은 충돌 방지 복원 후 재계획한다. 미확정 쓰기·외부 셀 변경·알 수 없는 native 오류는 자동 재전송하지 않는다. 인증/접속 장애 자체나 지원하지 않는 Excel 기능을 AI가 해결했다고 간주하지 않는다.

[실패→수정→재검증 녹화](verification/recovery-preview.html)는 실제 C# 변경 엔진이 잘못된 굵게 입력을 거절한 뒤, 완료한 값 변경을 유지하면서 올바른 서식으로 다시 적용하는 흐름이다. 모델 응답과 Excel COM은 테스트 구현이며 실모델 복구율은 미측정이다. [검증 기록](verification/recovery-checks.json)과 `tests/recovery.test.mjs`에 오류 전달·수정 실행·원래 범위 보호·중복 쓰기 방지·연속 실패·취소·정보 질문 검사를 남겼다. 실모델 평가 기록에도 `recoveries`와 복구 호출 수를 포함한다.

## 0.3.0에서 바로잡은 점

이전 감독 코드에서 요청값 42와 실제 관찰값 1이 달라도 완료되는 결함을 재현해 수정했다. 기록은 [기존 결함 재현](verification/harness-baseline.json)에 있다. [진행 중 화면](verification/plan-running-380.png)은 단계 두 개 완료, 세 번째 진행, 마지막 검증 대기 상태를 보여준다. 이 화면은 제어/화면 시험 기록이며 실모델 수행의 증거가 아니다.

계획을 채팅에 표시하기 전에는 실행기를 시작하지 않는다. 완료 개수는 실제 셀 검증과 단계 검토로 갱신하며, 모델이 완료 표시를 임의로 바꾸는 도구는 제공하지 않는다. AI Pro·ChatGPT·FabriX·AI Pro CLI·OpenAI 호환 연결 모두 같은 하네스를 거친다.

현재 검토 호출은 선택한 모델을 별도 문맥에서 사용한다. 검토 모델도 틀릴 수 있으므로 실제 모델의 정확도를 보장하지 않는다. 기업 공용 카탈로그·반복 테이블 확장은 미구현이다. 선택 범위 필드 매핑/등록의 새 소스는 위 양식 채우기를 참고한다.

## 검증 상태

- 새 .NET Framework 4.7.2 네이티브 호스트: macOS에서 참조 어셈블리를 사용한 Release 교차 컴파일.
- 제공자 계약·실제 Pi 루프 테스트: 합성 응답을 사용해 모든 제공자 경로와 편집 실패 처리를 검사.
- 실제 C# 변경 엔진: Excel COM 포트만 모의 구현하여 범위·충돌·중복 실행·복구 검사.
- 브라우저 통합: 실제 프런트엔드 + 실제 Pi + 실제 C# 변경 엔진을 연결, 수정→readback→복구 검증. 320/380/600/1100px에서 넘침과 JavaScript 오류 확인. 추가 질문 답변 후 초안 보존·도움말 복귀 포커스·모델 갱신 실패도 검사.
- 실제 XLSX 12개: LibreOffice로 자체 정답 파일 재계산·재열기. 모델 실행 결과가 아니다.
- Windows 전용 평가 실행기: 생산 Excel COM 포트와 변경 엔진을 사용하는 STA EXE 교차 컴파일. 정답·비대상 셀 보존·저장 후 재열기 채점 준비. 현재 환경의 사전 점검은 `blocked`, 정확도 `null`.

## 개발자 빌드

AI Workspace의 이 소스는 `vendor/nubi-shared`의 공유 소스 스냅샷을 사용하여 독립 빌드합니다. 원본 `llm_router`에서는 기존 확장 소스를 직접 참조합니다. `SOURCE-EXPORT.md`를 참고하세요.

```sh
npm ci
npm run build
npm ci --prefix dist --omit=dev --ignore-scripts
node scripts/download-runtimes.mjs
dotnet build native/Nubi.Office.EvalHost/Nubi.Office.EvalHost.csproj -c Release
npm test
# Resolve shared runtime imports against Office-pinned Pi dependencies
npm run test:pinned
dotnet run --project native/Nubi.Office.Tests -c Release
PLAYWRIGHT_CHANNEL=chrome npm run test:browser
node tests/bundle-smoke.mjs
npm run design:check
npm run package
```

`runtime-lock.json`은 공식 Node 22.23.2 Windows x86/x64 ZIP의 SHA-256을 고정한다. Node 실행 파일과 라이선스를 번들에 포함한다. `npm run package`는 Node와 고정된 fflate를 사용하는 개발 환경에서 실행하며 한글 파일명은 UTF-8 ZIP 헤더로 저장한다. 사용자는 이 명령을 실행하지 않는다.

Windows 설치본은 GitHub Actions의 `Nubi Office Windows installer` workflow에서 빌드합니다. 개발 PC는 Visual Studio 2022, .NET SDK, .NET Framework 4.7.2 targeting pack, NuGet CLI, Inno Setup 6이 필요합니다. Office 개발 도구가 없으면 빌드 스크립트가 Visual Studio Installer를 사용해 추가합니다.

```powershell
.\scripts\Build-Installer.ps1
# Optional: use a publisher certificate already installed in CurrentUser\My
.\scripts\Build-Installer.ps1 -CertificateThumbprint <thumbprint>
# This installs and removes Nubi; only run on an isolated Windows test machine.
.\scripts\Test-Installer.ps1
```

새 설치 경로는 Excel/Word/PowerPoint의 최소 VSTO 진입점 세 개와 공통 네이티브 호스트·누비 UI·worker를 묶도록 구성했습니다. 선택형 설치는 다음 최종 빌드에서 검증합니다. `Build-Windows.ps1`은 이전 upstream 전체 프로젝트를 대상으로 하는 개발 참고용입니다. 설치 EXE 제작에는 사용하지 않습니다. `CertificateThumbprint`는 VSTO manifest 서명이며 EXE Authenticode 서명은 별도입니다. 기본 빌드는 사전 배포용 자체 서명을 생성하며 신뢰 저장소에 추가하지 않습니다.

### 작업 위치와 화면

검증된 수정 후 Excel 범위, Word 문단/입력칸, PowerPoint 슬라이드/도형을 실제 선택해 보여준다. 채팅에서 작업 위치와 캡처를 펼쳐 확인할 수 있다. 화면 검토는 명시적으로 이미지 입력을 지원하는 선택 모델에만 이미지를 전달하며 그 외에는 UI 요소만 읽는다. 이는 전체 문서 동일성이나 저장 성공 검증을 대체하지 않는다. [Office 화면 하네스와 검증 범위](docs/OFFICE-VIEW-HARNESS.md).

사용자 커서를 움직이지 않는 AI 가상 커서와 Office UIA 클릭/선택/스크롤을 연결했습니다. 클릭/스크롤은 대상 확인 승인을 받으며, 입력 뒤 화면과 문서를 다시 확인합니다. 미확정 입력은 자동 재전송하지 않습니다. 적용 라이브러리와 제한은 [Office 화면 하네스](docs/OFFICE-VIEW-HARNESS.md)를 참고하세요. A2A는 구현 보류입니다.
