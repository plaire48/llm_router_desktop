# Nubi Office execution contract

- Readability and meaning MUST take priority over decoration or maximum information density. Lead with the essential sentence, retain decision-relevant specifics and remove redundant prose. Use bold selectively for the exact target, key result or needed decision; use the shared blue for action/selection and semantic warning colors for actual states, never color alone. Prefer real captures, file icons and familiar action icons when they communicate more clearly, with accessible names/alt text. Do not turn important document content into icon-only hints or truncate it to make the UI shorter. Keep the approval target visible before expanding evidence, and keep unknown/preservation states explicit.

- Visual identity MUST follow `agentfactorysdkdeck.html` and the reviewed shared Nubi cascade for every component, modal, form, toast and state. NEVER introduce Office-only font/color skins or raw form controls. Use shared CX controls, `deck-dialog`, DeckDisclosure and semantic tokens; the HTML presentation scale is adapted to desktop body/input 14/22px and modal titles 16/24px with bundled Noto Sans KR. Keep only the current action, essential outcome and decision-relevant detail visible. Put supporting evidence behind disclosures, never hide errors, uncertainty, preservation warnings or approval scope. Familiar auxiliary actions MUST use icons with accessible names and hover/focus hints; keep short labels where an icon is ambiguous or a consequential decision needs context. Changes MUST pass `npm run design:check` and the affected UI tests; visual changes also require `npm run test:visual` and screenshot review. Updating snapshot hashes alone is not a visual review. See `docs/UI-IDENTITY-CONTRACT.md`.

- The product is a Windows Office 2016 copilot for Excel, Word and PowerPoint. Use native host-specific document contracts and deliver the requested document, not merely a plan. The same installer offers optional Excel/Word/PowerPoint components and one shared runtime.
- The baseline model is the enterprise catalog's Qwen 3.8 27B. Never invent its API ID or capabilities. Preserve every supported Nubi provider/model and explicit user selection.
- Analyze requirements, display a plan, run small tools sequentially, inspect actual results, independently review requirements, repair and continue. Verified results alone advance completion.
- For EVERY task and decision, MUST consider relevant methodologies, improvement approaches, best practices and open source across requirements, design, implementation, UI/UX, harness, recovery, evaluation and distribution. Do not wait for a failure. Check existing research first and verify adoption-critical facts against current official documentation and source. See docs/HARNESS-BP.md.
- Prefer existing agent/SDK components over rebuilding general-purpose harness, skills, edit/search, context and concurrency infrastructure. Document-authoring scope uses Pi Coding Agent SDK tools/skill loading with per-run memory operations, and p-map for analysis scheduling. Keep only Office/native policy adapters custom. Never use the SDK default global auth/resource/session discovery. Pure JavaScript transform(input) may run only through the bounded QuickJS WASM worker with explicit JSON data; NEVER use Node vm/eval, shell or host API bindings. Python uses bundled uv, managed Python 3.12 and exact wheel dependencies in a Nubi-only venv. Environment installation and each exact code/input execution require HITL. A venv is NOT an OS security sandbox; disclose local user permissions. Do not pass credentials or Office/NASCA paths; return bounded JSON for guarded native tools. Use process ceilings, cancellation, source/lock hashes and shared no-progress recovery, never blind process retries. See docs/PYTHON-SKILLS.md. Script results cannot authorize native writes or completion; retain current source/result hashes and existing Office commit/readback. Long memory resources MUST remain retrievable through version-bound character pages, and chained scripts MUST keep inputPath separate from resultPath. Run release/debug evaluator lifecycle checks without bundling the debug dependency into the product. Keep the versioned CX toast patch applied with patch-package before tests/builds; do not fork the UI. Source tests run sequentially to avoid VM deadline noise. See docs/QUALITY-REVIEW-2026-09-23.md. See docs/CODING-SDK-ADOPTION-2026-09-23.md and docs/DOCUMENT-SCRIPT-RUNTIME-2026-09-23.md.
- Compare fit to Windows Excel 2016 and the Qwen baseline, demonstrated quality, recovery behavior, licensing, maintenance, dependencies and cost. Apply suitable improvements, including design patterns or changes to existing libraries; discovering a candidate is not a reason to add it. Reuse prior evaluations while their assumptions remain valid. On repeated failure or no progress, revisit the cause and alternatives instead of repeating the same request. Briefly record selection/rejection reasons, actual adoption versus reference, and evidence boundaries. This rule never overrides the user's final-build gate or existing HITL requirements.
- Ask grounded multiple-choice or free-text questions for missing requirements. Obtain HITL for existing-cell transactions and final document saving. Never resume after user cancellation or interpret silence as approval.
- Retry recoverable failures with visible state, bounded request size, cancellation and backoff. Preserve completed work. Read receipts and actual state before recovering uncertain mutations; never blindly replay writes.
- Error recovery follows docs/ERROR-RECOVERY-BP.md. p-retry owns inference/allowlisted-read retries; the Office supervisor alone owns delays and no-progress HITL. MUST honor Retry-After after HITL, fence late callbacks, preserve HTTP status, and keep permanent configuration errors out of retry loops. NEVER wrap writes or runStart in generic retry; worker status/receipt redelivery also pauses after three failures. Native Excel busy classification applies only to explicit reads.
- Successful-call loops follow docs/TOOL-PROGRESS-BP-2026-09-23.md. The shared tool-progress guard compares canonical inputs and observed state, requests one replan, then pauses the same run on repeated unchanged calls. Keep it across context renewal; continuation MUST request a fresh decision rather than replay the blocked tool. Native mutation receipt guards and the existing error retry owner remain separate.
- Each Pi decision MUST expose one tool and consume its receipt before the next decision. Independent read-only analyses may run concurrently inside analyze_ranges/analyze_document/review_office_view; Excel COM reads/writes remain serialized on UI/STA. A subagent MUST NOT receive write tools or broaden the original write scope. Three failures without changed accepted work pause the same run for retry/cancel HITL; this is not a total work budget. A retry alone NEVER means progress or success.
- The bundled worker uses Windows system CA trust without installing certificates or disabling TLS verification. Classify safe connection error codes; never publish raw endpoints, tokens or server bodies in errors.
- Distinguish scripted tests, actual generated files, cross-compilation, real Excel 2016 COM, corporate authentication and live model quality. No unavailable environment is a passing evaluation.
- Evaluation MUST NOT autoapprove recovery HITL or count unanswered semantic grading as a pass. Bound each evaluation case; abort the suite after uncertain native transport failure. Source hashes and build-artifact hashes are separate evidence. The source-only rubric/audit in eval/ is implementation review, NEVER live Qwen accuracy; see docs/HARNESS-ASSESSMENT-2026-09-23.md.
- Do not access authentication stores belonging to other applications. Credentials remain in the Office worker's dedicated memory.

- Windows distribution uses the minimal Excel/Word/PowerPoint VSTO entry points, one shared Nubi host, and the Inno Setup installer. Build with `scripts/Build-Installer.ps1`; verify app selection changes, registered files, both worker architectures, reinstallation and uninstall on Windows. Preview manifest signatures are not trusted publisher signatures; never install a preview certificate into certificate trust stores.

- Run Windows installer builds and generate a new installer ONLY after the user explicitly requests the final build. During iteration, make source changes and lightweight checks without triggering the installer workflow.

- Excel 2016 feature work MUST follow docs/EXCEL-2016-AGENT.md and the actual capability catalog. Keep native workbook/sheet identity binding, source fingerprint checks before edits, isolated analysis contexts, and original evidence through compaction. Referenced methods from Anthropic/Pi for Excel are not claims of live Qwen or Excel performance. Do not enable catalog entries for unimplemented COM mutations.

- Existing-template work MUST separate the original workbook, observed field schema and answer data. Template mode only fills confirmed scalar input anchors, preserves formulas/layout, and retains HITL answers within the same run. Merged input writes require the complete merge in scope and its top-left non-formula cell. Rebind after source drift. Confirmed field profiles may persist inside Excel-created .xlsx copies as Custom XML Parts; answers stay in memory. NASCA-protected files MUST use Excel open/save, NEVER a plaintext sidecar, external decryptor or generic ZIP rewrite. This is not a shared company catalog. Preservation reports MUST distinguish observed equality, differences and unverified properties; metadata readback is not visual identity or encryption proof. Warn and review copy differences; never waive damaged formulas, incorrect data or uncertain writes. See docs/TEMPLATE-FILLING.md.

- Model context may encode repeated format/property grids losslessly; keep raw observations for write guards and evidence. This preflight NEVER replaces native calculation/readback or requirement review. JSON tool fallback MUST retain the same model, scope, HITL answers and verified work; a terminal answer cannot waive checks. See docs/AGENT-QUALITY-BP.md.

Receipt collisions fail closed; final-review answers require a fresh, unchanged Excel fingerprint. Lost runStart responses use read-only runLookup by a client request ID, NEVER automatic runStart replay. This is current-process continuity, not durable or NASCA-protected checkpoint storage. fast-check is a dev-only state-sequence test dependency. Evaluation host protocol 4 covers private generated document/template fixtures; building and validating the new native paths still requires the user's final-build request. See docs/HARNESS-IMPROVEMENTS-2026-09-23.md.

React Testing Library, jsdom and axe-core are dev-only; static Chromium source previews are not interactive WebView2 or Excel evidence. See docs/USABILITY-IMPROVEMENTS-2026-09-23.md.

Review and update `design/shared-ui.json` together with the publication UI snapshot; `scripts/check-ui-parity.mjs` detects drift. Desktop text/input/status use 14px/22px, dialog titles 16px/24px; narrow Excel panes are not mobile layouts. The user describes the desired outcome; NEVER require a work-mode picker. Read-only intent routing chooses the existing guarded executor with the same selected model. Clarify only missing target/facts using grounded choices/free text, retain answers and the public run ID through handoff, and keep real write/save HITL. Preserve the complete welcome composition: mascot, Excel-specific brand title, supporting description and the separate Nubi invitation. Do not conflate these with redundant tool controls. Keep the composer to request input, the user-requested template +, model selection and send/stop; show only the active template name in a removable chip. Put cell inspection and optional template file-copy opening under More, consolidate usage in the header, and collapse accepted answers.
