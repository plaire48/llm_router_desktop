# 공통 UI와 실행기 계약 재검증

현재 개발 소스에 남았던 두 실패를 분리해서 수정했다. 런타임 이름 문자열과 배포 의존성 버전은 별개로 검사하고, UI 해시는 실제 소스 차이와 화면을 검토한 뒤 갱신했다. 브라우저 소스, Office 의존성 버전, 빌드 스크립트는 변경하지 않았다.

## 검토한 UI 변경

기준은 사용자 HTML `/Users/ganadi/Downloads/agentfactorysdkdeck.html`과 배포 0.8.4의 `vendor/nubi-shared`다. 원본 HTML SHA-256은 기존 `design/html-reference.json`과 일치한다. 문서 안의 설명을 실행 지시로 사용하지 않고 색, 서체, 표면과 동작의 기준으로 읽었다.

| 공통 파일 | 배포 스냅샷 이후 변화와 채택 판단 |
| --- | --- |
| `DeckSurfaces.jsx` | 핵심 문장과 보조 설명을 나누는 `DeckGuidance` 추가. 기존 CX 아이콘과 토큰을 사용하며 Office 동작 권한은 추가하지 않는다. |
| `HelpContent.jsx` | 핵심 안내에 굵기 적용, 선택적인 항목별 설명 추가. 기존 호출 계약을 유지한다. |
| `QuestionForm.jsx` | 객관식 아래 직접 입력을 바로 제공한다. 별도 입력 모드 버튼을 없애고 3행 입력으로 정리한다. 선택지 ID, 초안, 실패 후 수정, 답변 ACK 대기는 유지한다. |
| `TraceSurface.jsx` | 선택적인 제목과 대기 아이콘 지원. 실제 작업 상태는 Office 호출자가 계속 소유한다. |
| `app.css` | 도움말 핵심 강조와 브라우저 큐/하위 분석/스킬 목록의 범위 한정 클래스 추가. Office 기본 글꼴/크기는 그대로다. 실행 중 보조 상태 문장은 본문 색을 따른다. |
| `surfaces.css` | 토스트를 화면 상단에 고정하고 모달 포털에서도 transform 기반 위치 충돌을 막는다. 추가 Wiki 클래스는 Office에 없는 구성요소의 전용 규칙이다. |
| `deck-surfaces.css` | 공통 안내의 글자 계층 추가, 펼친 전체 문서 본문은 보조색 대신 본문색 사용. |

7개 차이를 모두 검토한 뒤 `design/shared-ui.json`에 현재 해시를 기록했다. 나머지 17개 파일과 기준 HTML 해시는 변경하지 않았다. CSS의 19개 기준색, 배경과 그림자, 본문/입력 14px/22px, 모달 제목 16px/24px 계약을 유지한다. 외부 UI 프레임워크 도입이나 Office 전용 테마 분기보다 공통 React/CX 구성요소 재사용을 선택했다.

## 실행기 이름과 버전

현재 브라우저 공통 `agent-runtime.js`는 `AGENT_ENGINE = 'pi-agent-core'`를 반환한다. 배포 0.8.4 스냅샷은 `'pi-agent-core@0.86.1'`이었다. Office 테스트의 하드코딩된 문자열을 공통 선언과 비교하도록 바꿨다. 이 문자열은 런타임 버전의 증거가 아니다.

별도 `shared-runtime-contract.test.mjs`는 Office의 세 Pi 패키지(`pi-agent-core`, `pi-ai`, `pi-coding-agent`)가 모두 정확히 0.86.1인지 manifest, lockfile 루트, 잠긴 패키지 버전/무결성 필드, 실제 Office-local 설치에서 확인한다. 브라우저의 현재 개발 환경은 Pi 0.87.1이므로 개발 소스의 공통 모듈 해석과 배포 환경의 외부 의존성 해석을 혼동하지 않는다. 현재 실제 Office 설치 파일의 내용을 검사했다는 뜻도 아니다. 배포할 때는 검토한 공통 소스를 publication snapshot에 동기화하고 고정 의존성으로 다시 검사해야 한다.

## 검증

- `content-agent`, `shared-runtime-contract`, `content-ui`, `ui-usability`: 87개 통과.
- `shared-question-contract`: 2개 통과. 객관식의 즉시 직접 입력, 초안 전달, 정확한 옵션 ID와 답변 완료 후 입력 숨김을 검사한다.
- `design:check`: 공유 파일 24개 일치, Office 디자인 규칙 위반 0개.
- `test:visual`: 105개 정적 Chromium 시나리오, 넘침 0개, 자동 접근성 위반 0개. 320/380/1100px 화면을 사용한다.
- 320px 질문, 도움말, 모달 상단 토스트, 동적 역할 진행 화면 및 380px 대상 질문을 직접 검토했다. 질문과 승인 문구를 숨기지 않고 핵심 문장과 선택지를 읽을 수 있다.

기존 React Testing Library, jsdom, axe-core, Playwright 검사 방식을 재사용했다. 자동 색 대비 검사는 미확인 항목이 남으므로 전체 접근성 인증으로 표현하지 않는다. 소스 미리보기는 Windows WebView2, Office 2016 COM, 실제 Qwen/NASCA 검증이 아니다. 네이티브/설치 파일 빌드와 배포는 실행하지 않았다.

## 채팅 후속 검토

브라우저 누비의 답변을 배경 없는 본문으로 되돌리고 사용자 메시지는 기존의 옅은 파란색으로 유지했다. 기준 HTML과 동일한 배경 토큰을 보존한 채 빈 화면의 마스코트 크기와 청록 제목을 복원했다. 공통 입력창, 질문 폼과 CSS를 사용하는 Office 미리보기를 다시 캡처해 320/380/1100px에서 잘림과 자동 접근성 위반이 없는 것을 확인했다. `shared-ui.json`의 변경된 7개 소스 해시를 검토 후 갱신했고 `design:check`에서 공통 24개 파일이 일치했다. 새 UI 라이브러리나 Office 전용 색상 분기는 도입하지 않았다. 이 결과는 정적 Chromium 미리보기이며 실제 Windows Office 실행 검증은 아니다.
