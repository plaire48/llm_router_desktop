# 실행 전 도구 입력 검증과 복구

2026-09-23. 게시 기준 `1146c1b6c192aac0852e0dd957c7b440aaa36276`. 목표는 Windows Office 2016과 사내 Qwen 3.8 27B다. 모델의 실제 카탈로그 ID, 사용자 선택, native 승인과 저장 계약은 유지한다. 이번 검증은 소스와 실제 Pi 실행기의 제어 경로이며 모델/Office 응답은 fixture다. 실모델 정확도나 Office COM 성공을 뜻하지 않는다. 빌드와 설치 파일 생성은 하지 않았다.

## 발견한 누락

지난 변경은 `execute()`가 반환한 로컬 오류를 감독기에 연결했다. 그러나 Pi 0.86.1의 `prepareToolCall`에서 없는 도구와 잘못된 인자를 거절하면 `execute()`와 `afterToolCall`을 거치지 않는다. 설치된 SDK의 `dist/agent-loop.js`에서 immediate 결과 경로를 확인했다.

새 회귀 검사에서 같은 호출 ID를 반복할 때 Excel 셀 작업은 4회, 새 문서 작성은 9회 실패한 뒤 복구 확인을 받았다. 기존 셀 실행기는 호출 ID 집합으로 오류를 구분해 ID를 재사용하는 제공자의 다음 실패를 놓칠 수 있었다. 새 문서 실행기는 일반 `agent_stalled`가 된 뒤에야 실패를 집계했다. 이전 검사 358개 통과는 이 입력 경로의 완전한 검증이 아니었다.

## 실제 반영

- `tool-response.mjs`의 한 도구 선택 직후, 현재 제공한 도구의 실제 스키마로 호출 이름/JSON/인자를 검사한다. 누비 공통 `toolArgumentIssues`와 기존 TypeBox `Errors`를 직접 재사용한다. 별도 스키마나 수작업 타입 검증기를 만들지 않았다.
- 네이티브 tool-call 응답과 JSON 도구 대체 형식에 같은 검사를 적용한다. 기존 JSON의 `plan/chunk/sheet` 객체를 문자열로 바꾸는 규칙은 유지하고 변환된 최종 값을 검사한다. 추측으로 문자열/숫자 타입을 맞춰 통과시키지 않는다.
- 거절된 호출은 Pi 실행 전에 차단하고 `actionIssued:false`, 원래 오류, 선언된 필드 경로와 위반 규칙을 각 앱의 기존 복구 실행기에 전달한다. SDK는 승인된 입력도 계속 검증한다.
- 호출 ID가 아닌 실제 모델 판단의 실패를 한 번 집계한다. Excel 셀의 기존 AI 복구 계획과 최신 셀 확인을 유지한다. Excel 초안과 Word/PPT도 원인을 다음 문맥에 전달한다. 세 번 진전이 없으면 같은 실행에서 HITL을 기다린다.
- 검증기 메시지나 입력값 전체는 진단에 넣지 않는다. 누비 공통 검증기가 선언된 필드/배열 위치만 반환하고 알 수 없는 속성 이름은 가린다. 없는 도구 이름도 진단에서는 `unavailable_tool`로 표시한다. 최대 네 가지 문제만 전달한다.
- 여러 호출을 한꺼번에 제안하면 첫 호출만 선택하는 기존 정책을 유지한다. 뒤의 호출은 실행하거나 미리 승인하지 않는다. 오류 복구 승인은 실제 편집/최종 저장 승인을 대신하지 않는다.

## BP와 오픈소스 선택

|---|---|---|
| [Anthropic 도구 설계와 평가](https://www.anthropic.com/engineering/writing-tools-for-agents) | 실제 실패 호출을 재현하고 모델이 수정할 수 있는 구체적인 결과를 다음 판단에 전달 | 문구를 바꾼 것만으로 실제 모델 품질 향상을 주장하지 않음 |

| [Pi](https://github.com/earendil-works/pi) 0.86.1, MIT | 도구 실행과 대화 관리는 유지하고 Office 어댑터에서 거절을 감독기에 연결 | SDK/브라우저 실행기 수정 없음. 도구 실행기 복제 없음 |

게시 작업폴더의 첫 전체 검사에서 새 참조인 공통 검증 파일이 기존 snapshot에 없어 import가 실패했다. 해당 `tool-validation.js` 원본 한 파일을 수정 없이 포함하고 TypeBox MIT 고지를 명시적으로 보존했다. 이후 게시본의 이전 worker 소스로 되돌린 두 실패 재현도 같은 4회/9회를 확인한 뒤 수정본을 다시 검사했다. 공유 UI와 브라우저 실행기 snapshot은 바꾸지 않았다.

패키지 추가, lockfile 변경, 새 사용자 설치 요구는 없다. 범용 retry로 도구를 재실행하지 않고, 실제 오류를 받은 모델이 다음 동작을 결정하도록 기존 경로에 연결했다.

## 검증

- 실패 재현 두 건: ID 반복 시 Excel 셀 4회/초안 9회 → 수정 후 모두 3회에서 같은 원인으로 대기.
- Excel의 없는 도구도 3회에서 대기. Word/PPT는 네이티브/JSON 형식 각각 잘못된 인자와 없는 도구를 검사했다. JSON 대체 모드 진입을 위한 최초 도구 없는 응답도 실제 실패 한 번으로 집계한다.
- Excel 셀은 HITL 뒤 같은 실행으로 이어가며 `/plan`의 타입 오류를 받는다. 별도 편집 승인 전 쓰기 0회, 승인 뒤 값 42를 정확히 한 번 반영한다.
- Excel 초안은 이미 수락한 A1 내용을 유지하고 `/chunk` 오류를 모델에 전달한다. 복구 뒤 전체 문서를 검토해 최종 저장 승인에서 멈춘다.
- 잘못된 인자의 타입/필수 필드/길이/중첩/범위/추가 속성, 네이티브와 JSON의 동일한 진단, 원문 미변경, 배치 꼬리 미실행, 잘못된 JSON과 진단의 민감값 제외를 검사했다.
- 관련 개발 검사 76개 통과. 게시본 전체 검사 수와 파일 해시는 `verification/tool-schema-recovery-review.json`에 기록한다. 모의 HITL 답변과 native 응답은 실사용 승인/Office 동작의 증거가 아니다.

## 남은 개선

실제 Qwen/Office 2016/NASCA 검증은 P0 미측정이다. 180,000자 초과 최종 근거의 계층 검토, 보호된 재시작 복구, Python/외부 스킬 의존성 준비, 복잡한 Word/PPT 보존 편집은 별도 미완료 항목이다. 개발 중인 다른 공유 UI 7개 파일의 기준 불일치를 이번 변경으로 해결했다고 표시하지 않는다. 이번 게시본은 기존 고정 UI를 유지한다.
