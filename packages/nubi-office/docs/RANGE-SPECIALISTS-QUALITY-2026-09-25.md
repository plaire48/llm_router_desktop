# 긴 항목의 구간 배정과 재검증

2026-09-25. Windows Office 2016과 카탈로그의 Qwen 3.8 27B 기준 소스 개선이다. 새 native/설치 빌드는 실행하지 않는다.

## 이번에 해결한 미완료 항목

기존 하위 분석은 항목 전체를 보내므로 단일 문단/노트가 32K source 예산보다 크면 실패했다. `analyze_document`와 `delegate_document_tasks`에 선택적인 `textRanges`를 추가했다. 모델이 `read_document_text`로 먼저 읽은 구간을 역할별로 배정한다.

각 범위는 `{itemId,field:text|notes,offset,length}`이며 UTF-16 기준이다. 작업당 최대 4구간, 구간당 최대 8000자, 합계 24000자다. 배정한 항목마다 적어도 한 범위가 있어야 하며 같은 필드의 중복/겹침, 잘못된 길이, 미관찰 구간은 하위 모델 호출 전에 거부한다. 전체 DAG의 구간을 먼저 검사하므로 나중 단계의 미관찰 구간 때문에 앞선 모델 호출만 낭비하지 않는다.

별도 저장소의 현재 문서/fingerprint/필드 해시와 일치하는 조각만 사용한다. 전체 원문을 수집하지 않고도 이미 읽은 부분을 활용할 수 있다. 인접 조각을 이어 읽되 누락 구간은 메우거나 추측하지 않는다. 원본 native 페이지와 편집 권한은 변경하지 않는다.

하위 모델은 고유 range ID와 해당 필드만 받는다. 인용을 검증한 뒤 원본 item ID, 절대 오프셋, 배정 범위와 필드 해시를 붙인다. 반복된 문구는 배정 범위 안에서 첫 일치 위치를 반환한다. 결과의 `coverage.kind=assigned_text_ranges`, `completeDocument=false`를 보존한다. 배정된 좁은 과제를 마친 것과 원문 전체를 읽은 것은 다르다. 모델이 요구사항을 의미적으로 올바르게 이해했는지는 실모델 평가가 필요하다.

캐시와 진전 판정에는 배정 범위가 포함된다. 같은 역할로 다른 구간을 분석하면 별도 과제이고, 작업 ID만 바꾸거나 범위 순서를 바꾸면 새 진전으로 인정하지 않는다. 의존 작업에는 원래 인용/범위/미확인 정보를 포함한 보고서를 전달한다.

## 품질 점검에서 추가 수정

- 직접 `analyze_document`도 모델 호출 전후 부모가 native 문서를 재확인한다. 모델 호출이 모두 끝난 뒤 순차 확인하며 문서, 모델, 원래 조건이 바뀌면 캐시를 비우고 이번 결과를 진전으로 계산하지 않는다.
- 새 원문 조회, 위임 결과 조회와 세 위임 도구를 기존 반복 감지기에 연결했다. 성공 응답이 반복돼도 문서/검증 상태가 그대로면 재계획 후 같은 실행의 HITL에서 기다린다. 쓰기 재전송 권한은 추가하지 않는다.
- 공통 CSS 검토 해시가 1개 달라져 디자인 검사가 실패했다. 추가된 `.subagent-scope`/`.subagent-evidence` 12개 규칙을 제거한 가상 비교본의 해시가 이전 기준과 정확히 일치함을 확인했다. 추가 규칙은 기존 본문색/보조색/간격/포커스 토큰과 범위 한정 클래스를 사용한다. 브라우저 공통 소스는 수정하지 않고, 실제 차이와 Office 화면을 검토한 뒤 해시만 갱신했다. 설치/배포 스냅샷은 생성하지 않았다.

## 적용한 방법론과 오픈소스

[Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)의 명확한 목표/출처/경계 배정과 복잡도에 맞춘 병렬 실행을 참고했다. 기존 [dependency-graph](https://github.com/jriecken/dependency-graph), Pi 0.86.1, p-map 7.0.4의 실제 DAG/모델 실행기를 확장했다. 새 일반 에이전트 프레임워크와 의존성을 추가하지 않았다. 기존 MIT 의존성 재사용으로 Windows 번들, 현재 Qwen 공급자 계약과 단일 복구 주체를 유지한다. Anthropic이 제시한 성능 수치를 우리 제품 성능으로 사용하지 않는다.

범용 청크 검색 라이브러리로 임의 유사 문장을 찾는 대신, Office native의 정확한 필드/UTF-16 오프셋과 기존 해시 저장소를 사용한다. 편집 대상과 인용 원문을 구분해야 하므로 정확한 위치가 이 경로의 핵심이다. MiniSearch는 기존 검색에 유지한다. 부모 Office 쓰기는 순차 처리하고 하위 모델 호출만 최대 두 개 병렬 처리한다.

## 검사와 남은 과제

**고정 Pi 0.86.1 전체 652/652 통과**, 디자인 공통 24개 일치/위반 0개다. 정적 Chromium 105개에서 가로 넘침/자동 접근성 위반 0개이며 색 대비는 미확인이다. 320px 위임 진행 화면과 380px 모델 모달을 직접 확인했다. `../verification/range-specialists-quality.json`에 검사와 소스 해시를 기록한다. 새 회귀 검사는 긴 Word/PPT 말미, 인용 위치, 미관찰 구간, 위조 인용, 범위 정규화/겹침/예산, DAG 사전 검사, 캐시, 의존 작업, 원문/모델 변경과 반복 방지를 포함한다. 실제 Pi 실행기의 원문 읽기 → 구간 위임 → 질문 대기 흐름도 합성 provider/native로 확인한다.

| 항목 | 상태 |
|---|---|
| 32K를 넘는 단일 항목의 역할별 구간 배정 | 소스 반영 및 합성 검사. 사용한 구간만 분석 근거로 표시 |
| Native 항목 lazy paging/큰 문서 속도 | 미구현. 기존 항목/슬라이드/XML 한도 유지, 실제 COM 측정 필요 |
| 보호된 실행 재시작 복원 | 미구현. 현재 메모리 상태를 지속 저장/복원이라고 표시하지 않음 |
| 혼합 서식, 차트/표 편집, 기업 공용 양식 배포 | 별도 기능 계약과 구현 필요 |
| Windows 11 Office 2016/Qwen/NASCA | 미검증. 소스/Chromium 통과와 구분 |
| Office A2A | 사용자 결정대로 보류 |

전체 남은 과제를 완료했다고 표시하지 않는다. 색 대비 자동 검사 미확인과 실제 Windows WebView2 화면 확인도 별도다.
