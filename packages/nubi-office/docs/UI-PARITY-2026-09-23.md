# 브라우저 누비와 Excel 누비 UI 일치

사용자가 제공한 `agentfactorysdkdeck.html`과 현재 브라우저 누비를 기준으로 Excel 작업창을 정리했다. 문서의 설명문을 실행 지시로 취급하지 않았으며, 디자인 값과 구성만 참고했다.

## 확인한 차이와 적용

- 개발 소스는 현재 브라우저 컴포넌트를 직접 참조했지만, 배포 저장소의 `vendor/nubi-shared`는 이전 UI를 담고 있었다. 상단 새 대화 버튼, 모델 선택, 대화 삭제 확인, 글자 굵기와 크기에서 차이가 났다. 검토한 공통 UI 24개 파일을 같은 내용으로 맞췄다.
- HTML의 파랑, 보라, 청록 계열과 옅은 그라데이션, 둥근 흰 표면을 기존 누비 토큰으로 공유한다. 로컬 Noto Sans KR, 본문/입력/상태 14px, 22px, 대화상자 제목 16px, 24px을 사용한다. 발표용 HTML의 큰 제목 크기를 작업창에 옮기지는 않았다.
- `InteractionSurface`와 `ApprovalPreview`를 분리해 브라우저 질문, 승인과 Office 승인에서 직접 공유한다. 값/수식/양식 상세는 접어 보고, 주요 확인, 취소 동작은 유지한다. 양식 차이와 미검증 경고는 접힌 상세 밖에 남긴다.
- `TraceSurface`와 `TraceStep`을 브라우저 실행 기록과 Office 도구 기록이 공유한다. 작업 중에는 펼치고 완료 시 접는다. 사용자가 직접 열어 둔 기록은 유지한다. 캡처 저장이나 브라우저 실행 API는 Office로 가져오지 않았다.
- 큰 하단 상태 카드를 간결한 상태 행으로 변경했다. 확인된 완료 단계 수를 표시한다. 질문/승인 카드가 화면 밖에 있을 때만 질문 보기, 변경 확인, 복구 확인을 표시한다. 전송과 혼동되는 위쪽 화살표를 제거하고 화면에 이미 보이는 질문으로 이동하는 버튼은 숨긴다. Excel 선택 범위와 값은 상단 더 보기의 선택한 셀 확인에서 읽는다. 요청을 보낼 때에도 현재 선택을 새로 읽고, 변경 대상은 승인 카드에 표시한다. 작업 모드 선택을 제거했다. 사용자는 요청만 입력하고, 에이전트가 실행 경로를 결정한다. 모호한 대상만 채팅 내 질문으로 확인한다. 저장된 양식 사본 열기는 더 보기에서 선택적으로 제공한다.
- 상단은 누비의 대화 이력, 사용량, 더 보기 구성으로 통일했다. 사용자 수정 요청에 따라 연결 선택은 AI Pro, ChatGPT, FabriX 3개만 표시하고, 추가된 AI Pro CLI, OpenAI 호환 및 직접 연결 메뉴는 제거했다. 각 서비스 내부 모델 목록은 필터링하지 않는다. 새로고침과 로그아웃은 제공자 탭에서 분리해 창 하단 오른쪽에 모았다. 새 대화는 이력 검색 옆 + 버튼이며 실행 후 입력창으로 초점이 돌아온다. 모델 목록은 기존 선택을 유지하고, 새로고침 실패를 목록 안에 표시한다. 실패가 무한 재조회나 모델 삭제를 유발하지 않는다.

## 가독성 우선

현재 할 일, 필요한 질문과 확인, 결과 순서로 읽히도록 정리했다. 질문이나 승인 대기에는 계획과 도구 기록을 접고, 실행 중에는 최근 3개 기록과 진행 중인 도구를 보여준다. 요구사항과 참고 범위는 참고한 내용으로 묶었다. 반복되는 상태 배지, 경과 시간, 완료 문장, 작업 방식의 장식 아이콘과 긴 설명을 제거했다. 원문 근거와 미확인 경고는 확인할 수 있다. 제품이 작성하는 화면 문구와 도구 진행 문구에서 중간점을 제거했다. 사용자 문서나 모델 원문은 일괄 치환하지 않는다.

## 적용한 방법과 의존성

기존 연구의 QuestionForm 재사용 원칙을 확장했다. 컴포넌트 복제 대신 호스트 독립적인 표시 계층을 공유하고, 의미별 디자인 토큰과 파일 해시 계약으로 드리프트를 감지한다. 상태/질문/승인 데이터와 Excel 변경 권한은 각 호스트가 소유한다.

기존 React, CX, react-markdown을 그대로 사용한다. 검사는 기존 React Testing Library, jsdom, axe-core, Playwright로 수행한다. 새 UI 프레임워크나 agent 런타임은 추가하지 않았다. 현재 라이선스 고지와 의존성 버전은 유지했다. 외부 UI 키트 도입은 누비와의 시각적 차이 및 중복 테마 비용 때문에 선택하지 않았다.

`design/shared-ui.json`은 참조 HTML SHA-256과 검토한 UI 파일 해시를 기록한다. `node scripts/check-ui-parity.mjs` 및 소스 테스트가 이를 확인한다. 브라우저 UI를 변경하면 해당 UI 변경을 검토하고 배포 스냅샷, 명세를 함께 갱신한다. 인증 저장소, provider/agent 런타임이나 기업 데이터는 동기화 대상이 아니다.

## 검증 경계

`tests/ui-usability.test.mjs`는 실제 App/컴포넌트와 스크립트로 제어한 WebView 브리지를 사용한다. 모델 목록 실패 후 유지, 명시적 재조회, 새 대화 후 초점, 질문의 입력/ACK 보존, 승인 이중 클릭 방지, 완료 기록 접기를 검사한다.

`PLAYWRIGHT_CHANNEL=chrome node tests/ui-preview.mjs`는 현재 소스를 메모리에서 변환하여 실제 컴포넌트의 정적 HTML을 Chromium에서 표시한다. 로그인, 실행 중, 질문, 승인, 복구, 모델, 작업 대상 질문, FabriX 연결, 대화 이력, 셀 속성, 변경 기록을 320/380/1100px로 확인한다. 렌더링된 글꼴, 크기, 가로 넘침, 상태 행 위치와 axe 결과를 `verification/usability-preview.json`에 기록한다. 자동 대비 검사가 판정하지 못한 항목은 incomplete로 남긴다. 정적 화면의 클릭 동작이나 Windows 런타임 검증으로 표현하지 않는다.

이 작업은 소스 수정이다. 사용자 요청에 따라 번들, Windows 호스트, 설치 파일을 빌드하지 않았다. 설치된 앱의 화면은 새 최종 빌드 후 업데이트해야 바뀐다. 실제 Excel 2016, 회사 SSO, Qwen 문서 정확도와 NASCA는 이번 UI 검증 범위 밖이다.

자동 판단, 질문 후 이어가기와 적용한 BP는 [자동 작업 흐름](AUTOMATIC-FLOW-2026-09-23.md)에 기록했다.


## 전체 AI Pro 목록과 상단 토스트 확인

AI Pro 모델은 `/api/models` 응답의 유효한 고유 `name` 전체를 표시한다. CLI, `target`, `is_agent`, Qwen 기본 선택 여부로 제외하지 않는다. 몇 개만 보이던 모델 창의 440px 고정 높이를 없애 내용과 화면 높이에 맞춘다. 앞선 정적 미리보기의 임의 모델 3개를 제거하고 저장된 API 응답 10개 전체를 사용한다. 이는 실시간 회사 계정에서 받은 목록은 아니다. 서버가 반환하지 않은 모델 ID는 추측해서 추가하지 않는다.

모델 검사는 구형 Office 패키지의 인증 파서 대신 실제 `worker/aipro-auth.mjs`를 사용하도록 바로잡았다. `model-catalog-ui.test.mjs`는 현재 Office 파서와 제공자, 공통 모델 선택창을 연결해 전체 모델 표시, AI Pro Fast 검색, 각 모델 선택과 원래 ID의 completion 요청 전달을 검사한다. 가짜 HTTP 응답으로 실행하며 실계정 모델 추론 성공은 별도다.

토스트는 공통 누비 `surfaces.css`의 기존 상단 배치를 유지한다. CX `notifyToast`를 실제 호출해 만든 일반 안내, 모달 내 안내, 모달 내 오류 화면을 Chromium에서 측정한다. 세 너비 모두 화면 상단 좌표, 가로 범위와 하단에 붙지 않는 실제 위치를 검사하고, 모달에서는 접근 가능한 활성 dialog 안에 남는지도 확인한다. 임의로 두 번째 토스트 시스템을 추가하지 않는다. 사용자 요청에 따라 빌드와 설치 파일 생성은 하지 않는다.

배포 스냅샷의 기존 팝업 transform 애니메이션을 50ms 지점에 정지해 상단 토스트 위치가 틀어지는 실패를 재현했다. 현재 공통 누비의 그림자 전환 애니메이션을 동기화해 고정 토스트가 팝업 좌표에 종속되지 않도록 했다. 모션 감소를 끈 상태에서도 같은 상단 좌표 검사를 수행한다.

## 입력 중심 레이아웃 재점검

기본 화면의 주 동작은 요청 작성과 전송이다. Excel을 위한 보조 도구를 모두 입력창에 두면 사용자가 먼저 셀, 파일, 사용량 중 무엇을 선택할지 판단해야 했다. 기존 React/CX 버튼과 DetailPanel, 누비 DeckDisclosure를 이용해 점진적으로 정보를 펼치는 방식으로 정리했다. 새 메뉴 라이브러리는 추가하지 않았다. 이것은 사용성 가설을 반영한 구현이며 사용자 실험으로 입증한 생산성 수치는 아니다.

| 점검 전 | 적용 후 | 이유 |
| --- | --- | --- |
| 소개 영역을 한 문장으로 축약 | 브랜드 제목 + 두 줄 설명 + 별도 입력 유도 복원 | 사용자가 지정한 누비의 소개 구성과 정체성을 유지한다. |
| 선택 범위가 있으면 입력창 주변 버튼 7개 | 모델 선택과 전송/중지 2개 | 요청에 집중하고 셀 확인을 선행 절차로 오해하지 않게 한다. |
| 선택 범위, 셀 상세, 새로 읽기 상시 노출 | 더 보기 → 선택한 셀 확인 | 열 때마다 현재 선택을 읽는다. 실패 시 이전 값을 재사용하지 않는다. |
| 양식 파일 아이콘 상시 노출 | 더 보기 → 등록 양식 사본 열기 | 특별한 파일 작업만 필요할 때 연다. 취소 시 작성 중인 요청은 유지한다. |
| 상단 사용량과 하단 컨텍스트 아이콘 중복 | 상단 사용량에 합계와 마지막 호출 상세 | 제공되지 않은 수치를 빈 게이지로 보여주지 않는다. |
| 계정과 모델 관리가 설정에도 반복 | 입력창 모델 선택에 통합 | 모델 창 하단 새로고침/로그아웃 위치를 유지한다. |
| 실행 중 사용할 수 없는 빈 입력란 | 진행 상태와 중지만 남기고 입력란 접기 | 위쪽 실행 결과와 현재 질문에 공간을 더 준다. |
| 답변이 끝난 질문과 답변이 계속 펼쳐짐 | 확인한 내용으로 접기 | 다음 질문과 결과를 먼저 읽되 이전 답변을 다시 열 수 있다. |

새 Excel 문구와 작업 모드 선택은 앞선 수정에서 제거한 상태를 유지한다. 도움말도 현재 경로로 고쳤다. 실제 반영/저장 승인, 양식 차이 경고, 진행 상태와 중지는 계속 노출한다. 선택 확인만으로 작업을 시작하거나 셀을 쓰지 않는다.

색, 글꼴, 간격은 검토된 공통 토큰을 그대로 사용한다. Office 전용 스타일에서는 불필요해진 범위 칩 규칙을 제거하고 더 보기의 행 배치만 정의한다. 본문과 입력 14px/22px, 팝업 제목 16px/24px을 좁은 작업창에서도 유지한다. 모델 목록, 질문, 승인, 진행 기록은 기존 공통 컴포넌트를 사용한다.

정적 미리보기에서도 실제 App과 같은 OfficeComposer를 사용하도록 바꿨다. 기존에 미리보기에서 빠졌던 입력창 아이콘 차이를 다시 만들지 않기 위해서다. 실 App의 스크립트 브리지 검사에서 현재 선택 다시 읽기, 읽기 실패 후 재확인, 셀 요청 초안 유지, 양식 파일 취소, 변경 기록 접근, 답변 접기를 확인한다. 변경 전후 표와 실제 소스 화면은 `verification/nubi-ui-review.html`에서 함께 본다.

소개를 지나치게 축약했던 변경을 사용자 피드백에 따라 바로잡았다. 첫 화면은 캐릭터 → “엑셀을 누비는 AI Agent, 누비” → “작은 뱁새가 엑셀을 누비며 / 문서 작성부터 수식과 서식까지 대신합니다.” → “누비에게 무엇을 맡길까요?” 순서다. 로그인에는 같은 제목과 설명을 쓰고 입력 유도 대신 연결 버튼을 둔다. 도구를 줄이는 기준을 브랜드 소개 삭제에 적용하지 않는다. 더 보기의 연결 진단은 공통 DeckDisclosure를 유지한다.

## HTML 원본과 다시 대조

`design/html-reference.json`은 사용자 HTML의 SHA-256, 19개 색상, 배경, 그림자와 컴포넌트 대응을 기록한다. HTML의 편집 가이드와 제품 설명을 실행 지시로 사용하지 않는다. 현재 브라우저 누비가 이미 사용하는 흰 표면, 옅은 블루/보라/민트 배경, 28% 아이콘 타일, 둥근 입력창과 선택 상태를 유지한다. 로컬 Noto Sans KR는 원본의 대체 서체이며 외부 폰트 요청을 추가하지 않는다. 발표용 제목 크기 대신 좁은 작업창의 글자 크기를 유지하고, 작은 글자에는 원본의 진한 블루를 쓴다.

Office 결과 카드는 원본 `.file-card`와 달리 투명 표면에 맨 아이콘만 있었다. 문서와 양식 결과를 같은 OfficeDocumentResult로 묶어 흰 표면, 옅은 블루 테두리, 파일 그림자와 색면 타일을 적용했다. 실제 결과 데이터와 열기 동작은 그대로 연결한다. 질문/승인, 실행 기록, 모델/연결, 이력, 셀 상세, 변경 기록, 사용량, 토스트는 기존 공통 컴포넌트를 유지하며 같은 스타일 계층으로 검사한다.

소스 미리보기는 19개 기준색의 실제 CSS 값, 소개 제목/설명/별도 질문 표시, 320px 짧은 창과 일반 창 배치를 검사한다. 세부 폰트/줄 높이/넘침/접근성 자동 검사와 기존 UI 동작 검사를 함께 수행한다. 색 일치나 소스 화면 검사는 실제 Excel의 문서 작성 정확도를 증명하지 않는다.
