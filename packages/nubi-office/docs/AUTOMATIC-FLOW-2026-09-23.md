# 요청 중심의 Excel 에이전트 흐름

사용자는 작업 방식을 고르지 않고 원하는 결과를 입력한다. 현재 선택한 모델이 요청과 제한된 셀 표본을 보고 기존 문서 작성, 셀 분석/수정, 양식 채우기/등록 실행기로 연결한다. Qwen 3.8 27B를 기준으로 짧은 JSON 응답을 사용하며 별도 분류 모델로 바꾸지 않는다. 회사 모델 ID나 정확도는 추정하지 않는다.

## 사용자 흐름

1. 요청 입력. 예: “수능 성적표 양식을 만들어줘.”
2. 대상이 명확하면 계획 표시 후 기존 도구 실행. 대상이 모호하면 “새 문서로 만들기 / 현재 양식 채우기” 같은 실제 선택지와 직접 입력을 제공한다. 필요한 학생 수나 데이터는 문서/양식 실행기가 추가 확인한다.
3. 답변을 받으면 같은 실행 안에서 이어간다. 요청과 승인된 답변을 유지한다. 셀을 임의로 확대하거나 현재 선택만으로 기존 문서 편집을 추정하지 않는다.
4. 실제 셀 변경과 최종 저장은 구체적인 결과를 보여주고 확인받는다. 원본, 수식, 양식 보존과 readback 검증은 기존 실행기가 담당한다.
5. 완료 결과를 전달한다. 세 번 진전 없는 실패는 같은 실행의 재시도/중지 확인으로 전환한다. 취소 후 늦게 도착한 응답은 새 실행을 시작하지 않는다.

등록 양식은 상단 더 보기의 파일 동작으로 사본을 열 수 있다. 기존 Excel 양식 분석과 등록은 자연어로 요청할 수 있다. 별도 모드 화면이나 사전 작업 설정을 요구하지 않는다.

## 참고와 실제 적용의 구분

| 근거 | 이번 반영 | 도입 범위 |
| --- | --- | --- |
| [Anthropic Building effective agents](https://www.anthropic.com/engineering/building-effective-agents), routing 및 environment-feedback/HITL | 짧은 의도 판단 뒤 전문 실행기로 전달, 도구 결과 확인, 필요한 지점의 질문 | 설계 패턴 참고. Claude 서비스/SDK를 추가하지 않음 |
| [Pi agent core](https://github.com/earendil-works/pi) 0.86.1 | 기존 셀/문서 도구 루프를 재사용, 입력 답변을 도구 결과와 다음 검토 문맥에 유지 | 이미 고정한 오픈소스 런타임 재사용. 새 의도 분류는 로컬 통합 코드 |
| [p-retry](https://github.com/sindresorhus/p-retry) 8.0.1, MIT | 기존 감독기로 모델 응답/허용된 읽기 재시도, 3회 무진전 HITL | 기존 의존성 실제 사용. 쓰기 재시도에는 사용하지 않음 |
| React Testing Library, jsdom, axe-core, Playwright | 실제 UI 질문/ACK와 읽기 흐름, 정적 화면 검사 | 기존 개발 의존성 사용. Windows/실모델 검증 대체 아님 |

Anthropic 문서는 2024년 방법론이며 현재 관리형 에이전트 제품과 구분한다. 이 작업에서는 모델 독립적인 routing과 도구 피드백 패턴만 확인했다. LangGraph 등의 두 번째 실행 엔진은 선택하지 않았다. 현재 메모리 실행/Excel COM 경계에 새로운 상태 저장과 직렬화 계층을 더할 필요가 없고, 기존 Pi와 승인/receipt 계약을 유지하는 편이 이 변경의 범위를 작게 만든다. 별도 실험 없이 성능 향상을 주장하지 않는다.

## 구현과 검사

- `intent-agent.mjs`: 읽기 전용 분류, 관찰 범위 확인, 질문/복구 대기, 취소 차단, 실행 ID 유지. 허용 목록 밖 경로는 실패 처리한다.
- `input-contract.mjs`: 질문과 답변을 합해 64,000자 이내로 검증하고 실행기에 그대로 전달한다. 초과 답변을 조용히 자르지 않는다.
- 기존 셀 실행기: 자동 흐름에서는 계획/도구/검토 중 질문에 답해도 같은 실행을 유지한다. 질문 중 셀 fingerprint가 바뀌면 기존 변경을 진행하지 않는다.
- 기존 문서 실행기: 분류 중 수집한 답변을 기존 질문 기록과 동일하게 보존하고 최종 저장 승인을 유지한다.
- 실제 App에서 `mode:auto`로 요청하며 새 모드 선택 화면을 표시하지 않는다. 전송 직전에 현재 선택을 읽되, 새 문서는 셀 선택이 없어도 요청할 수 있다.

스크립트 모델로 자동 경로 5종, 질문과 장문 답변, 잘못된 분류, 취소 후 응답, 범위 미선택, 양식 바인딩, 응답 중복/충돌, 실제 문서/셀 실행기와 승인 경계 연결을 검사한다. 소스 테스트 성공은 회사 Qwen의 의도 판단 정확도나 실제 Windows Excel 2016 성공률이 아니다. 사용자 요청에 따라 빌드와 설치 파일 생성은 수행하지 않는다. 재시작 후 실행 복구도 이번 범위가 아니다.
