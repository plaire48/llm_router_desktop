# 기존 Excel 양식 분석과 작성

2026-09-23 소스 반영. 설치 파일 미생성. 실제 Windows Excel 2016과 기업 Qwen 3.8 27B 정확도는 아직 검증하지 않았다.

## 분석 명세와 원본의 역할

원본 Excel은 문서의 틀과 계산기를 맡는다. 분석 명세는 에이전트가 어느 항목을 어디에 입력할지 판단하는 안내서다. 분석 결과로 원본 XLSX를 다시 생성하거나 모델 가중치를 학습하지 않는다.

| 자료 | 보관하는 내용 | 작성 시 역할 |
|---|---|---|
| 원본 Excel | 수식, 병합, 서식, 테두리, 행·열 크기, 입력 제한 | 확인된 입력 칸에 값만 쓰고 Excel에서 계산 |
| 분석 명세 | 구조 식별자, 항목 ID, 셀 주소, 값 종류, 필수 여부, 관찰한 선택지 | 질문과 입력 도구의 허용 대상 |
| 작성 데이터 | 사용자 요청과 항목별 답변 | 확인된 항목에만 값으로 전달 |
| 실행 증거 | 적용 영수증, 원본 지문, 실제 셀 readback | 완료 판단과 충돌·복원 검사 |

분석과 작성은 역할이 다르지만 하나의 실행에서 이어진다. 입력값을 받을 때마다 전체 작업을 새로 시작하지 않는다. 답변과 실행 기록은 메모리에만 유지한다. 확인된 입력 명세는 Excel 사본 내부의 Custom XML Part에 등록하고 다시 불러올 수 있다. 회사 공용 카탈로그·재시작 후 실행 복원·양식 버전 배포는 아직 구현하지 않았다.

## 분석 후 등록과 재사용

1. `.xlsx` 양식을 Excel에서 열고 입력 영역을 선택한다. 채팅 입력창 **+ → 현재 양식 등록**을 누르고, 대화에서 용도와 업무 규칙을 설명한다. 작업 방식 선택기는 사용하지 않는다.
2. AI가 구조를 읽고 항목/셀/자료형/필수 여부를 제안한다. 사용자가 확인한 뒤 **사본으로 등록**에서 새 저장 위치를 고른다. 원본 파일을 덮어쓰지 않는다.
3. Excel `SaveCopyAs`로 전체 통합문서를 복제하고, 복사본에 `urn:nubi:office:template:1` Custom XML Part를 추가한다. 내부 레코드는 필드 명세와 용도/메모를 담고 인스턴스 답변/셀 원문은 담지 않는다. Base64는 XML 운반용 인코딩이며 암호화가 아니다.
4. Excel에서 저장하고 다시 열어 명세를 읽고, 선택 범위의 셀 속성을 비교한다. 차이가 있으면 실제 주소·속성·이전/이후 값을 보여주고 등록 완료 전에 확인받는다. 취소해도 이미 생성한 사본은 남으며 성공으로 표시하지 않는다.
5. 등록 검사가 끝나면 현재 Windows 계정의 보호된 목록에 색인한다. **+ → 양식 선택 → 이 양식으로 작성**에서 새 문서 위치를 고른다. Excel이 전체 사본을 만들고 비교 결과를 채팅에 표시한다. 새 사본의 문서 ID로 범위를 새로 묶는다. 파일로 직접 여는 기존 메뉴도 유지한다.
6. 명세의 구조 해시와 고정 문구 해시를 실제 셀과 대조한다. 달라졌으면 이전 연결로 쓰지 않고 사용자가 재분석/취소를 선택한다. 일치하면 기존 명세를 재사용하고 부족한 값만 질문한다.

현재 이미 열려 있는 등록 파일은 복제 대상으로 받지 않는다. 저장 후 닫고 다시 선택해야 한다. `.xls`/`.xlsm`을 `.xlsx`로 자동 변환하지 않으며 회사 암호화 정책을 우회하지 않는다. XML 레코드의 업무 메모와 문서 내용은 모델의 실행 명령이나 권한이 아니다.

## NASCA 경계

사용자가 확인한 환경은 Excel 열기/저장 시 NASCA가 자동 처리하는 방식이다. 추가 기능은 Excel COM의 열기·복사 저장·저장을 사용하며 해당 흐름에서 이벤트를 끄지 않는다. 별도 `File.Copy`, ZIP 재작성, 평문 JSON 명세 파일, 외부 복호화 도구를 사용하지 않는다. Node에는 권한 있는 Excel이 읽은 제한된 셀 데이터만 전달한다. 기존 선택 LLM으로 보내는 데이터의 사내 전송 정책은 NASCA 암복호화와 별개다.

Excel 저장 및 명세 재열기 성공은 NASCA 암호화 검증이 아니다. 현재 영수증은 `nascaEncryptionVerified:false`로 남기고 화면에도 미확인으로 표시한다. 회사 NASCA 정책·권한·실제 암호화 상태와 전체 문서 보존은 실 PC 검증이 필요하다. 경로 선택 후 저장 응답이 유실되면 자동으로 사본을 다시 만들지 않는다.

## 작성 흐름

1. 원본 양식을 Excel에서 열고 작성할 영역을 선택한다. 현재 단일 연속 범위, 최대 1,000셀이다. 병합 입력 칸은 병합 전체를 포함한다.
2. 필요한 내용을 자연어로 요청한다. 등록한 양식은 입력창의 **+**에서 선택한다. 에이전트가 적합한 실행 경로로 연결한다.
3. 누비가 원본을 읽어 수식/배열 수식/병합의 나머지 셀/숨김 영역을 입력 후보에서 제외한다. 인접 문구는 항목명 힌트이며 권한이나 확정된 업무 의미로 취급하지 않는다.
4. **항목명 → 셀 위치 → 값 종류 → 필수 여부 → 기존 표시 형식**을 제안하고 사용자가 연결을 확인한다. 취소는 중지다. 연결을 변경하려면 수정할 내용을 넣어 다시 요청한다.
5. 필요한 값만 누비의 기존 객관식·주관식 폼으로 묻는다. 예시로 채워진 값은 승인된 기본값이 아니다. 미응답을 동의로 보지 않는다.
6. 현재 계획 단계의 입력값을 독립적으로 검토하고 구체적인 변경 내용을 HITL로 보여준다. 확인된 항목 외에는 쓸 수 없다.
7. 값을 반영하고 Excel 계산값을 읽는다. 기존 수식·병합·지원 서식·테두리·입력 제한·행열 크기의 변경이나 새 계산 오류는 완료로 인정하지 않는다. 기존 문서의 저장은 Excel에서 한다.

객관식은 실제 데이터 유효성 검사의 인라인 목록과 Excel의 목록 구분자를 사용한다. 4개를 넘는 목록은 주관식 입력과 값 검증을 사용한다. 이름 정의/다른 범위를 참조하는 목록 수식은 추측해서 선택지로 만들지 않는다. 실제 검증은 Excel readback이 담당한다. 날짜는 ISO 입력을 원본의 1900/1904 날짜 체계로 변환하고, 코드 앞자리 0과 숫자 0·false를 유지한다. 표시 형식은 자동 교체하지 않는다. 값 종류와 표시 형식의 업무 적합성은 사용자 연결 검토와 독립 AI 검토 대상이다.

## 실행 경계

- `inspect_template`은 20셀씩 원본의 입력 후보와 보존 영역을 조회한다. 긴 미리보기는 160자로 제한하고 생략 사실을 표시한다.
- `define_template_fields`는 최대 30개의 단일 셀 항목을 제안한다. 확인 전에는 명세로 입력할 수 없다. 사용자 답변이나 적용 이력이 있으면 연결을 자동 교체하지 않는다.
- `ask_template_field`는 동일 실행에서 질문하고 답변을 항목 ID와 원본 지문에 연결한다. 사용자가 직접 Excel을 수정하면 이전 답변을 새 셀에 자동 적용하지 않는다.
- `fill_template_fields`는 값만 쓴다. 원시 `apply_changes`는 이 모드에 광고하지 않는다. 수식 덮어쓰기·서식 변경·행 추가·병합 해제는 허용하지 않는다. 긴 항목 값은 2,000자, 질문 답변 묶음은 16,000자로 제한한다.
- 병합 입력은 전체 병합 영역이 선택 안에 있고 기존 수식이 없는 맨 왼쪽 위 셀만 허용한다. C# 엔진과 COM 포트가 모두 검사한다. 보호된 시트는 현재 전체 쓰기를 차단한다. `Locked=true`만으로 보호 중이라고 오인하지 않는다.
- 분석 명세는 값과 별도의 구조 해시를 갖는다. 원본 수식/서식/보호 속성이 바뀌면 재분석해야 한다. 값만 직접 바뀌어도 지문 충돌로 멈춘다.
- 다른 시트는 기존 읽기 도구로 참고할 수 있지만 편집 권한이 생기지는 않는다. 차트·그림·조건부 서식·페이지 전체 시각 일치 검증, 반복 행 확장, 다중 시트 일괄 입력은 지원 완료 범위가 아니다. 이 항목은 화면에서 미확인으로 표시한다.
- 모든 모델 호출은 기존 선택 제공자/모델을 따른다. 품질 평가의 기준은 기업 카탈로그에서 반환한 Qwen 3.8 27B다. 공개 Qwen 이름을 만들어 대체하지 않는다.

## 동일성 검토와 사용자 알림

사용자의 최종 기준은 완전 동일을 무조건 보장하는 대신, 유지 가능한 부분을 보존하고 차이·검증 한계를 사전에 알리는 것이다. 새 `template-preservation.mjs`는 모델 점수가 아닌 실제 관찰값 비교를 사용한다. 비교한 속성은 **일치 / 차이 있음 / 미확인**으로 나누고 세 범주를 화면에 표시한다. 일부 속성을 못 읽어도 다른 속성의 실제 차이는 숨기지 않는다. 최대 20개 차이를 표시하고 전체 차이 수를 함께 남긴다.

선택 범위의 수식·지원 글꼴/색/정렬/숫자 형식·병합·테두리·행열 크기·숨김·유효성·잠금을 비교한다. 허용된 입력값과 기존 수식의 계산값 변경은 고정 양식 차이와 구분한다. 그림·차트·조건부 서식·기타 셀 효과·인쇄 모양·선택 밖 범위·NASCA 상태는 미확인이다. 전체 문서의 바이트 일치나 시각적 일치를 판정하지 않는다.

매핑/쓰기/등록 확인 카드에 검증 범위를 넣고, 사본 열기·등록·최종 결과에도 보고서를 남긴다. 복제 시 차이는 사용자 검토 대상으로 보이되, 실제 입력 시 수식 손상·예상 밖 값·원본 변경·적용 불명은 여전히 실패다. 경고 확인으로 데이터 오류를 통과시킬 수 없다.

다음 실 PC 평가는 대표 양식별 원본과 결과를 보관해 동일 버전 Excel에서 셀 비교 + 승인된 XML 부분 비교 + 인쇄/화면 비교 + 사람 검토를 나누어 수행해야 한다. XML 순서·ZIP 메타데이터·계산 캐시 변경과 업무 양식 변경을 구분해야 하므로 단순 파일 SHA 동일성은 합격 기준이 아니다. XML 규격 검사만으로 시각적 동일성을 입증하지 않는다. 현재 전체 OPC 패키지/시각 비교기는 구현하지 않았다.

Docling 런타임은 추가하지 않음: 현재 Excel COM 입력과 중복되고 DRM/서식 보존 엔진이 아님 |

이번 변경은 새 외부 라이브러리를 추가하지 않는다. 기존 Pi 실행기·누비 폼·Excel COM을 사용한다. Pi 공통 도구 인자 검사가 boolean/integer/nullable 타입을 거절하던 결함도 수정했다. 단계·도구·결과의 실제 실행 경로로 이 결함을 재현했다.

## 검증 상태

- 양식 전용 Node 회귀는 질문 후 동일 실행 재개, 병합 첫 셀, 수식 차단, 날짜/코드, 0/false, 직접 수정 충돌, 취소, 예시 값 오인 방지, 저장 명세 재사용, 차이/미확인 구분, 사용자 취소와 저장 응답 누락을 다룬다. 최종 검사 수와 소스 지문은 `verification/template-harness.json`에 기록한다.
- 새 C# 병합/보호 계약 시나리오 3개를 추가했지만 컴파일·실행하지 않았다. UI 소스의 실행/브라우저 렌더링도 이번 검증에 포함하지 않았다.
- 사용자 요청에 따라 앱/Windows/설치 파일 빌드와 CI 빌드 실행을 하지 않았다. 기존 설치 파일에는 이 기능이 들어 있지 않다.
- 실제 Excel 2016의 병합 입력·테두리 readback·되돌리기와 회사 모델 응답의 정확도는 미검증이다. 이전 설치 검사 실패도 미해결이며 새 소스 테스트를 설치 성공으로 표현하지 않는다.
