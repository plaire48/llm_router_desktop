# Excel 2016 작업창 사용성 개선과 남은 부족점

2026-09-23 · Qwen 3.8 27B 기준, 기존 제공자/모델 선택 유지 · 소스 개선, 빌드/설치 파일 생성 없음.

## 확인된 문제와 반영 내용

| 문제 | 사용자에게 생기는 영향 | 반영한 개선 |
| --- | --- | --- |
| 누비 질문창 16,000자 / Office 실행기 10,000자 | 긴 답변이 거절되는데 질문창이 먼저 닫혀 작업 종료 | UI·실행기 공통 한도, 현재 질문을 포함한 64,000자 답변 이력 예산. 질문 수신 확인까지 폼/입력 보존, 거절 후 같은 질문에서 수정 |
| 질문 대기에도 진행 중 표시·회전 아이콘 | AI가 무엇을 기다리는지 모름 | 실행 / 답변 대기 / 반영 전 확인 / 자동 재시도 멈춤 / 재요청 대기 구분. 대기 상태의 회전 아이콘 중단 |
| 진행 기록에 질문과 승인 묻힘 | 답변할 위치를 찾기 어려움 | 작성창 위 현재 상태·확인된 완료 단계·질문/승인 이동 버튼. 클릭할 때만 이동·포커스, 자동 포커스 탈취 없음 |
| 대화 전체에 aria-busy | 보조기기의 진행·질문 알림이 작업 끝까지 지연될 수 있음 | 전체 대화의 busy 제거, 필요한 상태 메시지로 진행 안내 |
| 진행 로그가 계속 늘어남 | 현재 단계와 실패 원인이 읽기 어려움 | 최근 5개와 진행/대기 이벤트 우선 표시, 이전 기록은 펼쳐 확인. 오류 기록을 삭제하지 않음 |
| 단순 분석에도 셀 검증 완료 문구 | 실제 변경 여부 오해 | 읽기만 완료 / 변경 확인 / 문서 저장 확인 구분. 중지·실패 시 확인된 단계 수와 다음 미완료 단계 표시 |
| 오류 문구만 있고 다음 행동 없음 | 설정·변경 기록 위치를 찾아야 함 | 원인별 연결/모델·현재 범위·변경 기록 확인 버튼. 쓰기 재실행 버튼 없음 |
| 양식 현재 값 0/false가 비어 있음으로 표시 | 승인 근거가 사실과 다름 | 0과 false를 그대로 표시 |

답변 전달은 `입력 → 검증 → 같은 callId로 전달 → worker 수신 확인 → 질문 닫기` 순서다. 서버가 검증 오류를 반환하면 worker의 대기 질문도 소비하지 않는다. 응답 유실의 재전달은 기존 중복 방지·3회 실패 HITL 정책을 사용한다. 취소 후 늦은 수신 응답은 대화를 재개하지 않는다. 일반 셀 분석의 이전 질문 경로는 새 요청 한도 8,000자를 사용한다.

## BP와 오픈소스의 실제 적용

- [Anthropic: Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)의 단계 계획 공개, 실제 도구 결과 기반 진행, 필요한 시점의 사람 개입 원칙을 적용했다. 내부 추론 전문을 표시하는 기능은 아니다.
- [W3C 상태 메시지](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)를 참고해 상태 전달과 사용자 포커스를 구분했다. 질문/승인을 사용자가 직접 찾아갈 수 있고, 상태 변화만으로 입력 중인 포커스를 빼앗지 않는다.
- [React Testing Library](https://testing-library.com/docs/react-testing-library/intro/) 16.3.3과 jsdom 27.4.0을 **개발 검사에 실제 도입**했다. 실제 App·공유 질문 폼·상태·승인 컴포넌트를 접근 가능한 이름으로 조작한다. WebView RPC 응답은 시험용이다.
- [axe-core](https://github.com/dequelabs/axe-core) 4.13.0을 **개발 검사에 실제 도입**했다. JSDOM의 알려진 한계 때문에 색 대비는 DOM 검사에서 제외하고 별도 Chrome 정적 화면에서 확인한다. 자동 검사만으로 접근성 인증을 주장하지 않는다.
- 기존 fast-check 상태 시퀀스, p-retry 오류 복구, Pi 실행기, 누비 컴포넌트는 유지한다. XState/LangGraph 전체 실행기를 추가하는 대신 현재 상태를 하나의 표시 모델로 정리했다. 이번 결함은 실행기 교체 없이 고칠 수 있고, 별도 상태 저장소/실행기를 추가하면 Excel 쓰기·인증·취소 계약 재검증 비용이 커진다.

새 패키지는 모두 devDependency이며 제품 런타임에서 import하지 않는다. 정확한 버전·무결성·라이선스를 잠금 파일과 THIRD-PARTY-NOTICES에 기록했다. 공유 QuestionForm의 변경은 선택적 maxLength 인자만 추가하며 브라우저 확장의 기본값은 유지한다. npm 설치는 `--ignore-scripts`로 실행했다.

## 검증 범위

- `npm test`: 입력 거절·수신 지연·중복 전송·취소 후 늦은 응답·실제 App의 질문 이동/입력 유지, 기존 에이전트·문서·양식 회귀 검사. **200/200 통과**(소스/업로드 작업본 각각). 상세 결과는 `verification/usability-checks.json`에 기록한다.
- axe DOM 검사: 질문, 승인, 복구, 실패 화면의 규칙 위반 0개. 실제 App의 대화 aria-busy 제거와 질문 이동 포커스는 별도 동작 검사로 확인한다.
- `PLAYWRIGHT_CHANNEL=chrome node tests/ui-preview.mjs`: **현재 소스 React 컴포넌트의 정적 렌더링**과 기존 CSS를 320·380·1100px, 답변/복구 2상태에서 표시한다. 6화면에서 가로 넘침 없음, 상태/이동 버튼 영역이 화면 안에 있음, 자동 접근성 위반 0개. 색 대비 일부는 자동 판정 불가(incomplete)로 남으므로 전체 색 대비 합격으로 취급하지 않는다.
- 미리보기는 모션 축소 설정으로 애니메이션 중간의 불투명도 때문에 생기는 불안정한 측정을 피한다. jsdom/Chrome 결과는 Windows WebView2·실제 스크린리더·키보드 전체 흐름 검증을 대신하지 않는다.
- JSX는 검사 시 메모리에서 변환하며 번들·배포 파일을 만들지 않는다. 예시 화면/스크린샷은 합성 성적표 질문으로 생성했다. 회사 문서를 읽거나 저장하지 않는다.
- 공유 JSX/CSS와 제품 CSS/HTML도 소스 해시 목록에 포함했다. 검사가 실제로 어떤 소스를 대상으로 했는지 추적하며, 오래된 설치 파일을 현재 소스와 동일하다고 주장하지 않는다.

## 아직 부족한 부분 — 우선순위

| 우선순위 | 남은 부족점 | 다음 검증/개선 기준 |
| --- | --- | --- |
| P0 | 실제 Qwen + Windows Excel 2016 + NASCA 연동 품질 미측정 | 대표 기업 양식의 수식·서식·저장/재열기·수정 충돌 평가와 사람의 결과 판정. 정확도 null 유지 |
| P1 | worker/프로그램 재시작 후 보호된 실행 복원 없음 | 암호화된 실행 상태·도구 수신 기록·보존 기간 설계, 재연결 시 통합문서 신원/실제 변경 대조. 평문 로그 우회 금지 |
| P1 | 설치형 WebView2의 실제 조작·배율·스크린리더 검증 없음 | 최종 빌드 요청 후 실제 Excel 작업창에서 질문·중지·복구·포커스·125/150% 배율 확인 |
| P1 | 기업 양식 다양성 및 동일 모델 검토 편향 | 고정 합성 사례 외 실제 업무별 정답·부분 실패 기준, 독립 사람 채점과 반복 평가 |
| P2 | 지원 기능 범위 제한 | 여러 시트 문서/양식 채우기 외 차트·피벗·매크로 등은 구현된 도구와 검증이 있어야 기능 추가 |

기존 구현 성숙도 **62/100**은 별도 하네스 루브릭의 코드 리뷰 점수다. 이번 사용성 검사 결과를 더해 임의로 올리지 않았다. 실모델 업무 정확도는 여전히 **미측정**이며, 새 설치 파일도 만들지 않았다.
