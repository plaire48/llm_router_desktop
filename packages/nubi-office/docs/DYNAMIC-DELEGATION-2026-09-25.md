# 동적 역할 배정과 품질 재점검

2026-09-25. Word/PPT 주 실행기가 읽은 문서를 대상으로 필요한 전문 역할, 목표, 담당 항목과 선행 작업을 정하고 `delegate_document_tasks`를 호출한다. 고정된 역할 순서만 실행하던 분할 검토에 선택 가능한 동적 분석 도구를 추가했다. 실제 문서 반영과 최종 판정은 기존 부모 하네스에 남는다.

## 방법론과 실제 도입

| 근거 | 선택과 적용 |
|---|---|
| [Anthropic Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) | 조정자가 요청에 따라 역할과 하위 작업을 정하고 결과를 통합하는 패턴을 적용했다. 모든 간단한 요청에 멀티에이전트를 강제하지 않는다. Claude 서비스나 별도 모델을 추가한 것은 아니다. |
| [OpenAI Agents SDK multi-agent](https://openai.github.io/openai-agents-js/guides/multi-agent/) | 부모가 도구 형태로 하위 분석을 호출하고 결과를 받는 구조를 참고했다. 문서 쓰기나 승인 권한을 하위 에이전트로 넘기는 handoff 및 별도 SDK는 도입하지 않았다. |
| [dependency-graph 1.0.0](https://github.com/jriecken/dependency-graph) | MIT, 런타임 전이 의존성 없음. 실제 `DepGraph.addDependency`와 `overallOrder`를 사용해 존재하지 않는 선행 작업과 순환을 거절한다. 버전과 배포 해시는 lockfile 고정, 원본 LICENSE 보존. 라이브러리는 그래프 검증만 담당한다. |
| 기존 Pi, p-map, p-retry | 주 실행기, 제한된 병렬 호출, 취소/모델 바인딩/문맥 예산과 단일 복구 감독기를 재사용했다. 추가 실행 프레임워크나 중복 재시도 감독기는 만들지 않았다. |
| Codex/OpenCode | [기존 소스 검토](COMPETITIVE-BENCHMARK-2026-09-25.md)의 실제 결과 기반 진행, 작업 권한 분리, 무진전 감지를 유지했다. 이번 변경에 별도 런타임을 복제하지 않았다. |

## 실행과 사용자 표시

1. 부모가 현재 읽은 항목을 기준으로 최대 8개 역할을 정한다. 각 역할에 목표, 제약, 완료 조건, 원문 ID와 선행 작업 ID가 필요하다.
2. 독립 작업은 최대 2개 동시 모델 호출로 실행한다. ChatGPT는 기존 제공자 정책에 따라 1개다. 한 배치는 최대 4개다.
3. 하위 모델에는 지정한 원문과 부모의 원래 요청/요구사항/확정 답변, 실제 역할을 전달한다. 선행 결과는 참고 자료로 분리한다. 인용은 지정 원문과 직접 비교한다.
4. 배치가 끝난 뒤 부모가 Office를 순차 조회해 원본 버전을 확인한다. 그 후에만 완료된 결과를 채택하고 후속 역할을 실행한다.
5. 정보가 부족한 보고서는 미완료로 남고 후속 작업은 대기한다. 같은 조건으로 다시 호출해도 같은 부분 보고서를 재사용한다. 부모는 필요한 정보를 질문하거나 계획을 바꾼다. 분석 결과 자체는 쓰기 승인이나 최종 완료 증거가 아니다.
6. 채팅에는 분석 수신 수, 확인 필요/대기 수, 실행 중인 역할과 담당 작업을 보여준다. 전체 역할, 선행 역할과 미확인 내용은 펼쳐 본다. 비공개 추론을 노출하지 않는다.

완료 결과는 현재 실행 안에서만 보존한다. 문서, 선택 모델, 부모 요청/답변이 달라지면 새 근거로 처리한다. 문서를 쓰거나 새 사본으로 바꾸면 기존 분석은 무효화한다. 재시도나 같은 결과의 재조회는 새 진전이 아니다. 작업 ID나 그래프 순서만 바꾸어도 진전 수치는 늘지 않으며 실제 역할/원문/조건/선행 계약을 기준으로 집계한다. 취소 뒤에는 늦은 응답을 채택하지 않는다.

## 함께 수정한 문제

영구 인증/설정 오류가 발생해도 대기 워커를 계속 호출하던 경로를 차단했다. 이미 시작한 읽기 작업은 정산해 성공 결과를 보존하고, 아직 시작하지 않은 요청은 보내지 않는다. 사용자 취소와 인증 실패는 구분한다. 429 또는 분기 실패 이후 새 배치를 시작하지 않고 실패와 Retry-After를 기존 부모 복구기로 반환한다. 정보 부족에 따른 부분 결과와 네트워크 실패의 재시도는 구분한다.

Office A2A는 사용자가 보류한 범위다. 이를 구현됐다고 기대하던 낡은 테스트를 미지원 계약 검사로 정정했다. 외부 위임 프로토콜은 추가하지 않는다.

## 지원 경계와 후속 우선순위

- 최초 연결은 Word/PPT였다. 후속 점검에서 기존 Excel 통합문서 실행기에 같은 DAG와 결과 재조회 도구를 연결했다. 최신 범위와 검증은 [Excel 후속 기록](EXCEL-DELEGATION-QUALITY-2026-09-25.md)을 따른다.
- Word native 읽기는 문단/필드 2,000개 한도이며 문단 4,000자 초과는 잘림으로 표시한다. PPT는 200슬라이드/2,000항목, 개별 text/notes 4,000자 한도다. 초과 원문을 이 변경으로 전부 읽을 수는 없다. native 지연 페이지 조회와 버전에 묶인 긴 텍스트 구간 읽기를 별도 구현/Windows 검증해야 한다.
- 워커가 임의로 도구를 만들거나 다른 워커를 재귀 생성하지 않는다. 현재 부모가 모델 응답에 따라 다음 계획을 구성한다. 의존 관계의 문법적 유효성, 인용 일치와 사실 추론의 정확도는 다르다.
- Qwen의 실제 모델 응답 품질, 토큰 비용/속도, Office 2016 COM와 NASCA는 연결된 실환경에서 별도 측정해야 한다. 테스트용 모델 응답은 성능 인증이 아니다.
- 설치/native 빌드는 실행하지 않았다. 기존 0.8.4 EXE에는 이번 소스 변경이 아직 없다.

검증 결과와 남은 전체 검사 실패는 [개선 상태표](IMPROVEMENT-STATUS.md)의 최신 기록을 따른다.
