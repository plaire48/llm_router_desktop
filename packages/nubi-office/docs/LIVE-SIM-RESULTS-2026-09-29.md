# 실모델 실측 결과와 수정 기록

2026-09-29, macOS. 모델 `gpt-5.6-luna`(ChatGPT 로그인), 호스트는 모의 호스트(`eval/sim`).

**근거의 경계:** 이 문서의 수치는 실제 Excel 2016, 사내 Qwen 3.8 27B, NASCA, 회사 양식의 결과가 아니다. 사례는 모두 합성 자료다. Luna는 기준 모델보다 강하므로 약한 모델에서만 나타나는 실패는 여기 드러나지 않는다. 실행마다 편차가 있어 1회 측정은 참고값이다.

## 요약

| 측정 | 시점 | 통과 | 실패 | 중단 | 검토 필요 |
|---|---|---:|---:|---:|---:|
| 기준선 | 수정 전 | 2 | 1 | 15 | 2 |
| 1차 | 계획 거절 사유, 시트 이름 주소 등 수정 후 | 5 | 0 | 13 | 2 |
| 2차 | 편집 작업 모양, 기대값 해석 등 수정 후 | 14 | 0 | 4 | 2 |
| 3차 | 빈 값 비교, 수정 전 검토 안내 수정 후 | 12 | 2 | 4 | 2 |

각 측정은 같은 20건(양식 등록 4, 재사용 4, 양식 채우기 4, 편집 8)이며 제품과 같은 분류 경로를 거쳤다.

### 반복 측정 (모든 수정 반영 후)

| 묶음 | 통과 | 시행 |
|---|---:|---|
| 양식 등록 | 9 / 12 | 4종 × 3회 |
| 재사용 | 10 / 12 | 4종 × 3회 |
| 편집, 결정적 채점 | 12 / 12 | 6종 × 2회 |
| 편집, 사람 검토 대상 | 4건 모두 검토 대기 | 2종 × 2회 |
| 양식 채우기 | 3 / 8 | 4종 × 2회 |

통과 사례 평균: 모델 호출 11~12회, 모델 응답 시간 36~45초, 요청 최대 크기 4.8만~6.6만 자.

## 모델이 잘한 것

- 양식 등록에 성공한 모든 실행에서 제안한 입력 항목이 정답 항목표와 같았다. 값 종류와 필수 여부까지 일치했다. 견적서는 품목 표 16칸을 포함해 21개였다.
- 재사용에서 계산 결과가 맞았다. 견적서 합계 605,000원, 출장 신청서 예상 경비 150,000원.

## 하네스에서 찾은 결함과 조치

모두 기록에서 확인했고, 재현 검사를 먼저 작성한 뒤 고쳤다. 검사는 `tests/plan-address.test.mjs`, `tests/live-findings.test.mjs`.

| 번호 | 기록된 동작 | 원인 | 조치 |
|---|---|---|---|
| 1 | 같은 계획을 3번 반복하다 복구 승인 요청 | 계획 거절 시 오류 코드만 전달 | 거절마다 어느 항목이 왜 틀렸는지, 허용 형식이 무엇인지 전달 |
| 2 | 주소를 `CaseSheet!A2`로 작성. 주소 115개 중 18개 | 시트 이름이 붙은 주소를 거절 | 선택한 시트의 이름이면 떼고 수용. 다른 시트면 거절 |
| 3 | 계획에 `validationValid`, `validation` 검사 작성 | 허용 목록에 없음. 모델은 관찰값에 보이는 속성을 검사하려 함 | 호스트가 직접 비교하는 속성이므로 검사로 만들지 말라고 안내 |
| 4 | 편집 작업을 `{"set_values":{...}}`로 전송. 11회 | 도구 설명의 `set_values {address,values}` 표기가 모호 | 그 모양을 수용. 도구 설명에 실제 JSON 예시 추가 |
| 5 | 등록 성공 뒤에도 실패 처리 | 계획이 "입력 칸이 비어 있지 않을 것"을 완료 조건으로 넣음. 등록은 쓰지 않으므로 충족 불가 | 등록에서는 현재 양식이 이미 충족하는 검사만 유지 |
| 6 | 최종 검토가 계속 반려 | 호스트가 관찰할 수 없는 항목(그림, 인쇄 모양, NASCA)의 확인을 요구 | 관찰 불가 항목은 답변에 밝히되 반려 사유가 아님을 명시 |
| 7 | 등록 성공 뒤 무관한 도구 호출, 같은 항목 연결을 다시 제안 | 성공 응답에 다음 행동 안내 없음 | 항목 확인과 등록 응답에 다음 행동을 명시 |
| 8 | 기대값 `"2026-11-02"`, `"80%"`가 실제 값 46328, 0.8과 불일치 | 표시 문자열을 기대값으로 작성 | 대상 셀의 표시 형식을 보고 날짜, 비율, 숫자로 해석 |
| 9 | 양식 계획을 두 단계로 나눈 뒤 한 번에 채워 모든 시도가 거절 | 쓰기 허용 범위가 계획의 단계 구분에 묶임 | 양식에서는 사용자가 확인한 입력 칸이 허용 범위. 이미 쓴 칸의 단계는 다시 쓰지 않고 완료 |
| 10 | 등록본을 불러왔는데 항목 연결을 다시 제안 | 등록본이 있어도 항목 제안 도구를 노출 | 등록본을 불러온 실행에서는 그 도구를 숨김 |
| 11 | 비고 칸이 빈 셀에서 빈 문자열로 바뀜 | 선택 항목의 빈 값을 그대로 씀 | 빈 값은 쓰지 않음. 예시 값이 있으면 지움 |
| 12 | 기대값 `""`가 빈 셀(`null`)과 불일치 | 빈 값 비교가 엄격 | 값 검사에서 `null`과 빈 문자열을 같은 빈 값으로 비교 |
| 13 | `read_worksheet_range {"sheetId":"견적서"}` 실패 | 시트 ID 자리에 시트 이름 | 목록을 읽어 정확한 이름이면 수용 |
| 14 | 분류 단계가 `{"mode":"template","question":{...}}`를 3번 반복 | 실행 방식과 질문을 함께 반환하면 거절 | 질문을 버리고 분류만 수용. 질문은 실행 단계가 한다 |
| 15 | 값을 읽기 전이라 기대값을 `null`과 `valueType: number`로 작성. 빈 셀이 이미 충족해 편집 단계가 닫힘 | 형식 있는 검사에 `null` 허용 | 거절하고 `not_empty`를 쓰도록 안내 |
| 16 | 수정 전 검토가 "편집 후 검증이 필요하다"며 반려 | 수정 전 검토에 주어진 근거가 편집 전 상태라는 설명 없음 | 수정 전 검토 지침에 명시 |
| 17 | `numberFormat: "General"`을 이미 General인 셀에 전송해 편집 거절 | 계획에 없는 서식 쓰기가 추가됨 | 셀이 이미 가진 표시 형식은 쓰지 않음 |
| 18 | 단계 불일치 거절이 반복 | `plan_step_mismatch`에 설명 없음 | 현재 단계와 그 단계가 다루는 셀을 전달 |

## 아직 남은 것

| 항목 | 내용 |
|---|---|
| 불필요한 질문 | 요청에 있는 값을 다시 묻거나 등록 허락을 구함. 등록 실패 3건이 모두 이 유형. 지침을 보강했지만 계속 발생 |
| 분류 단계의 이른 질문 | 요청이 "물어본 뒤 입력"이라고 하면 분류 단계가 먼저 물음. 양식 채우기 중단 5건의 원인. 기존 사례의 답변 규칙이 실행 단계의 질문 문구에 맞춰져 있어 채점이 중단됨 |
| 값 축약 | "견적일로부터 30일"을 "30일"로 줄여 씀. 2회. 수정 전 검토가 잡지 못함 |
| 양식 읽기 비용 | 셀 20개씩 조회해 양식당 2~4회 호출 |
| 도구 설명 크기 | 실행 요청마다 도구 20~23개, 약 1.6만 자를 전송. 실제 사용은 3~5개 |
