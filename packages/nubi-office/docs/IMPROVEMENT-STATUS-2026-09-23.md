# 개선 적용 상태 재확인

현재 소스와 이전 평가 목록을 대조한 상태다. 모든 개선이 끝났다는 판정은 아니다. 소스 테스트 통과, 실제 모델 품질, 실제 Excel 동작, 설치본 반영을 구분한다. 이번 확인은 기존 기록의 62/100을 새로 채점하거나 정확도로 환산하지 않는다.

| 영역 | 코드에 반영된 내용 | 남은 범위 |
| --- | --- | --- |
| 계획과 단계별 실행 | Pi 기반 계획 표시, 도구 결과를 받은 뒤 다음 판단, 요구사항 검토와 수정, 진행 기록 | 실제 Qwen의 요구사항 누락률과 문서 완결성 측정 |
| 사용자 질문과 이어가기 | 문서 계획/작성/검토의 같은 실행에서 HITL, 수락한 초안 유지, 중복/충돌 답변 차단 | 프로세스 종료를 넘는 보존과 재개 |

## 실제 사용하는 오픈소스와 참고만 한 방법

- **실제 런타임:** Pi agent core/AI 0.86.1, p-retry 8.0.1, excel-formula-tokenizer 3.0.0, ExcelJS 4.4.0. ExcelJS는 새 문서 생성 경로이며 기존 NASCA 파일을 외부에서 암복호화하거나 다시 ZIP 저장하지 않는다.
- **실제 개발 검사:** fast-check 4.10.2의 상태 순서 검사, React Testing Library/jsdom의 실제 UI 컴포넌트 검사, Playwright/axe의 소스 화면 검사. 모의 응답 검사는 Qwen 정확도 검사가 아니다.
- **방법 적용:** Anthropic의 실행 결과 중심 검토와 독립 평가, 단계별 관찰/실행/검증, 컨텍스트 분리, 사람 개입. Claude 전용 모델이나 런타임으로 바꾼 것은 아니다.
- **설계 참고:** LangGraph의 interrupt/resume와 checkpoint 개념. LangGraph 라이브러리는 도입하지 않았다. 현재 재개는 메모리 안에서만 가능하다.
- **평가 연결 준비:** Promptfoo custom provider/설정은 있다. Promptfoo 본체와 실제 회사 모델을 돌린 비교 성적은 없다.
- **보류:** OpenTelemetry SDK와 영속 비식별 진단. 외부 텔레메트리 서비스에 자동 전송하지 않는다.

기술 근거는 [후속 하네스 개선 보고서](HARNESS-IMPROVEMENTS-2026-09-23.md), [오류 복구 계약](ERROR-RECOVERY-BP.md), [컨텍스트와 문서 품질](AGENT-QUALITY-BP.md)에 있다. 실제 적용 위치는 `worker/main.mjs`, `worker/document-agent.mjs`, `worker/agent.mjs`, `worker/resilience.mjs`, `worker/workbook-context.mjs`, `tests/document-continuity.test.mjs`, `eval/`다.

## 아직 해결되지 않은 핵심

1. **보호된 영속 checkpoint:** Excel/worker 종료 후 완료 상태·초안·영수증을 복원하는 저장소가 없다. 회사 문서를 평문 JSON에 저장해 임시 해결하지 않는다.
2. **실제 업무 평가:** 대표 기업 문서, 자유 배치 문서, 사람 기준에 보정한 독립 평가와 Qwen 반복 성능 비교가 없다.
3. **실환경 검증:** Excel 2016 설치·재시작·수식 계산·저장/재열기·NASCA·인쇄와 시각 보존을 확인하지 못했다.
4. **관측과 지원 범위:** 영속 비식별 진단·실제 비용/지연 측정이 부족하다. 차트·피벗·매크로 생성은 아직 지원하지 않는다.

사용자 요청에 따라 최종 빌드는 하지 않았다. 새 소스가 이전 설치본에 자동 반영됐다고 안내해서는 안 된다.
