# 새 Office 문서의 완료 판정 개선

2026-09-25. 앞선 구조 조회와 검색 이어보기 개선에 이어, 문서 작성의 실제 결과를 검토했다. Windows Office 2016과 사내 Qwen 3.8 27B 기준을 유지한다. native/설치 빌드와 릴리즈는 실행하지 않았다.

## 재현한 문제

새 Word/PPT 실행에서 `create_document`만 호출하고 내용 반영을 건너뛰어도, 스크립트형 모델이 단계/최종 검토를 complete로 반환하면 저장 승인까지 도달했다. 두 앱 모두 회귀 검사로 재현했다. 기존의 내용 readback, 텍스트 넘침 차단과 최종 AI 검토가 있어도 **작성 내용 자체가 없는 경우를 별도 차단하지 않았기 때문**이다.

이는 실제 사용자 문서에서 발견한 사고나 실모델 실패율 측정이 아니다. 모델 판단이 잘못됐을 때 하네스가 막아야 하는 재현 가능한 제어 결함이다. 저장에는 기존 HITL이 있어 무단 저장된 것은 아니다.

다운로드와 검토 파일 해시: [출처 기록](../verification/delivery-source-review.json). 누비 0.8.4 릴리즈 소스와 경쟁 프로젝트의 이전 다운로드/라이선스 검토는 앞선 [비교 기록](OFFICE-AGENT-BENCHMARK-2-2026-09-25.md)을 재사용했다. Microsoft Copilot과 Claude의 비공개 제품 코드는 확보하지 않았다.

이번에는 새로운 범용 검사 패키지보다 기존 **Pi 실행기와 복구 감독기**를 재사용했다. 검증된 native 관찰에 대한 작은 Office 전용 규칙이며, 파일을 다시 파싱하는 라이브러리나 별도 에이전트 런타임을 추가할 이유가 없었다. 신규 런타임 의존성과 복사한 외부 코드는 0개다.

## 반영한 동작

새 문서 작성의 최종 검토 전에 전체 원본 페이지와 긴 본문을 기존 경로로 읽고 다음을 확인한다.

1. 검증된 내용 반영 기록이 한 번 이상 있는가.
2. 실제 본문 텍스트가 있는가. 이름/레이아웃 라벨, 입력 안내 문구, 공백/제어 문자와 발표자 노트만으로는 충족하지 않는다.

미충족이면 구조화된 `document_delivery` 진단을 반환하고 **동일한 초안의 보완 단계**로 돌아간다. 새 문서를 다시 만들거나 완료한 쓰기를 반복하지 않는다. 정보가 부족하면 기존 객관식/주관식 질문 도구를 사용할 수 있다.

같은 문서/반영 기록/사용자 답변으로 완료 요청이 세 번 반복되면 기존 복구 감독기의 재시도/중지 HITL에서 기다린다. 보완 단계는 하나를 재사용하고 반복해서 추가하지 않는다. 사용자 중지는 종료 상태를 유지한다. 보완 후 실제 본문이 확인되어야 독립 AI 검토와 기존 최종 저장 승인으로 진행한다. 결정적 검사 횟수는 `deliveryChecks`/`deliveryFailures`, AI 검토 시도는 기존 `reviewCalls`로 구분한다.

이 검사는 **최소 작성 증거**이며 본문 한 줄만으로 요청 전체가 충족된다는 뜻이 아니다. 내용 정확성, 모든 요구사항, 수식/서식 보존과 저장 성공은 기존의 후속 검증이 담당한다. 기존 문서 분석/양식 등록/원본 편집에 새 문서의 최소 작성 조건을 강제하지 않는다. 내용 없이 빈 컨테이너만 만드는 용도로 이번 완료 경로를 사용하지 않는다. 추후 이미지/차트 전용 문서를 지원할 때는 실제 native 생성/관찰 증거에 맞춰 이 규칙을 확장해야 한다.

## 검증과 남은 범위

- 수정 전: Word/PPT 두 재현 사례 모두 예상과 달리 저장 승인에 도달했다.
- 수정 후: 두 사례 모두 보완 단계에서 사용자 입력을 기다리고 저장하지 않았다.
- 반복 완료: 세 번째에 recovery HITL, 보완 단계 1개, 문서 생성 1회, 저장 0회를 확인했다.
- 복구 완료: 같은 초안에 본문 1회 반영 → 독립 검토 → 사용자 승인 → 저장 1회를 확인했다.
- 단위 검사: 공백/입력 안내/노트만 존재하는 사례, 정상 본문, 미열람 페이지와 잘린 원문을 구분했다.

`npm run test:pinned` 전체 **676/676 통과**, 실패/건너뜀 0개다. `npm run design:check`는 공통 24개 파일 일치와 위반 0개를 확인했다. UI 스타일과 컴포넌트는 변경하지 않았다. 실제 Pi 실행 경로에 스크립트형 모델과 native fixture를 연결한 검사다. 실제 Windows 11/Office 2016/Qwen/NASCA 성공률과는 별개다. 전체 검사 및 소스 해시는 [검증 기록](../verification/delivery-gate-quality.json)을 따른다.

이번 수정으로 표/차트/도형 편집 확대, native lazy paging, 보호된 재시작 복원, 기업 공용 양식 배포가 구현된 것은 아니다. 이 과제와 실제 환경 검증은 [개선 상태표](IMPROVEMENT-STATUS.md)에 계속 남긴다. 설치 파일은 갱신하지 않았다.
