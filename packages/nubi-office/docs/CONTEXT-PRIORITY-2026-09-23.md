# 최신 사용자 원문을 보존하는 문맥 재구성

2026-09-23. Windows Office 2016과 사내 Qwen 3.8 27B 기준. 모델 ID, 승인, native 편집 범위는 변경하지 않았다.

## 재현한 결함과 수정

긴 과거 자료 4개를 조회하고 자동 요약을 설치한 뒤 사용자 정정 뒤에 긴 assistant 응답 2개가 있으면, 기존 12,000자 문맥에서 최신 사용자 정정이 통째로 빠졌다. 별도로 반환된 요약을 변경하면 다음 문맥의 내부 요약도 바뀌었으며, 작은 예산에서는 요약과 메타데이터만으로 예산을 초과했다.

- 최신 사용자 메시지의 정확한 원문을 먼저 배치한다. 전체가 들어가면 모두 유지하고, 긴 메시지는 첫 구간과 마지막 구간을 먼저 넣고 나머지를 채운다. 정렬은 원래 시간/위치 순서다.
- 자동 요약은 원문을 배치한 뒤 남은 공간에만 넣는다. 들어가지 않으면 `summaryOmitted`로 표시하고 요약 원본은 유지한다.
- `latestUser`는 최신 사용자 메시지의 전체/포함 구간 수와 완전성을 표시한다. 모든 과거 요구사항이 포함되었다는 뜻이 아니다. 누락된 원문은 기존 `recall_context`의 sourceId/offset으로 조회한다.
- 반환 요약은 깊은 복사본이다. 소비자의 변경이 다음 모델 입력에 전파되지 않는다.
- 메타데이터와 JSON 이스케이프까지 포함한 직렬화 길이로 검사한다. 기본 봉투조차 담을 수 없는 예산은 `input_context_limit`로 거절한다. 문자 예산은 Qwen 토큰 한도 측정이 아니다.

공통 `createHistoryContext`를 사용하는 Excel, Word, PowerPoint 경로에 적용한다. 전체 원래 사용자 요구사항 패킷, 현재 요청, HITL 답변, native 영수증과 변경 전후 검증은 별도로 유지한다. 요약은 승인이나 완료 근거가 아니다.

## 방법론과 오픈소스 선택

[Anthropic의 문맥 관리 방법론](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)은 압축으로 중요한 세부 사항을 잃는 위험과 필요한 원문을 다시 조회하는 접근을 설명한다. 이를 참고해 최신 원문 우선 배치, 명시적 부분 범위, 원문 재조회에 적용했다. 특정 Claude 모델/서비스를 추가하거나 성능을 전용한 것은 아니다.

기존 [MiniSearch](https://lucaong.github.io/minisearch/classes/MiniSearch.MiniSearch.html) 7.2.0(MIT)의 검색 색인과 점수 기반 조회를 유지한다. 설치된 소스의 `results.sort(byScore)`와 `boostDocument` 경로도 확인했다. 검색어와 일치하지 않는 최신 정정까지 반드시 후보로 넣으려면 점수 가중치만으로 부족하므로, 검색 엔진 교체 대신 Office 문맥 조립 단계에서 원문 순서를 제어한다. 새 벡터 DB, 외부 서비스, 인증이나 모델 비용을 추가하지 않는다.

기존 fast-check 4.10.2(MIT)를 테스트에서 재사용해 한국어, 이모지, 따옴표, 역슬래시, 줄바꿈과 수식이 섞인 입력 100개를 고정 seed 2392305로 검사했다. 새 런타임 의존성이나 패키지 업그레이드는 없다.

## 검증과 남은 경계

추가 회귀 검사 7개: 최신 정정 보존, 반환 객체 격리, 작은/불가능한 예산, 큰 원문 부분 범위와 정확한 재조립, 이스케이프 임의 입력, 요약보다 원문 우선, 빈 대화/assistant-only 역할 구분. 처음 작성한 5개 검사 모두 수정 전 실패했으며, 실제 동작 결함과 새 범위 메타데이터 부재를 함께 포함한다. 관련 개발 검사 34개 통과. 게시본 전체 결과와 소스 해시는 [검증 기록](../verification/context-priority-review.json)에 남긴다.

이는 실제 MiniSearch/fast-check/Pi 실행기의 로컬 제어 검사다. 기존 통합 검사 모델 응답과 Office 결과는 픽스처다. Qwen의 정정 이해 정확도, Windows Office 2016, WebView2, NASCA는 측정하지 않았다. 설치 빌드도 수행하지 않았다.

아직 남은 기능: native 긴 Word 항목의 추가 조회, 대용량 문서 최종 검토의 계층화, 보호된 재시작 복구, 외부 Python 스킬 설치/실행. 긴 최신 메시지가 예산을 넘으면 여전히 일부만 현재 문맥에 들어간다. 현재 동작은 정확한 범위 표시와 원문 재조회이며 모든 과거 조건의 자동 의미 보존을 보장하지 않는다.
