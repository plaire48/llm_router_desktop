# Office 에이전트 구성요소 품질 개선

2026-09-23. 기준은 Windows Office 2016에서 사용자 요구사항에 맞는 문서를 실제로 완성하는 것이다. 아래는 소스 결함과 통제 계약의 개선이며 실모델 정확도나 Office 호환성 점수가 아니다.

## 발견과 반영

| 구성요소 | 발견한 부족함 | 이번 반영 |
|---|---|---|
| 하위 분석의 요구사항 전달 | 모델이 만든 개별 brief와 지정 원문만 전달해 원래 요청과 같은 실행의 확정 답변이 빠질 수 있음 | Excel/Word/PPT 분석에 실제 요청, 계획의 요구사항, 확인된 질문/답변을 별도 패킷으로 전달. 자식이 만든 요약으로 대체하지 않음 |
| 결과 재사용 | brief/원문/모델은 캐시 키에 있지만 부모의 최신 답변이 빠짐 | 부모 패킷의 해시까지 연결. 답변/요구사항/모델이 달라지면 기존 결과를 다음 문맥에서 제거하고 다시 분석 |
| 늦은 응답 | clear가 저장된 캐시만 지워 진행 중 분석이 나중에 옛 결과를 다시 저장할 수 있음 | 세대별 AbortController와 결과 수신 전후 확인. 근거 무효화 시 진행 중 대기를 종료하고 대기열의 후속 호출도 차단. 취소를 무시한 제공자 응답도 보관하지 않음 |
| 스킬과 도구 선택 | 규칙 프리셋 위주 등록, Word 도구 설명에 PPT 형식 혼재 | ZIP/폴더 스킬 탐색/활성화/필요 파일 읽기, 앱별 도구 설명과 지원 범위 조회. 지원하지 않는 Office 기능을 스킬이 허용하지 못함 |
| 진전 없는 호출 | 새 기능 조회 도구가 기존 반복 감지 대상에서 빠질 여지 | 스킬 탐색/활성화와 기능 조회도 공통 진전 검사에 연결. 반복 조회를 문서 작업 진전으로 집계하지 않음 |

부모 패킷은 현재 요청, 계획의 요구사항, 같은 실행에서 받은 답변만 포함한다. 이전 전체 대화, 스킬 전체, native 영수증과 권한은 자식에게 복제하지 않는다. 자식은 지정한 원문만 근거로 사용하고 미전달 사실을 `missing`으로 돌려준다. 주 실행기가 원문 검색/질문/추가 분석을 결정한다. 부모 패킷의 JSON 96,000자 한도를 넘으면 조건을 자르지 않고 거절한다. 전체 요청 예산은 기존 공통 경로로 검사한다. 이는 측정한 Qwen 토큰 예산이 아니다.

하위 분석은 기존과 같이 **격리된 읽기 전용 1회 모델 호출**이다. 자식에게 임의 도구 루프나 COM 쓰기 권한을 추가하지 않았다. 독립 분석은 최대 2개, ChatGPT는 1개로 실행하며 COM은 주 실행기 UI/STA 경로에서 순차 처리한다. 성공한 분기는 기준이 같을 때 재사용하고 실패한 분기만 다시 요청한다. 기존 p-retry 복구 소유자, HITL, 쓰기 영수증과 readback을 유지한다. A2A는 구현하지 않았다.

## 공식 방법론과 오픈소스 선택

| 근거 | 적용 판단 |
|---|---|
| [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system) | 독립 과제와 명확한 목표/결과 계약, 주 실행기의 종합, 실제 최종 상태 평가를 적용. 에이전트 수 증가나 해당 사례의 성능 수치를 Office 품질로 간주하지 않음 |
| [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | 필요한 원문을 그때 읽는 방식, 격리 문맥과 요약 후 핵심 조건 유지. 부모의 확정 답변은 선택적 요약 대상에서 제외 |
| [OpenAI Agents SDK agents](https://openai.github.io/openai-agents-js/guides/agents/) 및 [agent evals](https://developers.openai.com/api/docs/guides/agent-evals) | 주 실행기가 작업을 유지하면서 전문 분석 결과를 소비하는 방식과 호출 기록/최종 결과를 구분하는 평가 방법 참고. SDK를 추가 설치하지 않음: 기존 Pi 제공자/승인/취소/복구 체계를 중복시키지 않기 위함 |
| [Pi](https://github.com/earendil-works/pi), MIT | 기존 0.86.1 에이전트 루프, 스킬 파서, 파일 도구를 실제 재사용. Qwen을 OpenAI/Claude 모델로 교체하지 않음 |
| [p-map](https://github.com/sindresorhus/p-map), MIT | 설치된 7.0.4 소스의 concurrency/signal/stopOnError 계약 확인. 기존 병렬 스케줄러에 계속 사용하고 Office 근거 무효화만 별도로 연결. 패키지의 취소만으로 이미 시작된 제공자 요청/늦은 결과까지 차단된다고 가정하지 않음 |
| MiniSearch / p-retry / QuickJS / uv | 기존 원문 검색, 추론 복구, 계산 및 Python 환경 관리를 유지. 라이브러리를 추가한 개수로 개선을 평가하지 않음 |

새 에이전트 런타임이나 모델 종속 서버를 설치하지 않았다. 위 패키지의 기존 고정 버전과 라이선스를 유지하며 추가적인 클라우드 기록 전송도 없다.

## 검증 및 남은 우선순위

`analysis-lifecycle.test.mjs`는 부모 조건 전달, 답변 변경, 모델 변경, 분석 중 근거 무효화, 취소를 무시한 늦은 응답, 캐시 오염, 대기열 차단과 입력 보존을 확인한다. 기존 Excel/Word/PPT 실제 Pi 실행 연결 테스트도 부모 패킷 전달을 검사한다. 모델 응답과 native Office는 테스트 대역이므로 이는 제어 계약 검증이다.

남은 가장 중요한 검증은 Qwen 실계정에서의 스킬/도구 선택 정확도, Office 2016 COM 결과와 저장 후 재열기, Windows 설치 및 NASCA 환경이다. 현재 Windows 테스트 PC와 모델 연결이 없으므로 측정하지 않았다. 보호된 재시작 복구, 범용 Python 다중 모듈 스킬, Office 미지원 기능도 여전히 별도 과제다. 자동 요약과 같은 실행의 복구가 프로세스 재시작 복구까지 제공한다고 표시하지 않는다.

최종 소스 검증: 배포 소스 체크아웃의 `npm test`에서 490개 통과, 실패/취소/건너뛰기 0개. 새 Windows native 컴파일, 설치 파일 빌드, 실모델 호출은 실행하지 않았다.
