# Excel 역할 배정과 결과 보존 재검증

2026-09-25. 기존 Excel 통합문서 조회/선택 범위 편집 하네스에도 동적 역할 배정을 연결했다. Word/PPT에서 사용한 dependency-graph 기반 조정기를 공통화하고 Excel 고유 범위/수식/셀 인용 검증기를 연결했다. 모델이 실제 카탈로그에서 선택된 ID를 계속 사용하며 Qwen 3.8 27B 기준을 바꾸지 않는다.

## 반영 내용

- `delegate_range_tasks`에서 모델이 역할, 목표, 제약, 완료 조건, 미리 읽은 snapshotIds와 선행 작업을 정한다. 최대 8개 작업, 배치당 4개, 모델 호출 동시성 2개이며 ChatGPT는 1개다.
- Excel 조회는 부모가 순차 실행하고 배치 전후에 원본을 재확인한다. 하위 모델에는 도구를 주지 않는다. 다른 시트를 읽어도 원래 쓰기 범위와 승인 조건은 늘어나지 않는다.
- 독립된 결과를 받은 뒤에 의존 작업을 실행한다. 미확인 사실이 있으면 후속 작업을 보류하고 부모가 같은 실행에서 필요한 질문을 한다. 연결 실패는 기존 복구기가 Retry-After를 지키며 실패한 부분만 다시 요청한다.
- 상태는 기존 채팅의 역할/담당 범위/선행 작업/미확인 내용에 연결한다. 역할 이름만 바꾸거나 요약을 다시 받는 것은 진행으로 계산하지 않는다. Excel 복구 진전 판정도 변동하는 보고서 본문 대신 검증된 진행 상태를 사용한다.
- `read_delegation_results`는 모든 Office 하네스에서 planId와 작업 ID 1~2개로 원래 작업 계약과 보존한 보고서를 다시 가져온다. 원본과 모델/부모 조건을 확인하며 새 모델 호출은 하지 않는다. 현재 문맥에는 모든 노드의 상태/의존관계/미확인 정보와 15K 이하의 전체 보고서 묶음을 유지한다. 긴 미확인 목록을 생략하면 생략 개수와 조회 필요를 표시한다.

## 발견하고 수정한 오류

| 재현 | 수정과 확인 |
| --- | --- |
| 같은 배치에서 401과 성공이 섞이면 조정기가 성공 보고서를 잃고 재호출 | 종료한 배치의 응답을 수집하고 native 재확인 뒤 성공 결과 보존. 재현 호출 수가 실패 2/성공 2에서 실패 2/성공 1로 변경됐다. 원본 변경이나 취소면 보존하지 않는다. |
| 보고서 8개 중 앞의 부분 결과가 최근 4개 문맥에서 사라짐 | 전체 작업 상태와 미확인을 남기고 ID 기반 원문 결과 조회 추가. 다른 도구가 마지막 응답을 덮어써도 원래 작업과 부족한 정보를 회수한다. |
| get_range_data의 상세조회 메타데이터가 원본 변경처럼 처리될 수 있음 | 실제 source binding에서 조회 보강용 details만 제외했다. 값/수식/원본 서식/속성/원문 fingerprint는 유지한다. |
| 공유 실행기 이름과 UI 기준 불일치 2개 | [공통 UI/실행기 검토](UI-PARITY-2026-09-25.md). 실제 diff/HTML/화면을 검토한 뒤 UI 기준을 갱신하고 실행기 식별자와 의존성 버전을 별도 검사한다. |

## BP와 오픈소스 선택

[Anthropic의 조정자/워커 패턴](https://www.anthropic.com/engineering/building-effective-agents)과 [OpenAI의 manager/tool orchestration](https://openai.github.io/openai-agents-js/guides/multi-agent/)을 현재 Office 권한 구조에 적용했다. 하위 분석은 선택 가능한 도구이며 단순한 셀 편집에 항상 여러 모델 호출을 강제하지 않는다. 별도 Claude/OpenAI 런타임이나 A2A 위임 권한은 도입하지 않았다.

[Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)의 필요한 순간에 자료를 다시 읽는 방법을 적용했다. 압축된 문맥에는 식별자와 미해결 상태를 남기고 원래 계약/보고서는 전용 읽기 도구로 회수한다. 모델 요약이 실제 원문이나 미확인 상태를 대체하지 않는다.

실제 라이브러리는 이미 검토한 `dependency-graph 1.0.0`(MIT), Pi, p-map, p-retry다. Word/PPT와 Excel에 별도 스케줄러를 복제하지 않고 하나의 조정기에 앱별 원문 어댑터를 넣었다. 라이선스와 고정 의존성은 변경하지 않았다. 새 패키지 수는 0개다. 복구/문맥 조회는 Office 제약을 적용하는 로컬 어댑터이며 외부 영구 문서 저장소는 추가하지 않았다.

## 검증 경계

현재 개발 의존성의 전체 590개와 추가 조회 경계 8개가 통과했다. 같은 최신 소스를 Office의 고정 Pi 0.86.1 세 패키지로 해석한 전체 598개도 모두 통과했다. 디자인 공유 파일 24개 일치와 토큰 위반 0개, 정적 Chromium 105개 화면의 가로 넘침/자동 axe 위반 0개를 확인했다. 색 대비 미확인 항목은 남는다. 최신 수치는 [개선 상태표](IMPROVEMENT-STATUS.md)와 `verification/excel-delegation-review.json`을 따른다. Pi 의존성 해석을 고정한 소스 검사는 실제 설치 파일 실행이 아니다.

기존 선택 범위 실행기와 캡처한 범위 분석의 개선이다. 새 XLSX 문서 생성 실행기의 다중 작성자, 무제한 시트/원문 처리, 서브에이전트의 직접 COM 편집은 추가하지 않았다. 현재 8개 보존 범위, 범위당 최대 1,000셀과 전체 문맥 예산을 유지한다. Word/PPT의 긴 문단과 초대형 native 조회 한도도 남아 있다.

Windows 11/Office 2016 COM, NASCA와 실제 Qwen 성능/비용은 미검증이다. 이번 작업에서 native/설치 빌드, 배포는 하지 않았다. 기존 0.8.4 설치 파일에는 새 소스가 반영되지 않았다.


### 반복 검증 명령

```sh
npm test
npm run test:pinned
npm run design:check
npm run test:visual
```

`test:pinned`는 테스트 전용 Node ESM 해석 훅으로 Office에서 외부 의존성으로 묶는 세 Pi 패키지만 Office-local 설치에서 해석한다. 전이 패키지는 자신의 원래 경로에서 해석한다. 초기 임시 훅이 모든 Pi 전이 패키지를 강제해 조회 오류를 낸 것은 검증기 설정 오류였고, 세 직접 패키지만 고정하도록 수정한 뒤 전체 598개를 다시 검사했다. 저장한 전용 훅으로 Excel 통합과 의존성 핀 4개도 재확인했다. 제품 런타임이나 인증 경로를 바꾸는 훅이 아니다.
