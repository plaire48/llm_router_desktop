# 긴 Word/PPT 문서 검토

후속 [멀티 워커 적용](MULTI-WORKER-OFFICE-2026-09-25.md)에서 아래 순차 구간/통합 검토를 기존 p-map 스케줄러의 최대 2개 병렬 호출과 워커 진행 화면으로 확장했다. 문서/인용/완료 판정 제한은 유지하며 아래 검증 수는 최초 분할 구현 시점이다.

2026-09-25. [공개 소스 비교](COMPETITIVE-BENCHMARK-2026-09-25.md)의 긴 문서 검토 공백을 개선했다. 기존 단일 요청 검토를 유지하고, 근거가 180,000자를 초과하면 **원문 구간 검토 → 요구사항별 통합 검토**로 전환한다. 문서를 더 짧게 요약해 같은 검사를 통과시키는 방식은 사용하지 않는다.

소스 다운로드와 라이선스는 이전 비교 기록의 고정 커밋을 재사용한다. Microsoft/Claude 상용 제품의 비공개 소스를 분석한 것은 아니다. 신규 라이브러리나 범용 에이전트 런타임은 추가하지 않았다. 기존 Pi 실행기, p-retry 기반 복구 감독기, 요구사항 파서와 문맥 예산을 재사용하고 Office 근거를 다루는 정책만 추가했다. 전체 LangGraph/OpenCode 런타임을 넣으면 승인과 재시도 소유자가 중복되므로 이번에는 채택하지 않았다.

## 실행 계약

1. 전체 검토 전에 페이지의 연속성, 동일 문서/fingerprint, 중복 항목과 원문 잘림을 확인한다. 누락되거나 잘린 원문을 분할해서 정상으로 바꾸지 않는다.
2. 항목 하나를 온전히 유지하며 최대 48,000자씩 최대 64구간으로 나눈다. 구간은 원래 native 페이지의 일부임을 표시한다. 항목 하나가 예산을 초과하거나 구간 수가 초과하면 명시적으로 중단한다.
3. 구간별 모델은 모든 요구사항에 대해 근거/충돌/미확인/무관을 반환한다. 근거와 충돌에는 실제 원문의 정확한 인용이 필요하다. 다른 구간의 항목이나 꾸며낸 인용은 거절한다. 구간 근거가 있다는 것만으로 요구사항 충족을 선언하지 않는다.
4. 요구사항마다 모든 구간의 결과를 대조한다. 모델이 완료라고 해도 어느 구간이든 충돌이나 미확인이 있거나 인용한 지지 근거가 없으면 완료를 거절한다. 통합 모델 자체가 보완을 요구한 결과도 완료로 바꾸지 않는다. 원문 전체 대신 제한된 결과를 읽는 통합 검토이므로 문단 간 관계/합계/순서를 입증하지 못하면 미확인으로 남긴다.
5. 매 검토 결과 뒤 native fingerprint와 선택 제공자/모델을 확인한다. 문서나 모델이 바뀌면 중단한다. 기존 승인/반영/저장 경로를 유지하며 추가 쓰기 도구는 제공하지 않는다.
6. 실제 구간과 요구사항 검토 호출을 채팅 진행 기록에 표시한다. 같은 문서/요구사항/단계/답변의 같은 구간을 다시 검토하는 것은 새 진전으로 계산하지 않는다. 기존 무진전 HITL과 취소를 유지한다.

구간 호출은 순차 실행한다. 모델 병렬 수를 늘리는 것보다 회사 모델 부하와 동일 실행의 복구 소유자를 유지하는 것을 우선했다. 기존 읽기 전용 하위 분석은 유지하고 A2A는 추가하지 않았다.

## 검증

[고정 입력 측정](BENCHMARK-CONTENT-REVIEW-2026-09-25.json): 200개 항목, 직렬화 원문 254,861자에서 배포판 0.8.4는 `evidence_limit`을 반환한다. 개선 경로는 7구간, 최대 47,851자의 구간 근거로 나누며 200개 항목의 원문을 정확하게 재구성한다. 입력과 비교 소스의 SHA-256을 기록했다.

- 관련 검사 26개: 원문 누락/중복/잘림/변경, 인용 조작, 요구사항 누락, 충돌과 미확인 강제 보존, 보완 판정 유지, Unicode 경계 100회, Word/PPT 실제 worker 흐름, 사용자 조건 유지, 모델 변경, 취소, 반복 실패 HITL.
- 고정된 0.8.4 공통 소스에 현재 Office 변경을 적용한 전체 검사: **530/530 통과**.
- 현재 개발 폴더 전체: **531개 중 528개 통과, 기존 3개 실패**. 공통 실행기 버전, 공통 UI 검토 해시, 보류한 A2A를 기대하는 테스트다. UI 해시 불일치는 현재 `DeckSurfaces.jsx`를 포함한 7개 파일이다. 이를 숨기거나 미검토 해시로 갱신하지 않았다.

측정 명령은 `node eval/compare-content-review.mjs <신뢰한-배포판-content-context.mjs>`다. 인자로 받는 모듈을 실행하므로 자체 배포 아카이브에서 검증한 모듈만 사용한다. 관련 검사는 `node --test --test-concurrency=1 tests/content-review.test.mjs tests/content-long-review.test.mjs tests/content-context.test.mjs`로 실행한다.

**검증 범위는 코드와 합성 입력/모델/native 응답이다.** 실제 Qwen이 무관/충돌을 올바르게 판별하는지, 인용이 결론을 충분히 뒷받침하는지, 구간 사이 관계를 놓치지 않는지, 실제 Office 2016 및 NASCA에서 보존되는지는 별도 검증이다. 구간 수만큼 모델 호출이 추가되므로 속도나 비용이 개선됐다는 주장은 하지 않는다. 통합 검토는 요구사항 수만큼 호출하며, 전체 요청에는 기존 240,000자 전송 제한이 그대로 적용된다.

이번에는 native/설치 파일을 빌드하거나 릴리즈를 갱신하지 않았다. Windows 11 실설치, Office 요소 편집 확장, 공용 양식 카탈로그와 재시작 실행 복구는 여전히 남아 있다.
