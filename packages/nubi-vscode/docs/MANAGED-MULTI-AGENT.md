# 누비 Workspace 멀티 에이전트와 배포 설계

2026-10-01. 사용자 결정으로 OpenMetadata를 현재 범위에서 제외합니다. 이 문서는 설계이며 추가 구현이 완료됐다는 의미가 아닙니다.

## 제품 구조

사용자는 VS Code의 누비 대화에서 요청합니다. 누비 주 실행기가 OpenWiki 조사와 Computer Use 작업을 분담하고 결과를 검토합니다.

```text
VS Code의 누비 대화
  └─ 누비 주 실행기: 요청, 계획, 분담, 질문, 검토, 최종 답변
      ├─ OpenWiki 하위 에이전트: 문서와 코드 근거 조사
      └─ Computer Use 하위 에이전트: 앱 관찰, 동작 제안, 결과 대조

확장 호스트
  ├─ 기존 번들 Node와 Pi 실행기
  ├─ OpenWiki 코어와 플랫폼별 드라이버
  └─ 실제 입력과 반영: 기존 호스트 검증과 HITL
```

별도 카탈로그 서버, Docker 설치, 관리자 계정 초기화는 이 제품 구성에 포함하지 않습니다. 기존 직접 DB 메타데이터 수집 도구는 유지하며 새로운 DB 하위 에이전트나 DB 서비스 배포를 이번 설계에 추가하지 않습니다.

## 역할과 하네스

| 역할 | 반환 | 권한 |
|---|---|---|
| 주 실행기 | 분담, 최종 검토와 답변 | 질문과 승인 흐름의 단일 소유자 |
| OpenWiki | 답변, 인용, 누락과 충돌 | 지정 범위의 조사 |
| Computer Use | 다음 동작 제안, 호스트 영수증, 관찰 결과 | 승인된 단일 동작 또는 기존 배치 |

같은 선택 모델을 기본으로 사용하되 하위 문맥은 분리합니다. 인증값은 모델에 전달하지 않습니다. 외부 A2A 서버는 추가하지 않습니다. 분담 입력은 taskId/runId, 목표, 범위, 완료 기준, 근거 버전과 취소 신호를 갖습니다. 반환은 상태와 결론, 근거, 미확인 사항, 다음 동작으로 구성합니다.

독립 읽기 분석은 기존 최대 2개 병렬 호출을 재사용합니다. 같은 앱의 입력과 의존 작업은 순차 실행합니다. 단순 질문은 불필요한 분담을 생략합니다. 하위 조사 완료와 전체 업무 완료를 구분합니다. 하위 소스 읽기는 주 실행기의 수정 권한이 아니며, 미확정 쓰기는 호스트 기록과 실제 상태로 대조합니다. 중지와 질문은 하위 호출에도 전파합니다.

## 첫 실행

[FIRST-RUN.md](FIRST-RUN.md)의 흐름을 따릅니다. 필요한 LLM을 연결하고 현재 프로젝트에서 바로 대화합니다. 프로젝트가 없으면 열고, 앱 조작을 처음 요청할 때 대상 창을 선택합니다. 기능 준비 완료와 실제 작업 성공을 구분합니다.

## 배포와 업데이트

기존 플랫폼별 VSIX에 검증된 Node, OpenWiki 코어, 해당 OS 드라이버를 포함합니다. 사용자가 Node나 별도 서버를 설치하지 않도록 기존 번들 방식을 유지합니다. Windows 앱 제어는 Windows 지원 범위에서만 제공합니다.

배포 산출물은 플랫폼별 VSIX, SHA-256과 번들 라이선스 목록입니다. 확장/Node/OpenWiki/드라이버의 호환 버전을 고정해 검사합니다. 별도 컨테이너 이미지와 DB 마이그레이션 묶음은 배포하지 않습니다.

GHES 계정과 하단 업데이트 버튼은 기존 `GHES-ACCOUNT-AND-UPDATES.md`의 설계를 따르며 아직 미구현입니다. main push는 CI 검사의 시작이며 사용자에게는 검증된 릴리스를 제공합니다. 다운로드, 설치 요청, 재시작과 실제 버전 확인은 구분합니다. 설치 중단 시 기존 버전을 보존합니다.

## 구현 우선순위

1. 첫 실행: 기존 연결과 현재 프로젝트를 재사용하고 불필요한 질문 생략.
2. 분담 계약: OpenWiki의 근거와 Computer Use의 관찰/승인/영수증을 같은 목표에 연결.
3. 복구: 중단과 문맥 압축 뒤 원래 요청과 답변을 유지하고 미확정 동작 재실행 방지.
4. 배포: 실제 Windows VS Code에서 첫 설치, 기존 버전 갱신과 재시작 후 버전 확인.

대표 검증 업무는 Wiki 절차 조사 → 필요한 질문 → 앱 입력 제안과 승인 → 실제 결과 대조 → 근거 기록입니다. 합성 모델, 실제 제공자, Windows 입력 성공을 별도로 보고합니다. 현재의 개별 도구 구현을 전체 분담 흐름의 완료로 표시하지 않습니다.

## 방법론과 재사용

- [OpenAI manager 패턴](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/): 주 실행기가 사용자를 담당하고 전문가를 도구처럼 호출.
- [Anthropic orchestrator-workers](https://www.anthropic.com/engineering/building-effective-agents): 범위별 문맥 분리, 독립 읽기 분담과 실제 결과 기반 검토.
- 기존 Pi, OpenWiki DeepAgents 통합, 모델 어댑터, AJV와 SQLite를 재사용합니다. 새 프레임워크와 인프라 의존성은 추가하지 않습니다.
- [VS Code 플랫폼별 VSIX](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#platform-specific-extensions)의 공식 패키징 방식을 유지합니다.
