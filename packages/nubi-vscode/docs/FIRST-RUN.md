# 첫 실행과 기능별 연결 UX

2026-10-01 설계 제안. 제품 화면 구현 전입니다. 기반 구조는 `MANAGED-MULTI-AGENT.md`를 따릅니다.

## 핵심 흐름

**누비 열기 → 필요한 LLM 연결 → 현재 프로젝트에서 대화.**

VS Code에 이미 열린 프로젝트와 호스트에서 확인한 연결 상태를 재사용합니다. 앱 연결은 처음 조작을 요청할 때 같은 작업 안에서 진행합니다. 사용자가 하위 에이전트를 직접 선택할 필요가 없습니다. 별도 로컬 서버 설치와 관리자 계정 설정은 첫 실행에 포함하지 않습니다.

## 첫 화면

기존 누비 Welcome과 연결 컴포넌트를 재사용합니다. 가입 설문, 기능 체크리스트와 별도 계정 등록 화면은 추가하지 않습니다.

| 상태 | 화면 문구 | 주요 동작 |
|---|---|---|
| LLM 연결 필요 | 누비와 함께 시작해 볼까요? / 사용할 AI를 연결해 주세요. | AI 연결 |
| 연결과 프로젝트가 준비됨 | 무엇을 도와드릴까요? | 요청 입력 |
| 프로젝트 없음 | 작업할 프로젝트를 열어 주세요. | 폴더 열기 / 저장소 가져오기 |
| 다중 프로젝트 | 어느 프로젝트에서 작업할까요? | 현재 열린 폴더 이름으로 선택 |
| 신뢰/지원 환경 확인 필요 | 실제 호스트가 확인한 이유와 다음 행동 | VS Code의 기존 신뢰/로컬 작업 공간 안내 |

AI 연결은 기존 AI Pro/ChatGPT/FabriX 선택과 로그인 흐름을 사용합니다. 모델은 실제 목록과 저장된 유효한 선택을 사용하고, 선택이 필요한 경우 같은 연결 화면 안에서 끝냅니다. 별도 완료 화면 없이 기존 누비 채팅으로 이동합니다. 연결 검증 실패를 로그인 성공처럼 표시하지 않습니다.

GitHub App 로그인은 사내 저장소 가져오기 또는 인증이 필요한 배포 접근 시에 요청합니다. 로컬 폴더와 유효한 LLM 연결이 있는 사용자의 첫 대화를 불필요하게 막지 않습니다. 조직 정책상 배포 인증이 선행되는 환경은 설치 도우미에서 설명하고 처리합니다.

## 기능별 첫 요청

### 문서와 코드

예: `이 프로젝트 구조를 설명해 줘.`

현재 프로젝트 범위에서 기존 Wiki를 확인합니다. Wiki가 없어도 소스 조회로 시작할 수 있습니다. 전체 Wiki 생성처럼 추가 시간/모델 사용이 큰 작업은 요청 범위와 기존 생성 흐름을 따릅니다. 프로젝트 열기만으로 전체 저장소를 자동 업로드하거나 모든 문서를 생성하지 않습니다.

### 컴퓨터 조작

예: `이 내용을 업무 프로그램에 입력해 줘.`

기존 앱 연결 카드를 통해 사용자에게 대상 창만 선택받습니다. 이미 같은 작업에 연결된 창은 다시 선택시키지 않습니다. 연결 뒤 관찰하고, 대상/입력값/예상 결과를 기존 승인 카드에 표시합니다. 첫 시작 설정으로 모든 창의 마우스/키보드 입력을 허용하는 항목은 만들지 않습니다. 현재 Windows 지원 범위를 표시하고 다른 OS에서 가능한 것처럼 안내하지 않습니다.

## 진행과 재진입

- 준비 상태는 실제 다운로드/설치/기동/연결 결과에서 표시합니다. 현재 단계 한 줄과 펼치는 상세 기록을 사용합니다.
- 창 닫기/VS Code 재시작 뒤 설치 상태와 비밀값이 아닌 연결 설정, 원래 요청을 복원합니다. 인증이 만료됐다면 필요한 연결만 다시 인증합니다. 저장되지 않은 비밀번호는 복원된 것으로 표시하지 않습니다.
- 설치 중단은 해당 단계부터 복구하며 기존 서비스 소유권과 완료 기록을 먼저 확인합니다. 재부팅 뒤 작업 실행/앱 입력을 자동 재개하지 않고 이어갈 요청을 보여줍니다.
- 연결 성공 후 목록 읽기만 실패하면 `연결은 완료됐지만 목록을 새로고침하지 못했어요.`와 `다시 읽기`를 제공합니다. 완료한 연결을 재실행하지 않습니다.
- 설정은 상태별 완료 단계를 동적으로 생략합니다. 사용자에게 항상 고정 5단계 마법사를 통과시키지 않습니다.
- 데스크톱/VS Code가 동일한 모델 연결, 폼, 질문/승인 CX를 공유합니다. 별도 제품용 화면 복사본을 만들지 않습니다.

## 사용자에게 요청하는 정보

| 시점 | 사용자가 할 일 | 누비가 처리할 일 |
|---|---|---|
| 첫 사용 | 필요한 LLM 로그인, 프로젝트가 없으면 열기 | 환경 확인, 현재 프로젝트/유효한 모델 선택 복원 |
| 첫 앱 요청 | 대상 창 선택, 정확한 동작 승인 | 드라이버 상태 확인, 관찰과 입력 제안, 결과 대조 |
| 이후 사용 | 요청 입력, 만료된 연결만 재인증 | 기존 준비 상태 확인과 작업 연결 |

## 검증 기준

- LLM과 프로젝트가 이미 준비되면 추가 설정 화면 없이 첫 요청 가능.
- 처음 사용자는 별도 관리자 계정과 CLI 명령 입력 없이 연결 흐름 완료.
- 기본 화면은 핵심 문장과 주요 버튼 1개, 필요한 보조 동작만 제공. 선택지와 동작에는 이해 가능한 아이콘/짧은 이름, 입력에는 항상 보이는 라벨 적용.
- 좁은 화면/키보드 탐색/오류 수정/로그인 취소/다운로드 중단/재부팅/목록 새로고침 실패를 실제 흐름으로 검사.
- 설치 완료, 연결 완료, 모델 답변과 실제 작업 성공은 별도로 검증.

## 근거

[W3C Forms](https://www.w3.org/WAI/tutorials/forms/)의 필요한 입력만 요청하기, [짧은 필수 경로](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o5p02-short-paths/)의 선택 단계 분리, [단계별 안내](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o4p07-step-instructions/)를 적용한 설계입니다. memory-load-reduction 스킬의 기존 정보 재사용과 진행 보존을 참고했으며, 인증 만료/실행 승인까지 자동 복원하는 의미로 확대하지 않습니다. 기존 Nubi/CX/QuestionForm을 재사용하고 새로운 온보딩 프레임워크는 도입하지 않습니다.
