# 1.3.0 설치와 사내 업데이트 배포 초안

**아직 배포된 설치 안내가 아닙니다.** 1.3.0 설치 파일과 CI 검증을 확인한 뒤 배포 담당자가 확정합니다. 앱의 표시 이름은 누비 Workspace Beta입니다. 현재 package 버전은 1.2.10이며 Task 10에서 1.3.0으로 바꿉니다. 이 문서는 버전 변경이나 릴리스 실행을 하지 않습니다.

## Windows 사용자

최종 확인된 `Nubi-Workspace-beta-1.3.0-x64-Setup.exe`와 함께 제공되는 `.sha256`을 받습니다. 다운로드 위치는 배포 담당자가 확정한 링크를 사용합니다. 아직 이 문서에는 실제 자산 링크나 해시가 없습니다.

1. 진행 작업과 파일 반영을 마치고 미저장 문서를 저장합니다. 승인 대기와 결과 미확정 작업은 상태를 확인하고 앱을 종료합니다.
2. 설치 파일의 SHA-256을 함께 제공된 값과 대조한 뒤 실행합니다. 기존 프로젝트 원본을 삭제하거나 앱 데이터 폴더를 수동으로 지우지 않습니다.
3. 설치 후 앱을 열고 프로젝트, 대화, 고정 목록과 문서를 확인합니다. 새 기능의 첫 워크플로우 실행은 감독 확인을 거칩니다.

PowerShell 해시 확인:

```powershell
Get-FileHash .\Nubi-Workspace-beta-1.3.0-x64-Setup.exe -Algorithm SHA256
```

기존과 같은 앱 저장 위치를 쓰는 것이 목표입니다. 릴리스 CI에서 데이터 보존/업그레이드/재실행을 확인하기 전에는 마이그레이션 무손실을 보장하지 않습니다. 중요한 미저장 자료와 설정의 백업 정책은 회사 절차를 따릅니다. 이전 버전으로 내릴 때는 새 저장 형식의 역호환을 먼저 확인합니다.

## 사내 배포 담당자

검증된 설치 파일, `Publish-NubiUpdate.ps1`, `release-notes.txt`를 같은 폴더에 둡니다. 아래는 **배포 승인 뒤 사용할 명령 예시**이며 이번 문서 작업에서 실행하지 않았습니다.

```powershell
gh auth login --hostname code.sdsdev.co.kr
.\Publish-NubiUpdate.ps1 -Installer .\Nubi-Workspace-beta-1.3.0-x64-Setup.exe -Version 1.3.0 -NotesFile .\release-notes.txt
```

기존 스크립트는 사내 `Manufacturing-IT/nuri`의 버전별 Release에 설치 파일을 올리고 해시를 확인한 뒤 `latest/windows-x64.json`을 갱신합니다. EXE를 latest 폴더에 직접 넣거나 이미 발행한 같은 버전 자산을 덮어쓰지 않습니다. 자세한 계약은 [기존 배포 안내](../packages/nubi-desktop/docs/WINDOWS-UPDATE-DEPLOYMENT.md)를 따릅니다.

앱은 회사 GitHub 연결을 통해 새 버전을 확인합니다. 새 버전이 있으면 AI Workspace 위 업데이트 아이콘에서 다운로드, 설치와 재실행을 진행합니다. 최신이면 다운로드 아이콘을 숨깁니다. 실제 1.3.0 설치판에서 이 동작을 검증한 뒤 이 단락을 확정합니다.

외부 GitHub 릴리스와 사내 nuri 배포는 별개입니다. 외부망 업로드만으로 사내 latest가 바뀌지 않습니다. 사용자 공개 지시 전에는 초안 릴리스로 유지합니다. 공개/비공개 저장소 대상은 배포 담당 Claude가 확인하고 수행합니다.

## 1.3.0 메모

- 변경 안내는 [HOTFIX-1.3.0](HOTFIX-1.3.0.md)에 있습니다. 구현 중 기능은 배포 직전 실제 포함 여부를 확정합니다.
- 워크플로우 정의와 fixture 변경 시 감독 통과 조건을 다시 확인합니다. dry-run 성공만으로 무인 실행 자격을 주지 않습니다.
- 실행 중이던 단계는 저장 기록과 영수증으로 복구합니다. 미확정 쓰기나 승인 대기를 업데이트 후 자동 반복하지 않습니다.
- Office가 없는 CI의 OOXML 생성 검사는 실제 Office 2016 COM/NASCA 검사가 아닙니다. 회사 문서에 적용하기 전 별도 확인이 필요합니다.
- 외부 브라우저의 로그인 세션, 회사 메일 수신과 문서 연결은 해당 PC의 실제 연결 결과로 확인합니다. Chrome fixture 통과를 삼성 브라우저 세션 검증으로 표시하지 않습니다.
- 첨부 읽기 기능의 최종 ON/OFF와 설치 파일 포함 여부는 릴리스 커밋의 `distribution-capabilities.json` 및 관련 설정과 대조해 확정합니다. 이전 1.2.9 문구를 그대로 복사해 켜져 있다고 안내하지 않습니다.
- Windows x64 EXE가 이번 설치 안내의 대상입니다. macOS 설치 자산이 준비됐다는 뜻이 아닙니다. 서명 유무도 실제 설치 파일로 확인해 기록합니다.

## 같은 버전의 수정 빌드

같은 1.3.0의 수정 빌드는 run id와 SHA-256으로 구분합니다. 숫자 버전 비교 방식에서 같은 버전 업데이트 버튼이 나타난다고 약속하지 않습니다. 기존 자산과 사내 latest를 덮어쓰지 않고, 수동 재설치 또는 다음 숫자 버전 배포를 담당자가 결정합니다.

## 배포 담당자 확정란

| 항목 | 값 |
|---|---|
| 입력 커밋/릴리스 가지 | 미정. 이 작업에서 생성/푸시하지 않음 |
| fast/full Actions run URL과 결과 | 미실행 |
| 초안 릴리스 태그/공개 상태 | 미생성 |
| 설치 파일 이름/바이트/SHA-256 | 미생성 |
| 서명/게시자 | 미확인 |
| 업그레이드 기준 | 계획: 검증된 1.2.9 run 38856253676. 정확한 asset/SHA는 R2에서 기록 |
| 최초 설치/업그레이드/재설치/제거 | CI 및 실제 대상 환경 결과 대기 |
| 회사 Windows 11/Office 2016/NASCA | 실측 전 |
| 사내 nuri 버전별 Release/latest | 미배포 |

문서만 작성한 상태에서 이 표를 통과나 완료로 바꾸지 않습니다. 원본은 루트 docs의 초안이며 Task 10에서 확정한 뒤 계획상 패키지 docs 위치와 동기화합니다.
