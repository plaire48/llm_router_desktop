# 브라우저 누비 요청 해석부터 완료까지 재점검

2026-09-28. 사용자 선택: 요청 해석과 계획부터 전체 점검.
초기 진단 상태: 소스의 1차 구조 검토, 계획 입력/파서의 국소 재현과 기존 회귀 확인 완료. 아래 A1/A2와 소스 해시는 변경 전 관찰이다.

최신 재측정은 GPT-5.6 Luna 고정 5개 실행 완료, 답변 전달 4/5, 독립 통과 2/5다. 앞선 3/5보다 낮고 호출/시간도 증가해 품질 개선을 확인하지 못했다. 날짜/값 근거 연결, 규칙 예외 미확인, 최종 검토의 추가 조건으로 인한 답변 차단이 남았다. [최신 원자료·채점·수정 우선순위](../../extensions/aipro-chat/verification/naver-sso-luna-2026-09-28T03-25-57-335Z-evidence/FINDINGS.md)를 따른다. 아래 기록은 단계별 과거 경과이며 최신 결과를 대신하지 않는다.

후속 사용자 지시로 A1/A2의 첫 개선을 구현했다. 참고 대상은 최종 정정에 따라 Claude Code와 연동하는 Claude in Chrome 확장이며, 방법론은 Claude Code와 OpenAI Codex다. [변경과 검증](../../extensions/aipro-chat/docs/PLAN-INPUT-CONTRACT-2026-09-28.md)을 별도로 기록했다. 이후 새 후보로 GPT-5.6 Luna 5개 실측을 완료했다. 답변 전달 5/5, 독립 과제 통과 3/5이며 날씨와 규칙 설명의 잘못된 완료 2건이 남았다. [실행 기록과 후속 수정 명세](../../extensions/aipro-chat/verification/naver-sso-luna-2026-09-27T22-28-12-862Z-evidence/FINDINGS.md)를 따른다. 전체 실모델 재점검과 배포는 미완료다.

추가 지시에 따라 Vercel agent-browser의 고정 소스와 Apache-2.0 라이선스를 확인했다. 문서 식별 불가 상태를 이전 문서와 연결하지 않는 패턴을 자동 본문 수집에 반영했고 A4도 재현 후 기술적 재시도 질문으로 수정했다. [적용/비적용과 회귀/Chrome 검증](../../extensions/aipro-chat/docs/AGENT-BROWSER-REFERENCE-2026-09-28.md)을 참고한다. 아래 초기 가설과 과거 수치는 당시 기록이며 후속 검증을 대신하지 않는다.

## 판단

이어 규칙의 조건/예외 검토 지침과 관찰한 기사 식별 쿼리 보존을 보완했다. 전체 자동 검사 1,346개와 선택 Chrome 검사 19개가 통과했다. 동일 후보의 고정 5개 실측을 시작했으며 결과는 [후속 보완 기록](../../extensions/aipro-chat/docs/SOURCE-SCOPE-REPAIR-2026-09-28.md)에 연결한다. 자동 검사 통과를 실모델 정확도 개선으로 취급하지 않는다.

5개 실측 이후 첫 개선: 일반 본문 읽기의 제목 고립을 재현하고 5,000자 연속 원문 창으로 수정했다. 새 후보의 Luna E-07 1회는 독립 3/3 통과했다. 전체 5개 점수는 갱신하지 않으며 E-04와 검토의 남은 문제를 유지한다. [변경/검증/다음 단계](../../extensions/aipro-chat/docs/CONTENT-WINDOW-REPAIR-2026-09-28.md)를 따른다.

먼저 확인할 것은 사용자의 요청과 조건이 계획, 실행, 검토에 일관되게 전달되는지다. 그다음 첫 관찰, 도구 실행, 복구, 최종 답변의 연결을 같은 과제로 추적한다. 새로운 기능이나 검토 계층 추가를 출발점으로 삼지 않는다.

현재 확인한 문제는 별도 계획 생성 입력에서 이전 조건이 사라지는 경로와, 완료 조건 없는 새 계획을 허용하는 계약 불일치다. 이 둘이 기존 실측 실패의 원인이었다는 인과관계는 아직 입증하지 않았다. 기존 실측에서는 검증 도구 형식 오류와 계획/검토 범위 교정 반복 뒤 최종 전달 실패가 관찰됐다. 현재 소스에는 이 실패에 대한 수정이 이미 있어 같은 후보로 재측정해야 한다.

## 현재 흐름

1. `src/api.js`가 대화와 첨부를 준비하고 `compactHistory`를 거친다. goal은 재개 목표 또는 마지막 실제 사용자 메시지다. 실행 문맥에는 별도 사용자 요청 보존 장치가 있다.
2. 주 실행 모델이 응답/도구를 제안한다. 일반 답변과 질문에는 계획을 강제로 만들지 않는다.
3. 브라우저 작업을 제안했는데 계획이 없으면 `agent-runtime.js`가 계획 저장을 먼저 넣는다. 주 모델이 준 계획을 쓰거나 `preparePlan`을 별도 호출한다.
4. 별도 계획 생성은 `planMessages(goal, packed.messages)`를 사용한다. 형식 실패는 한 번 교정하고 여전히 실패하면 실행하지 않는다.
5. 도구 선택과 입력 검증 후 관찰/행동을 실행한다. 한 동작의 결과를 다음 판단에 돌려준다. 쓰기 검증, 소유 탭/문서, 승인과 미확정 동작 보호가 별도로 있다.
6. 계획 단계 완료 제안은 단계 결과 검토를 받는다. 비완료 판정에는 범위 감사, 형식 교정, 복구가 추가될 수 있다. 계획 범위 교정이 필요하면 재계획이 후속 동작을 막는다.
7. 남은 단계를 검토하고 계획 저장 반환값을 대조한다. 모든 단계 뒤 최종 요청/답변 검토를 수행한다. 워커가 `FINISH_CHAT`으로 결과를 전달한다. UI 저장/재진입까지 이번에 직접 검증한 것은 아니다.

## 비교 설계

- B0: 고정한 현재 후보. B1: 요청/계획 입력 계약만 바꾼 후보. B2 이후는 B1의 원인별 결과를 확인한 뒤 별도로 정의한다.
- 개발 재현과 평가 과제를 분리한다. 첫 단계는 긴 대화, 짧은 후속, 관찰 가능한 부족 정보, 사용자만 아는 정보, 허용 대안, 최신 정정의 6종으로 개발 재현을 만들고 동일 유형의 보류 과제로 평가한다.
- 실제 기준 모델은 `QWEN3.8-27B-FP8-256K`다. 기존 Luna 실패 재현은 별도 비교군으로 유지한다. 현재 선택 모델을 임의로 바꾸지 않는다.

## 첫 구현 인계안

첫 변경 범위는 A1/A2의 요청·계획 입력 계약으로 제한한다. 주 실행기/별도 planner/검토기가 실제 사용자 목표, 최신 정정, 필수 제약, 허용 대안을 동일한 출처로 받는지 먼저 재현한다. 기존 userRequestAnchors를 우선 검토하되 제한된 보존을 전체 보존으로 오인하지 않는다. 문자열과 배열형 text를 일관되게 취급하고 조건이 예산 때문에 누락되면 이를 명시한다. 이전 assistant 주장이나 요약을 사용자 승인으로 승격하지 않는다.

새 계획의 완료 조건 누락과 기존 계획의 상태-only 업데이트를 구분한다. 후자는 기존 조건을 보존한다. 계획 단계에 안정적인 식별자나 요구사항 참조를 도입할 필요가 있는지는 저장/재개 호환까지 별도 설계한 뒤 판단한다. 모든 요청에 새 모델 검토를 추가하는 방식은 먼저 선택하지 않는다.

통과 조건은 요청 조건 보존, 새 계획의 관찰 가능한 완료 조건, 실제 모호함만 질문, 두 계획 경로의 동등한 의미 계약이다. 기존 승인/미확정 쓰기/취소/최종 검토는 유지한다. 완료 보고에는 합성 재현, 실제 모델 측정, 최종 전달을 각각 표기한다.
