# 누비 Workspace Beta 1.3.0 변경 안내 초안

**배포 전 초안입니다.** 1.3.0에 넣기로 한 범위를 사용자 관점에서 정리했습니다. 아직 끝나지 않은 항목은 아래 준비 상태에서 구분합니다. 설치 파일, 배포일과 공개 링크는 릴리스 확인 뒤 채웁니다. 앱의 표시 이름은 누비 Workspace Beta이며 내부 버전은 1.3.0입니다.

## 작업을 처음부터 끝까지 이어갑니다

- **업무 순서를 저장하고 다시 실행합니다.** 워크플로우는 자료 읽기, 초안 작성, 사람 확인과 결과 검증을 정해진 순서로 연결합니다. AI가 완료했다고 말해도 파일과 실행 기록이 맞아야 단계를 마칩니다.
- **대화에서 진행을 확인합니다.** 실행 화면의 본문은 대화 타임라인입니다. 단계별 기록과 접힌 하위 대화, 파일 카드와 보고서를 한 흐름에서 봅니다. 오른쪽 작은 지도에서 원하는 단계로 이동하고 좁은 창에서는 지도를 접습니다.
- **왜 기다리는지 바로 알 수 있습니다.** 현재 대기 사유와 다음 동작을 짧게 표시합니다. 첫 감독 실행에서는 단계를 확인하며 진행하고, 앱을 다시 열면 저장된 체크포인트를 확인해 이어갑니다. 결과가 불확실한 쓰기는 자동으로 반복하지 않습니다.
- **기존 업무 지도를 가져옵니다.** e2e task JSON과 Process Activity Maker Blueprint의 지원되는 구조를 읽습니다. 지원하지 않는 병렬, 반복과 연결 조건은 저장 전에 해당 노드를 알려 줍니다. 임의로 다른 흐름으로 바꾸지 않습니다.

## 긴 대화와 자동 작업을 더 편하게 씁니다

- **챕터와 목차:** 긴 작업의 원하는 위치로 바로 이동합니다. 워크플로우 단계 제목은 실행 기록에서 만들어 대화 챕터 한도와 섞지 않습니다.
- **읽지 않음과 보관:** 다른 대화의 새 결과와 질문을 표시합니다. 오래된 대화는 기본 30일 뒤 보관하며 고정한 대화는 제외합니다. 보관함에서 다시 꺼낼 수 있습니다.
- **산출물과 곁가지 제안:** 생성한 파일과 보고서를 대화 카드에서 엽니다. 추가 제안을 선택하면 같은 프로젝트의 새 대화로 이어집니다.
- **자동 모드의 승인:** 삭제, 되돌리기 어려운 명령과 외부 반영은 기존 승인 규칙을 따릅니다. AI가 검사 명령의 정의 파일까지 바꾸면 자동 모드만으로 그 명령을 실행하지 않고 승인 카드에서 확인합니다. 사용자가 정확한 명령을 직접 항상 허용한 경우는 기존 예외 규칙을 따릅니다.
- **편집 뒤 검사와 조사:** 반영 뒤 설정된 검사를 이어가고 실패와 미확정 결과를 구분합니다. 조사 작업자는 허용된 자료를 읽어 결과를 모으며 메인 에이전트가 근거를 확인합니다.
- **내보내기와 사용량:** 대화와 작업 기록을 Markdown으로 저장하고 비밀로 탐지한 값은 가립니다. 제공받지 못한 토큰은 0으로 채우지 않고 집계 범위를 표시합니다.

## 문서와 위키를 더 잘 활용합니다

- **문서의 바뀐 곳을 먼저 봅니다.** Word, Excel과 PowerPoint 변경 미리보기에서 원본과 수정안을 비교합니다. Excel 셀과 PowerPoint 개체의 변경 강조를 확인하고 승인합니다. 미리보기와 실제 Office 화면은 다를 수 있습니다.
- **PDF는 누비에서 제한된 항목을 편집합니다.** 지원하는 일반 텍스트 입력란을 승인 후 사본으로 저장합니다. 일반 본문 전체, OCR, 서명과 주석 편집은 지원 범위가 아닙니다. 메모장 앱 연결은 포함하지 않습니다.
- **큰 저장소를 나누어 위키로 정리합니다.** 제외 규칙을 먼저 적용하고 폴더 집계와 대표 파일을 사용합니다. 빠진 중요 자료와 처리 범위를 확인하고 필요한 부분을 보강합니다.
- **검색의 근거를 확인합니다.** 전체 페이지 색인과 제목 경로를 담은 문맥 청크를 사용하고 오래되거나 미검증인 근거를 표시합니다. 임베딩과 리랭커는 이번 범위에서 제외합니다.

## 루틴과 양식

- **루틴은 일정과 할 일을 함께 정합니다.** 자유 요청이나 워크플로우를 예약합니다. 워크플로우의 첫 감독 실행을 통과하기 전에는 무인 실행하지 않습니다. YAML의 예약은 자동 등록 대신 등록 제안으로 보여 줍니다. 앱이 꺼져 있는 동안 실행을 보장하지 않습니다.
- **양식은 채움표를 먼저 검토합니다.** 양식의 칸과 근거를 확인하고 승인한 뒤 반영합니다. Windows의 실제 Office(COM) 경로를 우선하고 Office 없는 환경의 OOXML 생성은 검증용으로 구분합니다. 기존 회사 문서의 NASCA 처리를 일반 ZIP 편집으로 우회하지 않습니다.

## 화면과 반응

화면과 모달의 글자, 아이콘, 강조색, 여백과 시작선을 공통 토큰으로 맞춥니다. 목록은 보이는 항목부터 표시하고 나머지를 이어 붙이며 선택과 입력 초안, 읽던 위치를 유지합니다. 화면 전환과 누름 반응은 공통 모션을 사용하고 모션 감소 설정을 따릅니다. 모델 제공자의 고유 색은 유지합니다.

로컬 P2 검사는 Chrome과 격리 macOS Electron에서 수행했습니다. 이 결과가 회사 Windows PC의 속도나 삼성 브라우저, Office 연결까지 검증했다는 뜻은 아닙니다. 숫자와 캡처는 [MOTION-1.3.0](MOTION-1.3.0.md)의 최종 로컬 검증 절에 있습니다. 최신 사용자 판정은 QA91 29개 통과, 프리징 장면 3회 실패입니다. P2 보완과 전체 게이트 재실행은 [QA91 재검증](MOTION-1.3.0-QA91.md)에 기록하며 Claude 검수와 업로드 전 전체 QA 완료로 표시하지 않습니다.

전체 캔버스 저작 UI는 다음 단계입니다. 메일 도착/A2A 트리거, 범용 병렬/반복 실행, 3차 물결의 미선택 항목은 이번 완료 기능으로 소개하지 않습니다. 대화 명령 기록 기본 접힘은 기존 결정을 유지합니다.

Windows 11 회사 PC, Office 2016 COM과 NASCA, 실계정 SSO/메일, 실제 외부 앱/브라우저 창 연결, 설치/업데이트/재실행은 각각의 검증 결과를 확인해야 합니다. sol/luna 실측(Task 0/13)은 사용자 측정 후 기록하며 두 제품의 품질 우위를 아직 주장하지 않습니다.

배포 직전 편집자가 위 표의 미완료 항목을 실제 커밋과 QA 결과로 갱신하고 포함하지 못한 기능을 본문에서 뺍니다. 설치 파일 SHA-256, run id와 공개 여부를 [설치 안내](INSTALL-AND-UPDATE-1.3.0.md)에 연결합니다. 근거 계획: [릴리스](superpowers/plans/2026-10-19-nubi-desktop-1.3.0-release.md), [워크플로우](superpowers/plans/2026-10-18-nubi-workflow-agent-phase1.md), [OpenWiki](superpowers/plans/2026-10-19-nubi-openwiki-reinforcement.md).
