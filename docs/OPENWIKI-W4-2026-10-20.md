## 결과와 결정

W1 대표 파일과 등록된 고정 경로를 기존 경로/ignore/원문 검사로 검증한다. 실제 생성 페이지의 완료 seedPaths와 현재 버전이 맞는 Claims에서 페이지↔파일 지도를 만든다. 초기화의 마지막 범위 뒤 중요한 파일이 빠졌으면 같은 내구성 예산과 체크포인트를 유지해 update 보강을 **한 번만** 추가한다. 남은 파일을 숨기거나 계속 반복하지 않는다. 페이지 수, 연결 비율, 미연결 파일, 크기/바이너리/인코딩 제외, 모델 호출 시도 수, 경과와 라운드를 기록한다. 호출 계수는 선택적 콜백이며 기존 진행 이벤트/일반 호출은 그대로다. 보강 문맥은 W1과 같은200KB 이내로, 생략 수를 명시한다.

계획 연결은 정확도 증명이 아니다. 페이지/소스 해시에 묶인 호스트 전용 색인으로 보관해 게시 후에도 이어 쓰고, 바뀐 해시나 외부/비밀/무시된 경로는 제외한다. 이 내부 색인은 화면의 갱신 결과에 싣지 않는다. 탐색용 index는 문서 수에 포함하되 사실 Claims를 요구하지 않는다. 네이티브 러너와 OpenWiki 코어는 수정하지 않았다.

위키 상단은 접힌 파일 연결 한 줄이다. 펼치면 마지막 준비 기록과 빠진 파일 선택이 보인다. ‘빠진 것 추가’는 선택 경로와 fingerprint를 가진 기존 제안을 준비한다. 기존 설정에서 실행 승인 후 사본 작성, 결과 확인 뒤 별도 반영을 유지한다. 실행 중 설정을 닫는 기존 흐름과 결과 재진입도 검사했다. 좁은 창의 체크박스 초점이 바깥 Workbench를 옆으로 밀던 문제는 위키가 스크롤을 소유하도록 clip 경계를 맞춰 해결했다. 글꼴/간격/파일 칩은 기존 토큰과 공통 컴포넌트, 제공자/승인 규칙 그대로다. 의존성 추가0.

## 최종 독립 검토와 인계

Important 두 건 중 W4 항목을 추가 보완했다. 외부의 완료 `.run.json` seedPaths를 현재 소스와 페이지의 연결 증거로 자동 승격하지 않는다. 공개 커버리지 읽기는 기본적으로 이 메타데이터를 무시하고, 기존 페이지/소스 해시 색인과 현재 Claims만 신뢰한다. 네이티브 초기화가 소유하고 체크포인트에 묶인 작업 사본을 복사하는 두 지점만 선택적 `nativeRun:true`를 준다. 외부 원문 또는 페이지 변경 뒤 연결0을 요구하는 실패 시험2건과 소유 초기화의 유효 연결/페이지 변경 회귀를 통과했다. 코어/네이티브 포트는 수정하지 않았다.

검토 후 관련41/41, 최종 전체 npm test **2465개 중2265통과/200제외/실패0**(574.8초),1280/440 화면 재검사 exit0, design/compile와 게이트 분할 통과. 첫 전체 실행의 Electron fixture2실패와 병렬 읽기 중간 회귀 로그는 보존했다. 본 결과는 수정 뒤 고정된 최종 소스 결과다. 오래된 W4 SHA 명세는 철회본으로 보관하고, 현재24파일 명세와 바이트 스냅숏을 새로 만들었다. 독립 package/gate 스냅숏에는 S1 검사 명령을 넣지 않았으며 현재 작업 폴더는 S1을 포함한다. 업로드 전 `w4-upload-inputs.json`의 snapshotPath를 SHA-256으로 대조한다. 전체 긴 게이트와 Windows/실계정 검증은 남는다.
