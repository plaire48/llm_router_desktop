## 결과와 결정

1. 기존 `ModelSelection` 네 제공자 탭, 아이콘, 모델명, 검색을 유지했다. 내장 선택기만 레이아웃 뒤와 크기 변경 때 선택 알약을 재측정한다. 1280/440, 열기와 전환 및 크기 변경 22측정의 x/y/너비/높이 오차 모두0px. 초기 기하 시험은 전환과 폰트 완료를 기다리면 기존 코드도 통과했으므로 이를 실패 재현으로 표시하지 않는다.
2. 검색 자리표시자는 ‘모델 검색’, 현재 모델은 기존 체크 아이콘. ‘자동 (호스트 선택)’은 목록 첫 행과 체크이며 머리글은 뒤로와 제목만이다. 선택 속성은 선택적이며 작성기의 기존 선택은 실제 클릭 회귀로 확인했다.
3. ChatGPT의 비활성 응답 상한 아래 ‘이 연결은 응답 길이를 서버가 정합니다’를 필드 설명으로 연결했다. 희망 상한은 보존하고 지원 제공자로 돌아오면 복원한다. 컨텍스트 창은 계정 카탈로그의 값으로 기존 입력 예산에 반영되지만, 응답 상한을 지원한다고 추정하지 않는다.
4. 추론 표시 표를 `reasoning-labels.mjs` 한 곳으로 모았다. 작성기와 위키는 Low/Medium/High와 기존 제공자별 Light/Ultra 표기를 같이 쓰며 전송 식별자는 그대로다. 응답 한도 안의 필드는 흰 표면 토큰이다. 새 의존성0.

기존 W3는 요청별 provider/model/connection/effort auto/도구8또는16, 동시성1~4(기본3), 지원 제공자 페이지 희망 상한16,384를 사용한다. 다른 대화의 모델 선택과 인증, 기존 승인/CLI 안전 모드를 보존한다. 합성 네이티브 비교(11소스, 내용3+탐색1, 모델 지연400ms)는 1/8=6770.9ms·22호출, 3/8=5689.2·22, 1/16=5539.1·18, 3/16=4847.2·18로 모두 검증했다. 관측 동시 최대2다. 이는 UI 후속 전 런타임의 합성 결과이며 실모델 속도나 W0의20회 성적으로 확대하지 않는다.
