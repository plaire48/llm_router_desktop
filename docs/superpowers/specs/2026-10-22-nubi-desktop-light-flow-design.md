# 누비 Desktop 가벼운 흐름 설계 (1.3.1)

작성 2026-10-22. 기준 main `e123ae82` (1.3.0 공개 Pre-release와 같은 커밋).

승인 2026-10-22(사용자 "네"). 색감은 사용자가 떠올린 것과 다르다고 했다("색감은 다르긴해요 그래도 일단 그런느낌"). 느낌과 구조는 확정이고, 색 값은 토큰 한 곳에서 나중에 맞춘다. 색 토큰은 바꾸기 쉬운 구조여야 한다.

## 1. 왜 하는가

사용자 말: "누비 데스크탑이 너무 무거워졌다. 애니메이션은 버벅이고 기능에 나사가 빠져 있다."
사용자 지시: 기능을 마구 빼지 말고 원인부터 찾는다. 워크플로우는 빼고, 기능을 검사한 뒤 다시 넣는다.
레이아웃을 정리하고, 아이콘은 간결하게, 글꼴은 잘 읽히게 바꾼다. 기준은 "애플, 가독성 최고".

### 1.1 측정한 원인 (Claude, 10-22)

- 빈 앱은 가볍다. Mac에서 GPU를 끄고 CPU를 4배 늦춰도 쉬는 동안 렌더러 CPU 1% 아래, 화면 다시 그리기는 10초에 4~6번, 주기 요청 0.
- 버벅임은 화면이 바뀔 때의 스타일 다시 계산이다. Windows CI(GPU 없음, 1.3.0 ac)에서 대화 장면 프레임 최대 133~172ms, 모달 열림 중 50~66ms 끊김. 시간 대부분이 앱 JS가 아니라 엔진의 (program) 시간이다.
- 대화 장면 추적(Chrome, GPU 끔, CPU 4배 느림): 스타일 다시 계산 308번에 2.7초, 한 번에 최대 80ms(요소 375개).
- 범인은 `:has()` 선택자다. 앱 CSS에 158개, CX 디자인 시스템에 44개. 앱 쪽 59개가 `:root:has(.desktop-shell)` 형태라 문서 어디가 바뀌어도 전체를 다시 계산한다.
- 실험(대화 장면, 같은 조건):

| | 지금 | `:root:has(.desktop-shell)` 59개만 `:root`로 | `:has` 전부 제거 |
|---|---|---|---|
| 50ms 넘는 긴 작업 | 108 | 26 | 3 |
| 프레임 p95 | 150ms | 50ms | 17ms |
| 놓친 프레임 | 24.8% | 19.0% | 3.4% |
| 스타일 계산 최대 | 79ms | 45ms | 12ms |

- CSS가 크다. 묶인 CSS 1.39MB, 규칙 10,586개, 선택자 11,683개, `:root:root` 551개. 덮어쓰기 층 `design/workspace-identity.css` 220KB, `design/workspace-density.css` 142KB.
- 배경 움직임 22개가 쉬는 동안 계속 돈다(파스텔 흐름, 새, 반짝임, 물결). GPU가 없을 때 대화 중 파스텔 흐름 하나만 멈춰도 놓친 프레임이 21%에서 9%로 줄었다. 부차 원인.
- 모델이나 프로젝트가 없으면 '파일', 'Git 변경', '워크플로우' 단추가 설명 없이 눌리지 않는다. "나사 빠진" 느낌의 한 예.

측정 도구는 scratchpad의 일회용 탐침과 `scripts/check-freeze-scenes.mjs`의 추적이다. 재현 조건은 §6에 적는다.

## 2. 목표

1. **가볍게**: GPU 없는 Windows 회사 PC에서 대화, 메일, 위키, 화면 전환이 끊기지 않는다.
2. **워크플로우 끄기**: 화면과 에이전트에서 워크플로우와 루틴을 없앤다. 코드는 남겨 나중에 다시 켠다.
3. **다재다능한 오른쪽 창**: 자세히 봐야 하는 것을 오른쪽 창 하나에 크게 띄운다.
4. **자연스럽게 흐르는 전환**: 가운데 모달 대신 옆에서 미끄러져 열리는 창. 사이드바가 열리듯 주르르.
5. **애플 느낌의 가독성**: 간결한 선 아이콘, 잘 읽히는 한글 글꼴, 정돈된 레이아웃.
6. **모래시계 기다림 표시**: 도는 스피너 대신 뒤집히기를 반복하는 모래시계 하나로 통일.

## 3. 하지 않는 것

- 기능을 마구 빼지 않는다. 워크플로우와 루틴만 끈다. 다른 기능은 그대로 두고 자리만 옮긴다.
- 워크플로우 코드를 지우지 않는다. 런타임, 테스트, 문서는 남긴다.
- 새 프레임워크를 들이지 않는다. React, Electron, CX 디자인 시스템 구조는 그대로다.
- Excel, PowerPoint 양식(1.3.1의 다른 범위)은 이 설계에 넣지 않는다.

## 4. 이러면 실패다

- 1.3.0에 있던 기능이 워크플로우 말고도 사라지거나 못 찾게 된다.
- 바꾼 뒤에도 GPU 없는 Windows에서 버벅인다. 수치로 확인하지 않고 "부드러워졌다"고 말한다.
- 애플 SF 글꼴이나 SF Symbols를 Windows 앱에 넣는다(라이선스 위반).
- 검사를 통과시키려고 시험, 한도, 정답을 고친다.
- 오른쪽 창이 자동으로 열려 사용자가 보던 것을 예고 없이 덮는다(§5.3 규칙 위반).

## 5. 사용자가 정한 것

### 5.1 워크플로우 끄기

- 워크플로우 기능을 뺀다. 나중에 기능을 검사한 뒤 다시 넣는다.
- 방식은 Claude 제안(사용자 반대 없음): 기존 출시 정책 스위치 `runtime/beta-features.mjs`의 `DESKTOP_FEATURES`에 `workflows:false`를 더한다. 이 스위치는 UI와 호스트가 같이 읽고, 환경 변수나 사용자 설정으로 우회하지 못한다(computerUse, a2a와 같은 방식).
- 루틴도 같이 끈다(사용자 '추천대로', Claude 판단): 호스트의 루틴 예약 실행(`runtime/routines.mjs`)을 멈춘다. 업데이트 뒤 처음 켤 때 한 번 "루틴은 다음 판에서 다시 켜집니다. 저장한 루틴은 그대로 있어요." 알림을 띄운다. 저장된 워크플로우와 루틴 데이터는 지우거나 고치지 않는다. 스위치는 `workflows` 하나로 둘 다 끈다.
- 끄면 사라지는 것: 왼쪽 메뉴의 '워크플로우' 단추, 루틴 설정과 '루틴으로 등록', 에이전트 도구 목록의 워크플로우 도구(실행, 저장, 가져오기, `browser.script` 단계 포함), 워크플로우 관련 알림.
- 브라우저 녹화(가르치기)는 남긴다. 녹화 카드에서 "워크플로우 단계로 저장"만 사라진다.
- 꺼진 기능의 검사는 기존 "끈 기능 시험 건너뛰기" 규칙대로 건너뛰고, 건너뛴 사실을 기록한다. 게이트 목록에서 빼지 않는다.

### 5.2 다재다능한 오른쪽 창

- 오른쪽 창은 자세히 봐야 하는 것을 크게 띄우는 자리다. 가운데는 대화와 지시가 그대로 남는다.
- 담는 것: 웹 콘텐츠 보기(내장 브라우저), UIA(누비가 Windows 앱을 조작할 때 그 앱 화면과 요소. Claude 판단: 1.3.1에서 `computerUse`는 꺼 둔 채로 두고, 이번에는 이미 켜져 있는 Office 창 도킹 화면만 이 자리에 띄운다. UIA 보기 자리는 같은 탭 구조로 만들어 두고 computerUse를 켜는 판에서 연결한다), 문서(Word, Excel, PDF, 쓴 사본과 원본 비교), 메일 원문, 위키 페이지. 지금 있는 파일, 터미널, 웹 탭도 그대로 들어간다.
- 대화의 카드(출처, 파일, 메일, 위키 링크, 문서 결과)를 누르면 오른쪽 창에서 열린다. 지금처럼 가운데를 통째로 바꾸지 않는다.
- Claude 판단: 메일 목록과 위키 둘러보기 화면은 지금처럼 가운데에 남는다. 그 안에서 메일 하나, 위키 페이지 하나를 누르면 오른쪽 창에 원문이 열린다.
- Claude 판단: 창이 좁아 오른쪽 창이 대화를 덮는 모드(겹침 모드, 440px 등)에서는 자동 열기를 하지 않는다. 대신 대화 안에 "오른쪽에서 보기" 알림 칩을 띄운다.

### 5.3 자동으로 열기

- 누비가 웹 페이지나 Windows 앱을 직접 조작하는 동안 오른쪽 창이 자동으로 그 화면을 띄운다.
- Claude 판단(사용자 확인 전): 문서를 쓰거나 고칠 때도 결과 문서를 자동으로 띄운다.
- Claude 판단: 자동 열기는 새 탭으로 열고 앞에 보여 주되, 사용자가 보던 탭은 닫지 않는다. 사용자가 그 창을 직접 닫으면 같은 작업 동안 다시 자동으로 열지 않는다.

### 5.4 자연스럽게 흐르는 전환

- 지금 가운데 모달로 뜨는 창(설정, 메일 설정, 모델, 스킬 등록, MCP, 위키 범위 등 약 40곳)은 옆에서 미끄러져 열리는 창이 된다. 사이드바가 열리는 움직임과 같은 결이다.
- 자리(사용자 결정 10-22, Claude 추천 채택): 오른쪽 창 안에서 맨 위 탭처럼 오른쪽 가장자리에서 미끄러져 열린다. 닫으면 보던 탭으로 돌아간다. 오른쪽 창이 닫혀 있었으면 오른쪽 창과 함께 열리고 함께 닫힌다.
- 꼭 답해야 하는 창(승인, 삭제 확인)이 열려 있는 동안에는 나머지 화면을 입력 불가(inert)로 두고, 초점을 그 창 안에 가둔다. 지금 deck-dialog의 초점 규칙을 그대로 옮긴다.
- 승인, 삭제 확인처럼 꼭 답해야 하는 창도 같은 흐름에 넣는다(사용자: "그런 뭔가 자연스럽게 주르르 흘러가는 느낌"). 대화 안의 승인 줄은 지금처럼 대화 흐름 안에 둔다.
- 움직임은 위치 이동(transform)과 투명도만 쓴다. 길이는 기존 모션 토큰(들어올 때 280ms, 나갈 때 180ms, 줄인 움직임 120ms)을 따른다.
- **스프링 크기 전환**(사용자 요청 원문 요지: "Spring Physics + Animated Resize + Layout Transition 조합"): 창, 오른쪽 창, 옆 창, 카드의 너비나 높이가 바뀔 때 즉시 바꾸지 않는다. 스프링 물리로 약간의 관성과 탄성을 주어 "슈욱" 모찌떡처럼 늘고 준다. 과하게 튀지 않고 목표 크기에 자연스럽게 안착한다(넘침 1.03 이하, 기존 `scripts/motion-spring.mjs` 검사 기준). 창 안의 내용도 크기 변화에 맞춰 부드럽게 새 자리로 옮겨 간다.
- 구현 방향(성능 제약 때문에 Claude가 정함): 너비와 높이를 프레임마다 바꾸면 매 프레임 레이아웃을 다시 계산해 GPU 없는 PC에서 끊긴다. 그래서 새 크기로 레이아웃을 한 번만 계산하고, 바깥 틀은 이전 크기에서 새 크기로 transform 스프링을 건다. 안쪽 내용은 각 덩어리(목록 행, 카드, 머리글, 입력창 등)의 이전 위치와 새 위치 차이를 transform 스프링으로 옮긴다(FLIP 방식의 레이아웃 전환). 글자는 늘어나 보이지 않는다. 기존 `ui/modalResizeMotion.js`를 이 방식의 공용 도우미로 넓힌다. 줄인 움직임 설정에서는 스프링 없이 바로 바뀐다.
- 브라우저와 Office처럼 운영체제가 그리는 화면(BrowserPane, OfficeWindowPane)은 CSS로 움직일 수 없다. Claude 판단: 움직이는 동안 그 자리에 정지 화면(캡처)을 보여 주며 함께 움직이고, 끝나면 실제 화면을 새 크기로 한 번 맞춘다. 캡처가 안 되면 스프링 없이 바로 맞춘다.

### 5.5 아이콘, 글꼴, 레이아웃

- 기준: 애플 느낌, 가독성 최고.
- 아이콘: 무료 간결한 선 아이콘. Claude 추천은 **Lucide**(ISC, 별 2.5만, SF Symbols와 가장 비슷)이고, 없는 모양은 같은 선 굵기의 **Tabler**(MIT, 별 2.2만)로 채운다. 지금의 직접 그린 아이콘을 바꾼다. 누비 새(브랜드 표시)는 그대로 둔다.
- 글꼴: Claude 추천은 **Pretendard**(OFL-1.1, 별 3.6천). Apple 시스템 글꼴 느낌을 Windows에서 내도록 만든 한글 글꼴이다. 지금은 Noto Sans KR이다. 코드와 터미널 글꼴은 그대로 둔다.
- 레이아웃: 사용자가 어수선하다고 짚은 곳은 모달 배치다. §5.2~5.4로 정리한다.

### 5.5.1 모찌 라운드 미니멀 (사용자 10-22, "이런느낌 좋네")

- 콘셉트: 모찌떡처럼 쫀득한 스프링 + 부드러운 라운드. 핵심 셋은 큰 라운드 모서리, 밀크톤 표면, 살짝 넘쳤다 안착하는 스프링.
- 누르면 딱딱하게 크기만 바뀌지 않는다. 형태가 잠깐 눌렸다가 탱글하게 돌아온다(기존 모찌 누름 스프링).
- 같은 움직임을 창 전환, 오른쪽 창과 옆 창 펼치기, 대화 창 펼치기, 크기 전환(컴팩트, 기본, 가로 확장, 세로 확장)에 일관되게 쓴다.
- Claude 판단(성능): 사용자가 본 예시의 "반투명" 표면은 뒤 배경을 흐리게 하는 backdrop-filter로 만들면 GPU 없는 PC에서 매 프레임 비싸다. 그래서 흐림 없이 밀크톤 단색(아주 옅은 그라디언트와 얇은 안쪽 빛 정도)으로 같은 느낌을 낸다. 그림자는 움직이는 동안 바꾸지 않는다.
- 모서리 반지름, 밀크톤 색, 스프링 세기는 모션과 색 토큰으로 한 곳에서 정한다(`design/workspace-motion.css`, 색 토큰).

### 5.5.2 다섯 가지 핵심 표현, 밝게 (사용자 10-22)

사용자 말: "Animated Mesh Gradient + Liquid Glass + Gooey Navigation + Spring Morphing + Ambient Glow를 핵심으로. 밝게."
- 밝은 화면을 기본으로 한다. 색은 누비 팔레트(파랑 #3182F6, 청록 #189BB0, 초록 #148A5C, 옅은 하늘 #E8F1FE, 옅은 민트 #E6F6EE)다.
- **Animated Mesh Gradient**: 배경에 누비 색 덩어리 다섯 개가 천천히 흐른다. 아주 작은 캔버스(48x30)에 초당 20번쯤 그리고 화면 크기로 늘려 보인다. 누비가 일하는 중이거나 창이 가려지면 멈춘다. 이것이 쉬는 동안 도는 배경 움직임의 전부다(§6의 "3개 이하" 안에 든다).
- **Liquid Glass**: 반투명 유리 표면, 위쪽 빛 테두리, 얇은 흰 안쪽 선. 실제 배경 흐림(backdrop-filter)은 작은 표면(내비게이션 알약, 칩, 작은 떠 있는 막대)에만 쓴다. 큰 창과 오른쪽 창은 흐림 없이 반투명 흰색과 그라디언트로 같은 느낌을 낸다. 배경이 이미 부드러운 메시라 흐림이 없어도 유리처럼 보인다.
- **Gooey Navigation**: 선택 표시 알약이 다음 항목으로 갈 때 앞쪽 끝은 빨리, 뒤쪽 끝은 늦게 따라가 늘어났다가 붙는다. 늘어날 때 위아래가 살짝 얇아진다. SVG 흐림 필터를 쓰지 않고 스프링 두 개와 잘라내기(clip-path)로 만든다.
- **Spring Morphing**: §5.4의 스프링 크기 전환과 레이아웃 전환, 누름의 모찌 눌림.
- **Ambient Glow**: 창 뒤에 누비 파랑과 청록의 은은한 빛. 미리 흐린 방사형 그라디언트 한 장을 쓰고(필터 없음), 창 크기를 따라 커지고 작아진다. 밝기만 아주 천천히 숨 쉰다.

## 6. 성공 기준

측정 조건은 두 가지다. 같은 조건에서 바꾸기 전과 후를 나란히 적는다.
- A. Mac, Chrome headless, `--disable-gpu`, CPU 4배 느림, `check-freeze-scenes` 장면(chat, wiki, mail, navigation, terminal), 너비 1280과 440.
- B. Windows CI gates-full(공용 러너, GPU 없음). 공용 러너의 시간 수치는 기록만 하고 판정하지 않는다(§8 답 15). 판정은 A와 사용자 Windows PC에서 한다.

목표(조건 A):
- 대화 장면 놓친 프레임 5% 이하, 50ms 넘는 긴 작업 장면당 5개 이하, 스타일 다시 계산 한 번 최대 16ms 이하.
- 오른쪽 창과 옆 창 열기, 닫기, 크기 바뀜 중 50ms 넘는 긴 작업 0. 크기 전환 중 레이아웃 계산은 시작과 끝 한 번씩만 일어난다.
- 앱 CSS의 `:has()` 0개. CX 디자인 시스템의 44개는 앱 화면에서 쓰이는 것만 대체하거나 범위를 좁힌다.
- Claude 판단: CX 디자인 시스템 패키지(aipro-chat도 같이 씀)는 이번에 고치지 않는다. Desktop 묶음을 만들 때 Desktop 화면이 쓰지 않는 CX 규칙을 빼는 단계를 넣어 크기를 줄인다. 빠진 규칙 목록은 빌드 기록에 남긴다.
- 묶인 CSS 크기를 지금(1.39MB)의 절반 아래로. 덮어쓰기 층을 실제 규칙으로 합친다.
- 쉬는 동안 도는 배경 움직임 22개를 3개 이하로. 남기는 것: 메시 그라디언트(§5.5.2), 은은한 빛의 숨쉬기, 브랜드 새의 가벼운 떠 있기. 파스텔 흐름, 반짝임, 물결, 새 표정 반복은 쉬는 동안 멈추고, 상태가 바뀔 때만 한 번 움직인다(Claude 판단).

기능 기준:
- 1.3.0의 기능 중 워크플로우와 루틴 말고는 전부 그대로 찾고 쓸 수 있다. 기존 검사가 같은 결과로 통과한다.
- 비활성 단추는 이유를 보여 준다(예: "모델을 연결하면 열 수 있어요").

## 7. 지켜야 할 것

- 사용자에게 보이는 글은 한국어, 짧은 문장, 가운뎃점 없음.
- 새 화면은 주변 UI 양식을 재사용한다(목록 행, 진행 행, deck-dialog 계열, 금지 목록, 캡처 검수). 글자 대신 아이콘, 강조 버튼만 채움, 중복 버튼 금지, 입력창 포커스 링 금지, 대화 순서 보존.
- 성능 검사 수치는 기록한다. 메인 스레드 50ms가 기준이다.
- 시험, 한도, 정답을 통과용으로 고치지 않는다. 화면이 바뀌어 검사가 찾는 대상이 바뀌면, 같은 기능을 확인하도록 검사를 옮기고 그 사실을 기록한다.
- 라이선스: Lucide(ISC), Tabler(MIT), Pretendard(OFL-1.1). THIRD-PARTY-NOTICES에 추가한다. 공식 SF 글꼴과 SF Symbols는 쓰지 않는다.
- 공유 파일은 다시 읽은 뒤 정확한 치환으로만 고친다. Codex는 UI 트랙을 맡고, 업로드와 릴리스는 Claude가 한다.

## 8. 짓는 사람에게 맡기는 것

- 오른쪽 창의 탭 모양, 탭 개수 상한, 너비 기억 방식.
- `:has()`를 무엇으로 바꿀지(상태 속성을 부모에 다는 방식, 구조 클래스, 컨테이너 질의 등). 화면 결과가 같아야 한다.
- 덮어쓰기 층을 합치는 순서와 단위.
- 모래시계 그림의 세부 모양과 뒤집히는 리듬. 줄인 움직임 설정에서는 뒤집지 않고 정지 그림을 보인다.
- 아이콘 이름 대응표.
