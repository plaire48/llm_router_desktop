# 누비 Workspace 사내 POP3와 OpenWiki personal 연계

날짜: 2026-10-01
상태: 구현 전달 명세. 서버 정보와 입력 화면 위임은 사용자 결정이며 아래 기본 동작은 설계안이다. 구현과 실서비스 검증은 아직 수행하지 않았다.

## 목표와 사용자 결정

사용자는 사내 메일을 OpenWiki personal에 축적하고, 누비가 관련 메일과 개인 지식을 찾아 업무를 수행하기를 원한다. 이후 새 메일의 의미를 판단해 등록 스킬과 기존 도구를 실행하는 자동화로 확장한다.

- 서버: `pop3.samsung.net`
- 프로토콜: POP3
- 포트: `995`
- 접속 방식: 연결 시작부터 TLS를 사용하는 POP3S. 실제 인증 방식, 인증서 신뢰, UIDL와 서버별 제한은 사내 연결 시 확인한다.
- 아이디와 비밀번호는 누비 Workspace의 전용 연결 화면에서 받는다. 채팅으로 요청하지 않는다.
- 구현 범위는 `packages/nubi-desktop`와 `packages/openwiki`다. 브라우저 확장, Office와 라우터의 인증 계약을 변경하지 않는다.

## 기존 경로와 적용 방식

OpenWiki에는 personal 모드, 소스별 커넥터, raw 자료와 manifest, source별 수집 후 Wiki 갱신 경로가 있다. 현재 Gmail 커넥터는 Gmail API 전용이며 POP3를 지원하지 않는다.

관련 소스와 문서:

- `packages/openwiki/src/connectors/types.ts`, `registry.ts`, `sources/gmail.ts`
- `packages/openwiki/src/ingestion/ingestion.ts`, `agent/prompts/personal.ts`
- `packages/openwiki/src/config/openwiki-home.ts`
- `packages/nubi-desktop/docs/FORM-CLARITY-2026-09-25.md`
- `packages/nubi-desktop/docs/INTENT-DRIVEN-AGENT.md`, `RECOVERY-HARNESS.md`
- `packages/nubi-desktop/docs/OPENWIKI-EVIDENCE.md`

OpenWiki의 기존 personal 수집 구조를 확장한다. Workspace 호스트가 감시, 인증과 소스별 실행 소유권을 관리하고, 수집된 자료의 개인 Wiki 합성은 기존 OpenWiki 경로에 연결한다. 누비가 개인 Wiki를 읽는 것은 기존의 읽기 전용 검색/스냅샷 경로를 활용하며, 그 API에 쓰기나 외부 메일 인증 권한을 추가하지 않는다.

현재 `runOpenWikiIngestion`은 소스마다 최근 24시간이라는 범위를 모델 메시지와 커넥터에 전달한다. POP3는 날짜 기준 검색 프로토콜이 아니므로 이 기본값을 그대로 적용하지 않는다. POP3 연결에서는 UIDL checkpoint와 정확한 수집 배치가 기준이고, 갱신 메시지도 실제 배치 범위를 표시한다. 이 변경은 Gmail 등 기존 소스의 24시간 계약을 유지해야 한다.

## 연결 화면

기존 연결 관리 위치에 `사내 메일`을 추가한다. 채팅에서 메일 연결을 요청하면 같은 작업에 연결 카드를 표시하고 이 전용 폼을 연다. 비밀번호는 QuestionForm의 자유 답변이나 대화 초안 저장 기능을 사용하지 않는다.

기본 화면:

```text
사내 메일 연결
pop3.samsung.net:995 / TLS

아이디       [                       ]
비밀번호     [                       ] [표시 아이콘]

연결 이후의 새 메일을 개인 Wiki에 정리합니다.
정리에 사용할 모델: 현재 명시적으로 선택한 제공자와 모델
비밀번호는 앱 실행 중에만 보관합니다.

[취소] [연결하고 새 메일 정리]
```

- 입력된 아이디를 그대로 사용한다. 이메일 도메인을 임의로 덧붙이거나 로그인 이름 형식을 추정하지 않는다.
- 서버와 포트는 이 연결의 고정값이다. 일반 사용자에게 별도 설정을 요구하지 않는다.
- 입력 필드에 보이는 label, 적절한 autocomplete와 비밀번호 마스킹을 적용한다. 표시 아이콘에는 접근성 이름과 툴팁을 제공한다.
- 기존 Deck/CX 폼과 토큰을 재사용한다. 상단 상태 알림과 폼 안의 오류 설명을 사용하고 입력값을 로그에 넣지 않는다.
- 연결 중 중복 제출을 막는다. 취소하면 연결을 정리하고 늦게 도착한 응답으로 감시를 시작하지 않는다.
- 연결 성공 뒤 renderer의 비밀번호와 임시 입력 참조를 비운다. 실패 시 열린 폼 안에서만 수정할 수 있고, 폼을 닫으면 비밀번호를 버린다. JS 메모리의 물리적 완전 삭제를 보장한다고 표현하지 않는다.
- 모델 미연결이면 `메일 연결됨 / 정리할 모델 연결 필요`를 구분하고 Wiki 갱신을 대기시킨다. 모델 연결 실패 때문에 확인된 POP3 연결을 실패로 표시하지 않는다.
- 사내 POP3와 모델 목적지는 별개다. 사용자가 선택한 제공자와 모델을 표시하고 다른 모델로 조용히 전환하지 않는다.
- 연결 버튼은 표시한 새 메일 수집과 personal 갱신 범위를 활성화한다. 파일 반영, 셸 실행, 외부 전송 승인으로 확대하지 않는다.

연결 후 카드에는 `연결 상태`, `감시 상태`, `마지막 확인`, `수집된 메일`, `개인 Wiki 정리 상태`를 표시한다. 보조 동작은 `지금 확인`, `감시 일시중지`, `연결 해제`다. 확인 간격과 기존 메일 가져오기는 펼친 옵션에 둔다.

## 인증과 저장 범위

- 아이디와 비밀번호는 호스트의 검증된 전용 RPC를 통해 POP3 커넥터에만 전달한다. 비밀번호를 모델 도구 인자나 실행 명령 인자로 만들지 않는다.
- 기존 Desktop 인증 규칙에 따라 인증값은 호스트 메모리에만 보관한다. `.env`, SQLite, localStorage, Git, Wiki, source manifest와 일반 대화 기록에 저장하지 않는다.
- 재사용 가능한 POP3 코어는 인증을 호스트가 주입받게 한다. OpenWiki CLI의 다른 제공자 인증이나 Gmail 환경 파일에서 사내 메일 비밀번호를 가져오지 않는다.
- 로그는 단계, 오류 코드, 시각과 처리 개수만 저장한다. 라이브러리 오류의 command, cause, stack에 USER/PASS 값이 포함될 수 있으므로 원문 예외를 UI, 로그나 모델로 보내지 않는다.
- TLS 인증서와 호스트 이름을 검증한다. 평문 POP3로 fallback하거나 `rejectUnauthorized: false`를 사용하지 않는다. 추가 사내 CA가 필요하면 기존 호스트 신뢰 설정으로 처리하고 OS 신뢰 저장소를 임의로 수정하지 않는다.
- 앱 완전 종료 또는 호스트 재시작 시 연결 상태는 `재연결 필요`다. renderer 새로고침과 호스트 재시작을 구분한다. OS 자격 증명 저장은 현재 범위에 도입하지 않는다.
- 인증 실패는 자동 반복하지 않고 재입력을 기다린다.

## 감시와 중복 방지

1. TLS 연결과 로그인 후 UIDL 지원을 실제 확인한다. 미지원이면 감시를 활성화하지 않고 지원 필요 상태를 표시한다. 메일 개수, 순번, 날짜나 Message-ID만으로 안정적인 새 메일 판정을 했다고 표시하지 않는다.
2. 최초 연결은 완료된 UIDL 목록을 기준 목록으로 기록한다. 이 목록의 과거 메일은 기본적으로 수집하거나 LLM에 보내지 않는다. 기준 목록 저장 실패 시 감시 시작으로 표시하지 않는다.
3. 기본 확인 간격은 한 확인 사이클 종료 후 60초다. 서버의 LOGIN-DELAY 등 실제 제한이 있으면 이를 우선하며 상태와 다음 확인 시각에 반영한다.
4. connection별 확인은 하나만 실행한다. `지금 확인`도 같은 잠금과 주기 조정 경로를 사용한다. 네트워크 대기 중 새 타이머로 접속을 겹치지 않는다.
5. 새 UIDL의 메일을 제한된 개수와 크기로 RETR하고 안전한 앱 전용 raw 저장소와 manifest를 만든다. 사용자 경로, 메일 제목과 첨부 파일명을 저장 경로로 직접 사용하지 않는다.
6. raw 내구성, manifest와 수집 기록을 대조한 뒤 배치를 대기열에 등록한다. 조회한 UIDL을 즉시 처리 완료로 표시하지 않는다. 다운로드 중단, 파싱 실패와 Wiki 갱신 실패를 별도로 기록한다.
7. POP3 연결을 짧게 종료한 뒤 모델 정리를 시작한다. LLM 작업 때문에 maildrop 접속을 장시간 유지하지 않는다. 서버의 메일을 삭제하는 DELE는 사용하지 않는다.
8. 수집 기록은 `connectionId + UIDL`로 소스 범위를 구분한다. 다른 연결의 UIDL, 신뢰하지 않은 Message-ID를 자동 합치지 않는다. 동일 UIDL 복사본을 서버가 구분하지 못할 수 있다는 표준의 한계를 숨기지 않는다.
9. 새 메일이 없으면 모델을 호출하지 않는다. 새 배치는 같은 personal Wiki에 순차 갱신하고, 누적 자료 때문에 전체 Wiki를 매번 재생성하지 않는다.

네트워크 실패는 증가하는 대기와 jitter를 사용하며 감시 상태와 다음 시각을 남긴다. 모델 추론 복구는 기존 누비 복구를 재사용한다. 수집 연결 재시도, 모델 재시도와 업무 재실행은 별개다. 절전/재접속 후에는 기록한 UIDL과 서버에 남은 목록을 비교하며 고정 24시간으로 누락시키지 않는다. 서버에서 이미 삭제된 메일의 복구를 보장하지 않는다.

## Personal 지식과 출처

- raw 자료와 개인 Wiki는 Git 프로젝트 밖의 명시적으로 바인딩한 personal 저장소에 둔다. 기본 경로는 기존 OpenWiki의 사용자별 설정을 따르며 source instance를 별도 식별한다. 프로젝트 경로에서 실행했다는 이유로 개인 메일을 프로젝트 Wiki에 저장하지 않는다.
- 정상화된 자료에는 내부 메일 식별자, UIDL, 원문 해시, 제목, 발신자, 수신자, 메일 Date, 누비 수집 시각과 첨부 metadata를 구분한다. Date와 From은 메일의 주장이고 인증된 신원이나 서버 도착 시각으로 승격하지 않는다.
- threading은 References와 In-Reply-To를 활용하고 제목만 같은 메일을 확정된 같은 대화로 합치지 않는다.
- 개인 Wiki는 관련 인물, 프로젝트 맥락, 요청, 합의, 기한과 미해결 질문을 정리한다. 각 중요한 항목에 원문 ID와 날짜/해시를 연결하고 실제 원문으로 돌아갈 수 있는 조회 경로를 제공한다.
- 개인 Wiki의 출처와 신뢰 표시는 기존 personal synthesis 정책을 따른다. 코드 mode의 repository Claims가 메일 사실까지 검증한 것으로 표시하지 않는다.
- 읽기 전용 검색은 Wiki부터 수행하고 필요한 원문만 조회한다. source ID와 해당 personal 범위를 확인하고 다른 사용자/프로젝트 범위를 섞지 않는다.
- 사용자가 수정한 Wiki 본문을 자동 덮어쓰지 않는다. 변경 전 버전과 생성 구간의 소유권을 대조하고 충돌 시 제안을 보존해 기존 확인 흐름에 연결한다.
- 본문은 신뢰하지 않은 입력이다. 외부 이미지/추적 URL을 자동 로드하지 않고 첨부파일은 목록과 상태부터 표시한다. 첨부 내용은 지원하는 기존 문서 읽기 경로에서 명시한 범위로 처리하며 매크로나 스크립트를 실행하지 않는다.
- 보관 위치와 수집 범위를 사용자에게 보여준다. 연결 해제는 인증과 감시를 해제하며 기존 개인 지식을 조용히 삭제하지 않는다. 삭제는 raw/지식의 대상과 파생 항목을 구분하는 별도 사용자 동작이다.

## 업무 자동화 연결

최초 사용 흐름은 연결 이후 메일의 personal 갱신과 조회다. 원래 요청인 자동 스킬 트리거도 후속 단계의 목표로 보존한다.

- 사용자가 설정한 자연어 지침과 관련 스킬 카탈로그를 새 배치에 연결한다. 메일 본문을 새 사용자 지침이나 승인으로 저장하지 않는다.
- LLM은 구조화된 실행/보류/무관 판단과 원문 근거를 반환한다. 판단 결과를 기존 Pi의 계획, use_skill, 도구, HITL과 결과 검토 경로에 연결한다.
- 승인 필요한 실행은 대기열에서 해당 작업을 만들고 기다린다. 메일 수신이나 스킬 선택만으로 파일 반영, 실행 명령과 발송을 승인하지 않는다.
- 이벤트, 규칙 버전, 작업 ID와 결과 영수증을 연결한다. 사용자 규칙 변경만으로 이미 처리한 메일을 재실행하지 않는다. 재처리는 사용자가 대상과 동작을 명시해야 한다.
- Wiki 갱신 실패 때문에 이미 실행한 업무를 반복하지 않는다. 업무 결과 미확정 시 영수증과 실제 상태를 확인하고 맹목 재전송하지 않는다.
- SMTP와 자동 발송, PC가 꺼진 동안 처리하는 외부 서버, 서비스 설치, 임의 인증 저장과 기존 사용자 대화의 자동 전송은 현재 명세에 포함하지 않는다.

## 방법론과 오픈소스 판단

| 후보 또는 기존 구성 | 적용 방향 | 판단과 확인할 점 |
| --- | --- | --- |
| [node-pop3](https://github.com/node-pop3/node-pop3), MIT | POP3/TLS/UIDL/RETR 클라이언트 후보 | 실제 Command.js, Connection.js와 package.json을 확인했다. 사내 인증 호환성, 제한/취소, TLS 신뢰와 오류의 비밀 노출을 검증하고 버전/커밋/라이선스를 고정한 뒤 도입한다. 후보 검토를 실서비스 성공으로 표현하지 않는다. |
| [MailParser](https://github.com/nodemailer/mailparser), MIT | MIME 원문 파싱 후보 | 실제 lib/mail-parser.js와 package.json을 확인했다. 스트림과 크기 제한, 한국어 charset, malformed MIME, 안전한 첨부 처리를 검증한다. POP3 감시 기능은 제공하지 않는다. |
| [Fetchmail](https://www.fetchmail.info/fetchmail-man.html) | 비교한 완성 수집 데몬 | 지속 감시는 지원한다. 별도 프로그램 배포와 전달 설정, Windows 패키징 및 원본 라이선스 검토가 필요하므로 이번 내장안의 우선 선택에서 제외한다. |
| 기존 OpenWiki personal 커넥터와 합성 | 실제 구현 시 재사용 | Gmail의 API/OAuth 계약은 유지하고 POP3 소스와 호스트 인증 주입만 추가한다. 전체 별도 지식 프레임워크를 추가하지 않는다. |
| 기존 누비 Pi/CX/SQLite | 실행, 화면, 대기열과 복구에 재사용 | 새 에이전트 실행기/폼 라이브러리/외부 대기열 서버 없이 기능을 확장한다. 자동화 실행 소유권과 승인 계약을 중복 구현하지 않는다. |

공식 근거: [RFC 1939](https://www.rfc-editor.org/rfc/rfc1939)의 POP3와 UIDL, [RFC 8314 §3.1](https://datatracker.ietf.org/doc/html/rfc8314#section-3.1)의 995 implicit TLS. 수집과 업무 실행을 분리하는 durable inbox/outbox 패턴을 적용하되 외부 동작의 exactly-once를 보장한다고 주장하지 않는다. 신규 큐/스케줄러 패키지는 필요성이 입증되기 전 추가하지 않는다. 비용은 실제 새 메일의 분류/지식 합성/업무 모델 호출이며 빈 polling에는 모델 비용이 없다.

## 구현 순서와 완료 조건

1. 기존 구조와 잠금 버전을 재확인하고 두 라이브러리를 TLS POP3 fixture로 검증한다. 설치기와 native 빌드를 수행하지 않는다.
2. 전용 연결 폼, 메모리 인증, 연결 영수증, UIDL 기준 목록과 한 소유자의 감시를 구현한다.
3. 내구성 있는 raw/manifest와 대기열, personal 배치 갱신 및 누비의 개인 Wiki 조회를 연결한다.
4. 수집/정리/업무의 별도 상태를 실제 Theia 화면에서 확인한다. 기존 Nubi/CX 디자인 검사를 수행한다.
5. 사내 네트워크의 사용자 입력으로 실제 서버 로그인, UIDL, 원본 보존과 새 메일 수집을 검증한 뒤 personal 모델 결과를 확인한다. 인증정보를 개발 도구나 채팅으로 전달하지 않는다.
6. 이 흐름을 확인한 뒤 같은 자료와 기록에 자연어 자동화 규칙, 기존 스킬 선택과 HITL을 연결한다.

필수 검증:

- 연결값 고정, 로그인 이름 비변형, 마스킹/키보드/취소/중복 클릭, renderer 새로고침과 앱 재시작 구분.
- USER/PASS 오류, 모델 요청, SQLite/Git/Wiki/일반 로그에 테스트 비밀번호가 없는지 검사.
- TLS/호스트 불일치 거부, timeout, 비밀번호 실패 중단, UIDL 미지원, 첫 연결 기준 목록, 새 메일과 동일 메일 재조회.
- 네트워크 응답 중단, raw 저장 실패와 manifest/DB 중단 시 checkpoint가 수집 완료로 앞서 가지 않는지 확인.
- 절전 후 24시간보다 오래된 미수집 메일, 겹치는 수동/자동 확인, source/account 분리, DELE 미사용.
- 한국어 MIME/HTML/attachment 한도, 비정상 원문 격리, 유실/미지원 내용을 완료로 표시하지 않음.
- personal 근거와 원문 조회, 사용자 편집 충돌, 모델 미연결과 Wiki 실패 뒤 수집 영수증 보존.
- 자동화 취소/승인 대기/규칙 버전/응답 유실/재시작에서 같은 업무의 자동 재실행 방지.

TLS fixture와 합성 모델/브라우저 통과는 사내 POP3 로그인, Windows 백그라운드/절전, 실제 모델 지식 품질이나 업무 성공의 증거가 아니다. 문서 작성 자체는 구현 완료가 아니다.

## 구현 담당자에게 전달할 프롬프트

> 이 명세와 적용되는 AGENTS.md를 읽고 Nubi Workspace의 사내 메일 연결을 구현한다. pop3.samsung.net:995 implicit TLS를 고정하고 사용자 아이디/비밀번호는 기존 CX 전용 연결 폼에서만 받는다. 인증은 Desktop 호스트 메모리 계약을 지키고 LLM/대화/로그/영구 저장에 넣지 않는다. 기존 OpenWiki personal 커넥터 구조, raw/manifest, 누비 Pi/CX/SQLite를 재사용한다. UIDL baseline와 단일 감시, 수집/지식 갱신/업무 상태 분리, 재시작/취소/미확정 동작의 중복 방지를 작은 단계로 검증한다. POP3에는 Gmail 수집의 고정 24시간 범위를 그대로 적용하지 않는다. 라이브러리는 위 후보의 실제 소스, 라이선스와 사내 호환성을 확인해 고정한다. 모델 목적지와 personal 저장 범위를 표시하고 기존 HITL을 유지한다. 설치기/native 최종 빌드를 수행하지 않는다. 결과 보고는 소스/fixture/브라우저/Windows/실서버/실모델을 구분하고 미검증 항목을 남긴다.
