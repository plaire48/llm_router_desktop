# 누비 브라우저 A2A 통합 범위

2026-10-01 사용자 요청: A2A 프로토콜 정상 동작을 확인하고 미연결 부분을 구현 범위에 포함한다. 이 문서는 기존 초안 전달을 복구한 결과와 추가 필수 구현을 구분한다. Office 연결은 포함하지 않는다.

## 현재 확인

공식 A2A 1.0 JSON-RPC와 @a2a-js/sdk 1.2.0을 재사용한다. packages/nubi-a2a는 SendMessage/GetTask/ListTasks/CancelTask와 인증된 Agent Card를 제공한다. 실제 SDK HTTP 코어 검사 13개, 브라우저 Chrome 검사 7개가 통과했다. SDK는 Apache-2.0, jose는 MIT이며 기존 번들 고지를 유지한다. 별도 유사 프로토콜이나 외부 실행기를 추가하지 않는다.

브라우저 설정의 누비 작업 연결에서 로컬 서버 연결, 초안 가져오기, 사용자 전송, 기존 Pi 실행, 실제 호스트 답변 회신을 검증했다. 인증은 trusted session에 있고 모델 입력에 전달하지 않는다. 작성 중 초안과 미응답 질문은 덮어쓰지 않는다. 소스 버전이 바뀐 결과와 실패/대기 중 답변은 회신하지 않는다.

이는 nubi-collaboration-v1 초안 전달이다. COMPLETED는 결과 전달이며 artifact.verification은 not_run이다. 실제 웹 작업 성공, 독립 정답 또는 저장 성공을 뜻하지 않는다. 고정 합성 모델로 Chrome를 검사했으므로 실계정 모델의 정확도 증거도 아니다.

Desktop의 project-service.collaboration은 현재 a2a_not_enabled로 거절한다. nubi-task-v1 코어에는 수락/진행/완료/취소 계약이 있으나 브라우저 수신 UI는 아직 초안 계약만 사용한다. 내부 분석 에이전트는 같은 실행의 Pi 호출이며 A2A 워커가 아니다.

## 추가 필수 구현

1. Desktop 송신 화면과 실제 런타임 연결을 복구한다. 선택한 프로젝트와 근거 버전을 요청에 고정하며 사용자가 전송한 요청만 보낸다. 브라우저는 받은 요청을 기존 채팅에서 수락한 뒤 시작한다. Agent Card의 지원 skill을 실제 호스트 능력과 일치시키고 지원하지 않는 업무는 보내기 전에 거절한다.
2. nubi-task-v1을 동일 호스트 실행에 바인딩한다. Task ID/Context ID/메시지 ID와 누비 대화 ID/실행 ID를 호스트가 보관한다. 제출은 자동 실행이 아니다. 수락 이후 working, 실제 호스트 질문/승인 대기는 입력 대기, 실제 완료/실패/사용자 취소는 대응 상태로 전달한다. 코어에 없는 입력 대기 전이와 조회 계약을 먼저 추가한다. 모델이 상태를 임의로 완료 처리하지 못한다.
3. 수신 실행 결과 artifact를 추가한다. 요약, 실제 호스트 실행 ID, 요청/출처 버전, 관찰 시간, 독립 페이지/파일 근거와 미확인 항목을 함께 보낸다. 호스트 검사와 내용 정답을 구분하며 모델의 report_facts나 verification 값만으로 host_checked를 허용하지 않는다. 실행 영수증과 도구 readback이 없는 항목은 not_run/unknown으로 남긴다. 인증, 로컬 절대 다운로드 경로와 필요 없는 파일 본문은 전송하지 않는다.
4. CancelTask를 현재 바인딩된 실행의 중지에 연결한다. 수신 요청 수락은 사이트 입력/제출 승인이 아니다. 기존 사이트 HITL을 유지한다. 취소와 응답 유실에서 미확정 쓰기를 자동 재전송하지 않는다. 네트워크 실패는 GetTask와 호스트 영수증을 먼저 조회하고 같은 요청을 새 실행으로 만들지 않는다. 이미 완료된 쓰기를 취소 성공으로 되돌렸다고 표시하지 않는다.
5. 재시작 연결은 기존 프로젝트/수신자/요청 fingerprint와 호스트 실제 상태를 대조한다. 입력과 결과 버전 불일치는 거절한다. 새 연결이 기존 인증/승인/실행 권한을 승계하지 않는다. 초기 적용은 로컬 Desktop와 Chrome이며 LAN/클라우드 자동 발견, push/streaming/gRPC는 별도 범위다.

## 통과 기준

- 실제 Desktop와 Chrome 두 앱에서 같은 요청이 한 실행으로 왕복하고 결과가 원 요청과 근거 버전에 연결된다.
- 수락 전 모델 호출과 사이트 동작은 0회. 기존 채팅 초안과 대기 질문을 보존한다.
- 사이트 입력/파일 전송 승인 전 부작용은 0회. 도구 완료와 A2A 전달 완료를 분리해 표시한다.
- 반복 SendMessage와 응답 유실/재연결에서 같은 실행과 일회 승인을 재사용하고 중복 쓰기는 0회.
- 취소 후 자동 재개는 0회. 이미 발행된 미확정 동작은 상태 확인 뒤 미확인으로 남긴다.
- 외부 요청의 문구, report_facts와 완료 선언이 실제 호스트 검증을 대신하지 못한다.
- 실제 Chrome DOM/다운로드 파일과 수신 artifact를 독립 비교한다. 변경된 출처는 결과 수락 전에 거절한다.
- 실계정 Sol/Luna 고정 과제 왕복은 합성 모델 검사와 별도 기록한다. 전체 30개 평가를 하지 않은 경우 전체 점수는 미측정이다.

## 근거와 검증

[공식 명세](https://a2a-protocol.org/v1.0.0/specification/)와 설치된 SDK 소스, packages/nubi-a2a/tasks.mjs/task-agent.mjs/receiver.mjs/client.mjs 및 Desktop의 실제 비활성 진입점을 확인했다. 연결 코어가 있어 재사용 비용과 라이선스가 적합하다. 새로운 A2A 프레임워크로 교체할 이유는 확인되지 않았다.

기능별 상태와 실제 적용/검사 기록은 [브라우저 점검 보고서](../../../extensions/aipro-chat/docs/FEATURE-SITE-A2A-2026-10-01.md), [Chrome A2A 증거](../../../extensions/aipro-chat/verification/a2a-2026-10-01/chrome.json), [후보 기록](../../../extensions/aipro-chat/verification/site-procedures-2026-10-01/feature-candidate.json)에 남긴다. 추가 필수 구현은 아직 완료하지 않았으며 현재 복구 범위와 혼동하지 않는다.
