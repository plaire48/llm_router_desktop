# 누비 Office 실모델 실측 루프와 양식 스냅샷 재사용 개선

- 날짜: 2026-09-29
- 상태: 사용자 승인된 설계. 구현 계획은 `docs/superpowers/plans/2026-09-29-nubi-office-live-sim-eval.md`. 4절의 모의 호스트, 중계 세션, 기록, 실행기는 구현했다. 실모델 측정은 아직 실행하지 않았다.
- 환경 결정(2026-09-29): 당분간 macOS만 사용한다. 회사 PC는 실행만 가능하고 결과 파일을 반출할 수 없으므로 진단 묶음은 화면 요약을 옮겨 적는 형태로 따로 설계한다.
- 대상: `packages/nubi-office` (Windows Office 2016 확장). 이번 범위는 Excel 실행기.
- 기준 스냅샷: `claude/nubi-office-baseline-20260929` 브랜치, 커밋 `45a2913`. main과 작업 폴더는 변경하지 않았다.

## 1. 목적

사용자가 원하는 제품 흐름은 다음과 같다.

> 에이전트 하네스와 하위 에이전트가 **기존 문서 양식을 보고**, 그 결과를 **스냅샷으로 저장**하고, 이후 그 스냅샷을 **재사용해 새 문서를 작성**한다.

현재 소스에는 이 흐름의 제어 장치가 상당 부분 있지만 실제 모델로 실행해 본 적이 없다. 검사 708개는 모두 미리 작성한 모델 응답을 사용한다. 이번 작업은 실제 모델로 돌려 보고, 관찰한 실패를 근거로 하네스를 고친다.

## 2. 조사로 확인한 사실

| 항목 | 확인 내용 |
|---|---|
| 회귀 검사 기준선 | 708개 중 702 통과, 6 실패. 문서 기록(704/704)과 다르다 |
| 실모델 실행 | 없음. 모든 문서의 정확도는 `null` |
| 평가 실행기 | `eval/run.mjs`는 `win32`가 아니면 `blocked` |
| 평가 사례 | 편집 8, 새 문서 4, 양식 채우기 4. **양식 등록과 등록본 재사용 사례는 없음** |
| 모델 | ChatGPT SSO, `gpt-5.6-luna`. Office 고정 Pi 0.86.1 카탈로그에 존재 |
| 개발 PC | macOS, Windows/Office/dotnet/로컬 모델 없음 |

### 양식 흐름의 구조적 한계 (코드 확인)

| 위치 | 현재 동작 | 영향 |
|---|---|---|
| `template.mjs` `inspect` | 20셀씩 페이지 조회 | 300셀 양식이면 읽기만 15회 모델 왕복 |
| `template.mjs` `analyzeTemplate` | 셀별 판정, 힌트는 왼쪽/위쪽 이웃 문자열뿐 | 영역(제목, 입력부, 표, 합계) 개념 없음 |
| `define_template_fields` | 단일 셀 항목 최대 30개 | 반복 행이 있는 표를 항목으로 표현 못 함 |
| 저장 명세 `profile` | 주소, 이름, 값 종류, 필수 여부만 저장 | 재사용 시 업무 의미와 작성 규칙이 남지 않음 |
| 양식 분석 실행 | 단일 실행기가 순차 수행 | 하위 에이전트 분석기(`analysis-jobs`)가 양식 등록에는 연결되지 않음 |

이 한계는 실측 전에 코드에서 확인한 것이다. 실제 영향의 크기는 실측으로 확인한다.

## 3. 접근안과 선택

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 모의 호스트 + 기존 평가기 재사용** | native 프로토콜을 JS로 구현한 메모리 통합문서. 사례, 채점기, 드라이버는 기존 것 사용 | **채택** |
| B. LibreOffice를 호스트로 사용 | 실제 계산 엔진. 설치가 무겁고 느리며 Excel 2016이 아님 | 보류 |
| C. 기존 테스트 픽스처에 실모델 연결 | 1행 픽스처라 업무 사례 실행 불가 | 탈락 |

## 4. 구성

```
eval/sim/
  workbook.mjs        메모리 통합문서: 시트, 셀 값/수식/서식/배치 속성, 병합, 입력 제한, 재계산
  calc.mjs            수식 계산 어댑터 (평가 전용 개발 의존성 @ironcalc/nodejs를 감싼다)
  fault.mjs           native OfficeFault에 해당하는 오류 형식
  engine.mjs          native WorkbookEngine의 JS 이식: Compile, ValidateTarget, Verify, 영수증, 복원
  host.mjs            native 프로토콜 메서드 구현
  model-session.mjs   로그인 1회 유지, 유닉스 소켓으로 모델 호출 중계
  relay-providers.mjs 실행 프로세스에서 쓰는 providers 대역 (중계 호출만 담당)
  transcript.mjs      모델 호출 기록
  run.mjs             실측 실행기
  forms.mjs           합성 양식 4종과 정답 항목표
  form-scoring.mjs    항목 제안 채점
```

### 4.1 모의 호스트

`native/Nubi.Office.Core/WorkbookEngine.cs`와 `ExcelPort.cs`의 공개 계약을 그대로 따른다.

- 스냅샷 형식은 `PublicState`와 같다: `values, formulas, errors, displayTexts, formats{10개}, properties{9개 + validationValid}, fingerprint`.
- 쓰기 검증은 native와 같은 오류 코드를 반환한다: `out_of_scope, invalid_grid, invalid_value, unsupported_formula, unsupported_target, overlapping_operations, workbook_not_writable, validation_failed, verification_failed, cells_changed`.
- 문자열 값은 Excel처럼 텍스트로 저장하고, 수식은 쓰기 후 재계산한다.
- 양식 등록은 통합문서를 복제하고 레코드를 내장한 뒤 다시 읽어 비교한다. 파일 선택창은 사례가 지정한 가상 경로로 대체한다.
- native 계약 검사(`native/Nubi.Office.Tests/Program.cs`)의 시나리오를 JS 검사로 옮겨 이식 오류를 막는다.

**모의 호스트가 검증하지 못하는 것:** COM 동작, STA 스레드, 실제 Excel 표시 형식 렌더링, 행 높이 자동 조정, NASCA, 파일 저장.

### 4.2 모델 중계 세션

코드를 고칠 때마다 로그인을 반복하지 않도록 로그인 보유 프로세스와 실행 프로세스를 분리한다.

- `model-session.mjs`는 제품의 `createProviders().login('chatgpt')`를 그대로 호출한다. 사용자가 브라우저에서 직접 로그인한다.
- 인증값은 세션 프로세스 메모리에만 둔다. 파일, 로그, 기록에 쓰지 않는다. 다른 앱의 인증 저장소는 읽지 않는다.
- 실행 프로세스는 권한 `0700` 디렉터리의 유닉스 소켓으로 `complete(messages, tools)`만 요청한다. 인증값은 소켓을 건너가지 않는다.
- 실행 프로세스는 매번 새로 시작하므로 수정한 worker 소스가 즉시 반영된다.

### 4.3 기록

모델 호출마다 다음을 사례별 `transcript.jsonl`에 남긴다: 순번, 역할(계획/실행/수정 전 검토/단계 검토/최종 검토/복구/하위 분석), 보낸 메시지와 도구 목록의 크기, 받은 내용, 도구 호출 이름과 인자, 종료 사유, 지연, 사용량, 오류 코드.

사례 자료는 모두 합성 자료다. 회사 문서는 사용하지 않는다.

### 4.4 보고서

`kind: 'simulated-host-live-model-evaluation'`으로 기존 `live-excel-model-evaluation`과 분리한다. 저장 위치는 `verification/sim-live/<실행 ID>/`.

기존 평가 규칙을 유지한다.
- 복구 승인은 자동 통과시키지 않는다.
- 의미 채점 대기는 합격에 넣지 않는다.
- 사례별 한도는 10분, 모델 호출 80회, 호스트 동작 120회.

## 5. 사례

| 묶음 | 수 | 내용 |
|---|---:|---|
| 기존 편집 | 8 | `eval/cases.json` 그대로 |
| 기존 양식 채우기 | 4 | `eval/cases.json` 그대로 |
| **양식 등록** | 신규 | 실제 업무 양식 형태를 분석해 항목을 제안하고 등록 |
| **등록본 재사용** | 신규 | 등록한 스냅샷으로 사본을 만들어 대화로 작성 |
| 기존 새 문서 | 4 | 문서 호스트 모의 구현 후 추가 |

신규 양식은 병합 제목, 라벨과 입력 칸 쌍, 반복 행 표, 합계 수식, 입력 제한 목록, 날짜/코드 형식을 포함한다. 예: 출장 신청서, 지출 결의서, 교육 신청서, 견적서.

등록 사례의 채점 기준은 모델에게 보내지 않는다.
- 항목 재현율: 정답 입력 칸 중 제안된 비율
- 항목 정밀도: 제안 중 실제 입력 칸인 비율. 수식/라벨/병합 종속 칸을 입력으로 제안하면 감점
- 값 종류와 필수 여부 일치
- 모델 호출 수, 도구 호출 수, 소요 시간

## 6. 개선 루프

1. 기준선 실측: 사례당 1회, 불안정한 사례는 3회
2. 실패 분류
3. 상위 유형마다 재현 검사를 먼저 작성한 뒤 하네스 수정
4. 같은 사례 재실측, 전후 비교
5. `docs/IMPROVEMENT-STATUS.md`에 근거 경계와 함께 기록

| 실패 유형 | 관찰 지점 |
|---|---|
| 도구 미호출 | 실행기 응답에 도구 호출 없음, JSON 대체 경로 진입 |
| 인자 형식 오류 | `invalid_plan`, `tool_arguments_invalid`, 스키마 거절 |
| 계획 파싱 실패 | `task_plan_invalid` 후 재요청 횟수 |
| 검토 오판 | 결정적 검사는 통과인데 검토가 거절, 또는 그 반대 |
| 무진전 반복 | 도구 진전 감시기 개입, 복구 승인 요청 |
| 과다 호출 | 사례당 모델 호출 수와 시간 |
| 양식 이해 오류 | 항목 누락, 오분류, 표 미인식 |

## 7. 양식 스냅샷 개선 방향

기준선 결과를 본 뒤 확정한다. 아래는 코드에서 확인한 한계에 대한 후보이며, native 프로토콜을 바꾸지 않는 worker 쪽 변경을 우선한다.

| 후보 | 내용 | native 변경 |
|---|---|---|
| 구조 개요 도구 | 셀 20개씩 넘기는 대신 영역 단위 요약을 한 번에 제공 | 없음 |
| 하위 에이전트 분석 | 영역별 읽기 전용 분석을 병렬 실행하고 부모가 통합. 기존 `createAnalysisJobs` 재사용 | 없음 |
| 스냅샷 명세 확장 | 영역, 표, 계산 칸, 작성 규칙을 레코드에 추가. native 검사는 30,000자와 필수 키만 확인 | 없음 |
| 표 항목 | 반복 행을 가진 표를 항목으로 등록하고 행 단위로 채움 | 없음 (`set_values` 영역 쓰기 사용) |
| 재사용 시 값 추출 | 사용자가 준 자료에서 항목 값을 뽑고 부족한 것만 질문 | 없음 |

## 8. 하지 않는 것

- 설치 파일과 native 빌드. 사용자가 최종 빌드를 요청한 뒤에만 한다.
- 공유 소스 `extensions/aipro-chat` 수정. 다른 작업이 진행 중이므로 읽기만 한다. 수정이 필요하면 따로 확인받는다.
- Word와 PowerPoint. Excel 흐름을 개선한 뒤 같은 방식으로 확대한다.
- 회사 공용 카탈로그, 재시작 후 실행 복원.

## 9. 근거의 경계

이 작업의 실측 결과는 **`gpt-5.6-luna` + 모의 호스트** 기준이다.

- 사내 Qwen 3.8 27B의 성능이 아니다. Luna가 더 강한 모델이므로 약한 모델에서만 나타나는 실패는 드러나지 않을 수 있다.
- 실제 Excel 2016 COM 동작이 아니다.
- 합성 사례이므로 대표 기업 양식의 정확도가 아니다.

문서와 보고서에 이 구분을 항상 함께 적는다.
