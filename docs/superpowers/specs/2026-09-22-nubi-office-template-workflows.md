# 누비 Office 기업용 양식 카탈로그와 대화형 작성

- 날짜: 2026-09-22
- 상태: 사용자 아이디어를 구체화한 기능 설계 초안. 현재 0.2.0 빌드에 구현된 기능이 아니다.
- 대상: Windows Excel 2016, `packages/nubi-office`, 기업 내 다양한 부서·업무 양식, 누비의 모든 기존 LLM 연결.
- 사용자 보정: 정해진 몇 종류의 양식에 맞춘 제품이 아니라, 다양한 기업 양식을 계속 등록·설정·운영하는 구조가 필요하다.
- 예시의 역할: 아래 견적 계산 등은 엔진 검증을 위한 테스트 사례다. 내장 양식 종류나 실제 고객의 업무 범위를 확정한 것이 아니다.

## 0. 제품의 중심

**기업 양식 카탈로그 + 양식 등록/설정 + 대화형 작성 + Excel 공동 편집**을 하나의 흐름으로 제공한다. 새 양식을 추가할 때마다 프로그램을 개발하지 않고, 원본 Excel 파일과 선언형 설정으로 등록한다. 지원하지 않는 새로운 Excel 기능이 발견됐을 때만 공통 엔진을 확장한다.

양식 한 건의 구성은 `원본 파일 + 항목/셀 연결 + 입력 검증 + 계산/참조 정보 + 질문/분기 절차 + 버전/배포 범위`다. 이 설정을 내부 저장 형식으로 사용하고, 일반 사용자는 셀 선택과 한국어 항목 편집 화면을 사용한다.

| 사용자 역할 | 주요 작업 |
|---|---|
| 양식 담당자 | 기존 파일 등록, 누비가 찾은 항목 검토, 업무 설명·입력 규칙·질문 순서 설정, 새 버전 작성 |
| 업무 사용자 | 내 업무에 맞는 양식 검색/추천, 대화·폼·Excel에서 입력과 수정, 작성 재개 |
| 운영 담당자 | 회사·부서·업무별 분류와 사용 범위, 양식 버전과 배포 상태 운영 |

역할의 분리는 기능 책임을 설명한다. 한 사람이 여러 역할을 맡거나 회사의 기존 검토 절차를 연결할 수 있다.

양식 목록과 배포 버전은 회사 공용 카탈로그에서 관리하고, 실제 편집은 로컬 Excel에서 실행하는 구성을 기본 제안으로 한다. 로컬 카탈로그는 개발·체험·오프라인 캐시용 어댑터로 둔다. 현재 패키지에 공용 카탈로그 서버나 기업 인증이 이미 있다고 가정하지 않는다.

## 1. 사용자에게 제공할 흐름

**양식 목록 → 양식 선택 → 필요한 항목 확인 → 대화 또는 직접 입력 → Excel 계산 → 수정·확인 → 파일 저장.**

처음 쓰는 양식은 열린 Excel 문서나 기존 양식 파일에서 등록한다. 누비가 발견한 입력 항목·수식·참고 정보를 보여주고 양식 담당자가 업무 의미와 연결할 셀을 수정한다. 등록 이후 업무 사용자는 셀 주소를 반복해서 지정하지 않는다.

사용자가 업무를 말하면, 접근 가능한 양식의 이름·용도·설명·부서·태그에서 후보를 찾는다. 후보가 여러 개라면 업무에 영향을 주는 차이만 한 번에 묻고 선택한 뒤 작성으로 넘어간다. 존재하지 않는 양식을 추천하거나 작성 데이터로 원본을 자동 생성했다고 표시하지 않는다.

등록 화면의 예시:

> “견적서에서 고객명·품목·수량·단가를 입력 항목으로 찾았습니다. 공급가액·세액·총액에는 기존 수식이 있습니다. 납기일도 매번 입력받을까요?”

작성 화면의 예시:

> 사용자: “A사에 키보드 10개, 개당 3만원으로 견적서 작성해줘.”
>
> 누비: “고객명·품목·수량·단가를 채웠습니다. 납기일은 언제인가요?”
>
> 사용자가 Excel 수량 셀을 직접 12로 수정.
>
> 누비: “Excel에서 바꾼 수량 12개를 반영했습니다.”

마지막 두 안내는 실제 셀 readback과 변경 감지에 성공한 경우에만 표시한다. 모호한 “3만원”은 해당 양식이 정한 통화·단위를 사용하며, 단위가 등록되지 않았다면 질문한다.

## 2. 양식 목록과 등록

목록에는 양식명, 용도, 소유 부서, 버전, 최근 사용, 작성 중 건수를 표시한다. 회사·부서·업무 분류, 검색, 태그, 즐겨찾기와 최근 사용으로 많은 양식을 탐색한다. 분류와 양식 종류를 코드에 고정하지 않으며 실제 제공되는 양식만 사용 가능 상태로 표시한다. 목록 API는 페이지 단위로 조회하고 전체 파일을 함께 내려받지 않는다.

각 항목에 `새 문서 작성`, `작성 이어가기`, `양식 설정`을 제공한다. 일반 문서 내용을 고치는 것과 원본 양식을 개정하는 행동을 구분한다. 사용자가 작성 중인 문서를 수정했다고 등록 양식의 수식이나 기본값이 자동으로 바뀌지 않는다.

등록은 다음 순서로 진행한다.

1. 현재 문서 또는 사용자가 선택한 Excel 파일을 읽는다.
2. 시트·이름 정의·표·수식·입력 제한·고정 문구를 구조 목록으로 수집한다.
3. 입력 후보와 계산 영역을 제안하고, `항목명 ↔ Excel 위치`를 사용자가 조정한다. 주소를 누르면 실제 위치를 강조한다.
4. 필수 여부·값 종류·단위·기본값·질문 문구·선택지를 지정한다. 날짜와 숫자 표시 형식만으로 업무 의미를 확정하지 않는다.
5. 원본 파일의 사본, 필드 정의, 양식 버전을 카탈로그 초안으로 저장한다. 기존 고객명 등 매번 바뀌는 값은 입력 기본값으로 남길지 등록 화면에서 정한다. 배포 범위를 정한 버전만 일반 목록에 노출한다. 회사에 양식 검토 절차가 있다면 이 단계에 연결한다.

파일은 Excel 자체의 복제/템플릿 기능을 사용한다. 셀 값 JSON만으로 원본을 다시 만드는 방식을 피해야 그림·테두리·행 높이·병합·인쇄 설정 등의 보존 가능성을 높일 수 있다. `SaveCopyAs`는 열린 문서를 바꾸지 않고 사본을 저장하고, `Workbooks.Add(Template)`는 기존 Excel 파일을 바탕으로 새 문서를 만든다. 실제 보존 범위는 테스트 양식과 Windows에서 확인한다. [SaveCopyAs](https://learn.microsoft.com/en-us/office/vba/api/excel.workbook.savecopyas), [Workbooks.Add](https://learn.microsoft.com/en-us/office/vba/api/excel.workbooks.add)

## 3. 셀의 업무 역할

| 역할 | 예 | 누비가 하는 일 |
|---|---|---|
| 입력 | 고객명·수량·단가·납기일 | 대화나 입력 폼에서 값을 받아 지정된 셀에 쓴다. |
| 계산 | 공급가액·세액·총액 | 원래 수식을 유지하고 Excel이 계산한 결과를 읽는다. |
| 고정 | 제목·회사 정보·안내 문구·로고 | 작성 중 유지한다. 변경은 양식 개정으로 다룬다. |
| 참조 | 품목 코드표·단가표·드롭다운 목록 | 현재 입력에 필요한 항목을 조회하고 선택지로 사용한다. |

수식이 없는 빈 셀을 모두 입력 셀로 판정하지 않는다. 색·잠금 상태·인접 라벨은 후보 제안에만 사용한다. 같은 라벨이 여러 곳에 있거나 병합·반복 행 때문에 위치가 모호하면 실제 셀을 보여주며 항목 연결을 확인한다.

연결은 `안정적인 필드 ID → 이름 정의/표 열/검증된 셀 위치`로 관리한다. 기존 이름 정의가 있으면 우선 활용하되 중복 이름·시트별 이름 범위를 구분한다. 주소만 있는 양식은 시트 식별자와 구조 지문도 보관한다. 이름 정의가 있다고 구조 변경에 항상 안전하다고 가정하지 않는다. [Workbook.Names](https://learn.microsoft.com/en-us/office/vba/api/excel.workbook.names)

## 4. 수식과 기존 기능 활용

등록 시 수식 원문, R1C1 표현, 계산 결과, 오류, 이름 정의와 데이터 유효성 규칙을 보관한다. 원본 파일은 전체 보존하고, 모델에는 현재 항목에 필요한 구조와 관련 수식만 전달한다. 모든 셀을 매번 프롬프트에 넣지 않는다. 수식 의존성을 완전히 해석하지 못한 경우 이를 미해석 상태로 남긴다. [FormulaR1C1](https://learn.microsoft.com/en-us/office/vba/api/excel.range.formular1c1), [Validation](https://learn.microsoft.com/en-us/office/vba/api/excel.range.validation)

일반 작성에서 수식 셀은 쓰기 대상에서 제외한다. 입력이 바뀌면 관련 계산을 실행하고 결과 셀을 다시 읽는다. LLM이 계산한 금액을 합계 수식 위에 덮어쓰지 않는다. 다중 시트 의존성은 한 영역의 `Calculate` 호출만으로 완결됐다고 판단하지 않고, 의존 시트 계산과 계산 완료 상태까지 확인한다. 계산 대상과 결과의 신선도를 보장할 수 없으면 `계산 확인 필요`로 남긴다. [Excel 계산 기능](https://learn.microsoft.com/en-us/office/vba/api/excel.application.calculate)

반복 품목은 첫 범위에서 미리 지정한 표/행 슬롯에 매핑한다. 수식 채우기는 등록된 계산 열 규칙을 따른다. 행 삽입·표 확장·이름 이동은 구조 변경이므로 별도 구현·복구 검증을 거쳐 지원한다. 기존 함수 사용과 임의 VBA/UDF 실행 지원은 동일하지 않다. 매크로·외부 연결·추가 기능 의존 양식은 의존성을 표시하고 개별 환경 검증 없이 지원 완료로 분류하지 않는다.

## 5. 대화와 입력 폼

같은 작성 세션을 채팅과 입력 폼이 공유한다. 각 필드에 `미입력 / 초안 / 반영됨 / 직접 수정됨 / 확인 필요` 상태와 값의 출처를 둔다.

- 사용자가 여러 값을 한 번에 말하면 알아낸 항목부터 채우고 남은 필수 항목만 묻는다.
- 누비는 금액·날짜·코드·선택지·단위를 등록 규칙에 맞춰 검증한다. `0`, `false`를 미입력으로 취급하지 않는다.
- 폼에서 값을 고치거나 대화로 “단가만 2만8천원으로”라고 말하면 같은 필드 초안을 갱신한다.
- “반영해줘” 또는 적용 버튼은 준비된 입력 변경에 대한 실행 요청이다. 각 셀마다 승인을 다시 묻지 않는다.
- 요청이 즉시 작성을 명시했다면 명확한 입력은 바로 적용하고, 애매한 항목만 대화로 정한다.
- 필수값 충족, 입력 검증, 실제 반영, 계산 검증, 파일 저장은 각각 별도 상태다. 입력 완료만으로 저장 완료를 표시하지 않는다.

다양한 기업 양식을 표현하기 위해 단일 값뿐 아니라 반복 행/표, 여러 시트의 항목 그룹, 코드 선택, 조건부 필수 항목, 단위, 기본값, 조회 기준을 정의할 수 있어야 한다. 예를 들어 특정 업무 구분을 선택했을 때 추가 항목을 묻는 규칙을 지원한다. 화면 표시·필수 조건·입력 검증은 허용된 선언형 규칙으로 실행하며, 양식별 JavaScript나 VBA를 생성해 실행하는 방식으로 해결하지 않는다.

공통 질문 흐름은 `이미 있는 값 읽기 → 대화에서 알아낸 값 연결 → 유효성 검사 → 부족하거나 모호한 항목 묻기 → 반영과 계산 확인`이다. 양식별 안내 문구와 질문 우선순위는 담당자가 설정한다. 특정 부서 양식에 맞춰 프롬프트나 UI 코드를 분기하지 않는다.

## 6. 직접 편집과 충돌 처리

Excel의 직접 셀 변경과 수식 재계산을 각각 관찰한다. `Worksheet.Change`는 재계산 결과 변경에는 발생하지 않으므로 계산 이벤트/완료 후 readback을 추가해야 한다. 이벤트는 변경 사실을 알리는 용도로 사용하고, 쓰기 직전 실제 셀 상태 검사도 유지한다. [Worksheet.Change](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheet.change), [Worksheet.Calculate](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheet.calculate%28even%29)

필드마다 마지막으로 읽은 Excel 값, 현재 Excel 값, 아직 적용하지 않은 대화/폼 초안을 비교한다.

| 상황 | 처리 |
|---|---|
| Excel만 바뀜 | 현재 값을 대화·폼에 반영하고 동일 항목을 다시 묻지 않는다. |
| 초안만 바뀜 | 적용 대상 변경으로 표시한다. |
| 양쪽 값이 같아짐 | 충돌 없이 반영된 값으로 합친다. |
| 양쪽이 서로 다르게 바뀜 | `Excel 값 사용 / 제안 값 적용`을 해당 필드에 표시한다. 다른 독립 필드 작업은 계속한다. |
| 수식 또는 입력 위치가 바뀜 | 값 충돌과 구분해 항목 연결을 다시 확인한다. 오래된 주소에 쓰지 않는다. |

누비가 쓴 값의 readback도 같은 상태 관리 경로로 처리한다. 자체 쓰기를 새 사용자 입력으로 받아 다시 쓰는 순환을 막는다. 다중 셀 붙여넣기·Excel 기본 Undo·수동 계산 모드·시트 이동·닫기 후 다시 열기도 검증 대상이다.

## 7. 저장 구조와 도구 계약

양식은 원본 사본과 버전별 매핑/규칙을 묶는다. 작성 세션은 특정 양식 버전과 실제 작업 문서를 가리킨다. 원본 버전이 바뀌어도 작성 중 문서에 자동 적용하지 않는다. 로컬 저장한 작성 상태와 실제 Excel 파일이 다를 수 있으므로 재진입 시 실제 문서를 다시 읽는다.

공용 카탈로그는 파일 저장소와 검색용 메타데이터를 분리한다. 로컬에 필요한 양식 버전만 캐시하며 원본 해시를 확인한다. 기본 상태는 `초안 / 배포됨 / 종료됨`이고, 배포된 버전의 파일과 필드 정의는 함께 고정한다. 접근 권한은 카탈로그 서버에서 메타데이터 조회와 원본 파일 다운로드 모두에 적용한다. 회사 카탈로그 인증과 LLM 제공자 인증은 별도 계약으로 둔다.

제안하는 저장 단위:

- `Template`: 양식 ID, 이름, 용도, 소유 부서, 태그, 접근 범위, 현재 배포 버전.
- `TemplateVersion`: 원본 파일/해시, 스키마 버전, 시트/이름/표 목록, 필드 정의, 수식/참조 정보, 지원 기능 상태.
- `FieldDefinition`: 안정적인 ID, 업무 명칭, 역할, 값 종류, 단위, 연결 위치, 필수/표시 조건, 선택지, 질문, 입력 검증.
- `TemplateSession`: 선택 버전, 작업 문서, 항목별 기준 값/현재 값/초안, 작성 단계, 충돌, 계산 검증 상태.

필드 연결은 단일 셀, 등록된 여러 셀, 반복 표 열을 표현한다. 단일 값의 여러 위치 표시가 필요한 양식도 의도를 등록한 뒤 지원한다. 복잡한 수식 의존성과 조회 원본은 필요할 때 부분 조회한다. 기업 전체 양식과 문서 데이터를 한 번에 LLM에 보내지 않는다.

```mermaid
flowchart LR
    Author[양식 담당자와 등록 화면] --> Library[기업 양식 카탈로그와 버전]
    Library --> Cache[현재 양식의 로컬 캐시]
    Cache --> Session[작성 세션]
    Chat[누비 대화] <--> Draft[항목별 초안과 검증]
    Form[입력 폼] <--> Draft
    Session --> Draft
    Draft --> Engine[항목 연결과 변경 엔진]
    Engine <--> Excel[실제 Excel 문서]
    Excel --> Result[기존 수식 계산과 결과 확인]
    Result --> Draft
```

등록·열기·복원은 네이티브 앱의 사용자 동작으로 실행한다. LLM에는 `read_template_state`, `propose_field_values`, `apply_field_values`, `verify_template_results`처럼 목적이 정해진 도구를 제공한다. 모델은 임의 셀 주소 대신 등록된 필드 ID와 값을 보낸다. 호스트가 실제 위치를 결정하고 입력 역할·자료형·버전·예상 상태를 다시 검증한다.

양식 작성 모드에서 기존의 자유 `apply_changes` 도구를 함께 노출하지 않는다. `수식 수정`이라는 명시적 양식 개정 작업에 들어갈 때만 수식 변경을 별도 계획한다. 모델이 바뀌어도 필드와 편집 규칙은 동일하며 AI Pro·ChatGPT·FabriX·AI Pro CLI·OpenAI 호환 연결을 그대로 사용한다.

## 8. 현재 코드에서 필요한 확장

현재 `WorkbookEngine`은 연속 선택 범위 1,000셀과 메모리 변경 기록에 한정된다. 이 값의 제한만 높여 다중 시트 양식을 처리하지 않는다.

| 현재 구성 | 추가할 책임 |
|---|---|
| `ExcelPort` | 원본 파일 사본/새 문서, 이름·표·검증 규칙 조회, 실제 입력/계산 영역 읽기, 변경·계산 이벤트 |
| `WorkbookEngine` | 불연속 입력 범위와 다중 시트 변경을 작업 단위로 관리하고, 입력 역할과 수식 불변성 검사 |
| 새 `TemplateCatalog` | 회사/부서 카탈로그 API와 로컬 어댑터, 검색·페이지 조회, 원본 사본, 버전, 항목 매핑과 규칙 |
| 새 `TemplateSession` | 초안/현재 값/기준 값, 부족한 필수 항목, 충돌, 재개 상태 |
| `worker/agent.mjs` | 양식 전용 도구와 질문 진행, 필드 ID 기준 값 제안, 결과 근거 |
| `src/app.js`·작업창 | 양식 목록, 등록 검토, 항목 입력, 계산 결과, 충돌 선택, 이어쓰기 |

기존 작업 ID 중복 방지·UI/STA COM 실행·부분 쓰기 후 재시도 금지·readback·복구를 유지한다. 다중 영역 적용은 Excel 전체 트랜잭션처럼 표시하지 않으며, 중간 실패 시 완료된 영역과 복구 가능한 영역을 정확히 기록한다. 원본 양식 보관과 값의 변경 기록은 서로 다른 복구 수단이다.

## 9. 수락 시나리오

1. 서로 구조가 다른 여러 부서 양식을 코드 수정 없이 등록한다. 단일 시트·다중 시트·반복 표·병합 제목·이름 정의·조건부 입력 등 기능별 검증 자료를 갖춘다. 한 종류 양식의 성공으로 전체 지원을 주장하지 않는다.
2. 고객명·품목·수량·단가를 한 문장으로 주면 올바른 필드에 연결되고 남은 필수 항목만 묻는다.
3. 지정한 세율 10%, 수량 10, 단가 30,000인 예시에서 공급가 300,000·세액 30,000·총액 330,000을 실제 Excel 계산 결과로 확인한다. 모든 계산 수식이 유지된다.
4. 사용자가 수량을 12로 직접 고치면 폼·대화와 총액 396,000이 일치한다. 누비가 10으로 되돌리지 않는다.
5. 적용 대기 중 같은 단가를 양쪽에서 다르게 고치면 해당 필드 충돌만 표시한다.
6. 반복 항목과 다른 시트의 단가표·이름 정의·드롭다운이 있는 양식에서 매핑과 결과를 확인한다.
7. 필수값 누락·잘못된 날짜·선택지 외 값·계산 오류를 완료 상태로 표시하지 않는다.
8. 수식을 직접 바꾸거나 행을 이동하면 양식 불일치를 감지한다. 수식 변경을 값 변경으로 덮어쓰지 않는다.
9. 저장·닫기·다시 열기 후 실제 문서에 맞춰 이어 쓴다. 저장하지 않은 초안은 저장된 셀 값과 구분한다.
10. 모든 제공자에 같은 도구 계약을 적용하고 실제 모델 평가를 수행한다. 로컬 합성 테스트와 Windows Excel 2016/실계정 검증을 구분한다.
11. 부서와 접근 범위에 맞는 양식만 검색·다운로드한다. 파일 다운로드에도 서버 권한 검사가 적용된다.
12. 같은 양식의 새 버전을 배포해도 진행 중 세션은 기존 버전을 유지한다. 새 작성은 배포 버전으로 시작한다.
13. 예시 부하 데이터 1,000건으로 카탈로그 페이지 조회·검색·선택 파일 로딩을 측정한다. 이 수치는 실제 기업의 양식 수를 추정한 것이 아니며 성능 요구는 실환경 규모에 맞춰 확정한다.

## 10. 적용 순서

첫 구현부터 카탈로그·양식 정의·작성 세션을 분리하되, 수락 검증용 다양한 양식을 사용해 공통 엔진을 완성한다. 양식 하나를 제품 코드에 넣고 다른 양식을 나중에 복제하는 접근을 피한다.

1. 양식 등록/분석과 필드 검토, 버전이 고정된 카탈로그 계약, 입력/계산/참조/고정 역할을 구현한다.
2. 반복 입력과 다중 시트, 질문 분기, 대화/폼/Excel 양방향 동기화, 계산 확인·복구를 연결한다.
3. 기업 공용 카탈로그 배포, 기존 기업 인증 연결, 실제 부서 양식군 평가와 Windows 설치를 검증한다.

모든 기존 수식/서식을 보존하는 것, 그 기능을 읽어 이해하는 것, 자동으로 수정하는 것은 각각 지원 상태를 기록한다. 새 양식은 이 기능별 지원표로 검토해 사용 범위를 알 수 있게 한다.

## 11. 구현 인계

> `packages/nubi-office`에 위 기업용 양식 카탈로그·등록/설정·작성 세션을 구현하라. 양식 종류나 업무 필드를 제품 코드에 고정하지 말고 원본 Excel 파일과 선언형 정의로 새 양식을 등록하라. 기존 모든 모델 연결과 Pi 실행기를 유지하라. 공용 카탈로그 API와 로컬 어댑터 계약을 분리하고, 입력/계산/참조/고정 역할, 반복 표와 다중 시트, 조건부 질문, 새 문서 생성, 대화/폼/Excel 양방향 동기화, 기존 수식 재계산·검증을 완결하라. 실제 양식에서 확인한 필드 ID만 편집하게 하며 입력·반영·계산·저장 상태를 구분하라. 다중 범위 복구를 확보하기 전에 전체 양식 편집을 노출하지 말라. 다양한 실제 부서 양식과 계산 검증용 파일을 구분해 테스트하고 기능별 지원 범위와 실환경 증거를 기록하라. 현재 0.2.0 ZIP에 이미 이 기능이 들어 있다고 표시하지 말라.

## 12. 0.6.0 선택 범위 기반 구현 현황

2026-09-22: `packages/nubi-office`에 저장 값/표시 텍스트 분리, 날짜 체계·잠금·병합 위치·입력 제한·행 높이/열 너비 조회, 텍스트/숫자/퍼센트/날짜/논리 값 정규화, 지원 서식 10개 수정, 선택 범위 안 기준 셀 서식 재사용과 값/서식 동시 검증을 연결했다. 수식/비대상 서식 보존과 복원을 컴파일된 변경 엔진으로 검사했다. 작업창의 `셀 값과 서식`에서 관찰값을 확인한다.

이는 위 설계의 기업 카탈로그·양식 등록/버전·필드 ID 매핑·반복 표·다중 시트·조건부 질문을 구현한 것은 아니다. COM과 LLM 테스트 대역 검사 결과는 실제 Windows Excel 2016 및 회사 양식 품질의 증거가 아니다. 지원 속성과 검사 증거는 패키지 README 0.6.0 절을 따른다.

## 13. 문서 전체 작성이 상위 목적

사용자가 “요구사항에 대해서 문서를 처음부터 끝까지 만들어내는 것”으로 목적을 명확히 했다. 양식 카탈로그와 셀 도구는 문서 완성을 위한 구성 요소다. 0.7.0에는 별도 새 문서 작성 흐름을 연결했다. 상세 경로와 경계는 `2026-09-22-nubi-office-document-authoring.md`를 따른다. 기존 파일을 읽어 회사 양식으로 작성하는 카탈로그 구현이 자동으로 완료된 것은 아니다.
