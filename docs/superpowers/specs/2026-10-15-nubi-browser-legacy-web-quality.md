# 범용 Browser Agent의 복잡한 구형 웹 대응

사용자 요구 2026-10-15: 사내 그룹웨어는 복잡한 폼, 오래된 구현과 의미 정보가 부족한 요소를 포함한다. 단순하고 접근성 이름이 완전한 화면만으로 품질을 판단하지 않는다. 사이트 전용 실행기로 분기하지 않고 범용 관찰/대상 확인/결과 검증을 강화한다.

## 관찰 전략

| 상황 | 공통 처리 | 실행 전 확인 |
| --- | --- | --- |
| role/label이 있는 요소 | 기존 접근성 snapshot과 ref 우선 | 현재 탭/문서/관찰에서 대상이 유일한지 |
| label 없는 input, div 버튼, 중복 문구 | 호스트가 허용한 DOM 구조/주변 텍스트/행과 열/속성으로 후보 제공 | 추정한 역할과 실제 요소를 구분하고 모호한 후보를 임의 첫 요소로 결정하지 않음 |
| 중첩 iframe, 본문 편집기 | frame 트리와 각 frame 문서의 현재 상태 관찰 | 탭/상위 문서뿐 아니라 frame/하위 문서 교체와 ref 소속까지 확인 |
| 주소록/조직도 팝업, 별도 작성 창 | opener/자식 창 소유 관계와 실제 새 탭을 확인 | 원래 작업과 창 바인딩 유지. 인증 창은 사용자에게 전달 |
| 이미지 버튼, canvas 등 DOM 정보 부족 | 필요한 영역의 캡처와 시각 판독을 선택 호출 | 이미지 영역/viewport/스크롤/배율/문서 버전에 결합. 읽기와 시각 조작은 별도 capability |
| 지연 렌더링, 동적 행 교체, 덮개 | 목표 요소가 보이고 조작 가능한지와 작업별 준비 조건 확인 | 고정 시간 sleep이나 모든 요청 종료만으로 준비 판정하지 않음 |
| contenteditable/iframe 에디터, 조직도 수신자 칩 | 지원되는 실제 입력 동작 후 결과를 관찰 | 표시된 문자열, 실제 선택된 주소/수신자, 저장 후 재열기 결과를 구분 |

우선 저비용 DOM 관찰을 사용하고 부족한 영역만 보강한다. 캡처/시각 모델을 매 행동마다 호출하지 않는다. DOM에서 보이지 않는 것을 반복 snapshot 호출로 해결했다고 취급하지 않는다. 필요한 capability가 없거나 대상이 계속 모호하면 작업을 보존하고 사용자 선택/직접 조작을 요청한다.

화면 인식은 후보 탐색의 근거다. 캡처에서 글자를 읽었다고 정확한 클릭이나 제출 성공이 검증된 것은 아니다. 좌표 실행을 도입할 경우 현재 화면에 결합한 제한된 호스트 도구와 승인/발행 영수증/후속 검증이 먼저 필요하다. 모델에 임의 JavaScript나 브라우저 전체 권한을 열어 우회하지 않는다.

## 결과 확인과 복구

- 수신자 표시 이름과 실제 주소, To/Cc/Bcc, 회신 원문/스레드를 독립 확인한다.
- 에디터에 값이 보이는 것과 애플리케이션이 값을 인식/저장한 것을 구분한다. 초안 저장 뒤 재열어 본문과 주소를 확인한다.
- 제출/전송은 정확한 대상과 내용에 대한 사용자 승인을 따르며 응답 유실 시 먼저 실제 상태를 읽는다. 성공 메시지가 없다는 이유로 다시 전송하지 않는다.
- 브라우저 외부 전용 구성요소나 지원하지 않는 렌더링/입력 방식은 미지원/미확인으로 남긴다. 새 도구 하나로 모든 구형 시스템이 지원된다고 보장하지 않는다.

## 구현 전 소스와의 차이

2026-10-15 소스 확인: 기존 Desktop의 Playwright 경로에는 snapshot/find/click/type/fill_form/select/hover/scroll/wait와 별도 capture가 있다. BrowserHost에는 팝업 opener/POST/세션 연결 경로가 있다. 이는 선택 코드의 확인이며 복잡한 사내 화면의 성공 증거가 아니다.

독립 core의 현재 `Binding`은 tabId/documentId/revision이다. frame과 하위 문서의 세대는 아직 명시 필드로 모델링하지 않았다. 따라서 중첩 frame의 정확한 바인딩을 이미 지원한다고 표시하지 않는다. 호스트 어댑터의 frame/ref 스코프 및 교체 감지 계약을 확정하고 호환 버전/체크포인트 영향을 검토한 뒤 구현해야 한다.

기존 capture는 시각 판독용이다. 현재 노출된 도구 목록만으로 범용 이미지 좌표 클릭이 구현됐다고 주장하지 않는다. DOM 구조 보강, frame 제어, 커스텀 에디터의 실제 저장, 시각 fallback은 각각 검증 대상이다.

## 개발/고정 평가에 포함할 변형

1. label/aria 없는 입력과 이미지 버튼, 같은 문구의 다른 행
2. 중첩/다른 origin frame, frame만 교체되며 상위 문서는 같은 경우
3. 주소록 팝업의 동명이인, 실제 주소와 표시 이름 불일치
4. iframe/contenteditable 본문, 입력 이벤트 뒤 별도 저장 반영
5. 느린 목록/가상 스크롤/DOM 교체/덮개로 오래된 ref가 되는 화면
6. DOM 정보가 부족한 화면과 시각 관찰도 모호해 사용자 개입이 필요한 화면

업무 의미가 같은 정상 화면과 구조가 나쁜 화면을 쌍으로 비교한다. JSM/메일은 개발 사례이고 같은 구조 문제를 가진 다른 업무 화면도 별도 고정 평가에 둔다. 위 6개 변형은 아직 구현/통과한 fixture가 아니다. 기존 단순 fixture 23개 검사 결과로 이 난이도를 통과 처리하지 않는다.

정확한 대상, 실제 저장/재열기 결과, 미승인/중복 실행, 실패 후 재개와 지연을 각각 측정한다. 추가 관찰/시각 모델 호출 비용도 전체 시간에 포함한다. 실제 사내/Windows/SSO 성공은 별도 증거가 있을 때만 표시한다.

공식 근거: [Playwright frames](https://playwright.dev/docs/frames), [locators](https://playwright.dev/docs/locators), [actionability](https://playwright.dev/docs/actionability). frame 내부를 명시적으로 다루고 최신 요소를 찾으며 조작 가능 여부를 확인하는 기능을 검토했다. 위 누비 적용과 평가 항목은 이를 바탕으로 한 설계이며 Playwright가 모든 레거시 UI를 자동 이해한다는 뜻이 아니다.

## 현재 구현과 확인 범위

후속 Pi/모델 연결과 편집 불가 대상의 발행 전 차단은 v0.3.0에서 추가했다. [실측/실패 이력](../../research/2026-10-15-browser-agent-pi-live.md)은 아래 v0.2.0의 도구 단독 성적과 별도로 기록한다. 합성 복합 양식을 실제 모델로 완료했지만 사내/Windows/실제 로그인 품질은 미검증이다.

사용자의 개발 지시 후 `packages/nubi-browser-agent` v0.2.0에 다음을 구현했다.

- API 1.1의 선택 frameTreeRevision과 observationId 검사. 1.0 호스트의 기존 관찰도 호환하며 frame-aware 관찰에는 정확한 observationId를 요구한다.
- 선택 `./playwright` 어댑터의 호스트 주입 Page/탭 전용 MCP client와 접근 분류. 브라우저/제공자 인증/Workspace를 자체 시작하지 않는다.
- 프레임별 문서 세대와 DOM/input 변화 관찰, 전체 frame tree의 바인딩. 상위 URL이 그대로여도 하위 문서 교체와 사용자 편집은 이전 참조를 무효화한다.
- 공식 MCP snapshot/ref 경로와 선택 구조 관찰. 이름 없는 입력의 표 행 문맥과 현재 ElementHandle을 관찰한 opaque targetId로 제공한다. native 보강은 같은 Playwright의 제한된 고정 동작이고 임의 selector/JavaScript 입력을 허용하지 않는다.
- 공식 MCP의 실제 도구 schema로 ref/target 인자를 협상한다. 이번 설치본의 인자와 기존 Desktop 선택 소스가 달랐으므로 버전 문자열만으로 동일 계약이라고 가정하지 않았다. Desktop 제품 코드는 변경하지 않았다.
- 성공한 동작 뒤의 새 관찰을 다음 실행에서 재사용한다. 관찰이 늦거나 바뀌면 동작 영수증만 반환하고 다시 관찰한다. 저장 완료는 별도 서버 상태와 재열기로 확인한다.
- 취소한 waiter와 진행 중인 실제 MCP 호출을 분리해 추적하고 해제 때 남은 호출 정리를 기다린다. 미확정은 유지하며 호스트 Page/client를 닫지 않는다.

기존 schema 1 체크포인트에 현재 ref/ElementHandle/관찰을 영속화하지 않으므로 새 schema migration은 추가하지 않았다. pending fingerprint와 receipt는 그대로 남고 재개는 새 관찰을 요구한다.

검증은 core/fixture 26개와 실제 Chrome+공식 MCP 10개다. label 없는 input, 지연 contenteditable의 실제 입력 이벤트, 중첩/다른 출처 iframe, 팝업 생성, 하위 문서/DOM 교체, 사용자 편집과 취소 중 해제를 확인했다. 로컬 저장 요청의 응답과 독립 서버 상태, 다시 연 화면을 각각 확인했다. 클릭 응답만 받고 저장이 끝나기 전에 검사한 초기 시험 오류는 실제 저장 응답을 기다리는 검사로 수정했다.

개발용 로컬 도구 지연은 [별도 측정](../../../verification/browser-agent-dual-benchmark-2026-10-15/legacy-browser-latency.json)에 기록한다. 모델/사내망/실제 SSO/Windows와 실제 두 참조군 비교는 포함하지 않는다. Stagehand/browser-use/DevTools는 이번에 추가하지 않았다. 추가 모델/엔진 없이 해결할 수 있는 관찰/바인딩의 공백부터 기존 Playwright로 개선했다.

시각 모델 fallback/좌표 실행, 이미지 전용 요소, 닫힌 Shadow DOM, 주소록의 실제 선택/복잡한 이벤트 연동, 임의 사이트의 완료 oracle과 자연어 자율 판단은 아직 미구현 또는 미검증이다. 이 한계를 시험 통과 숫자로 덮지 않는다.
