## Why

세 누비가 같은 프로젝트를 다루더라도 요구사항·코드 버전·문서 설명·실행 결과가 분리되면 사용자가 근거를 다시 설명해야 한다. 사용자가 개선한 문서를 보존하면서 소스 변경을 반영할 공통 작업 단위가 필요하다.

## What Changes

- 소스와 함께 요구사항, 사용자 지식, Wiki를 Git으로 관리한다.
- 자동 생성 문서는 바로 덮어쓰지 않고 기준 버전이 있는 변경안으로 제시한다.
- Desktop, 웹, Office가 요구사항 ID와 검증 근거를 전달한다.
- 앱별 실행/승인/취소 책임과 기존 단독 사용을 유지한다.

## Capabilities

### New Capabilities

- `project-knowledge`: 문서 개선 보존, 최신성, 근거를 포함하는 작업 전달.

### Modified Capabilities

없음. 이 디렉터리는 신규 설계 예제이며 실제 배포 기능을 수정하지 않는다.

## Impact

Desktop 프로젝트 서비스와 호스트별 연결 adapter가 후속 구현 대상이다. 기존 OpenWiki 생성/Claims, Git, 웹 읽기 연결, Office 실행 계약을 재사용한다. 런타임 설치와 실제 연결은 이번 예제에 포함되지 않는다.
