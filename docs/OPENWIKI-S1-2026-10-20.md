# S1 검색 전체화와 문맥 청크 검증 보고

**구현과 로컬 측정 완료, 최종 품질 수용 보류.** 검색 합성 지표와 교대3쌍 p95 기준은 통과했다. 실모델은 두 모델 모두 최종200응답/오류0이나 교차 검토16문항이 미판정이고 Sonnet 인용 정확도가 낮아졌다. 전체 답변 품질 통과나 릴리스 준비 완료로 표시하지 않는다. 업로드는 Claude. CI14차는 녹색(fast19분53초), Q2는2/3이며 이번 변경의 Actions는 아직 실행하지 않았다.

## 결과와 결정

기존 MiniSearch/Claims를 재사용하고 의존성/임베딩/리랭커 추가0. 누적64MiB에서 뒤쪽 문서가 누락되는 제한을 제거하고 페이지1MiB, 원문LRU8MiB, 소유자당 루트2개,16개 단위 양보, 검색 결과 전체 JSON10000자 한도를 유지한다. 소스/Claims/ignore의 현재 해시를 확인하고 비밀/제외 경로를 색인하지 않는다. 기존401번째 문서는 기준선도 통과하므로 실제 RED는 누적64MiB 누락이다.

원문 절에 파일/제목 계층과 존재하는 요약만 검색 힌트로 붙인다. 원본 발췌와 줄/offset/해시를 보존하고 힌트나 과거 Claims를 사실 증거로 승격하지 않는다. RRF 가중치는 유지했다. 독립 검토에서 반복 절이 후보24개/근거12개를 독점하는 결함을 재현해 페이지별2개 제한을 후보 상한보다 먼저 적용했다. 이후 독립 파일 읽기는4개씩 제한 병렬화하고 같은 버전의 검증/읽기 Promise를 공유해 중복 해시 확인을 없앴다. 고정64참조 상한과 인용 직전 파일 버전 재확인은 유지한다. 원문 출처에는 ‘검토 기록 없음’과 ‘원본 변경’을 구분하며 기록된 검토도 사실 참됨으로 표시하지 않는다.

## 고정200문항과 검색 지표

합성 개발 코퍼스1020파일/620Markdown, 사실/절차/코드/복합/답 없음 각40문항. 정답 span과 해시는 고정하며 런타임/모델 입력에 넣지 않았다. Recall 분모는 답이 있는160문항의 필수 근거200묶음이다. 개발 정답셋이며 독립 holdout이나 사내 데이터 성적이 아니다.

| 소스 | Recall@5 | MRR | 근거 전부 검색 | 검색 p95 |
|---|---:|---:|---:|---:|
| 최초 기준선 |67.5%|0.5143|59.375%|42.624ms|
| 전체 색인 |67.5%|0.5143|59.375%|38.007ms|
| 문맥 청크 중간본 |80%|0.7160|75%|34.705ms|

검색 결과가 비는 경우의 답 없음 정밀도100%, 재현율12.5%는 유지했다. 이 값은 모델이 의미적으로 답변을 거절한 정밀도가 아니다. 후보 다양성 수정 뒤 중간 성능3쌍 중2쌍은 악화했고 전부 보존했다(기준/수정80.171/42.857,48.483/52.990,45.473/119.933ms). 실패 측정을 삭제하거나 최초 표를 덮어쓰지 않았다.

제한 병렬 읽기와 중복 검증 제거 뒤 미리 고정한 교대3쌍의 **모든 쌍에서** p95 비증가를 요구했다. 원본200표본, cold 질의와 부하를 모두 저장했다.
