# Codex 진행/검토 표시 대조와 Workspace 반영

사용자 요청: 반영이나 승인을 누르면 폼을 붙잡지 않고 실제 작업을 바로 보여 준다. 문법 검사 도구의 지원 범위를 승인 판단으로 넘기지 않는다. 모호한 남은 확인 경고는 Codex의 흐름과 대조해 정리한다.

## 확인한 Codex 근거

- 설치된 `/Applications/ChatGPT.app/Contents/Resources/app.asar`의 패키지 이름은 `openai-codex-electron`, 버전은 `26.1007.71326`이다. 정적 한국어 리소스에서 작업 중, 승인 대기, 실패한 검사와 검토 댓글을 별도로 표시하는 키를 확인했다. 선택한 최소 리소스 근거는 `packages/nubi-desktop/verification/codex-progress-benchmark-2026-10-23/local-labels.json`에 남겼다. 실제 Codex 모델 실행이나 화면 조작을 벤치마크한 기록은 아니다.
- [OpenAI App Server 설명](https://openai.com/index/unlocking-the-codex-harness/): 도구 시작, 승인 요청/응답, 도구 완료와 메시지 조각을 각각 전달한다. 승인에 응답한 뒤 계속되는 실행 상태와 공개 메시지를 클라이언트가 표시할 수 있는 구조다.
- [Codex 변경 검토 문서](https://developers.openai.com/codex/app/review/): 변경 diff와 실행/검토 근거를 확인하고 구체적이며 우선순위가 있는 발견 사항을 검토한다. 승인/스테이징과 검토 결과를 구분한다.

여기서 가져온 제품 판단은 아래와 같다. Codex가 모든 상황에서 같은 문구/배치를 쓴다거나 문법 검사를 하지 않는다는 주장은 하지 않는다. 특히 기본 화면에 특정 배지가 없다는 사실을 문서만으로 입증하지 않는다.

| 상황 | 이전 Workspace | 적용한 흐름 |
|---|---|---|
| 반영/승인/답변 제출 | Promise가 끝날 때까지 같은 폼이 비활성으로 남음 | 명시적 제출 직후 숨김/inert, 처리 중 항목은 대기 수에서 제외. 초안/선택/오류 상태는 유지 |
| 파일 저장과 다음 실행 사이 | 저장된 폼이 사라진 뒤 다음 실행이 뜰 때까지 공백 가능 | 파일 대조/저장/재확인 단계와 다음 작업 준비 상태 표시 |
| 도구/명령 진행 | 주로 1초 폴링 후 표시 | 저장된 상태 변경의 프로젝트 ID 신호를 받고 현재 범위 상태를 다시 읽음. 폴링은 복구용으로 유지 |
| 작성 중 공개 응답 | 실행이 끝나기 전에는 숨김 | 실행의 진행 영역에 초안으로 갱신. 최종 답변은 기존 검토/메시지 위치에 한 번 전달 |
| 실행 중 명령 출력 | 기록을 펼쳐야 읽을 수 있음 | 접힌 기록 아래에도 실제 최신 출력 일부를 표시. 전체 기록과 중지는 기존 화면 사용 |
| 내장 문법 검사 범위 | 지원하지 않는 형식을 승인 폼의 배지로 표시 | 배지를 제거. 기존 문법 검사/오류 차단과 해시/저장 재읽기는 유지 |
| 미확인 결과 | 일반적인 남은 확인 경고 | 실제 미확인 항목이나 다음 동작을 중립적으로 표시. 검토 응답 실패는 원인/코드/복구와 함께 보존 |

별도 검토 항목, 미확인 근거, 누락, 오류나 다음 동작이 없는 일반 답변에는 빈 검토 경고를 추가하지 않는다. 이를 검증 성공으로 승격하거나 성공 배지를 붙이지도 않는다. 실제 미확인 항목이 있으면 구체적인 내용은 계속 표시한다.

## 실행과 보존 계약

`Store`의 저장/삭제 완료와 actor의 공개 스트림이 `notifyActivity`를 호출한다. 작업/제안/명령/프로세스만 대상으로 하며 이벤트에는 프로젝트 ID만 담는다. 소스 본문, 질문, 자격 증명이나 reasoning을 방송하지 않는다. worker의 notifier는 첫 변경을 바로 전송하고 80ms 내 후속 변경을 합쳐 마지막 변경도 전달한다. 연결 종료 시 타이머를 해제한다. 알림 실패가 이미 저장한 작업을 실패시키거나 재실행하지 않는다.

화면은 현재 프로젝트/대화의 상태를 읽으며 읽는 동안 생긴 추가 신호는 한 번 더 처리한다. 다른 프로젝트의 신호와 화면 이동 후 늦은 응답은 버린다. 질문/명령/파일 제출 잠금은 한 번의 명시적 동작만 실행한다. 폼은 처리 중에도 마운트를 유지해 오류와 초안을 보존하고 결과가 거절되면 복원한다. 제출을 실행 성공이나 파일 저장 성공으로 표시하지 않는다.

actor 텍스트 신호는 `workspace_stream`으로 분리한다. 현재 실행의 텍스트/메모/시각만 메모리에서 읽으며 SQLite 대화 전체, 제안 본문이나 백그라운드 프로젝트 상태를 토큰마다 다시 읽지 않는다. 실행별 증가 revision으로 늦은 전체 snapshot이 더 최신의 공개 초안을 되돌리지 않도록 하며, 새 실행과 완료 상태는 기존 상태 변경으로 교체한다. 원래 메시지 기준점과 다른 대화 객체도 보존한다.

초안 표시는 `modelTransport`의 기존 actor 공개 텍스트만 사용한다. 다른 목적의 planner/reviewer 응답과 provider reasoning은 이 초안에 넣지 않는다. 미완성 Markdown을 매 토큰 다시 파싱하지 않고 평문으로 표시한다. 기존 완료 판정, 승인 fingerprint, 보호된 편집기와 실제 저장 재읽기를 우회하지 않는다.

모델에는 지원하지 않는 내장 문법 분석을 코드 오류로 해석하거나 사용자 판단으로 넘기지 말고, 가능한 프로젝트 검사나 실제 화면 확인을 기존 승인 규칙 아래 진행하도록 지침을 보완했다. 실제 모델이 모든 업무에서 이를 수행했다는 검증은 별도다.

## 검증 범위

확정 결과는 `packages/nubi-desktop/verification/realtime-*/`의 보고서와 로그에 기록한다. `npm run test:realtime-actions`는 관련 Node 검사, Electron 빌드, 응답을 지연시킨 실제 Electron renderer의 1280/440px 흐름과 실제 앱 worker/IPC 신호 전달을 확인한다. 합성 승인/모델 텍스트와 실제 로컬 worker의 저장을 구분한다.

- 전체 기반 회귀: 2,609개 중 2,409 통과, 실패 0, 의도적인 기능 비활성 생략 200. `realtime-full-unit-2026-10-23.log`에 보존했다. 이후 가벼운 스트림/빈 검토 표시 보완을 이전 회귀 사례의 실행 버전으로 소급하지 않는다.
- 최종 집중 게이트: 13개 통과, 실패 0. 실제 actor 응답 지연, 상태 알림, worker 전달, 알림 합치기, 기록을 읽지 않는 스트림, 늦은 snapshot, 빈 검토와 구체적인 미확인 표시를 포함한다. 별도 관련 회귀 27개도 통과했다.
- 최종 실제 Electron renderer: 1280/440px 두 흐름 통과, 화면 오류 0. 응답을 붙잡은 상태의 폼 접힘은 각각 38/24ms였다. 중복 클릭, 실패 후 초안과 오류 복원, 후속 실행의 공백, 공개 스트림과 입력 초점, 명령 출력, 미확인/오류/빈 검토를 확인했다. 이 시간은 제공자 응답 시간이나 실제 파일 저장 완료 시간이 아니다.
- 최종 빌드 앱과 실제 worker/IPC: 임시 새 작업이 69ms에 화면에 반영됐다. 유휴 스트림 조회는 대화/다른 프로젝트 없이 `{stream:null}`만 반환했다. 실제 모델은 호출하지 않았다.
- 기존 질문/승인/순서 Electron 5장면 통과. 1280/440/360px에서 폼 하나, 초안 보존, 시작선과 원래 진행 순서를 확인했고 기존 검토 오류 상세도 유지했다.
- Electron 빌드와 디자인 검사 통과. 기존 Windows Bash CJS의 `import.meta` 빌드 경고와 macOS PowerShell 실행 부재는 그대로 구분한다.

집계: `packages/nubi-desktop/verification/realtime-interaction-2026-10-23.json`.

Windows GPU/설치판, 실제 회사 메일/SSO, 실제 제공자 모델과의 업무 성공률은 이 변경의 통과 근거에 포함하지 않는다. Codex와 같은 업무를 실모델로 실행한 속도/정확도 비교나 전체 OpenCode 품질 동등성도 이 기록의 결론이 아니다.
